# G18／P18.6-M2：巢狀 true／else 原 Lexer int 常值真返回與安全歸票（2026-11-13）

## 已核准來源及本批缺口

- 起點：main `22d78fc7eaf859cc9fc052e8ef0734523038fa94`（PR #760 已 Squash merge；推送主線兩個工作流程均 completed/success）。
- 原 Checker 已接受同步 self 方法內的 `if(bool){ if(bool){ return 41 } else { return 23 } } return self.n+1`，但 `PreparedPrivateSelfMethod::prepare` 只將巢狀返回編譯為 `self.int` 或 `self.int +/- Lexer int`，合法原 Lexer int 常值於 Runtime 計畫階段錯拒。
- 此批不修改 Lexer、Parser、Checker、型別或借用規格；只接通原 Checker 已授權的 `TermKind::Scalar(Integer)`，並用原 Lexer `TokenKind::Integer` 的半開範圍及完整字面內容雙重認證，拒絕未核准 int 與來源篡改。

## 真工程

1. 原 `true` 直接返回葉及巢狀 `else` 返回葉各自支援 `PrivateSelfIntReturn::Constant(i64)`。重用同一原 `integer_i64` 範圍檢查，保留原 `VerifiedMethodSafety.checked_returns`、真葉 `NodeSpan` 和 `matches_source` 重新編譯全欄位比對；不按名稱或字面值假推導返回。
2. 方法真執行只在外層已進入、內層從原已核准 bool 形參或 Lexer bool 常值選葉後返回對應常值；外層 false 仍落至最後原 Checked return，未選 true/else 的溢位不得提前運算。
3. 仍由原 `BorrowSafety` 唯一 self 票據管理 `SharedRead`，真正常值不產生 UTF-8 `ResourceEvent`。故障不假造 `Returned`，沿用 R05 退票與完整框架退出。

## 一、步驟 1：MVP-A 功能矩陣（P01.1／P01.4）

| 領域 | 首版接受 | 首版拒絕／不納入 | 依據 |
|---|---|---|---|
| 輸入與頂層 | 單一 `.voil` 檔，`fn`／`const`／`var` 可交錯 | 多檔、`import`、任意頂層執行語句、`share` | AR02、AT01、AU06、AS05 |
| 基本型別 | `int` 有號 64 位元、`bool`、小寫布林值 | `float`／`str`／`none` 等其他宣告型別 | AS01、D06、D02 |
| 函式 | `fn 名稱()->int` 或 `->bool`；`main()->int` 必備；函式可前向參照／合法遞迴 | 參數、其他回傳型別、無標註回傳、一般執行式函式呼叫語句 | AT02～03、AU01～03、AV02～03、AW06、AY03 |
| 區塊／條件 | 非空 `{}`、`if`／`else if`／`else`，每個一般條件必有 `()`，內容限 `bool` 常值或已綁定同型別名稱 | 條件中 `and`／`or`／`not`／比較／函式呼叫等；空語句區塊 | J06、AT04～05、AU04 |
| 一般宣告 | 型別明確標註的 `var`／`const`，`const` 立即給值、`var` 可延後；初始化 RHS 限同型別常值或可讀的已初始化名稱 | 推導型別、宣告初值加減或函式呼叫、`const` 延後賦值 | E06、H03、I01、AX02 |
| 賦值 | `var` 首次及再次賦值，只接受同型別常值或已合法初始化的具名來源 | `const` 再寫入、算術或呼叫結果作 RHS | AZ01、AY02 |
| 回傳／算術 | 函式體尾端明確 `return`，合法分支可提前 `return`；二元 `+`／`-` 左結合、算術括號、合法 `int` 零引數呼叫可參與加減 | `*`／`/`、未列運算子、布林加減、任意呼叫位置、一元負號（此首版不列入） | AU03、AV01／04、AW01～03、AX01、AY01、AZ02 |
| 其他完整語言功能 | 首版不引入 | Optional `is`、容器、`struct`、`while`／`for`、`async`、字串等 | AR05、AS05 |

**限定解讀**：首版「不接受的語法」沿用 AS05；不代表完整 voiles 語言不允許這些功能。既有 D05 複合賦值可作回傳的完整語言決策仍有效，但不因其存在就自動擴大 MVP-A。

## 二、步驟 2：受限首版文法（P01.1）

**BR01-A（依使用者 2026-10-25 編譯器具體相容建議委任，由助手選定）**：使用下列**閉合於首版驗收範圍的 EBNF 參考契約**；文法只列首版接受的構造。已有明確合法性的完整語言寫法，不因未列入此首版文法而變成永久非法。

```ebnf
Source       = Layout, TopDecl, { Separator, TopDecl }, Layout ;
TopDecl      = Function | TopBinding ;
Function     = "fn", Name, "(", ")", "->", Type, Block ;
Type         = "int" | "bool" ;
TopBinding   = Binding ;
Block        = "{", Layout, Statement, { Separator, Statement }, Layout, "}" ;
Statement    = Binding | Assignment | IfChain | Return ;
Binding      = "const", Name, ":", Type, "=", Init
             | "var", Name, ":", Type, [ "=", Init ] ;
Assignment   = Name, "=", Init ;
IfChain      = "if", "(", Condition, ")", Block,
               { "else", "if", "(", Condition, ")", Block },
               [ "else", Block ] ;
Condition    = "true" | "false" | Name ;
Return       = "return", ReturnValue ;
ReturnValue  = "true" | "false" | Arithmetic ;
Init         = "true" | "false" | Integer | Name ;
Arithmetic   = Atom, { ( "+" | "-" ), Atom } ;
Atom         = Integer | Name | Name, "(", ")" | "(", Arithmetic, ")" ;
Separator    = Newline, { Newline } ;
Layout       = { Newline } ;
Newline      = LF | CR | CRLF ;
```

**詞彙和版面限制**：

1. `Block` 內必須至少一個實際語句；`Function` 的**最外層最後一條語句**必須為 `Return`。其餘已核准分支提前返回仍可用，但本版不以此強行推定所有可達路徑驗證或不可達語句的一般合法性（AU03、AY01、AZ02）。
2. `Separator` 是**語句間的換行**，不接受分號；頂層宣告間以換行分開，無意義空白行及 `#` 單行註解忽略（D01、F06）。`if`／`else if`／`else` 中間的 `}` 銜接按核准的大括號與條件鏈例子使用（允許 `}else{`）；此文法不藉此制定完整語言全部排版／註解交界規則。
3. 圓括號內依 E07 允許換行；此處 `Layout` 為易讀省略，實際詞彙階段必須把圓括號內換行處理為合法續行，不可直接誤判成語句分隔。括號外其他跨行運算式未在首版增加許可。
4. `Integer` 沿用十進位及 `0x`／`0b`／`0o` 小寫進位前綴、合法數字間連續底線／前綴後底線及前導零的**已核准部分**（I03、J01～02、K01～03、L01～02）。其他底線邊界不自動放行。超出有號 64 位元範圍者須遵照既定錯誤原則；一元負號未在首版子集核准，不得自動推成完整語言取消負整數。
5. `Name` 在目前首批可追溯測試使用 ASCII 英文字母／底線開頭、後續英數及底線，且不得等於已列關鍵字；**此為 MVP-A 最小詞彙驗收支援集合的保守推薦**。Unicode 識別名稱在**完整 voiles** 的詞彙政策與其他合法範圍仍待日後獨立確認，不據此宣稱完整語言禁止 Unicode 名稱。識別字與關鍵字相鄰及註解的全部複雜詞彙邊界仍不得靠此段自創復原。
6. `Init` 只能用於 `const`／`var` 宣告及 `var` 賦值，**不因 `ReturnValue` 可含算術與函式呼叫就擴張**。`Arithmetic` 的合法運算元、呼叫結果、同型別和括號使用按既有 AV／AW／AX；`bool` 仍不能參與加減。首版 `Return` 必須有值。
7. **跨域邊界**：頂層變數初始化的實際求值時間、不同種類名稱重名衝突、所有權、不可達語句一般處置及非法語法後全面復原皆不由這份 EBNF 直接裁決。遇到會改動已核准語言可觀測行為的情境，應另選相容具體推薦或保留待決，不用例子偷渡合法性。

## 三、步驟 3：內部 AST 契約（P01.1）

**BR02-A（依相容編譯器建議委任由助手選定）**：沿用 BP01 節點概念分組，但僅要求以下**資訊不變量**，具體 Rust `enum`、`struct`、欄位擺法、所有權與生命週期配置由後續架構決定。

| 節點範疇 | 首版內部節點 | 必備資訊／測試 |
|---|---|---|
| 來源／頂層 | `SourceFile`、`FunctionDecl`、`TopLevelBinding` | 宣告順序、函式名稱、明確回傳型別、檔案及宣告半開跨度 |
| 語句 | `Block`、`LocalBinding`、`Assignment`、`IfChain`、`Return` | 各實際語句及分支次序、原始位置；`if` 與 `else if` 不被當成 Optional 專用檢查 |
| 表達式 | `IntLiteral`、`BoolLiteral`、`NameRef`、`Add`、`Subtract`、`ArithmeticGroup`、`ZeroArgCall` | `+`／`-` **左結合**、括號分組不丟失、無參數呼叫不得冒充名稱讀取 |
| 位置 | 每個必要節點 | 起含終不含；顯示行欄一基，欄為**原始 UTF-8 位元組**；內部原始偏移零基半開，依 BB／BC／BD 對照 |

驗收至少比對：`P01-正02` 加法、`正09` 條件鏈、`正10` 算術分組、`正11` 呼叫運算元、`正12` 函式前向／遞迴；不得要求錯誤時必回傳部分 AST（BH02），亦不建立外部 AST 列印 API（AY05）。

## 四、步驟 4：名稱、宣告順序及作用域（P01.2）

**BR03-A（依相容編譯器建議委任由助手選定）**：將已核准名稱規則轉成**靜態證明契約**，而不是指定特定符號表演算法：

- `fn`：合法無參數函式可在同一單檔內先使用後宣告，直接／互相遞迴均不得只因循環而報錯（AV02／03、AW06）。函式必須存在且型別與使用位置一致，不因此開放任意函式呼叫副作用。
- `const`／`var`：頂層名稱的**讀取處**必須位於有效宣告文字之後（AW04）；宣告值仍受 AX02；不得因 `fn` 支援前向參照就放寬變數前向讀取。
- 區塊名稱：同一作用域重複宣告同名一般變數拒絕（H05）；內層合法同名變數遮蔽外層（H06），不得錯把外層已初始化證明轉給新內層名稱。
- 其他名稱類別間（例如變數與函式重名、`const` 與 `var` 異類別重名）、頂層求值時間及跨函式全域可變寫入的安全規則未由 H05／AW04 完整規定。**此類未核准組合不列為正向驗收，亦不宣稱已補足完整語言符號空間政策**。

## 五、步驟 5：型別、回傳、資料流及溢位（P01.2）

| 靜態義務 | 正向案例 | 反向案例 | 精確界線 |
|---|---|---|---|
| `main()->int` 存在，其他函式可 `int`／`bool` | 正01、正08 | 反01、反02、反11 | AU／AX／AY；不執行主函式 |
| 有明確型別的宣告 | 正02、正13 | 反05、反06 | `const` 即刻初始化、`var` 可延後 |
| 同型別回傳值與算術 | 正10、正11 | 反08、反20 | `+`／`-` 的運算元必合法；不開放布林加減 |
| 宣告初始化式來源 | 正02、正07 | 反21 | AX02 不允許算術初始化 |
| `var` 首次／再次寫入 | 正13、正19（分支情境另見正05） | 反15、反22、反23 | AZ01、AY02 皆限相同類別 RHS；`const` 不能再寫入 |
| 各分支可達路徑上初始化 | 正05 | 反07、反24 | AU05：**沒有 else** 的未命中路徑不得忽略 |
| 一般條件型別／括號 | 正04、正09 | 反16、反17、反18、反19 | AT04～05、AU04，條件限 bool 常值／名稱 |
| 確定的 `int64` 溢位 | 正10 | 反29、反30 | 已確定超範圍時須拒絕；非靜態可知者不假裝前端有執行期 |

**資料流定義**：在任何可到達讀取位置，若存在任何合法可到達該位置但**尚未初始化**的路徑，該讀取必須拒絕；若所有可到達路徑已完成合法初始化，允許該讀取。這只重述 I05／AU05，未指定控制流程圖實作、不可達語句全面政策、全域求值順序或別名／所有權安全。

## 六、步驟 6：來源座標、錯誤及安全恢復（P01.1／P01.5）

**BR04-A（依相容編譯器建議委任由助手選定）**：已核准三階段 `DiagnosticKind` 的首版繁體中文 `Display` 類別標籤選定為 `詞彙錯誤`、`語法錯誤`、`靜態錯誤`，僅是分類標示，不代表完成每一項尚未選的訊息內容、識別碼或診斷子類別。

**BR05-A（同項委任）**：可定位語言診斷的首版 stderr 表示建議為 `來源路徑:行:欄: 類別: 訊息`；若有已知路徑卻無合法行欄，則為 `來源路徑: 類別: 訊息`；未知路徑時省去路徑前綴。此為**文字模板選擇**，不可捏造位置，且核心 IO 失敗依 BO05 為 `Failed`、空 `diagnostics`、有 `io_error`，CLI 用法／IO 錯誤另按 BD04 等呈現可辨識文字，而不硬塞進詞彙／語法／靜態診斷集合。Rust `Display` 只產出類別標籤（BN06／BO06）。

**BR06-A（同項委任）**：詞彙遇非法來源位元組以逐位元組記錄、各生成一項詞彙錯誤、保留原始半開位元組跨度；無效替代標記不可形成合法詞彙，於詞彙／語法邊界**略過標記並僅在安全可判定時續析**（AY04、AZ03、BA02、BB01／02、BC02、BD03）；合法 UTF-8 編碼的原始 U+FFFD 另歸詞彙錯誤並略過。不得針對同一來源問題重複生成同一詞彙錯誤；**真正獨立**後續語法問題可另外診斷，且不能透過錯誤復原杜撰有效名稱、型別或初始化證明（BE02、AX05）。若無法安全續析則停止，不強求以虛構 AST 或通用同步演算法修復。

| 觀察對象 | 原始座標與順序不變量 | 覆蓋資料 |
|---|---|---|
| 空檔 EOF | 原始 `[0,0)`、外顯 `1:1` | 源01／BF01 |
| CRLF／檔尾 CRLF | CR+LF 合為一次換行，但占兩原始位元組；完整換行的半開終點為下一行 1 欄 | 源02／03／06／BG02／BH01 |
| CR／LF 單獨 | 各自只加一次邏輯行號 | 源08／09／BA01 |
| 合法多位元組 UTF-8／Tab | 欄位數量依原始位元組，不依畫面寬度或 Unicode 字元數 | 源07／10／AW05 |
| 無效來源位元組 | 每原始位元組一筆詞彙錯誤，各保留單一原始位元組跨度 | 源04／11／BA02 |
| 合法原始 U+FFFD | 單一合法 UTF-8 編碼來源字元，仍為詞彙錯誤；與無效位元組逐筆錯誤區分 | 源05／BF03 |
| 多重診斷排序 | 原始位置優先；同位置詞彙→語法→靜態，同階段同位置按產生順序；無位置後置且按確認順序，AQ06 特例保持 | BC03、BF05、BG03、BN01、BO01 |

以上是**預期值與實作不變量**。既有向量是局部定位／詞彙驗收，不代表其原始片段是完整合法檔案。

## 七、步驟 7：首版不支援與完整語言隔離（P01.3／P01.4）

- **BR07-A（依相容編譯器建議委任由助手選定）**：P01.3 保留 AQ01～AQ06（以及 AL～AP 與其所依存的 Optional 規格）於**完整語言**權威草案；首個 MVP-A 明確**不實作 `is` 或 Optional 語意**。AQ06 雙重錯誤優先只在將來真正適用其專用條件時生效，不可誤套到一般 `if`。
- 首版不支援的已知功能依 AS05 **作首版語法拒絕**；已支援功能本身的已定詞彙／語法／靜態錯誤不因此被重新分類。
- 例如完整語言允許有參數函式、`share`、特定容器／Optional、`struct`、進階迴圈與某些運算，但**MVP-A 不接受**；不重開已選的完整語言規格，也不提前加入借用、複製／移動及其他 P13～P22 義務。

## 八、步驟 8：正反與來源案例的機器可追溯契約（P01.5）

**BR08-A（依相容編譯器建議委任由助手選定）**：沿用 BQ01～BQ03 的 UTF-8 測試素材、JSON 原始十六進位向量與標準函式庫檢查器，擴充成：

- `tests/fixtures/驗收矩陣.json`：**11 個**工作範圍群組，逐一引用已核准規則、現有來源檔案例與來源向量。

## 九、步驟 9：規格驗收及移交邊界

| P01 子任務 | 本次具體交付／證據 | 正式 P01 與 Rust 實作的區別 |
|---|---|---|
| P01.1 | 首版功能矩陣、EBNF、AST 概念／跨度、診斷範圍及正反測試契約 | 僅規格封閉；Rust AST／解析器屬 P04～P08 |
| P01.2 | 名稱、型別、初始化分支／溢位驗收表與可追溯案例 | Rust 名稱／型別／資料流屬 P09～P12 |
| P01.3 | Optional `is` 既有 AQ 規則已保留並與首版隔離 | 不是 Optional 已在首版實作 |

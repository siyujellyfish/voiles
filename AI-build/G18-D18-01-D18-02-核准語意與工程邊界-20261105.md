## D18-01：遞迴與資源耗盡（使用者核准 A／B／C／D）

1. **D18-01-A**：保留 AW06-A 已核准合法**直接遞迴、互相遞迴與前向函式參照**，不得以整個呼叫圖成環為由拒絕，也**不強制所有合法遞迴均須靜態證明終止**。原 Checker 的名稱解析、函式簽章、型別與安全限制仍適用；不等於所有遞迴都能繞過安全檢查。
2. **D18-01-B**：執行器須有可配置的安全預算（例如呼叫框架／已消耗步數）；**不得在語言規格寫入固定最大遞迴深度**，也不得依賴 Rust 宿主堆疊溢位。預算具體數值是每次執行環境配置，非通用語言常數；不因此自創 CLI 旗標。
3. **D18-01-C**：執行預算耗盡須回傳**受控執行期錯誤**，不回繞、不默默結束、不假造正常 `return`；錯誤映射至公開 OS 退出碼仍屬 D22-01，未在本次核准。
4. **D18-01-D**：每個真呼叫框架獨立持有其局部資源與借用票據，正常回傳／錯誤冒泡／耗盡時依既有作用域安全契約逐層逆序清理；每份 OwnedStr ResourceId 至多清理一次。借用依原 Checker 退出點與 BorrowFact 驗證後歸還，錯誤不可被吞噬成成功。
5. **工程順序**：先用無資源、無參數的 AW06-A 真函式遞迴及受控耗盡建立框架實測，再擴至已核准參數／資源；原 G18-P18.3 須包含多框架和資源清理正反，不能靠「拒絕遞迴」簽核。*程式實作與完整正反尚未完成。*

## D18-02：方法多載、self 與非同步（使用者核准 A／B／C／D）

1. **D18-02-A**：同名方法承接 S20，依**原 Checker 靜態參數數量、宣告順序及完整型別**唯一辨識（不是依實參 runtime 值、也不是僅依回傳型別）；同簽章重複宣告為靜態衝突，零符合為型別錯誤，多個仍可符合時為靜態歧義。欄位／方法同名仍禁止，跨結構與模組可見性不變。不因此引入隱含轉型或新方法語法。
2. **D18-02-B**：不重新決定方法 `self`。沿用 S11 自動提供、S12/S15 不得消耗、S14 離域歸還、S16 `instance.method(args)`、HC14-A 借用互斥及已核准依方法是否實際寫入推導**共享唯讀／獨占可寫**。動態借用票據必與原 Checker 來源 DeclarationId／BorrowKind 一致。
3. **D18-02-C**：延續已有 VB15-01-A：**有效借用跨 `await` 或無法證明正常歸還的異常邊界一律拒絕**；已在邊界前依法歸還的票據不能被當成存活阻塞。此項不授權跨 await 重新借用，也不創造例外語法。
4. **D18-02-D**：按「唯一方法簽章→同步 `self` 真執行→安全的非同步正向子集→異常／取消清理」推進。非同步方法正式驗收必須有真執行正例與反例；不能藉空測試或永久禁止所有 `async` 完成 P18.6。
5. **尚未被高階原則核准的細則**：非同步任務啟動時機、`await` 具體調度／喚醒政策、取消點及異常傳遞的完整語言契約、跨資源併發／跨模組安全；若工程需要選定新的可觀察語言行為，須另行裁決。**不得將建議自動擴展為完整 async／except 語法授權。**

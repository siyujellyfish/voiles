# P28～P30 自舉與發行

P28 第一個核心為整數字面值的進位累積。bootstrap/digits.voil 使用現有明確型別、結構、移交及受檢 int 加法重寫二、八、十與十六進位累積。編譯器從原有已檢查計畫匯出唯讀整數 ABI，宿主負責字元及前綴驗證。Rust 種子保留原版從字串解析的演算法以供獨立比對及恢復。

## P29 自舉編譯器與兩代重建

G06 依本次委任採混合語言工具鏈。bootstrap/compiler.voil 實作自己的遞迴下降語法分析與 Rust 產生，包括函式、條件、整數常值、受檢加法及呼叫。這份來源只使用明確 int 函式、return、if／else 及私有 host 模組。host 提供正式 lexer 記號、有限緩衝輸出及檢查過的名稱；此介面限自舉元件使用。一般程式走既有模組與所有權檢查。公開完整前端、借用檢查、執行期及宿主連結仍由 Rust 實作。

種子包含可獨立編譯的 bootstrap/compiler_seed.inc。第一代從 .voil 產生編譯器模組，取代種子編入 CLI；第二代以第一代的編譯器重新處理它自己的完整來源。每代另外重編數字核心。生成模式只包含當代生成檔；Rust 種子模式僅在恢復時啟用。以固定工具環境比對兩代 CLI、兩個生成模組及種子快照位元組，交叉執行多檔、動態錯誤、借用反例與 build／pack 產物。修改合法的編譯器發射語句另驗證輸出跟隨來源變更。

重建第二代執行 python3 tools/bootstrap.py target/stage2 --previous target/stage1/voiles。恢復時從乾淨目錄以無 --previous 的命令重建 Rust 種子，再逐代重建。P28 與 P29 驗收可重跑 python3 tools/核對P28自舉.py target/seed/voiles。

## 公開語言實作的自舉詞法分析器

第一批以 bootstrap/compiler.voil 為完整輸入。bootstrap/lexer/scanner.voil 接收原始位元組並移交記號清單，詞值以來源檔的半開位元組跨度引用。入口按來源順序輸出種類、起點與終點。驗收使用正式 Rust lexer 逐筆核對，涵蓋空檔、檔尾、混合換行、中文字元、無效 UTF-8 與含跳脫字元的引號。執行 python3 tools/核對自舉詞法.py target/p02/voiles 可比對直譯、建置與封裝產物。本批以編譯器來源使用的詞法為範圍；接入兩代重建前仍須處理完整自舉輸入的常值與錯誤診斷。

兩代重建時，上一代的 voiles run 先執行掃描器。建置工具移除 run 的返回值行，把完整記號流交給 bootstrap-compiler 的私有 --tokens 入口。來源切片負責提供名稱、整數與字串內容，字串跳脫仍沿用 Rust 解碼。舊種子命令保留作獨立對照與恢復。兩代皆比對產物位元組，再將掃描器改成把普通名稱歸為關鍵字，確認兩代的編譯器都對改變後的輸入產生名稱診斷。

### 運算式優先序

bootstrap/compiler.voil 的遞迴下降解析器按括號、乘除、加減分層；同層二元運算由左向右。整數除法朝零截斷。以 Rust 的 checked 運算維持溢位與除零失敗。驗收實際編譯並執行生成的 Rust，與公開四入口和兩種產物比對。缺運算元與缺右括號由三代編譯器各自驗證。

自舉子集的條件可比較整數的相等或大小。while 的條件在每次進入時求值，迴圈體接受同步呼叫，執行一次即計入一次宿主預算，離開後繼續解析最終返回語句。驗收以實際產生的原生碼消耗零筆與三筆輸入，逐次核對游標與預算計數。

擴充控制流程後，完整來源首次觸及既有十萬步預算。掃描器改為一次略過連續水平空白，以有序分支辨識關鍵字，保留相同來源跨度及執行預算。

### 純整數函式簽章與呼叫

自舉子集的普通同步函式接受零個或多個 `int` 位置參數，生成的 Rust 形參保持來源順序。函式本體可讀取參數，普通呼叫的實參按來源順序求值並傳入。宿主呼叫仍使用既有受限 ABI，不擴張公開語言接口。驗收用雙參數函式產生並執行 Rust，另以 `check`、`run`、`build`、`pack` 和兩種執行檔交叉核對。非 `int` 參數與尾隨逗號由三代語法分析器拒絕；實參個數先由語法保留，再由後續名稱階段依簽章拒絕不符來源。

函式語法使編譯器來源增加長識別字。掃描器只對完整編碼成正整數的八字母內小寫名稱進入關鍵字樹；較長名稱、底線名稱及其他普通名稱直接分類為識別字，維持相同詞法結果及十萬步上限。

逐記號對照入口仍保留正式 lexer 的換行記號。兩代重建傳入第二個內部引數，掃描時將換行當作可驗證的空白跨度，不建立稍後必定被 Rust 宿主濾除的記號；名稱、常值、符號及其原始位元組跨度完全相同。此模式只用於自舉重建，不改公開程式的詞法或命令介面。

重建模式在確認一筆記號後立即輸出該筆種類與跨度，不先放入清單再由入口二次走訪；一般逐記號對照仍建立並移交完整 `list[Token]`。兩條路徑使用同一判定及相同輸出格式，重建路徑減少的是中間容器操作，不改記號內容。

完整編譯器來源的逐記號核對使用重建模式，對照端同樣移除正式 lexer 的換行記號後逐筆比較。空檔、混合換行、UTF-8 與錯誤位元組等小型邊界語料仍走完整清單與二次走訪，包含換行記號的原始跨度核對。

原子解析先辨識保留的 `host.方法(...)` ABI，再以名稱後是否接左括號區分普通函式呼叫與參數讀取；宿主名稱不會被當成一般參數值。

逗號後必須立即解析下一個完整參數或實參，函式簽章及呼叫均不接受尾隨逗號。

自舉編譯器來源會持續成長，重建及該份長來源的逐記號核對改走隱藏的 `bootstrap-run` 命令。隨完整來源納入混合巢狀容器後，私有工具鏈上限由二十五萬步調整為四十萬步；公開 `run`、一般程式與邊界語料仍維持十萬步預算。兩者使用同一份已檢查執行計畫、錯誤定位與資源清理，差異僅為自舉工具鏈明確傳入的步數上限。

完整編譯器的詞法對照只由此自舉入口執行；一般 `build`、`pack` 產物仍以空檔、混合換行、UTF-8、無效位元組及跳脫字串語料逐筆核對，並由函式批次另行實跑真實多函式程式。避免為測試長來源而改變一般原生程式的十萬步契約。

### 函式名稱解析

函式宣告、參數與普通呼叫由自舉解析流程登錄到有界宿主表；這是私有自舉 ABI，不改公開語言接口。每個函式本體只可讀取自己的參數，重複函式、重複參數及未知值名稱立即拒絕。普通呼叫先保留名稱與實參數量，完成整份來源後再統一核對，因此維持公開語言既有的前向呼叫、遞迴與互相遞迴語意；未知函式及實參數量不符不再交給生成的 Rust 編譯器才發現。

呼叫以堆疊分隔每層實參計數，先為後續運算式降階保留正確邊界；本批不把尚未降為暫存值的巢狀普通呼叫列入原生產物支援面。驗收把 `main` 放在被呼叫函式之前並實跑雙參數呼叫，同時由 Rust 種子、第一代、第二代及公開 `check` 共同拒絕名稱和簽章反例。名稱表只保存本次編譯所需的文字與數量，編譯結束即釋放；Rust 種子仍保留為獨立恢復入口。

### 簡單模組匯入與限定呼叫

自舉解析器接受既定的 `import 模組` 與 `模組.函式(...)`，私有 `bootstrap-project` 對照入口從入口檔所在目錄尋找同名 `.voil`，依賴優先且每檔只編譯一次。生成的 Rust 名稱帶原始模組身分，避免不同模組的同名函式碰撞；跨模組只可呼叫非 `_` 前綴函式，並沿用上一批的實參數量核對。缺少模組、未知或內部函式及循環依賴均在產生 Rust 前拒絕。

模組探索與檔案讀取仍由 Rust 恢復宿主負責，自舉來源負責消耗匯入及限定呼叫語法並驅動名稱核對。這個私有入口不取代公開 `check`／`run`／`build`／`pack`，驗收以同一個兩檔整數專案交叉執行三代自舉產物、生成 Rust、公開四入口及兩種執行檔。選擇性匯入 `import name from a as local`、結構與模組初始化順序留待後續批次，不在本批擴張。

### 純整數結構宣告與讀取

自舉子集加入具有一個以上 `var int` 預設欄位的結構宣告、函式內明確型別區域變數、空建立式及欄位讀取。生成端以來源結構和欄位身分產生 Rust 結構，預設值在每次建立時寫入；函式內結構區域名稱不與參數或其他區域名稱混用。重複結構／欄位、缺少或非整數預設值、未知結構、建立式型別不符及未知欄位均在生成前拒絕。

第一批刻意不開放欄位寫入、具名建立參數、bool／float／str 欄位、方法、結構參數或返回、整筆移交及跨模組結構。這些能力依原公開設計逐項移植，避免以 Rust 結構可表達為理由繞過確定初始化與所有權階段。驗收實際編譯並執行生成 Rust，並以同一來源交叉核對公開四入口及 build／pack 產物。

純整數結構的下一批加入具名建立參數及 `var` 實例欄位寫入。具名值可依任意順序提供並允許尾逗號；未提供欄位使用宣告預設值，重複或未知欄位在生成前拒絕。欄位寫入右側走相同的受檢整數運算式，生成 Rust 的可變區域只限本批已驗證的 `var` 實例。

此擴充不改變上一段對其他欄位型別、方法、跨模組結構、移交與確定初始化的限制；`const` 結構實例及 `const` 欄位仍未進入自舉子集，不能由生成端的 Rust 可變性反推已支援。

### 純整數清單常值與長度

容器第一批加入函式內 `var xs:list[int] = [...]`、空或多元素整數清單常值及 `len(xs)`。每個元素依來源順序生成擁有自己的 Rust `Vec<i64>`；`len` 只接受已登錄的 `list[int]` 區域名稱。錯誤元素型別、未知清單、缺少結束符號、尾逗號與同作用域重複名稱在生成前拒絕。

本批不開放索引、元素寫入、dict、巢狀容器、容器參數／返回或 move／borrow。這些涉及邊界錯誤、型別遞迴及所有權的部分依序後移，不以 Rust `Vec` 的現成功能冒充語言驗收。正例同時實跑三代生成 Rust、公開四入口及 build／pack 產物。

容器第二批依公開 P33 既有介面加入 `with xs[index] as item`，不另開放裸 `xs[index]`。索引使用同一套受檢整數運算式；負值及越界在執行時失敗，不轉成 Rust 無號索引。`int` 元素以唯讀區塊別名使用，名稱只在區塊內有效，不能與參數或區域名稱重複。本批的自舉子集要求 `with` 區塊以 `return` 結束；成功選取會明確返回，失敗選取直接成為執行期錯誤，因此函式可在該區塊後結束，不附加不可達的外層 `return`。

生成端以安全 `get` 讀取，不使用 Rust `[]` panic；三代生成 Rust 實跑成功選取與越界失敗。正常公開降階的路由也把區域容器宣告與 `with` 明確送入既有容器控制流，不再落入結構建立路徑；同一來源實跑 `check`／`run`／`build`／`pack`、兩種產物及越界反例。元素寫入、dict、巢狀選取與跨函式容器移交仍留待後續容器整合批次。

### 清單尾端可變操作

容器第三批沿用公開 P33 的方法式介面，讓函式內 `var list[int]` 使用 `append(value)` 與 `pop()`。`append` 依既有語意回傳操作後長度，`pop` 回傳移除的尾端整數；空清單 `pop` 是可診斷的執行期錯誤。自舉生成端只將已登錄為 `list[int]` 的區域名稱降成可變 `Vec<i64>`，不據此放寬 `const`、其他元素型別或未宣告名稱。

生成的 `pop` 使用安全的 `Option` 錯誤轉換，不以 Rust panic 取代語言錯誤。相同來源跨三代自舉產物生成並執行 Rust，同時通過公開 `check`／`run`／`build`／`pack` 與兩種產物；錯誤元素型別、錯誤實參數量和空清單反例亦逐路徑驗收。元素指定寫入、巢狀容器及跨函式容器移交仍留在後續批次。

### 純整數字典常值與長度

字典第一批加入函式內 `var entries:dict{str,int} = {...}`、空字典與多筆 UTF-8 字串常值鍵。值依來源順序接受自舉子集的受檢整數運算式；`len(entries)` 沿用公開 P19 語意回傳鍵數，空字典為零，且不消耗持有者。生成端使用保留來源順序的獨立鍵值序列，不把 Rust 集合的排序、覆寫或索引行為冒充 voiles 語意。

同一常值內的重複鍵在生成前拒絕，錯誤鍵和值型別、缺少冒號及尾逗號亦以三代反例和公開 `check` 交叉驗收。正例跨三代生成並執行 Rust，同時通過公開 `check`／`run`／`build`／`pack` 與兩種產物。`set`、巢狀容器與跨函式移交仍由後續批次接續。

字典第二批將公開既有的 `with entries["鍵"] as item` 接入自舉子集，鍵使用正式 lexer 解碼後的 UTF-8 字串常值，元素別名仍只在區塊內有效。查找不移動也不複製整份字典；純整數值建立獨立的唯讀區塊值。缺少鍵是通過靜態檢查後的可診斷執行期錯誤，不改成未執行區塊或預設值。

生成端以安全的迭代查找取得值，不使用 Rust 索引或 panic。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 及兩種產物同時實跑命中與缺鍵反例；錯誤鍵型別、未知持有者及別名衝突在生成前拒絕。動態字串鍵、巢狀容器與跨函式移交仍留待後續批次。

字典第三批沿用公開 M7 的 `entries.set("鍵", value)`：既有鍵原子覆寫而不增加長度，新鍵按呼叫順序加入，兩者都回傳操作後的 `int` 鍵數。自舉子集只接受已登錄的可變 `dict{str,int}`、UTF-8 字串常值鍵及受檢整數運算式值，不以 Rust 容器方法擴張其他鍵值型別。

生成端先完成右值求值，再提交覆寫或新增；右值失敗不會先改動字典。有效 `with` 元素借用期間禁止修改同一持有者，並同步補上既有清單 `append`／`pop` 的同一守門。三代生成 Rust、公開四入口與兩種產物實跑覆寫、新增及操作後長度；錯誤實參數量、鍵值型別與借用衝突均在生成前拒絕。動態字串鍵及跨函式移交仍留待後續批次。

### 巢狀純整數清單與外層選取

巢狀容器第一批加入函式內 `var matrix:list[list[int]] = [[...], ...]`，包含空外層、空內層及多列整數常值。`with matrix[index] as row` 對外層執行安全索引，區塊內 `row` 是共享唯讀的 `list[int]` 元素別名，可使用 `len(row)`；不建立內層清單的隱含複本，也不允許經該別名呼叫 `append`／`pop`。

生成端以擁有巢狀列的 `Vec<Vec<i64>>` 表示外層持有者，選取使用安全 `get` 並保留對原列的共享參照；負值或越界是可診斷執行期錯誤。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑空列、命中及越界；錯誤元素型別、扁平值、尾逗號、別名衝突及借用中修改均在生成前拒絕。巢狀字典與容器跨函式移交仍留待後續批次。

### 巢狀清單第二層唯讀選取

`with matrix[index] as row` 的共享列別名可在其區塊內繼續以 `with row[index] as item` 唯讀選取整數。生成器把待完成的清單借用由單一欄位改為有界堆疊，每層各自記錄持有者與別名，並依後進先出順序移除區域名稱；內層結束不會提前釋放外層借用，也不建立列或元素的隱含複本。

每一層索引都獨立使用安全 `get`，負值或越界均轉為既有的「清單索引越界」執行期錯誤。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑第二層命中和第二層越界；重複別名及對整數再次索引在生成前拒絕。本批維持共享唯讀語意，不開放可變元素別名、第三層一般化容器、巢狀字典或容器跨函式移交。

### 字串鍵至整數清單的巢狀字典

混合巢狀容器加入函式內 `var rows:dict{str,list[int]} = {"鍵":[...], ...}`，包含空字典、空清單值與多筆 UTF-8 字串鍵。`with rows["鍵"] as row` 取得原字典內清單的共享唯讀別名，可使用 `len(row)`，也可在其區塊內以 `with row[index] as item` 繼續安全選取整數；不建立清單的隱含複本。

生成端以保留來源鍵順序的 `Vec<(&str, Vec<i64>)>` 擁有字典及其清單值，字典查找與清單選取各自維持既有缺鍵／越界錯誤。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑混合兩層選取及缺鍵；錯誤鍵和值型別、重複鍵、尾逗號、別名衝突、經共享列修改及對此型別使用尚未核准的 `set` 均在生成前拒絕。本批不開放可變元素別名、更深的遞迴容器或容器跨函式移交。

### 整數模式比對

自舉控制流程接入公開 `match(expr){ case 常值{...} case _{...} }` 的整數部分。比對運算式直接成為單一 Rust `match` 主體，只求值一次；各分支接受同型整數常值，包含合法負整數，分支本體先沿用自舉子集既有的終端 `return` 形式。相同數值的不同進位寫法視為重複模式，於生成前拒絕；`_` 仍只能位於末尾。

未提供 `_` 時，生成端加入不可見的未命中空分支，讓來源在沒有相符模式時繼續執行 `match` 後的語句，不改變公開語法。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑多分支命中；另實跑負常值及無預設分支的後續控制流。空分支集合、重複常值、布林模式混入整數比對、非常值模式及預設分支非末尾均由三代與公開檢查拒絕。布林模式與具型別例外由後續批次接續。

### 布林模式比對

自舉控制流程在相同公開 `match` 介面加入布林常值主體與 `case true`／`case false`。主體仍只求值一次，模式必須與主體同型；整數與布林模式不得混用。只列出一個布林值而未提供 `_` 時，沿用整數比對的未命中後續執行語意；同時列出 `true` 與 `false` 則視為完整涵蓋，不產生隱藏分支。

重複布林常值於生成前拒絕；兩個布林值均已有分支後不得再附加 `_`，維持公開前端既有的可達性判定。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑完整涵蓋及單分支落空；異型模式、重複模式與完整涵蓋後的多餘預設分支逐路徑拒絕。本批不擴張一般布林運算式、函式布林簽章或例外型別；具型別例外依下一批接續。

### 運算例外處理

具型別例外第一批把公開 `try { ... } except EvaluationError { ... }` 接入自舉控制流程。受保護區塊與處理區塊先限定為既有終端 `return int` 子集；整數溢位與除以零沿用生成器既有的 `Fault::Overflow`，只由最近一層 `EvaluationError` 捕捉。正常返回不執行處理區塊，未匹配的故障原樣向外傳遞，不以 Rust panic 或無條件吞錯取代語言語意。

生成端使用明確回傳 `R` 的封閉區塊建立局部故障邊界，巢狀 `try` 依來源結構選擇最近處理者。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑除零捕捉、正常返回及巢狀溢位；缺少 `except` 與未知型別逐路徑拒絕。區塊內一般寫入及資源清理依後續批次移植，公開 Rust 前端既有支援面不因本批縮減。

### 運算例外訊息綁定

`except EvaluationError as 名稱` 在處理區塊建立唯讀 `str` 綁定，內容沿用公開執行期既有的「運算失敗」訊息。自舉子集先允許以 `len(名稱)` 讀取其 Unicode 字元數；生成端不以 UTF-8 位元組長度冒充公開字素長度。綁定只在對應處理區塊有效，離開時恢復外層同名區域的型別登錄；巢狀處理者各自保有作用域，不把訊息提升為函式區域。

三代生成 Rust、公開 `check`／`run`／`build`／`pack` 與兩種產物實跑除零後的訊息長度。對訊息賦值及區塊外讀取由三代與公開檢查共同拒絕。本批訊息使用生成物內的唯讀靜態文字，不宣稱已移植一般擁有字串；一般 `str` 區域與跨例外資源清理仍由後續批次接續。

### 整數轉換例外

自舉運算式加入 `str` 常值的 `.to_int()`，成功時產生有號 `int`，失敗時產生獨立的 `Fault::Conversion`。`except TypeConversationError` 只捕捉此轉換故障；`EvaluationError` 仍只捕捉算術故障，兩者不互相吞沒。例外分類在處理區塊開始前由生成器明確登錄，不依診斷文字猜測型別。

`except TypeConversationError as 名稱` 的唯讀訊息沿用公開執行期「整數轉換失敗」，並使用相同區塊作用域與 Unicode 長度規則。三代生成 Rust、公開 `check`／`run`／`build`／`pack` 及兩種產物實跑成功轉換、失敗捕捉與訊息綁定；另以 `EvaluationError` 處理轉換故障驗證型別不符時必須向外傳遞。本批只開放常值接收者，不冒充一般擁有 `str` 區域、跨函式字串傳遞或清理已完成。

完整自舉編譯器來源在加入第二種例外分類後超過一般程式十萬步與九十六層框架上限；Rust 種子與後續生成編譯器的私有遞迴下降入口改用與既有自舉長來源相同的四十萬步，並以一百九十二層涵蓋編譯器自身的巢狀語法。公開 `run`、一般程式及非自舉入口仍維持十萬步與原框架界線，不因編譯器來源成長而放寬。

# G18／P18.4-B4／P18.6-M3：原 Checker 純 int 巢狀 helper 與同步 self 真共通退出（2026-11-15）

## 起點與原執行器缺口

基線 `main db33b0f7a4014deaf0d3cfdfe08aad53825cb981`（#789 合併後同 SHA「文件與工作紀錄」「Rust 前端建置」「Rust 獨立架構測試」三項 completed/success）。#787 已在同一方法圖支持多個**不同名稱**普通純 int helper，但 `owner.read(add(sub(9,2),3))` 這種原 Parser 有限巢狀呼叫仍在 `method_direct_pure_int_helper_argument` 被限制單層，方法執行器既沒有子呼叫在父函式求參期間真退出，也沒有對應的共享框架事件。此差距屬已批准的 Copyable int／普通函式 B4/M3 共通 CFG，不新增語法或借用規則。

## 嚴格範圍及單一型別權威

僅方法的**直接實參**可接有限層同步普通純 int helper。每層名稱與參數宣告來自原 Lexer／Parser／Checker、原 `DeclarationId`、同源 TypedHIR；helper 的**本體**仍是單一 Return 純 int 常值／具名形參／加減，不能巢狀呼叫、遞迴、await、自借用、str Move/Borrow、資源配置或普通函式未經證明的副作用。禁止方法返回表達式再混用巢狀函式、禁止 `1+helper(...)` 額外計算框架，這些未核准執行圖仍原樣保守拒絕。

`safety_checker.rs::method_direct_pure_int_helper_argument` 僅遞迴稽核原 AST 中每份參數是否可證純 int、或另一次完全同規則的直接純 int helper；不是用字面文字重新解析，也不改一般呼叫或 Checker 的借用約束。

`execute_method_nested_helper.rs` 直接在既有 `PrivateSelfApprovedHelper` 的 map 上選每層來源函式身分；prepare 做完全無事件的純值快照，Runtime 自左至右遞迴求完成所有子引數，才記父框架 `FunctionEntered`；真 Returned／FunctionExited(true) 或 UnwindStarted／FunctionExited(false) 都寫回原 `PrivateSharedCallExitEvent` 與 `ordinary_calls_entered/completed`，自始至終由同一 self 方法執行器持有原 BorrowTicket。任意子參數失敗，尚未 Enter 的父函式不能虛構事件，尚未進入的同步 self 不能提前簽票。只替換「方法直接引數」真求值，main 初始化／方法局部／方法 return 的其餘允許模式不擴張。

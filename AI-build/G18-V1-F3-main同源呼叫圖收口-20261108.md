# G18 V1／F3：主函式 main 改由原 Checker 已編譯工作計畫建立可達呼叫圖（2026-11-08）

> 承接 #648 空迭代不可達與 #649 普通函式 Checked 工作計畫閉包，並承接 #650 多語句區塊全返回後不再編譯不可達語句。本批**不是**原 P18.1 或 V1 全項正式驗收，六原項維持 0／6 Passed。

## 真工程缺口

`src/struct_stage/execute_call_scalar.rs` 的 `PreparedPrivateScalarCall::prepare` 已對普通函式的依賴使用 `prepare_function_locals` 編譯後的 `PrivateScalarReturnExpr/PrivateScalarLocalStep::collect_calls`，但 **main 的可達閉包仍走舊的 `collect_source_calls_in_statements` 來源 AST 掃描**。在合法 `main` 前置空 `for` 或 `while(false)` 時，該掃描可能不一致地保留不會進入執行工作計畫的 `idle()`，讓具有合法但此受限標量執行器尚未支援的結構局部的函式污染整個可達閉包。

**本批改動**：在建立 `main_names` 時先呼叫原已存在、以 Lexer／Parser／Checker／TypedHIR／DeclarationId 嚴格守門的 `prepare_function_locals(main, &verified)`；只從編譯後的返回表達式及局部／控制步驟 `collect_calls` 取得候選被呼叫者。**不提前執行**、不預測未知條件選中側、不自行建立新 Checker 或 Runtime，合法正迭代的未接通結構建構仍拒絕。正常／錯誤／耗盡原 ResourceId 和 BorrowTicket 安全協定保持不變。

## 真來源正反

1. `g18_v1_main空for內可達性被原Checker排除不污染呼叫圖`：`main` 的 `for i in 0..0` 內有 `idle()`，`idle` 包含合法結構局部建構，但迴圈不產生任何執行事件；返回 `good()=7`，無假 ResourceId 或 `idle` 函式進入。
2. `g18_v1_main_false_while內結構函式零建構且返回真目標`：`main` 的 `while(false)` 內合法函式不可達，返回 `good()=11`，真控制事件與資源帳平衡。
3. `g18_v1_main真迭代可達的結構函式不可藉呼叫圖略過`：把相同迴圈改成 `for i in 0..1`，原 Checker 合法但受限標量 runtime 尚未有結構局部建構安全交接證據，故 `prepare` 仍 **Unsupported**，不允許把「未通過的真執行」當成「不可達」。

普通函式專項 Gate **321→324**；原六項 P18.1、P18.2、P18.5 同步來源追溯。新增僅位於 G18 專項，不動 F00 凍結 Rust 測試群、G6/G17 正式證據、公開 CLI 和新語言語意。原 V0 機讀清冊 26 義務仍維持原狀；本批是 F3 的**具體已修復缺口**，非整項 F3 Closed。

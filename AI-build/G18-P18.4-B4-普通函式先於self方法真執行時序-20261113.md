## 此批真正解決的缺口

原 `execute_method_self.rs` main 局部 `const n:int = helper()` 雖被原 Parser／Checker 視為合法 Copyable 整數初始化，方法執行器只允許常值／名稱／加減，即使 helper 已由 #748 的原 Checker 安全子集證明仍一律 Unsupported。若單純把 helper 的預期 int 值提前填入 main 局部，會遺失真正執行過的普通函式框架；後續方法 self BorrowTicket 也可能被錯誤提前簽發。

此批只開放 **原 Checker 已准許、唯一同步零參數、單一 int 常值返回且無資源／借用操作** 的 `helper()` 作為 main Copyable int 局部初始化，保留原 `PrivateScalarReturnExpr` 與 Lexer／TypedHIR 位置證明：

- `prepare` 的靜態常值快照僅用於來源一致性；不可將其當成真正執行。真正 `execute` 必須遇到該 main Call 才執行原 Checker 的 helper 返回工作，並在共用 R05 帳中真記錄 `FunctionEntered → Returned → FunctionExited(true)`。
- 完成全部 main int 局部與最後方法 int 實參的動態求值後，才可真正取得 `self` BorrowTicket，繼而進入方法；若 main 後序發生 int overflow，方法永不進入、BorrowTicket 不得假簽或假歸還。
- 同一 helper 可在 main 重複調用、也可稍後在方法局部調用。普通函式框架彼此獨立，內層方法 helper 於 self 活躍票據期間執行；同一 `PrivateSharedCallExitEvent` 日誌以動態巢狀深度及實際進／退出數核驗。
- 注入方法故障時，先前成功的 main helper `Returned` 不得被撤銷或改成故障，而方法仍須按原 Checker 的 self Fact 歸票；任一來源計畫變造必在執行前拒絕。

# G18／P18.6-M2：原 bool 形參動態驅動同步 self 真控制邊（2026-11-13）

## 從已驗收首批走到真正動態形參

上批 [M2 if 常值早退安全子集](G18-P18.6-M2-同步self真if提前返回安全子集-20261113.md) 已於 `main 33f1dced568eab62101903ab710259b8cacc6cfb` 同 SHA 三必要 CI 完成；但語言原 Checker 合法的 `fn read(flag:bool)->int { if(flag){return self.n} return self.n+1 }` 搭配 `owner.read(true/false)`，同步 self Runtime 原本將 bool 實參誤送僅供 int TypedHIR 的求值器，故在進方法前保守 Unsupported。不能用 bool=0/1 假裝 int 形參或提前捏造分支。

## 真來源、動態安全及範圍

此批僅從原 Parser 的 `MethodCall` 精確**一個 bool 字面實參**建立動態形參橋接：

1. 先以原 Lexer `Keyword(true/false)` 與實參半開跨度、Checker 選出的唯一方法簽章核對 `bool` 型別，從 `VerifiedTypedMember(Parameter)` 取得真正 DeclarationId；原既有多 int 值傳遞不受影響，絕不把 bool 轉成 i64。
2. 原 Checker 的方法 `if(flag)` 必須只引用該同名 bool 形參，並由原 Lexer `Name` token、原 Checker bool 類別與原方法 `VerifiedMethodSafety.checked_returns` 確保條件真身分。只允許首句條件單葉 `return self.int` 與既有最後 return；未證多分支、bool 別名／跨框架再借一律拒絕。
3. 真 `execute` 在完成 main 動態局部後，把該 Copyable bool 值放入**獨立 bool 動態參數框架**，不配置 UTF-8 或額外 BorrowTicket；已按同一 call 計畫進入同步 self 方法且取得原 BorrowSafety self Ticket 後才讀取 bool 參數框架，選中葉提前 return 或繼續到最後算式，並記錄真已到達的 bool 判斷。
4. 修改後的返回計畫、bool 形參值及 DeclarationId 都要與原 Checker 同一來源重新編譯結果完全一致；篡改拒絕，不能以相同數值、冒用名稱或假造安全檢查通過。溢位、注入故障及重跑均按原 R05 真動態進退與票據歸還。

## 八條獨立正反 Gate

`src/struct_stage/g18_m2_bool_parameter_tests.rs` 及 `tools/核對G18-P18.6-M2同步self布林參數真控制.py` 逐項真執行：

- true 參數在自借用存活時真正選中早退並正確讀取目前欄位；
- false 參數跳過早退，執行原 Checker 最後算式；
- true 不提前執行未選的溢位算式；
- false 已到達溢位，受控故障、不偽造 Returned，真歸票；
- 方法入口故障尚未檢查條件，不能冒記 bool 判斷；
- 重新執行相同 Checked 計畫，各次 bool 值槽／真 self Ticket 互不污染；
- 篡改 bool 參數動態值及 DeclarationId，必在真正執行前 SourceChanged；
- int 冒充 bool、呼叫引數型別不符皆由原 Checker 靜態拒絕。

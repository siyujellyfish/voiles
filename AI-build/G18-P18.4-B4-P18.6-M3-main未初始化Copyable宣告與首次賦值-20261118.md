## 原 Checker 與現有主線對照

此批自 `main 6f92a1abce730192777ac29c2017ecef9c625b50` 建立，該 SHA 文件／Rust 前端／獨立架構三項必要 CI 全部 `completed/success`。#826～#832 已接通原 Checker 已核准的同步 self、main `int`／`bool` 具名 Copyable 來源、重賦值與混合純 helper 的原 Parser 逐語句工作圖。

原 Checker `Checker::statement_body` 對不含初始式的 `var step:int`／`var gate:bool` 會建立 `ValueSlot::uninitialized`；後續原 `StmtKind::Assign` 在完成 RHS 準備、型別與來源安全後 `commit_rebind`，並記錄真正 `TypedUse`／DeclarationId。首次賦值之前仍不允許讀取。此前受限 `PreparedPrivateSelfMethod::prepare` 強制每一 `main` Copyable 局部有 `initializer`，而既有 int/bool 賦值分支及 Runtime 均強制舊值存在，因而錯拒這一原 Checker 合法子集。

## 只採用已核准的最小擴張

1. 先核對原 `verified.plan.declarations.matches(id, &local.ty, local.mutable)`，僅允許**唯一、可變、原 Checker 已核准的 int／bool** 無初始化宣告；不可為無初始化的 const、其它型別或未經 Checker 核准的程式造值。
2. `PrivateSelfMainScalarStep` 新增 `BoolDeclareEmpty(index)` 和 `IntDeclareEmpty(index)`，仍由原 Parser main 語句順序產生，與既有 BoolDeclare／IntDeclare／BoolAssign／IntAssign 使用同一工作清冊。既有 `main_bool_locals`／`main_int_locals` 保留原 DeclarationId；空宣告中的 `false`／`0` 僅供私有已驗證清冊的佔位，**執行時不得建立任何 bool/int 值槽**。空 int 宣告的 `PrivateScalarReturnExpr::Unreachable` 也只作不可動態求值的私有佔位，不能解讀成真執行來源。
3. `known_bool_bindings`／`known_int_bindings` 登記已宣告原 Checker DeclarationId，但 `known_bool_values`／`known_int_values` 在空宣告後不提供值；首次原 Parser `StmtKind::Assign` 的 RHS 仍必通過 Lexer 身分／原 Checker ScalarHIR 與已初始化上游來源查核，才能在準備期以原 Checker 已核准的同一 Target DeclId 封存預期值。後繼具名複製／方法引數不得拿空宣告佔位當已初始化值。
4. 真 `execute_with_fault` 在任何方法自借票或 helper 前驗證四個來源清冊索引均完整、連續及非重播。執行空宣告時只將 DeclId 放入 `declared_*／pending_*`，絕不在 `main_values`／`main_bool_values` 寫入 0/false。第一筆合法 Assign 先真求完整 RHS（若含普通 helper，經原 SharedCallExit 動態 Enter／Exited），再使用來源的唯一 DeclId 提交值槽，移除 pending；之後同一目標再賦值須已有舊值，不能重複視為首次。
5. 對 `IntegerOverflow` 仍沿用原 RuntimeFailure 與主函式逐語句短路，未到達的空宣告或首次賦值不得假完成，也不能提前簽 self BorrowTicket。main 退出時清除所有真正建立的純 Copyable 值槽；尚未初始化、且原 Checker 已證明不會被讀取的局部沒有可釋放的值槽，不能因其無值而錯誤報 `SourceChanged`。
6. `matches_source` 原本使用同一份原 Parser／Checker、完整 Lexer Token 與全部工作清冊驗證，本批沿用它核對新增 Empty 步驟；不新增對外入口、不開放一般資源／Borrow／Move，也不擴張 V7 E1 的延遲佇列前置局部安全界線。

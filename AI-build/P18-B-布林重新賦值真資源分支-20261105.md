# P18-B｜已驗證可寫 bool 真重新賦值驅動資源條件分支（2026-11-05）

> **非公開受限真執行子批，不是 P18.2 或 G18 正式結案。** 基準 `main 7cd18b0cb33a5fa36f3246dcc536ff38e41f610f`，該 SHA 新主線三項必要 CI 均 success。維持 P17-C 原 Checker→P16 真資源執行的唯一安全鏈。

## 原實作限制

既有 `PreparedPrivateStr` 已能由正式 P13～P16 Checker 的 `DeclarationId` 讀取單一 `main` 中直接常值初始化的具名 `bool`，並正確選擇 `if／else if／else`、巢狀資源分支及 int 返回，但目前 `StmtKind::Assign` 只接通了可寫 `str` 重新賦值；原 Checker 已核准的 **`var flag:bool = true; flag = false`** 在私有 evaluator 被保守拒絕。

## 新增真工程

- 只在原完整 `verify_source_with_ability` 安全驗證成功後，對已有同函式 `bool_bindings` 的賦值讀取真 `DeclarationId` 與 `typed_declaration`。目標必須 `ty == bool` 且 `mutable == true`。
- RHS 僅接入原 Lexer／Parser 已核准**直接 `true`／`false` 常值**，以原來源 `term.start..term.end` 完全對照，其他 bool 表達式不藉此自行放行。
- 新 `PrivateStrAction::AssignBool { identity, value }` 於真正執行時使用同一 `BTreeMap<DeclarationId,bool>` 直接替換**既有** bool slot，不根據同名文字創造新宣告。
- 後續原 `if／else-if` 和巢狀條件照既有 `PrivateBoolCondition::Bound(DeclarationId)` 取值，只有實際選中分支呼叫原 P16 `OwnedStrRuntime`，嚴格逆序釋放。bool 自身**沒有 ResourceId**，也不能偽造字串事件。
- 原 P17-C `is_same_prepared_payload` 仍在任何資源配置前重跑唯一正式 Checker 並比較整份新動作計畫，防止賦值值被偷換。

## 六項真正 Rust 正反

| 來源行為 | 真正結果 |
|---|---|
| `true → false` | 未選 if 無事件，選中 else 建立並釋放 |
| `false → true` | 選中 if，提前 return int 並先清理局部字串 |
| 相同宣告多次賦值 | 最後動態值決定資源路徑 |
| 具名 bool 的 else-if 多段條件 | 賦值後兩個條件皆 false，只有最後 else 建立字串 |
| `const bool` 嘗試賦值 | 原 Checker 先拒絕 |
| 準備後竄改 `AssignBool` | `SourceChanged`，零 ResourceEvent |

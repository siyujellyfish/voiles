## 既有缺口與本批工程

原 DirectAwaitSession 可跨呼叫保留 P01 已驗證公開純值來源，但尚不能封存原私有 async fn 的 Lexer／Parser／Checker／TypedHIR 來源。PR #707 可在真私有 await 點執行另一份核准工作，但原工作的顯式動態工作堆疊仍須在同一 Rust 呼叫內恢復。

本批在 src/struct_stage/execute_call_scalar.rs 增加 PrivateCheckedDeferredAwaitQueue，**直接持有同一份 PreparedPrivateScalarCall**（原 UTF-8 bytes、Checker 身分、原 TypedHIR／函式圖）。不重新解析第二份 AST、不模擬假 BorrowTicket 或 ResourceId，也不改公開 CLI。

## 嚴格工作入口

1. prepare：先由原私有 PreparedPrivateScalarCall::prepare 進行完整來源核准，再要求 main 唯一語句是直接 await 返回、main_dynamic_call 為已核准 awaited Call，且 main_dynamic_steps／main_dynamic_inits／main_owners 全空。具有前置宣告、複合 await、一般同步 Call 或任何未保存的前置動態狀態均拒絕；不可事先執行到 await 後重跑。
2. suspend：僅由 Prepared 轉 Suspended，保留完整原 Checker 執行計畫但**尚未執行**，沒有任何真資源或副作用可被編造。多工作僅按實際 wake 順序開始執行。
3. wake：僅從 Suspended 執行唯一計畫，透過原私有 execute() 再次核對同源，使用真正 Runtime 回傳結果與執行事件；成功進 Succeeded，真運算溢位／預算失敗進 Failed；同工作不可二次執行。SourceChanged 在任何真執行前拒絕，保留 Suspended 可取消。
4. cancel：只有 Prepared／Suspended 可取消，原工作從未開始，零執行／零資源事件；Running／Succeeded／Failed／Cancelled 不可反覆取消。

這是 E1=A 延遲啟動且只允許直接 await、E2=A 單執行緒、E3=A 安全點取消、E4=A 原失敗傳遞、E5=VB15-01-A 的已核准保守子集。不開放 spawn、背景工作、跨執行緒、OS 退出碼或新異常語法。

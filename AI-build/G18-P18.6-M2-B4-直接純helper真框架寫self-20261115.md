# G18／P18.6-M2／P18.4-B4：同步方法直接純 helper RHS 真執行及借票清理（2026-11-15）

## 起點與具體缺口

來源 `main a697bf894e628fe17667686909c0c17f60807725`，三項必要主線 CI 均 `completed/success`。上一批 PR #802 已通過原 Checker `if／else` 真選葉 `self.count = add(payload,3)`。原 Checker 的 `method_pure_value_type` 及 PR #802 新增的 `record_method_checked_helper_write_hir` 已同樣核准**直接**欄位 RHS 的同步純 int helper，並簽發完整 ScalarHIR；但 `PreparedPrivateSelfMethod` 對方法首句 `self.count = add(n,3)` 或 `self.count = add(n,3)+2` 仍只接受不含 Call 的純加減，構成相同已核准語意在直接方法欄位賦值時錯誤 `Unsupported` 的缺口。

## 實作

1. 方法首句原 Checker 欄位 RHS 只接收 `TermKind::Call` 或 `BinaryInt`，經 `PrivateScalarReturnExpr::from_checked_bindings` 從**原**已認證 ScalarHIR／正式 int 方法形參 DeclarationId 構建計畫。全部 Call 須經既有 `private_self_approved_int_call_arithmetic`，保證真同步純 int 單筆 helper、原參數數量／順序／來源、無 await／Borrow／Move／資源；與 PR #802 的原 Checker 正式 HIR 生成一體。
2. 執行器不再對有 Call 的 `write_checked_int` 錯用純 `evaluate`。只有原方法入口已取得唯一 ExclusiveWrite `BorrowTicket` 才可依原 RHS 位置真正進入 `private_self_execute_arithmetic_call`／`private_self_execute_nested_argument_call`；內層函式真 Enter/Returned/FunctionExited 經既有 SharedCallExit 計帳，整個 RHS 成功完成後才 `write_int_field`。
3. 實參／函式本體／包裝算術任何溢位不得提交欄位，必先依原 `UnwindStarted`、FunctionExited 和 self BorrowTicket 返回規則清理；其他所有 P15/P16/HC14/R05 資源邊界不變。保存 `matches_source`／`SourceChanged`，篡改預備式或 helper 不得執行。

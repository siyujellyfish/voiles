# P16.3 真正 voil 已知分支、提前返回與跨詞彙作用域清理（2026-10-30）

> 本批依 #257～#262 已合併的真實 UTF-8 String 唯一所有權、混合 Copyable 結構及 P15 既有控制流程靜態安全，補上真正 .voil 分支內、外作用域清理與提前 return 的可重現資源事件。限制只針對能證明的受限 AST 路徑，不表示通用 P17 執行器已完成。

## 核准政策

- 每個已建立的 str 緩衝區以 OwnedUtf8 真正持有，離開其最後持有作用域時依完成初始化反序清理；內層作用域退出不能提前清理外層仍有效所有者。
- 已知 if bool 常值只執行其可達分支；不可達分支不建資源、不發出故障事件。非靜態可證 bool 條件與尚未執行的巢狀控制流程保守拒絕。
- if 分支內直接 return 0 的確定出口，必須先依序清理內層，之後清理函式外層持有者；故障中斷只清理真正已成功取得的 String，不藉宿主 Drop 假造語言清理證據。
- P13～P15 原始語意不變；只在私有來源已通過 Lexer／Parser／Checker 後，才以模型追蹤確定可執行的分支。

## 受限執行期來源與測試

- src/struct_stage.rs 新增 test-only trace_scope_struct_source，僅接受 main 的「外層 str 結構建立 → 單次已知 bool if（最多單一內層結構建立及可選提前 return 0）→ 外層 return 0」。
- 直接從已驗證 AST 取得結構欄位預設與具名字串常值，沿用 OwnedStructRuntime 持續資源分配、enter_scope／leave_scope／finish 和真正逐身分事件。
- 十項真正 .voil 正反：if true、if false 搭 else、if false 無 else、實際內層 RHS 故障回滾、分支提前返回、提前返回故障、未知條件、額外副作用未支援拒絕、不可達分支故障注入拒絕、多層巢狀缺少完整執行證明拒絕。

## 正式驗收關係

- 本批補強 P16.3／P16.4／P16.5 與 P16.6 的跨作用域安全證據；既有 #257～#262 涵蓋返回整筆 str／混合結構、純值整體複製、var str 欄位原子覆寫及各步驟失敗。

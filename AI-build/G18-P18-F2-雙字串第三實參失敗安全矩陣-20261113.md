# G18／P18.1-F2：雙字串暫存於第三實參失敗時的安全驗收（2026-11-13）

## 目的及來源限制

延續已合併 PR #737 的 F2 真同步字串轉發八項 Gate，針對原 Checker 可接受的兩個 str-return 函式先完成實參求值，第三個 int 實參才發生整數溢位的情境補上原始來源、逐步數中斷和動態雙帳身分反證。

此批只使用原 `PreparedPrivateScalarCall::prepare` 取得原 Lexer／Parser／Checker 之核准工作圖，使用真正 `execute_with_budget`、`OwnedStrRuntime::ResourceEvent` 與 `audit_graph_outcome`。沒有新語言語法、假造的成功 Return、寬鬆 Checker 或公開入口。

## 正反工程矩陣

| 原 F2 風險 | Rust 測試（真私有來源） | 必要判準 |
| --- | --- | --- |
| F2-S01 雙暫存，第三參數溢位 | `f2_forward_budget_雙字串已返回第三實參溢位逆序回收而不入被呼叫者` | `Created(1),Returned(1),Created(2),Returned(2),Released(2),Released(1)`；不准進 `consume`，也不能假轉交 |
| F2-S02 動態各步數故障 | `f2_forward_budget_雙字串前置實參逐步數截斷均無遺漏與重複釋放` | 對每個實際 Created id 都有且只有一筆 Released；已建兩份時須 2→1 回收，步數耗盡與真正溢位都不得當成功 |
| F2-S03 假參數綁定 | `f2_forward_budget_雙實參將第二個轉交目標竄改成第一個即使id正確仍拒絕` | 不修改真事件數與 ResourceId，僅改第二個目標 DeclarationId；必須拒絕 |
| F2-S04 跨來源假返回 | `f2_forward_budget_雙來源第二個str返回偽冒第一個id必遭稽核拒絕` | 保持 Created／Released 資源總數正確，改寫第二 str-return 的 id，仍須拒絕 |

嚴格重跑：`python3 tools/核對G18-F2字串跨函式轉發步數安全.py --test-bin target/p02/p04_source_internal`，須 `--list` 精確十二個名稱及每筆 `--exact` 實際通過；與原 F00／G6／G17／R06、主線文件 Gate 同時成功才認證本批。

# P16 持續結構 var str 欄位覆寫、首次初始化與原子提交（2026-10-30）

> 本批延伸已合併的持續結構真實 UTF-8 擁有者模型，實作 VA16-03-A 受限右值先求值、成功後提交並清理舊值的資源責任。不是新 .voil 語法決策，尚不開放完整來源欄位寫入或提前驗收 P16.1～P16.6。

## 核准規格

- VA16-03-A：右側先求值，成功後才能原子覆寫已有 var str 欄位；舊值在新資源成功提交後才清理，失敗不得提前釋放或破壞舊值。
- S13／S18：const 結構實例不可寫、const 欄位不可覆寫；var 欄位可在合法權限下首次初始化或覆寫，後者仍須遵守 P13～P15 靜態安全。
- S19／S21：str 不可隱含複製，struct 的整體移動不代表欄位可個別移動。
- VA16-01/02-A：真實 UTF-8 單一資源身分，成功後依實際完成初始化次序反向清理；失敗時只釋放新求值暫存資源，舊欄位所有權保持完整。

## 本批私有執行期

- struct_initialization.rs 的 OwnedStructRuntime 保存建立時的欄位宣告可寫性及結構實例 var／const 權限。先確認持有者仍有效、欄位存在與可寫，再配置真實 UTF-8 暫存資源。
- assign_field_checked 對 RHS 模擬失敗先釋放暫存、維持舊持有者及舊欄位值不變；成功才將新唯一資源放入原欄位責任，並在提交後釋放舊資源。更新後欄位資源的完成初始化時點晚於其他欄位，最終按新責任次序逆序清理。
- 原本沒有預設值的 var 欄位首次完成初始化不虛構舊資源、不產生多餘 Released；失敗仍保留其未初始化狀態。
- 整筆結構 .move() 後原來源不可再寫，新持有者可依自身 var 權限進行同一安全流程。不得以此推定一般借用別名、函式回傳資源或任意運算式覆寫已可被 P17 正式執行。

## 八項正反測試

1. 右側新資源建立後才提交並釋放原值，最終依新完成初始化次序清理。
2. 右側求值失敗僅釋放新暫存，原值可讀且其資源保持有效。
3. const 欄位在配置前拒絕覆寫。
4. const 結構實例即使欄位宣告 var 仍在配置前拒絕。
5. 無預設 var 欄位首次完成初始化無不存在舊值的釋放事件。
6. 不存在欄位在配置前拒絕。
7. 已整筆移動的舊實例不能再覆寫；新持有者合法覆寫。
8. 同一欄位先失敗再成功，兩個暫存及舊資源清理事件身份／順序皆精確。

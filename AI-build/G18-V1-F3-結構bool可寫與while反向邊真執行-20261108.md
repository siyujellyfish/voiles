## 來源差距與施工

PR #656 已能在普通函式中讀取真 P16 結構 `bool` 欄位作為 `if`、`while` 與實參；PR #659 已接通原 Checker 合法 `int` 欄位可寫並在動態值更新後稽核。然而原合法 `meter.enabled = false` 仍缺分支、迴圈與一般函式同一執行工作，無法由動態 `while(meter.enabled)` 重讀更新後的值。

本批將 P16 既有 `write_int_field` 的真持有者與欄位可寫保證，同型別延伸至 `write_bool_field`（不接通 str、無額外 OwnedUtf8）。普通函式中同一原 Lexer／Parser／Checker 的 `StmtKind::FieldAssign`，先從當前 `DeclarationId` 取得正式結構型別與 `var` 權限，確認欄位確實為可寫 `bool`，再以真 TypedHIR 編譯 `PrivateScalarBoolExpr`，只在動態抵達工作時執行 `evaluate_runtime`。保留同次函式當前 `BorrowSafety` 和原 P16 真實結構欄位持有者，不靠字面名稱捏造資源。

新 `CopyStructBoolFieldAssigned(DeclarationId,field,bool)` 只有真更新成功後才發出；R05 原局部稽核及共享退出表須核對本框架仍存在相同 `CopyStruct` 身分，且沒有偽造額外 ResourceId。所有未經原 Checker 核准的 `const`、不匹配型別、錯誤資源來源仍直接拒絕。

## 六項真來源正反

1. 合法 `enabled=false` 後 `if` 當輪真重讀，選中 false 路徑返回 2。
2. 合法 `while(item.enabled)` 第一輪將欄位改為 false，反向邊下一次真讀 false 並安全退出，沒有固定展開。
3. 不走的 `if` 分支不能記錄假 bool 欄位更新，唯一選中分支返回 8。
4. 動態 bool 更新後整數溢位，唯一 `UnwindStarted`，真結構一次建構、一次離域。
5. 原 Checker 對 `const` 持有者或欄位的寫入拒絕。
6. 真更新事件 `DeclarationId` 遭人工改寫，聯合事件稽核失敗。

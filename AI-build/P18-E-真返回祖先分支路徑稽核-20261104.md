# P18-E｜返回事件須符合真實祖先分支路徑（2026-11-04）

> 本批為 P18-E 非公開控制事件安全子批，**不是 G17/G18 全面驗收**。基準 `main 209fb2c26c9281ebece5add4453c7ff59402c634`，前一批 #510 已完成條件鏈順序稽核及主線必要 CI。

## 安全缺口與修正

已完成的 `audit_control_events_against_source` 能確認每個 `return` 都對應同一份 P07 AST 中的真正 return 節點，並驗證條件鏈實際檢查順序；但一個函式可能有多個來源合法的 return，未執行分支的 return 不可僅因跨度與角色合法就冒充實際返回。

本批 `src/execution/trace.rs` 建立 `ReturnRoute::{Arm,Else}`，由原 Parser 的巢狀 `Block/StmtKind::IfChain` 唯讀累積每個 return 所屬**全部祖先分支**。執行期每個函式已有獨立 `SourceFrame`，在 `Returned` 事件到達時需逐筆滿足：
- 來源是某個 `if/else if` 內的 return，該鏈真實選中的 arm 序號須與原 AST 的祖先一致，且不是 else。
- 來源是 `else` 內的 return，該鏈必須真實完成所有 false 條件並發出 `ElseSelected`。
- 巢狀時**每層**祖先都需符合；未選分支雖有合法跨度、名稱與型別，也不得執行或冒稱 return。
- 原已驗證 HIR/Source/CFG 不變，新增的是 Runtime 事件稽核，不是第二 Parser，也不產生任何靜態假 ResourceEvent。

## 五項新增真 Rust 正反

1. 真正 true 分支 return，通過。
2. true 分支真回傳的事件跨度改成未執行 else 的合法 return，必須拒絕。
3. else 真的返回被偽造成未成立第一個 if arm return，必須拒絕。
4. false 無 else 而執行外層 return，偽造為未執行 arm return 必須拒絕。
5. 巢狀 if/else 的正確所有祖先路徑真返回通過。

既有全量 Rust 真執行新增五項，`tools/核對G17內部切片.py` 由原 50 增至 **55** 個只核對 `--list` 的內部案例。保留 F00 四凍結、G6、公開 CLI／check_file 的原始契約。

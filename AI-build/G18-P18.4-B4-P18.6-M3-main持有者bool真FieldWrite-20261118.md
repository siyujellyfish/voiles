## 保守且同源的唯一 Checker → P16 真工作圖

1. 主函式唯一原 owner `DeclarationId`、原 Parser 真 `StmtKind::FieldAssign` 及其 `statement.start` 必具有正式 `verified_field_write(owner_id, span, owner_type, field)`。本次 `main_owner.mutable` 必真可寫，目標必為額外 `additional_copy_fields` 中**原 Checker 已核對的 var bool**；原第一個 int 欄位仍走先前的獨立 int 原路徑，const／str／未知欄位一律原 Checker/保守拒絕。
2. RHS 只從 `PrivateScalarBoolExpr::from_checked` 核對的原 Checker bool `ScalarHIR::expression`、原 Lexer 真 Token 與具型別 `DeclarationId` 編譯。只接受 `Constant(bool)`、`Bound(main局部已初始化bool DeclId)`、`CopyStructBoolField{原owner DeclId, owner_name, field_name}` 三種 Copyable 來源；無隱含 int/bool 轉型、不製造一般化 AST、無擴張函式呼叫、Borrow、Move、str 資源。
3. `main_owner_bool_field_assignments: Vec<(field, planned, Option<PrivateSelfBoolArgumentSource>)>` 完整保存已核准原 Parser 寫入的欄位、準備快照與 RHS 來源。新的 `OwnerBoolFieldAssign` 依原 main Lexer/Parser 步驟先後與 bool/int 局部及其他 int 欄位寫入共同排程；不能把後續 bool 寫入在 int helper 溢位前提前提交。
4. `known_copy_fields` **只供 prepare** 原 Checker 的前序一致性快照：上一筆 bool FieldWrite 準備成功才更新後一筆的 expected value，同樣供既存 main bool 局部與方法 bool 實參的快照。原 `additional_copy_fields` 封存不變，真 Runtime 初始化仍使用原始 Checker 種子，絕不可預寫出結果。
5. `execute` 在真正 `OwnerBoolFieldAssign` 到達時，來源 `MainLocal` 讀真 main bool frame，來源 `OwnerField` 必重新 `MixedStructRuntime::field(owner, rhs_field)` 取得 `Observed::Bool`；原 Lexer bool 常值才直接用已封存值。確認結果與原 Checker 快照一致後，**同一步**以 `MixedStructRuntime::write_bool_field(owner,target,actual,owner_mutable)` 真正原子提交。若原欄位拒絕、型別不符或前序溢位，不能進後續方法、不能提前產生 `self` BorrowTicket／OwnedStr 資源事件。
6. `matches_source` 與 fresh 原 Checker 重建必逐項比對封存 bool 欄位計畫與原 `main_scalar_steps`；preflight 強制每個 `OwnerBoolFieldAssign(index)` 恰一次且原類別索引依序遞增，任何欄位名或 RHS DeclId 篡改皆於副作用前 `SourceChanged`。方法本體 SharedCallExit、HC14 自借、R05 正常／故障唯一退票維持不變。

## 真缺口

此前 PrivateScalarGraphContinuation::new 僅接受 plan.main_dynamic_call.is_some() 的主圖。真正 .voil 的常見寫法如「fn main()->int { return wrapper() }」，原 PreparedPrivateScalarCall 仍合法且 execute() 能正確運作，但原 Checker 在未涉及複合算式時會選擇既有直接呼叫快路（main_dynamic_call=None）。因此其內層合法 await 即使有完整真 P16/HC14 證據，也不能跨 Rust 呼叫暫停／取消，先前測試只能把 main 改成 wrapper()+0 以啟用主圖。這不是語言使用者應承擔的限制。

## 改動

- 在原 PrivateScalarGraphContinuation 增加 root_for_graph（**從唯一原 PreparedPrivateScalarCall 取出同一函式計畫**），依原 Checker 編譯選擇真 main_dynamic_call 或原直接快路的 self.return_expr／self.root_local_steps／callee 已核准 int 參數。不是文本重寫，也不編譯第二個 AST。
- 直接快路僅接通已驗證純 Copyable int 參數的形式；bool／str 尚未經同一原直接快路完整證明者保守拒絕；main 有無法安全封存的前置動態步驟時也拒絕。沿用原 D18-01 真執行預算，不額外占用假的 main 呼叫框架。
- 只在第一個 poll 依原 Checker 真參數宣告順序發出 ArgumentEvaluated／FunctionEntered／ParameterBound，之後每次恢復不重複綁定。原 evaluate_graph_driver 直接使用相同計畫，完整保存真 UTF-8／BorrowTicket／顯式工作棧／步數。
- 原直接快路的根函式在正式完成時補回其既有 Returned／FunctionExited 事件，並核對同一 audit_graph_outcome／R05 事件雙帳；溢位時只產生原真 UnwindStarted、FunctionExited(returned:false)，絕不造假 Returned。
- 原直接快路若在真 await 安全點取消，仍由同一 evaluate_graph_driver 的 E3 取消模式逐框架真離域。因根函式在快路由入口記錄 FunctionEntered，完成取消退場後也只補唯一 FunctionExited(returned:false)，不加入未啟動 async 子函式事件。

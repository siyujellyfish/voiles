## 核准、安全與起點

起點為 `main 5f779ad6f2d5ca57221c118e67232509f0f1dca3`，相同 SHA 三必要 CI「Rust 前端建置」「Rust 獨立架構測試」「文件與工作紀錄」均 `completed/success`；前批 #814 已由真 Lexer／Parser／Checker 直接 await async self 工作接通 E2 單執行緒可重播 Ready FIFO、錯誤清理與取消歷史。當前核准仍為 D18-02-E1-A 延遲且只限直接 await、E2-A 協作式單執行緒、E3-A 安全點逐框架取消、E4-A 既有執行期錯誤、E5 維持 VB15-01-A 有效借用不可跨未證 await，以及已核准的 `await owner.method(args)`。**方法本體內新 await 仍保守拒絕，不新增背景工作或任意搶占**。

原 `PrivateCheckedDeferredSelfAwaitQueue` 可保存無內部 await 的真 async self 方法計畫，Prepared／Suspended／Succeeded／Failed／Cancelled 已有單一執行及真退出；但已完成的 `jobs` 仍永久持有 `PrivateSelfMethodOutcome`，取消的空工作仍留在 active 工作索引。若直接從 `jobs` 移除而沒有獨立原事件收據，又會在全域 FIFO 驗證時把退休誤當遺失，或者容許多本帳一起被清空而假稱從未執行。這是**真 E3/E2 工作資源與 T4 歷史閉合缺口**，不能只新增測試來替代清理。

## 新增的實際安全生命週期

在原 `src/struct_stage/execute_method_async_deferred.rs` 加入以下資料與介面，不碰原 Checker 單一權威、不創造另一本假 BorrowTicket：

1. `PrivateSelfRetiredJob::Completed(PrivateSelfMethodOutcome) | Cancelled`：僅允許已由原方法真 `Returned` 或 `UnwindStarted`、SharedExit／LoanReturned 及相應終態證據核准的 Succeeded／Failed／Cancelled 工作結案。合法執行結果**移交 Rust 呼叫端唯一所有權**；取消只交付 `Cancelled`，不得假造 ResourceEvent。Prepared／Suspended／Running 不可退休，未知 ID 與重複退休明確拒絕。
2. 退休時先由現有 `verify_ready_history` 核對**全體**已登錄工作、真 Ready、已完成/失敗退出帳；提取欲退休工作原已驗證的終態、`checked_self_loan`、真 `result.is_ok()`，以及每筆全域 `ready_history` 的精確 **(index, PrivateSelfReadyTransition)**、原 `execution_order` 位置和原 `cancellation_order` 位置。這些原歷史位置被封為 `PrivateSelfRetiredReceipt`，不從來源文字或工作名稱自行重算，也不產生新的執行事件。
3. `retire_terminal(id)` 只在取得完整收據後，從原 `jobs` 真移除該工作（Checker AST/Token/plan 與持有的 Outcome 退出隊列），以一份無動態資源控制權的 `retired: BTreeMap<u64, PrivateSelfRetiredReceipt>` 保存終態可稽核性；已交付的 Outcome 不得在佇列中再留第二份可用結果。
4. 每次 `verify_ready_history` 仍從全部 `Prepared`、`Suspended`、`Woken`、`Cancelled` 逐筆重建真全域工作清冊，現在強制每份 ID **恰好在 active jobs 或 retired receipts 其中之一**，而且原 Ready／歷史／實際執行及取消位置皆與退休當下封存值完全一致。可證完成工作必有當時真 Checker self Loan 身分，原成功與失敗終態布林必一致；取消不得憑空出現執行位置或真票據。
5. 退休後仍可 `prepare()` 新合法工作並維持原 `next_id` 單調身分；取消／關閉另一份待命工作前仍須全體通過歷史預檢。退休收據被改寫、執行事件被刪、取消紀錄被抹或 Ready 被同步清空，**不能**悄悄視為合法的空佇列。收據只是結構化同進程獨立歷史，不是不可篡改的密碼學簽章；不保證任意惡意 Rust 程式同時控制所有帳冊下的防偽能力。
6. 既有 `wake(id)`／`drive_next()`／`cancel(id)`／`shutdown()` 的核准狀態及真正 LoanReturned 原有執行路徑不改；新退休只能在這些原執行路徑提供的終態上進行，不允許重新執行已退休工作或偽造取消事件。

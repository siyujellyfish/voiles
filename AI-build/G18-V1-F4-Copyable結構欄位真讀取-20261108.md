# G18／P18 V1-F4：原 Checker int 欄位真 P16 動態讀值（2026-11-08）

> 本文件在已合併 `main 6520b8a7360a9ae2335f714f3302bfd90e60bb86`（三必要 CI 同 SHA completed/success）上接續施工，**只記錄 Copyable 結構欄位讀值子批，非 V1 或原六項正式結案**。

## 本批問題與實作

PR #653 的普通函式已能真正建立與離域 int/bool 欄位結構，但 `return note.count` 及 `return note.count+3` 仍由標量 int evaluator 於 Prepare 階段保守拒絕；原 P16 自己的 `PreparedPrivateStruct` 雖可讀真欄位，普通函式顯式框架尚缺接線。

本批新增 `PrivateScalarReturnExpr::CopyStructIntField { declaration, owner, field }`，且必須同時有：
- 原 Checker 已驗證 `ScalarType::Int` 的 FieldRead 整式 `TypedHIR`；
- 原 Lexer／Parser 的來源起迄 token 與 `TermKind::FieldRead`；
- 目前詞彙 `DeclarationId` 的原 Checker 具型別宣告，結構宣告確實具有同名 `int` 欄位，且整個結構只有已接通 int/bool 欄位。

執行時再核對目前動態 frame 的來源 `DeclarationId` 與名稱，直接呼叫**同一個 P16 MixedStructRuntime** 的 `field(owner,field)` 真觀察 `Observed::Int`，不把欄位初始常值代替當前真值，也不退回沒有結構值的純 int 快捷路徑；動態溢位／作用域／回滾仍沿 PR #653 同一套責任帳。含 str／複合欄位及非 int 返回仍未放行。

## 新增五項原 Checker→真 Runtime 正反 Gate

1. 原 P16 預設純 int+bool `note.count+3`，真返回 10；
2. 具名 `count=9` 覆蓋原本會溢位的預設，只有真具名值到達執行，返回 9；
3. `first()`／`second()` 各自同名結構持有者，動態返回 4 與 9 合計 13；兩次建構／兩次離域，無錯誤跨框架讀值；
4. `bool` 當 int 返回或不存在欄位，先由原 Checker 阻擋；
5. 動態編譯後故意竄改欄位 `DeclarationId`，`SourceChanged` 執行前拒絕。

普通函式專項 Gate 331 → 336 項，P18.1／18.4／18.5 原項來源追溯增加五項；未變更 `--check` 嚴格標準、原始 V0 歷史清冊與 P18 六項正式狀態。

# P16 真實 .voil 結構來源至 UTF-8 資源事件（2026-10-30）

> 本批是 P16 執行期責任整合的候選證據，不代表 P16.1～P16.6 正式驗收、P17 直譯器或公開語言入口已開放。

## 核准依據

- VA16-01-A：以單一持有者 UTF-8 緩衝區追蹤 str，移動只轉交責任，借用不產生新所有者。
- VA16-02-A：只清理已成功建立並仍持有的資源，按初始化完成的相反順序釋放。
- VB16-01-A：先依來源具名參數的書寫順序求值，再依欄位宣告順序求值未覆蓋的預設值；不求值被覆蓋的預設。
- VA15／HC14 靜態來源安全、S07/S18 和原始 P13／P14 已驗收界線不變。

## 本批真正實作

- 新增僅供 Rust 測試的 `struct_stage::trace_string_struct_source`，先將真實 UTF-8 .voil 經來源診斷、Lexer、私有 Parser、Checker 檢查，通過後再以原 AST 的結構宣告、欄位預設及具名初始化資料呼叫 `struct_initialization::build_string_struct`。
- 以真正的 `OwnedStrRuntime` 保存 String 緩衝區、分配資源身分、記錄建立／釋放事件；比對具名兩欄與預設一欄的精確求值順序、中文內容及逆序清理。
- 對成功取得一、二、三個資源的各個模擬失敗切點，逐一核對已建立資源集合與逆序釋放事件相等。
- 明確拒絕含非 str 欄位、非直接字面值或轉義內容的來源；橋接只允許 `main` 的單一結構宣告與 `return 0`，不從來源 AST 推定條件分支、其他語句、函式副作用或真正執行先後。
- 失敗注入欄位若不存在，直接拒絕；型別不符仍由來源靜態檢查先擋下。七項正反回歸置於 `p16_真正_voil_來源至_utf8_緩衝區清理`，並繼續執行既有 P01 與 P13～P16 安全回歸。

- 此橋接是針對確定性的來源形狀進行資源事件模擬，**不是**一般 .voil 程式碼的直譯執行；不可據此聲稱 P16 的一般結構、容器或跨函式所有權析構責任已完成。

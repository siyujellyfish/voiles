# G18／P18.5-T3／P18.4-B4／P18.6-M3：main 普通函式必於 self 借票前完成的原 Checker 時序防偽（2026-11-15）

## 起點、來源與可實際繞過的安全缺口

起點 `main b480e44784de9b8e7c0a385c4bcd223c4d00abb8`，三項必要 GitHub CI 已在同 SHA 完成且成功。#795 已依原 `BorrowTicket.fact()` 把方法局部綁到唯一真 `self` 方法深度 1，並拒絕局部整段被移植至 main/helper。**剩餘不同缺口**：原 `PrivateSelfMethodOutcome::has_balanced_self_borrow_trace` 還沒有要求「原 Parser／Checker 的 main 整數局部與同步方法直接實參中，應真正先完成的普通函式呼叫」都位於 `self LoanAcquired` **之前**。把原 main 普通 helper 的同一 `FunctionEntered/Returned/FunctionExited` 三事件移到方法借票後的內層 helper，甚至方法退出後，保留事件總數、BorrowTicket、方法 result、局部歸屬不變時，通用 SharedCallExit 仍可能完全平衡，原方法結果亦可能誤判成功。

## 原 Checker 來源責任，不另造動態事件

只從已經通過原 Lexer／Parser／Checker 的 `PreparedPrivateSelfMethod.main_init_plans` 和 `argument_plans` 的原 `PrivateScalarReturnExpr.collect_calls` 收集**靜態應執行的原普通函式數**，並隨真結果移交唯讀 `expected_pre_method_calls`。所有 main／方法直接引數都已核准為純 Copyable int，且只有執行完全部這些來源後，原 `tracker.acquire(self.loan.source, self.loan.kind)` 才可取得 self 票。故凡真進入 `self` 方法的成功／異常路徑，借票前真 `FunctionEntered` 與 `FunctionExited{returned:true}` **都必須精確等於**原靜態預計數。若在 main 引數／局部執行中已故障、尚未進方法，則只可能完成原序列的已達前綴，允許已進入未成功的最內層函式，禁止超出原計畫。

原方法 `FunctionExited` 必是同步 main→self 子圖最後一筆 `PrivateSharedCallExitEvent`；不能在此後才虛構「原本應在借票前的 main 普通函式」。本批只在既有 `execute_method_self.rs` 的真 Outcome 對帳加入唯讀計數與時序，原 `PrivateSharedCallExitEvent` 定義、原 BorrowFact/HC14、P16 所有權與資源事件、Checker 語意、async 規格、公開入口全部不修改。

## 基礎與原工程缺口

#710 已在同一個原 Checker 動態工作圖實作 PrivateScalarGraphContinuation<'a>，可真正執行多層函式、建立 P16 OwnedUtf8 後，在合規 await 前封存 PrivateScalarTask、所有 PrivateScalarActiveFrame、BorrowSafety、OwnedStrRuntime 與控制／值棧，跨 Rust 呼叫恢復；然而已暫停的真動態函式並沒有取消出口。丟棄 Rust 工作物件不等於經 P16 Runtime leave_scope 的真 ResourceReleased／HC14 票據歸還，不可冒稱取消已驗收。

## 程式：原工作圖的唯一真退出核心

1. 在原 evaluate_graph_driver 增加僅內部使用的 cancel_at_checkpoint；只有 checkpoint 實際存在且 PrivateScalarGraphContinuation.status==Suspended 時才有資格取消。
2. 取消前用原 check_await_safe_point_chain 再次核實**所有活躍祖先幀** BorrowSafety 與 incoming_borrows；有效票據未歸還時保留原 snapshot 和狀態，不能預先釋放持有者或讓使用者工作進入下一指令。
3. 通過守門後，原 driver 只把此次呼叫設定成受控「不再執行使用者指令」，不再 EnterCall 或進入新 async 子框架；不生成虛構 int 返值，不把取消誤當成原執行器 RuntimeFailure。
4. 原圖既有 R05/HC14 逆序退出流程使用 must_unwind=cancel_at_checkpoint||result.is_err()，先按原追蹤器歸還可能的待結算票據，再由最內層向外真正 P16 OwnedStrRuntime.leave_scope／MixedStructRuntime 退場，逐項記錄 Released(ResourceId)、FunctionExited(returned:false)，最後原 resources.finish() 再以 event_trace_balanced 和 has_balanced_frame_trace 的同一既有驗收核對；**不另寫第二份資源清理器**。
5. 原真 checkpoint 消耗完成，狀態才進入 Cancelled；返回 PrivateScalarGraphCancellation 保存真 events／resource_events，沒有正常成功 outcome，也沒有對外創造 StateMismatch 執行期錯誤。若內部清理／稽核失敗，保守 Failed／RuntimeTraceMismatch，不聲稱取消成功。
6. 既有同步 evaluate_graph、合法完成與真 RuntimeError 的一般路徑在 cancel=false 時維持原行為；禁止任何未啟動、Running、Succeeded、Failed、Cancelled 的工作透過此接口冒稱安全點取消。

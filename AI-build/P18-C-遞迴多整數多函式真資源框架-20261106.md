# G18／P18.3、P18.4｜多 Copyable int 及多函式真 UTF-8 遞迴鏈（2026-11-06）

> 基線 main ed330910ca9e7a3ece2181287253fabc38007e1f，同 SHA 三項必要 CI success。延續 AW06、D18-01、原私有 Checker／P16／HC14。此為真正已核准子集的擴充，不能將原 G18 六項標記 Passed。

## 驗收級缺口

前一批 #559 已在同一遞迴實例接通 bool、單 str 預設借用與一個 Copyable int，含真多框架參數值與底層 HIR 算術。但 src/struct_stage/execute_recursive_str.rs 仍固定最多三個函式（main+2）且只接受單一 int，這是早期工程子集限制，不是使用者已核准的語言規格。其阻礙原 Checker 可通過的合法多個 int 與三層以上混合資源函式圖正式驗收。

## 本批實作

- 原私有遞迴準備器取消固定 2–3 函式限制，保留 main 及原 Checker 核准的各函式真簽章、ScalarHIR、TypedMember 與 call_borrows；不因未呼叫的函式存在而假造資源事件。
- 每個原 Checker 真函式接受 bool 首參、可選單一 str 預設借用和**任意個已核准 Copyable int 參數**，不指定新的語言最大參數數量。實參依原 Parser 簽章逐項比對，可用原 Lexer int 常值、任一同層 int Parameter 的 Reference HIR，允許同一 Copyable 來源按值傳給不同子參數。
- 每條真呼叫邊依順序求出所有 int 值，逐 DeclarationId 綁定到新的動態函式參數表。即使重入同一個詞彙宣告，每層仍用自己的 map；不把值或借用誤串層。唯一 str 的 BorrowFact 在持有者當前父框架 tracker 真簽發，子框架歸還後才逆序清理 OwnedStrRuntime ResourceId。
- 已有原 Checker Arithmetic HIR 底層計算、動態呼叫深度和步數預算延用；若多參數加減溢位、預算耗盡或故障，所有已執行 int 槽與真 UTF-8 ResourceId 均按函式/分支作用域逆序回收。
- 八項真來源正反：雙 int 互換、三 int 位置輪轉、同 Copyable 來源重用、五函式混合長鏈六層成功回傳、長鏈框架預算耗盡、多 int 底層溢位、多參數來源／函式身份篡改，以及 Checker 型別／個數拒絕。原 G18 逐框架資源 Gate 27→35，P18.3 原驗收來源追加八項。

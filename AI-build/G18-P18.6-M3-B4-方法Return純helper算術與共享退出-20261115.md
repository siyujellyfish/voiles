## 原始依賴與缺口

起點 `main 29fe5893458a629f345c72a4a804924f39f6311e`，其「Rust 前端建置」「Rust 獨立架構測試」「文件與工作紀錄」同一 SHA 均 `completed/success`。前批 #802／#804／#805 已完整證明同步 self 的欄位寫入 `add(n,2)+seed()` 可由同一原 Checker TypedHIR 真執行，與原 SharedCallExit 內後外退出吻合。然而原 `method_pure_value_type` 對 `fn read()->int{return seed()+2}` 或合法 `if/else` Return 內加減仍靜態核准，`method_branch_checked_pure_helper_return` 只有最外層 Call 才建立 ScalarHIR；`PreparedPrivateSelfMethod` 的 BinaryInt Return 又只接自欄位／參數加減，未將其已核准的純 Call 算術接到同一動態框架。形成 M3／B4 重要的「普通函式 × 方法 CFG × Return」有效路徑錯拒。

## 同一原 Checker／動態責任接線

1. 原 Checker 的 `method_branch_checked_pure_helper_return`，在原 `method_return_type` 已核對 int 及 Copyable／self 借用合法後，對 `TermKind::BinaryInt` 直接重用先前 #802 已驗收的 `record_method_checked_helper_write_hir`。只有所有運算葉皆為原方法 int 形參、Lexer 整數、已核准同步／單筆無副作用 int helper 時，才由**原 Checker `evaluate`** 建立相同 `ScalarHIR`。未含純 Call 的原 `self.field ± int` 專用 Return 不重簽、不新增 HIR，保持舊行為。
2. `private_self_checked_helper_return_leaf` 改為先由完整原 Checked ScalarHIR 編譯 `PrivateScalarReturnExpr`，要求 `collect_calls` 至少一份原普通函式來源，且整顆 `private_self_approved_int_call_arithmetic` 樹均有真正純 int 同步 helper 簽章。拒絕資源、Borrow、Move、await、缺失 DeclarationId、未核准函式和非法型別。
3. 同步方法直接 Return、if true、else、巢狀 true/else 的 `BinaryInt` 僅在 AST 確有已解析具名 Call 時交給上述已認證編譯器；不含 Call 的 `self.field`／參數加減仍由既有專用計畫精確檢查。原提前 Return 只在選中葉執行，未選葉零 Enter、零副作用。
4. 真執行 `PrivateSelfIntReturn::CheckedScalar` 採與 #802/#804 完全相同的 `private_self_execute_arithmetic_call` 左右順序與巢狀 helper Enter/Returned/FunctionExited；失敗時先子函式 Unwind，再由唯一 self BorrowTicket 清理。若外層純加減溢位，已真正成功的 helper 不被虛改成失敗；原資源所有權及 P16 零假 ResourceId 不變。
5. 不修改語言文法、公開 CLI、E1～E5、P13～P16 Borrow／資源語意、既有 F00／G6／G17 原凍結測試。

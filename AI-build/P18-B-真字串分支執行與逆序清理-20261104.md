# P18-B｜真私有字串條件分支與區塊清理（2026-11-04）

> **受限非公開執行切片，不是 P18.2 或 G18 正式完成。** 基準主線 `7df7ab9605e137df1a687c85154ac287fdd912a0` 的三項必要 CI success。

## 本批新增能力及限制

從原 `struct_stage::verify_source_with_ability` 成功的真私有 AST／Checker／SafetyPlan 交接。只接受最外層 main 直線語句中，原有合法 `if (true/false) { ... }`（可選單一 `else { ... }`），每個分支區塊只能含真 `var/const str` 常值宣告，且 Checker 的型別、可變性、`DeclarationId` 必須完整吻合。**在任何資源分配前預檢兩個分支；拒絕 else-if、巢狀控制、分支內 return、方法、借用或其他未接通路徑**，不自行擴張語言文法。

`PrivateStrAction::LiteralBranch` 依真 bool 值只選中一個區塊。執行時使用原 P16 `OwnedStrRuntime::enter_scope`、`declare`、`leave_scope`；即使建立中途失敗也必須離開作用域。未選分支不配置任何 String、ResourceId 或 ResourceEvent；選中分支的局部字串於離域依完成初始化次序逆序釋放，原外層持有者不受影響。全部事件只由真正 P16 Runtime 產生，不由靜態 CleanupObligation 合成。

## 六項真 Rust 正反矩陣

| 類型 | 必要驗證 |
|---|---|
| 成立分支 | 建立兩筆內層真字串，於外層返回前逆序釋放 |
| 不成立分支與 else | 未選分支零配置、選中 else 才建立／釋放 |
| 不成立且無 else | 全程無內層假資源事件 |
| 同名遮蔽 | 內層擁有者先釋放，外層擁有者最後清理 |
| 逃逸負例 | 分支局部名稱跨作用域使用，由真 Checker 預先拒絕 |
| 未完成控制語意負例 | 分支內 return／其他未接通資源控制保守拒絕 |

`tools/核對P17私有字串切片.py` 對原 11＋新 6＝**17 項**真正 Rust 案例做 `--list` 存在核對；原 `rustc --test src/lib.rs` 全量測試只執行一次。原 F00 四組凍結、G6、公開 MVP-A CLI 必須保持。

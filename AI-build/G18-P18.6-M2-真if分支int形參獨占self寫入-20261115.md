# G18／P18.6-M2／P18.4-B4：原 Checker 真 if／else 選葉中的 Copyable int 方法形參獨占 self 欄位寫入（2026-11-15）

## 起點與真正 M2 功能缺口

基線 `main 25aa3074971922557f742cbb73e0ae3220286e81`，#797 Squash merge 後同 SHA 三項必要 CI completed/success。#797 已用原 VerifiedTypedMember(Parameter) 與 `BorrowFact/ExclusiveWrite` 驗證同步方法的直接 `self.n = payload` 真動態寫入，而 M2 原 Checker 的 `if(flag){ self.n = payload; return self.n }else{ ... }`，及巢狀 if 真選中葉可寫的 `self.n = left/right`，仍被受限方法執行器的「分支寫入僅 int Lexer 常值」條件錯拒。這種 Copyable int 原方法形參使用、bool 控制、共享／獨占自借語意均早已核准；本批只接通分支的同一真正值槽，不新增語法或借用規則。

## 唯一 Checker／Lexer／動態 BorrowTicket 工作圖

新增私有 `PrivateSelfApprovedBranchWrite::{Literal(i64), Parameter(DeclarationId)}` 與 `private_self_checked_branch_write`。原 Lexer int 常值仍逐 token 起訖核對；`Name` 只能解析成同一原 Parser 方法 `int` 形參、已由 Checker `VerifiedTypedMember(Parameter)`、`VerifiedMethodSafety` 和原實參位置繫結核准的唯一 DeclarationId，並以原 `TokenKind::Name` 證明使用位置確實相同。禁止同名 main 局部、bool 形參、Move／Borrow、str／ResourceId、未曾授權的 self 欄位與未知方法冒充。

只把現有四個可寫分支來源：外層 true、外層 else、巢狀 true、巢狀 else，從 `Option<(i64, NodeSpan)>` 改為 `Option<(PrivateSelfApprovedBranchWrite, NodeSpan)>`；原 `Span`、靜態 MethodSafety 中寫入分支的有無及獨占票據模式一律不變。現有 `matches_source` 完整重建並比較欄位計畫，禁止變造編譯來源。真執行只在原 bool 條件觀測、**真正選中葉**且持唯一 `ExclusiveWrite BorrowTicket` 之後，從方法參數真 frame 取已核准 int 值，以原 `MixedStructRuntime.write_int_field` 更新；未選中分支一律零寫入／零假值讀取。所有 Return／溢位／Unwind 仍用原 R05 和 HC14 逆序退票，不引進第二套動態資源帳。

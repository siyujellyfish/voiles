# P17-C｜真私有來源驅動 UTF-8 資源事件（2026-11-04）

> 第四批工作分支候選；基底為三批 Squash 後 `main` `69e7c3e19a17ddbb3a5d406de477402f97ddffec`（三項主線 CI 成功）。**本批不是 G17 結案，未公開 P13～P16 私有語法。**

## 同一驗證來源到真正執行

- `struct_stage::verify_source_with_ability` 原正式私有 Parser／Checker 唯一入口先建立 `VerifiedPrivateSource`；增加保存同次 Lexer tokens，避免另外解析字串跳脫。
- 新 `src/struct_stage/private_resource_execution_preflight.rs` 僅在全部私有 AST、DeclarationId、真 Checker `direct_moves`、typed declaration 和 return int HIR 一致時建立 `CheckedSingleMove`。
- **整份語法在第一次建立字串資源之前完成預檢**：只允許唯一 `main()->int`，沒有 struct，恰好兩個不同名稱 `var str` 宣告與尾端 `return int`；第一個為字串常值，第二個為 `owner.move()`。if、for、函式呼叫、借用、方法、欄位、其它資源形式不藉此放行。
- `execute_checked_single_str_move` 使用現有 `OwnedStrRuntime::declare`、`move_named`、`read`、`finish` **真正建立、移交、清理一次 UTF-8 String**。事件由執行期產生，並用 `NamedResourceTransfer::verify_actual_events`（真正 Checker 的兩個 DeclarationId）與 `event_trace_balanced` 逐 ResourceId 驗證。
- 此模型不將執行期事件倒推為語法許可，沒有假借用票據；未提供公開執行命令或自行決定 OS 退出碼。

## 真測試與界線

| 工作 | 證據 |
|---|---|
| 真字串／明確移動／清理 | `Created(1) → Moved(1) → Released(1)`，結果返回已核准的 `int` 常值 |
| UTF-8 跳脫 | 同次 Lexer 解碼字串，用真執行期持有與釋放 |
| 非 Copyable 來源 | `var duplicate:str = owner` 先由真私有 Checker 拒絕 |
| 不支援但合法 | 單純 `return 0` 及不在切片內語法仍 `Unsupported`，不造假執行 |
| 偽造安全事實 | 移除 Checker `direct_moves`，預檢拒絕、不建立資源 |

新增 5 個真正 Rust 測試並由 `tools/核對G17內部切片.py` 逐名檢查；現有整套 P01/F00/G6 全部繼續執行。**這不是** P17 所要求的完整 ResourceId／BorrowTicket／SafetyState 跨 if／loop／struct 清理 Gate，也沒有完成 P17-F 建立式。

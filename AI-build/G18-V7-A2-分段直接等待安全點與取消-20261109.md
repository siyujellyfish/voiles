# G18／P18 V7-A2：經 Checker 核准的工作分段等待安全點與取消（2026-11-09）

> **定位**：在 `main a276b44f43638b3223b47941b11d86747e04bb79`（#704 已 Squash merge、同 SHA 必要 CI success）上進行的 V7 A2 續作。這是已核准 E1～E5 的**非公開內部工作分段**，不是使用者 `.voil` async 函式的完整協程，更不是 P18.6 Passed。G18 原六項正式維持 0／6 Passed，A1/A2 仍 OpenEngineering。

## 先前真缺口

`AsyncSafePointFrames::await_verified_scalar` 既有實作先 `suspend()`，立即呼叫 `DirectAwaitSession::await_direct` 執行整份 P17 真 Checker 工作，然後 `resume()`，同一次 Rust 呼叫沒有可觀測的**已暫停且尚未執行**工作狀態。即使 `cancel_suspended` 對單獨持有 P16 資源的框架已成立，仍不能在「已分段等待的同一原工作」上執行取消或切換；也缺乏跨 DirectAwaitSession 相同 task 數字的身分保護。不可把普通的停／復狀態測試冒稱真正協作式工作交付。

## 此批正式程式變更

1. `DirectAwaitStatus::Suspended` 保留尚未執行的唯一 `CheckedTask`。經原 P01 Checker 產出的 PreparedProgram 是唯一執行計畫，`suspend_verified_await` 先驗證會話 BorrowSafety、工作狀態及 P16／HC14 安全點，之後將該工作標為 Suspended。待執行工作不產生 CheckedTask 本體事件。
2. 此批沒有背景執行。呼叫者可在第一工作 Suspended 時，以同一會話的 `await_direct` 真正執行**另一個尚未保留**的已核准工作；對 Suspended 本體直接 `await_direct` 必拒絕，避免工作被搶先消耗導致等待者無法清理。
3. `wake_verified_await` 僅接受原 `DirectAwaitSession` 及原工作 ID；`Rc::ptr_eq` 是**單執行緒 Rust 會話參考身分**，不是 voiles 語言借用或 ResourceId 權限。喚醒前重新驗證真 BorrowSafety 無有效票據，拒絕時保留 Suspended 與原 P16 框架；成功後透過既有 `await_direct` 真求值，交由唯一 `unwind_frames` 結清值／RuntimeFailure／ResourceEvent。
4. `cancel_verified_await` 只允許原會話及綁定工作在 Suspended／已提前 Cancelled 的合法狀態；先真正取消未執行計畫，再由既有 P16 OwnedStrRuntime 與 HC14 BorrowSafety 退出核心按內後外清理。已存在的 `cancel_suspended`／`resume` 不可繞過綁定工作偷放行，也不允許 Running 時強制中止。
5. 既有 `await_verified_scalar` 沿用這兩段相同途徑立即依序執行，避免第二套執行或清理機制。錯誤仍沿用 P17 RuntimeFailure，沒有公開 CLI、新語法、額外 Result 型別、跨執行緒並行或未核准跨 await 借用。

## 五筆獨立 Rust 正反（不可僅 --list）

- 已分段工作的真狀態是 Suspended：另一個已核准 P17 工作可先被等待完成；之後原工作在其原框架恢復、真返回，P16 父子 UTF-8 ResourceId 由內後外各釋放一次。
- 已分段工作在喚醒前取消：未執行零事件、原工作正式 Cancelled，真父子資源離域，普通取消入口不能跳過被綁定工作。
- 兩個不同會話 task ID 即使相等，仍不能交叉喚醒或取消；原工作仍可依法繼續。
- 暫停後，會話的真 BorrowTicket 新增且仍存活時，喚醒保持拒絕與原 Suspended；歸還後原工作才可執行。
- 已暫停工作若先經合法 `cancel_before_start` 取消，錯誤喚醒不讓等待者遺失資源；原工作取消後可由合法共通退出協定清理。

# G18／P18 V1-F3：原 Checker Copyable bool 結構欄位接入真控制與函式實參（2026-11-08）

> 起點為主線 `f307c70776d6f0f3ae499418440d03e00f0ba64d`，同 SHA 三必要 CI completed/success。僅收口 F3 的 **合法純 int/bool 結構欄位條件及實參**子集，不宣稱 V1 完整或原 P18 六項 Passed。

## 真缺口

PR #654 已接通結構 `int` 欄位之 Checker→P16 真讀值；但同樣獲 Checker 認可的 `note.enabled`（`bool`）仍無法在 `if`／`while` 與 `bool` 實參中求值。若將 bool 欄位當成常數或提前由來源字面解釋，會破壞具名覆蓋和未走分支的零副作用；若讓普通 `Name` 冒充欄位來源，會破壞 `DeclarationId` 與 HIR 型別證據。

## 本批實作

- `PrivateScalarBoolExpr::CopyStructBoolField { declaration, owner, field }` 只在原 Checker `ScalarType::Bool TypedHIR`、Lexer 首尾名稱 Token、相同詞彙 `DeclarationId` 的具型別結構、正式 `bool` 欄位，且結構只有已接通 int/bool 欄位時由原 Parser `FieldRead` 形成；無任何自行猜測語法。
- 同一個 `evaluate_runtime` 直接核對當前動態 frame 的 `copy_struct_scopes` 真宣告身分，再從同一 P16 `MixedStructRuntime::field` 讀 `Observed::Bool`；已涵蓋 `if／else-if`、`while` 真條件、bool 局部宣告／覆寫、正式 bool 實參。靜態未知條件不能被預先選邊；未選分支不進入函式、不配置資源。
- 補足區塊及函式局部 Copyable 結構在 bool 名稱索引中的 `DeclarationId`；原普通 bool 名稱仍須原 Checker `TypedHIR Reference` 與 `ty=bool` 才可使用，沒有把結構隱式轉型 bool。

## 原 Checker→真 Runtime 正反六例

1. `Meter.enabled=false` 真覆蓋預設 `true`，`if` 選 `no()` 返回 3，`yes()` 零進入。
2. `choose(meter.enabled)` 的 bool 實參真正求值並傳入子函式動態 if，選 false 返回 2。
3. `while(meter.enabled)` 讀真 P16 bool 值，一輪迭代後 break、返回 1，僅一次 true 條件事件。
4. `while(false)` 來自真欄位具名覆蓋，不執行本體，返回 8，有 false 條件事件。
5. 非法 `if(meter.count)` int 欄位作 bool 條件，原 Checker 靜態拒絕。
6. 對已編譯 `bool` 欄位 `DeclarationId` 人工篡改，`SourceChanged` 在執行前拒絕。

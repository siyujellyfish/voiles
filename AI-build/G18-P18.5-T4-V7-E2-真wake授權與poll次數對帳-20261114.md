## 唯一權威與計數公式

沿用原 `PrivateScalarCooperativeQueue` 的 FIFO 工作 ID，新增只由成功 `wake` 追加的 `wake_order` 記錄，`drive_one`、`cancel`、`shutdown`、`retire_terminal` 共用既有來源守門，不新造 Checker／BorrowTicket／ResourceId。

- Prepared：`polls=0`、`wakes=0`、`ready=1`，偽造 wake 歷史在消耗前拒絕。
- Suspended：`polls>=1` 且所有 poll 皆真 Suspended，`wakes=polls-1+ready_count`；其中 `ready_count` 只能是 0 或 1。真 wake 成功前 `ready=0`；成功後 `ready=1`；下次 poll 消耗後仍 Suspended 則 `ready=0`。手工塞入 ready、重複／缺失 wake 均拒絕，保留原 checkpoint 與資源。
- Succeeded／Failed：最後恰一次 Completed，`wakes=polls-1`，完成與退休均不得靠刪改 wake 歷史取得有效證據。
- Cancelled：完全未啟動者 `polls=wakes=0`；已暫停者可以在尚未 wake 時或 wake 已入列但尚未 poll 時取消，`wakes=polls-1` 或 `wakes=polls`；仍需原 R05／P16／HC14 真逆序清理證據。
- 所有拒絕必先於 `ready.pop_front`、原續行求值／資源事件或整批取消；原 API 對真正終止工作 `WrongState` 的分類不變。

本批修正前一批一項測試的恢復步驟：偽造 `ready` 與 Prepared 狀態被拒絕後，恢復 Suspended 不得沿用偽 token，而須移除後真正呼叫 `wake` 才可繼續。

# P18.1-F2：同步 str 函式直接 return str-return

## 原 Checker 權威
既有語意允許同型別同步函式結果作為另一個函式的 `return` 表達式，例如 `fn relay()->str { return make() }`。本批僅在 **原 Checker 已整體核准且函式簽章驗證 str** 時建立 `PrivateScalarReturnExpr::StrCall`；不把 `str` 借用返回、await、非 str、結構建構或其它來源偽裝成可轉交的所有權。

## 實際 P16 執行與 R05 證明
- 原 Checked Caller 與 Callee 都在相同顯式 LIFO 工作棧上執行，內層函式透過 `ExitCall` 產生 `StrReturned(resource_id)` 與 `FunctionExited`；父幀保存同一 `OwnedUtf8` 的 pending 身分。
- 父幀真的執行到 `return inner()` 後，`ForwardStrReturn` 對 **同一個** Detached `OwnedUtf8` 發出第二筆真 `Returned(id)`，而非偷複製 String 或合成新的 ResourceId。執行器的 parent `ExitCall` 接續再真返回。
- R05 trace 只在當前幀持有已由子幀真 `FunctionExited(returned:true)` 轉交的 pending ID 時允許第二次 `Returned`；若企圖從已釋放、已具名綁定或未曾 Returned 的資源偽造來源，一律拒絕。
- 呼叫引數或內層執行失敗仍走既有逐框架 rollback，不能先造假的成功 Return；既有 P15/HC14 借用票據守門不變。

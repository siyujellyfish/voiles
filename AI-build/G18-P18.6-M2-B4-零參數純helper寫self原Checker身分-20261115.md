# G18／P18.6-M2／P18.4-B4：零參數同步純 int 函式在 self 欄位 RHS 的真實執行（2026-11-15）

## 來源與原始缺口

施工基線 `main d85c1ae87b41047054939ee30d696b3c0dcb57a5`，其「Rust 前端建置」「Rust 獨立架構測試」「文件與工作紀錄」同一 SHA completed/success。前批 PR #802、#804 已驗收原 Checker 同步純 int 普通函式作為 `self` 寫入 RHS，直接寫入和 `if/else` 選葉都能真進函式框架。但正式 Parser 的 `seed()` 為 `TermKind::UnresolvedZeroArgs`，原 Checker `method_pure_value_type` 的 `ZeroArgResolution::Function` 可證明合法，且共用 `PrivateScalarReturnExpr::from_checked_bindings` 已支援該 AST；`record_method_checked_helper_write_hir` 卻只接 `TermKind::Call`，因此**合法但缺 ScalarHIR** 的零參數 RHS 會錯被準備器拒絕。方法直接與條件選葉準備器亦只認 `Call/BinaryInt`。

## 施工與安全性

1. 原 Checker `record_method_checked_helper_write_hir::approved_rhs` 新增 `TermKind::UnresolvedZeroArgs`，**先要求唯一 `resolve_empty_call(name) == Function`**，絕不以名稱推斷普通函式、不准把同名結構 `Seed()` 當成函式。其後與原 `Call` 共用 `is_async=false`、回傳 `int`、參數數量、單筆純 int `return`、無 Move/Borrow/str/資源、無不合法副作用的保守驗證。原 Checker `evaluate` 仍是唯一 TypedHIR 來源。
2. `private_self_checked_branch_write` 和 `PreparedPrivateSelfMethod::prepare` 的直接欄位寫入，將 `UnresolvedZeroArgs` 交給**既有** `PrivateScalarReturnExpr::from_checked_bindings`。它已要求原 Checker `ScalarHIR`、正式非 main 零參數 int 函式、真 Lexer 名稱及右括號、無 Call BorrowFacts；產生唯一 `PrivateScalarReturnExpr::Call`，由既有 `method_helpers` 具型別純值簽章及動態值框架執行。其他錯誤分類維持。
3. 執行不新增任何 P16 資源、BorrowTicket 或公開語法；僅在真正選葉及已持唯一 ExclusiveWrite `self` 票據後呼叫 helper。本體溢位先真 `FunctionExited(false)`，再原方法 Unwind、唯一退票；未選分支零執行。封存計畫／helper 本體被更動必經原 `SourceChanged` 拒絕。
4. 不變更原 VB15-01-A、V7 E1～E5、S17、P13～P16、安全借用規則，原公開 MVP-A 不因此新增零參數語法或一般化工作排程。

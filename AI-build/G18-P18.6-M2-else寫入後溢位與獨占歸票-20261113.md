# G18／P18.6-M2：else 真獨占寫入後加減、溢位與原 BorrowTicket 清理（2026-11-13）

## 起點與真正缺口

以已完成新主線同 SHA 三必要 CI 的 `main 5b34197a42966922bb42f1ed9c2146c3bd8d8e0d`（PR #756）為基準。M2 目前已證同步 `self` 之 if(true)／else(false) **各自真正寫入而互斥**，且 true 葉可以寫入後計算及 Unwind；但 else 葉的已核准動態返回仍只可 `return self.n`，無法實際驗證 **else 更新值後才發生溢位** 的真失敗與獨占 BorrowTicket 歸還。

## 真 Checker 身分／唯一資源權威

本批只接通原 Checker 已核准的安全最小式：
```voiles
struct Counter{
var n:int = 7
fn read(flag:bool)->int{
if(flag){
self.n = 19
return self.n
}else{
self.n = 23
return self.n+5
}
return self.n+1
}
}
fn main()->int{
var owner:Counter = Counter()
return owner.read(false)
}
```

- `else` 寫入後 `return` 可以是原來的 `self.n`，也可以是 `self.n + int`／`self.n - int`。左端一定是原 Parser `FieldRead(self,原欄位)`；右端一定是原 Lexer `Integer` token，原 source 左右端半開跨度之間的運算子字元必須精確符合 AST + 或 -。任何額外呼叫、非 Copyable 值、未核准借用／Move 依舊拒絕。
- `method_branch_else_field_return` 繼續保存原 Checker 已驗 Return 的 `NodeSpan`，`method_branch_else_calculation` 封存由原 Parser/Lexer 還原的 `PrivateSelfIntReturn(Field/Add/Subtract)` 真工作計畫。兩者必須同時存在、一起對照原 `VerifiedMethodSafety.checked_returns`；`matches_source` 重新驗證同一原 Checker 來源與計畫值，禁止竄改計算結果、借用身分、算式或來源位置。
- 整個方法若任一葉可寫入，入口借用仍是原 Checker 推導的唯一 `ExclusiveWrite`，不因另一葉只讀而降權。只有真正執行時遇到 else，先確認原 `BorrowTicket` 獨占身分，再更新真 `MixedStructRuntime` 欄位，並用同張活躍票據讀取**更新後**的 `self.int`，最後才計算核准的加減。
- 若已寫入後算術溢位，回報既有 `IntegerOverflow`，依原 R05 事件順序進行 `UnwindStarted`、原 Tracker 真歸票及逐框架清理，**不得產生成功 Returned**。若 true 分支被選中，整個 else 寫入與溢位算式都不可執行，也不得假造第二筆資源事件。
- 此子集全是 Copyable bool/int，不會改動 `OwnedStrRuntime` 或將任何假 `ResourceId` 寫入事件帳。

## 八條原 Rust 正反矩陣

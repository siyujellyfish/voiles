# G18／P18.1-F3：同一 Checker 函式呼叫位置動態安全批（2026-11-13）

## 工程目標

本批只修補原始 F3 需要的同一實際 Checker→TypedHIR→Runtime 工作圖證據，不新造語法、解析器或可達事件。正式 P18.1 原項仍為 SubsetVerified，F3 暫時 OpenEngineering，直到各必要等價類及真來源拒絕經獨立審查完全閉合。

## 六項新增正反

| 案例 | 實際驗證與不可出現情況 |
| --- | --- |
| F3-S01 | 同一 main 的函式宣告初始化、再賦值、if 選中再賦值及 return 再呼叫，必正確依序完成四筆進出、所有返回值一致 |
| F3-S02 | if(false) 不得呼叫或建立字串；選中 else 的 str 借用與 UTF-8 必須先還 BorrowTicket 再 Released(ResourceId) |
| F3-S03 | for 0..3 三次獨立字串、三次函式進出、三次 BorrowTicket 歸還、逐輪唯一 ResourceId 釋放 |
| F3-S04 | while 首輪函式真賦值後 break，僅一筆子函式 Return，不得重播下一輪 |
| F3-S05 | 已選 if 的被呼叫者溢位，不能執行尚未到達的 fallback，不能冒充成功 Returned |
| F3-S06 | 已編譯 main 工作圖於執行前遭竄改，即使原執行平衡，亦應 SourceChanged 拒絕 |

- Rust：`src/struct_stage/g18_f3_call_site_tests.rs` 六項。
- Gate：`tools/核對G18-F3合法呼叫位置.py` 必須核對完整名稱集合，逐一 `--exact` 實際跑 1 passed／0 failed／0 ignored。
- 必要 CI：Rust 前端建置、Rust 獨立架構測試及專案檢查；保留 F00、G6、G17、R06、R07 原有凍結。
- 後續要依 F3 原契約檢查條件/迴圈控制和來源防偽必要等價類，不因 Gate 由 N 增六項就提前 Closed。

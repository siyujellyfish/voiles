# G18／P18.4-B4：原 Checker 純整數 helper 加減、跨 self 溢位與真逐框架退出（2026-11-13）

## 本批具體修復

起點 `main fea500ae7ee2327fb3a0895dbe21db0299d85ad8`，PR #763 已 Squash merge，主線同 SHA 的「Rust 前端建置」「Rust 獨立架構測試」「文件與工作紀錄」皆 `completed/success`。

已核准同步純 int 普通函式 `fn helper()->int { return (8+5)-2 }` 可由原 Parser／Checker 通過，但 B4 方法橋接先前對原 `PrivateScalarReturnExpr` **只接受 `Constant`**，合法原 Lexer 加減 Group 在 `PreparedPrivateSelfMethod::prepare` 被保守錯拒；更嚴重的是若開放原 `Addition/Subtraction`，現有方法內 helper 溢位會被錯誤映射為 `WrongReceiver`，且不真正完成內層 `FunctionExited(false)`。這是 B4 兩類同一根因缺口。

## 原 Checker 身分、動態時序與安全不變式

- **唯一靜態來源**：只在同一份 `verify_source_with_ability` 已簽發原 `TypedHIR`／Lexer／Parser 的零參數同步普通函式，允許單一 `Return` 的 `PrivateScalarReturnExpr::Constant`、遞迴組合 `Addition`／`Subtraction`。新增 `private_self_pure_helper_int` 為**嚴格白名單驗證**，任何 `Call`、`Name`、`CopyStructIntField`、非 Copyable、bool、str、非正常路徑均不接受；不靠文字偵測或自行授權新語意。
- **保留真求值**：`prepare` 封存原 Checker 計畫，`matches_source` 真重編逐欄對照；即使可推算整數，helper 的 `FunctionEntered`、運算與退出都必須在真執行到達的 main 局部或已借用 self 的方法局部才產生，未達工作不得假提前執行。
- **原 R05 動態框架**：新增 `ordinary_calls_entered`（真的進入，包含故障）與原有 `ordinary_calls_completed`（真的成功返回）分別核對 `FunctionEntered`、`Returned`。真 helper 溢位先記唯一 `UnwindStarted`、退出失敗的 helper 框架 `FunctionExited(false)`，**方法內故障**再按原已存在逆序 `LocalScopeEnded`、唯一 `BorrowTicket` 歸還及方法 `FunctionExited(false)`；**main/helper 入口故障**尚未簽發 self 票據，不可假進入方法。外層不得重複發出第二個 Unwind。
- **既有安全保持**：`private_shared_call_exit_balanced` 仍以實際事件、借用唯一性、局部生命期驗證；`has_balanced_self_borrow_trace` 同時核對完成呼叫與已進入呼叫數。沒有額外 UTF-8 ResourceId，不更動 P14/P15 借用、P16 資源及任何未決語言規格。

## 八項不重複原 Rust 真來源／反向安全

新增 `src/struct_stage/g18_b4_helper_arithmetic_unwind_tests.rs`、`tools/核對G18-P18.4-B4純算術helper溢位還票.py`：

1. main 真先計算 helper `(8+5)-2=11`、正常退出後才借 self，方法返回 12。
2. 方法借 self 時，普通 helper 真計算 11，與已初始化 int 局部求和返回 14。
3. 同一個 helper 在 main 和方法內**各執行一次**，兩次框架獨立、結果及共通進退帳一致。
4. main helper `i64::MAX+1` 真溢位：一個失敗普通函式退出、唯一 Unwind、方法未進入、零 BorrowTicket。
5. 方法內 helper 溢位：失敗子框架先退出、無成功 Returned、再清理外層方法並歸還 self 唯一票據。
6. 方法在 helper 故障之前已初始化 int 局部：真 `UnwindStarted` 後僅清理已到達前綴，沒有未初始化的幽靈局部事件。
7. 已封存 helper 加減工作計畫遭替換為相同值的 `Constant`，必在執行前 `SourceChanged`；偽造已進入／已完成次數也不得通過退出對帳。
8. 原 Checker 的 bool 返回與未宣告 int 名稱保留靜態拒絕；未經核准的遞迴 helper 不可藉純值白名單進入受限執行器。

舊 `g18_b4_mixed_self_call_tests.rs` 的**原 Gate 名稱、測試數量保持**：既有「溢位計畫拒絕」負例原為合法 `i64::MAX+1`（本批轉成已實作、可驗證真 RuntimeError），因此原用例只改成 Lexer 超出 `i64` 的非法數字，維持靜態拒絕。沒有刪除或放寬合法正例；新增 Gate 獨立以 Rust `--list` 核名與每筆 `--exact --test-threads=1` 執行，保留全部 G17、F00、G18 既有 CI。

# G18／P18.6-M2：巢狀 true／else 真獨占 self 欄位寫入與錯誤退票（2026-11-13）

## 真 Checker 安全界線與合法缺口

起點 `main 8fce0d01f7062108a5756e7f11bb270c669186d0`，PR #762 已 Squash merge 且該主線 SHA 的三項必要 CI 均 completed/success。原 Checker 已接受同步方法在巢狀 `if(bool)` 中依不同葉寫入 var int 欄位並返回；先前受限 `PreparedPrivateSelfMethod` 僅支援巢狀兩葉各一筆 `return`，合法「寫入後 return」被誤判 Unsupported。

本批只接通原 Parser/Checker 可證的**外層 true 葉唯一巢狀 if**，其內兩葉各可有零或一筆 `self.n=原 Lexer int` 寫入，最後必須是原 Checker `Return`；其他巢狀結構、資源操作、動態 RHS、非 Copyable Move/Borrow 保守拒絕。

## 實作與權威

- 在已存在的巢狀 `if` 原 Parser AST 中，true/else 兩葉僅允許 `Return` 或 `FieldAssign + Return`。對寫入欄位再次驗證 `self` 接收者、原核准單一 `var int` 欄位、原 Lexer Integer token 精確字面與 UTF-8 半開區間，從 `integer_i64` 建構兩筆相互獨立的 `method_nested_true_write`／`method_nested_else_write` 計畫，不提前求值或實際更新。
- 凡原合法控制圖任一巢狀葉存在寫入，方法入口必以原 `VerifiedMethodSafety.self_borrow`、原 call_borrows 同一 `BorrowFact` 要求 `ExclusiveWrite`；只有 `var` 持有者與 `var int` 欄位可提交更新。真執行時必先確認外層 bool 條件，**外層 true 才讀取內層原 bool 形參或 Lexer 常值**，只取得被選葉的同一真 `BorrowTicket`，未選葉不得寫入或假記錄更新。
- 真更新透過既有 `BorrowSafety::check_ticket_access(ExclusiveWrite)` 和 `MixedStructRuntime::write_int_field`。更新後才以原相同真 `BorrowTicket` 讀取最新欄位、執行原 Checker return 計畫。新兩個 `nested_*_write_applied` 動態事實與 `expected_nested_*_write` 對帳，真成功時核對兩葉互斥／應寫已寫。溢位時沿用 `UnwindStarted`、零正常 `Returned` 和原 R05 歸票。
- 既有 `matches_source` 重新 Checker 編譯需完全比對兩個新寫入計畫與原 NodeSpan，偽造來源值或跨度即 `SourceChanged`；保留所有先前同步方法與 Copyable、F00/G6/G17 凍結回歸。

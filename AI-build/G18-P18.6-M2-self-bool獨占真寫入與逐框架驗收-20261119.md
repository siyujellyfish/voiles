## 同一來源權威與不擴權

1. 方法首句必為原 Parser `StmtKind::FieldAssign` 且 `receiver=self`，目標是原 Lexer 精確自借接收者及原 Checker `additional_copy_fields` 中的**獨立可寫 Copyable bool** 成員。原 Checker 的 `method_writes` 已檢查欄位型別、var 不可變限制、Copyable 以及整體 `VerifiedMethodSafety`；本批不創建第二 Checker、隱含轉型、自借來源或其它欄位能力。
2. 原 `Group` 括號逐層由原 Parser/真 Lexer 核對。RHS 僅允許 `PrivateSelfBoolWriteSource::{Literal(bool),Parameter(DeclarationId),SelfField(field)}`：精確 true/false 原 Token、已經 `VerifiedTypedMember(Parameter)` 核准且已綁定的真 bool 形參、或原 Checker `method_pure_value_type` 核准且真 Lexer `self.field` 來源。額外 str/Move/Borrow、複合 bool、任意函式及 async 方法本體內 await 保持拒絕。
3. `direct_method_bool_write` 封存原目標欄位名、唯一 RHS 來源與 **main 前序真欄位更新後的準備期快照**；`matches_source` 每次經 fresh 原 Checker 逐項再核。任何目標名、RHS 宣告身分或預期真值改動，在方法或資源副作用之前先 `SourceChanged`。
4. 原 Checker `VerifiedMethodSafety.self_borrow` 決定唯一 `ExclusiveWrite` 的 `BorrowFact`；在 `execute` 進入真 self 方法框架並得到唯一 HC14 借票後才按原 Parser 語句求完整 RHS。布林形參從真 bool frame 取得，`SelfField` 在活票據期間從同一 `MixedStructRuntime` 讀 `Observed::Bool`，且須符合原準備期安全快照；再由 `tracker.check_ticket_access(ticket,ExclusiveWrite)` 保證所有者與動態種類，透過 `runtime.write_bool_field` **原子提交**。提交後再從 P16 讀回記錄 `direct_bool_write_observed=(field,before,after)`，不以假 `LocalAssigned` 或 OwnedStr 事件冒充。
5. 既有第一個 `self.int` 欄位保持原 int 專用寫入／返回規則；本批如第一個 int 欄位為 `const` 而額外 bool 為 `var`，原 Checker 可合法只修改 bool，不應由私有層誤以第一個欄位不可寫而拒絕。若出錯則僅由原 R05／SharedCallExit 的同一 `UnwindStarted`、逐框架逆序清理與單張 BorrowTicket 歸還負責，方法未進入或故障不得假報 Returned。
6. V7 E1 直接 `await` 的延遲子集可沿用**同一份真方法原子寫入**，但只限原已核准「main 建構單一持有者，下一句即直接 await」；before-wake 不得提早寫 bool 或借票，安全點取消/背景/跨 await 活性借用邊界不放寬。尚未驗收完整 A1/A2。

## 受限來源、真值及防偽

1. 仍限定一個已由原 Checker 驗證的 struct、第一句唯一 owner、單一 Copyable int 欄位；只接受 main int **局部初始化式**的真正 `FieldRead(owner,field)` 葉節點。原 `private_self_checked_ungrouped_return` 核對全部 Group 外殼括號與跨度；內葉 receiver 必等於原 owner 名稱、field 必等於唯一已核准欄位；原 Lexer receiver Name Token 起點、'.' Symbol Token 與欄位 Name Token 終點須一致，且同一 `verified.plan.scalar_hir.expression(leaf.node_span())` 必為 `ScalarType::Int`。絕不重解析來源字串、自行給予 Copyable 或擴張未經核准欄位。
2. 在與 #835 共用的原 Parser 工作圖加 `IntDeclareOwnerField(index)`，仍指向同一 int 局部的原 Checker DeclarationId。另封存 `main_owner_field_read_sources: BTreeMap<DeclId,NodeSpan>`，保留讀取葉節點真位置；`main_init_plans` 中的 `Constant(planned)` **僅供既有宣告清冊一一對應與同源預檢**，不能在這個步驟中當成 Runtime 讀值權威。源碼準備時 `known_owner_field_value` 只追蹤已核准 var int 欄位預設值及前序 Checker FieldAssign 的靜態值快照；若前序動態 i64 溢位，真正執行必先中斷，不可到達這個讀取步驟。
3. `matches_source` 透過整份原 UTF-8 來源再次走唯一 Lexer／Parser／Checker，核對完整 Tokens、同源 scalar plan、欄位讀取 DeclId→NodeSpan 映射、方法借票計畫及跨型別步驟清冊；任何篡改、重播或把 `IntDeclareOwnerField` 偽裝成普通 `IntDeclare` 必 `SourceChanged`，不能在動態借票後才檢出。
4. 真 `execute_with_fault` 在任何動態事件前核對 field-read 原步驟與來源映射數量一致、index 連續不重播。抵達 `IntDeclareOwnerField` 時由 #835 已真正建構的**同一 `MixedStructRuntime`** 呼叫 `runtime.field(&owner,&field)` 並要求 `Observed::Int(value)`，與已封存的原 Checker 值一致後，才以該局部原 DeclarationId 原子建立 main Copyable int 值槽；此時仍尚未簽發 HC14 self BorrowTicket。若 runtime.field 故障則沿既有 RuntimeFailure 結束後續 main／方法並執行原退出清理。所有其它 int/bool 宣告與重新賦值、helper SharedCallExit、主函式自借後的方法真正讀取邏輯保持共通。
5. 此批只支援已核准**直接** owner.int 欄位到 int 具名局部；`owner.n+1` 等複合 FieldRead 算術與 `owner.n` 直接作方法實參尚未接通同一共用 ScalarHIR 運算樹，儘管原 Checker 可以核准，私有 Executor 仍必保守 `Unsupported`，不能用未證明的文字解析或 second evaluator 冒稱完成。E1 延遲佇列仍限制無前置 main 局部、E2～E5 原借用及清理安全界線不變，未擴張背景工作或一般資源／Move。

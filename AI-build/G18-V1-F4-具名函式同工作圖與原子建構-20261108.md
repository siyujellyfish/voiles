# G18／P18 V1-F1／F3／F4：具名結構值內普通函式真呼叫與原子建構（2026-11-08）

> 起點為已合併且同一 SHA 三項 CI successful 的 `main 77ac8c1adcc06639529f2267b5d401bc5ec3ba6f`。承接前一批具名 int 動態加減，這一批消除原 Checker 已接受 `Meter(count=compute(x))`／`Meter(count=compute(x)+1)`，但受限 evaluator 無法進入已驗證函式圖的合法來源錯拒。本批是 **V1-F1/F3/F4 真正程式交叉子批**，不是 P18 原六項 Passed 或完整 V1 收口。

## 根因及同源修正

原 `PrivateScalarTask::DeclareCopyStruct` 會在單一工作項裡同步讀取全部具名種子，不能承接需要 `EnterCall/ExitCall` 的正式普通函式。另 `collect_calls` 原只巡函式返回、控制、局部 int 賦值；它把合法結構具名值內的可達函式排除在 Checker 編譯候選圖外。直接在 P16 模型中另跑一個函式執行器、提前算出靜態整數或預填 `FunctionEntered`，皆違反原安全契約。

改為：
1. `PrivateScalarCopyStructSeed::IntCall` 只在原 Checker `ScalarType::Int`、函式原 Parser/Lexer、原 HIR 對所有子算式／實參核准後編譯，保留原 `PrivateScalarReturnExpr` 工作樹；`IntArithmetic` 仍用前批純值 evaluator，不新增第二條來源猜測。
2. `PrivateScalarCopyStructPlan::collect_calls` 的結果回到 `LocalStep`／`BranchAction` 原已編譯工作圖中，讓 `main` 和普通函式以同一候選 closure 證明真正可達 callee；不可達未選控制邊不會造成動態假進入。
3. 遇到 `DeclareCopyStruct` 先建沒有任何資源的 `pending_copy_structs` 動態快照，再依 Parser 具名欄位**書寫順序**排入 `CaptureCopyStructSeed`；需普通函式的 RHS 使用原 `Evaluate → EnterCall/ExitCall → Capture`，單純 bool/int RHS 仍由原動態 `DeclarationId/P16` 真值讀取；所有具名值完成後才以 `FinishCopyStruct` 交付唯一 P16 `construct`。
4. 顯式 LIFO `pending_copy_structs` 支援被呼叫函式自己再建構純值結構。任何呼叫預算不足、動態溢位、借用失敗、預算耗盡都在 `Finish` 前停止，不能發出 `CopyStructConstructed` 或擅自持有/釋放 UTF-8 資源；返回值暫存與 `completed_arguments` 仍由既有 D18 動態框架順序管理。
5. `Finish` 再核對原欄位名稱、型別、數量與 P16 原具名／預設求值計畫，對 Copyable `int/bool` 交付真正不可變快照；`str` 結構、無共同借用／資源證明的建構及新增方法語意仍保守拒絕。

## 六項真 Parser／Checker→Runtime 正反

- `build → add(base)` 具名欄位真求值，函式先返回，後建構一次，結果 9。
- 原順序 `first=plus(2),second=double(4)` 兩次不同 callee 先後入幀／退幀，再唯一 P16 建構，返回 11。
- `plus(plus(3))+2` 真兩層函式同一工作圖返回 7，無宿主遞迴推測。
- 被呼叫者 int 溢位時，只有一次 `UnwindStarted`，正常反向退出，零半成品建構與零 ResourceId。
- `if(flag)` 未選分支中的具名函式不產生任何 `FunctionEntered` 或 `CopyStructConstructed`。
- 編譯後把已核准 `IntCall` 竄改為靜態常值，執行前 `SourceChanged` 拒絕。

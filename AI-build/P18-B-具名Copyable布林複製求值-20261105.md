# P18-B｜已核准 Copyable bool 具名來源初始化與重新賦值真求值（2026-11-05）

> **非公開 P18-B 受限真執行子批，不是 G18 正式通過。** 基準新 `main 5208d471b0b101591e8fc384f83219c02ab04c64`，PR #521 的真 `var bool` 常值重新賦值已完成最新 HEAD 三項 CI 及 Squash merge。

## 已核准前提與唯一來源

- `bool` 為原 P13 已核准 Copyable；普通純值複製不建立 Rust/P16 `ResourceId` 或借用別名，也不能解除 `str` 非 Copyable 禁令。
- 上批的真私有 Checker／P18-B 已支援直接布林常值宣告、重新賦值、具名 `if/else if/else`、巢狀控制與原 P16 UTF-8 資源逆序退出；**本批只接通同一函式中已初始化具名 bool 的直接純值初始化或重賦值**。
- `verified_nested_bool` 早已依真私有 P13～P16 `scalar_hir.reference(NodeSpan)`、`DeclarationId`、`ScalarType::Bool` 與 Lexer 名稱 token 嚴格證明 `TermKind::Name` 的身份和型別；本批**重用同一驗證函式**，不以同名文字猜測或第二 Parser 重建 AST。

## 真執行

新增 `PrivateStrAction::DeclareBoolFrom { identity, source }`、`AssignBoolFrom { identity, source }`：

1. 在來源預檢階段僅接受真 Checker 已簽發的已初始化具名 bool；不可變目的地或非 bool 來源由原 Checker 提前拒絕。可寫目的地須 `typed_declaration.mutable`。
2. 真執行以現存 `BTreeMap<DeclarationId,bool>` 取**當下來源 bool 純值**，複製給另一宣告／既有可寫位置；來源之後改值不應影響已複製的另一 bool，不建立不當 alias。
3. 後續條件透過既有 `PrivateBoolCondition::Bound(DeclarationId)` 取得最新真值，只有選中分支才使用 P16 `OwnedStrRuntime` 配置、逆序釋放字串資源。
4. 原 P17-C `is_same_prepared_payload` 仍在第一筆真正資源建立前重跑原 Checker 比對完整動作序列，包括新具名來源身份；禁止竄改已驗證 `AssignBoolFrom`。
5. 本批仍不支援任意 bool 算式、方法或跨函式回傳／容器型別複製，不開放公開 CLI。

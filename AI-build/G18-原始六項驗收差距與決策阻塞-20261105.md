## 四、新增真來源驗收稽核 Gate

`tools/核對G18原六項驗收差距.py` 具有兩個不同語意的入口：

- `--audit`：對照六原項指定真 Rust 名稱、實際重跑公用 P18 控制、私有 str 分支、for/while 與普通函式 BorrowTicket 四組；每組 **N 大於零、零失敗、零忽略** 才可回報；列明 `SubsetVerified`／`BlockedByDecision`。它的流程成功只代表阻塞**已正確核實**，並**不是 G18 Passed**，可加入每次 GitHub CI 避免遺失真證據。
- `--check`：正式 G18 六項都應有確實已核准且真正執行的完整證據，六項狀態全 `Passed` 才可成功；只要 D18-01、D18-02 未封閉或 P18.1/2/4/5 範圍未滿，嚴格返回非零，禁止將 G18 狀態勾選。

此 Gate 應在最新 PR HEAD 三項必要 CI 全部 success 後 Squash merge；合併後新 main 同 SHA 重跑原 G17 6／6、G6/F00 與 G18 `--audit`，維持本文件狀態權威。**原始 P18.1～P18.6 六個 `[ ]` 全部繼續不變，直到真正 G18 `--check` 在新 main 同 SHA Passed**。

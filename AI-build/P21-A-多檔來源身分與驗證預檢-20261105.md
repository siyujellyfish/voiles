# P21-A｜非公開真多檔來源身分與零跨檔執行驗證（2026-11-05）

> **非公開 P21-A 前置施工子批**。P19/G19、P20/G20 與 P21/G21 尚未正式通過；本批只是依 2026-11-04 已定施工流程中「路徑資料模型／診斷基礎可先施工」的受限工作，不越過依賴 Gate。基準 main `d0b66c856a0be9248f74a4bb99ebfeacf73de65a`。

## 唯一 Checker 與範圍

新增 `src/execution/registry.rs` 非公開 `VerifiedSourceRegistry`：

- 呼叫者必須**明確提供真實檔案路徑清單**；此介面不搜尋模組、不推測 `import` 或檔案載入順序，也不新增任何公開 CLI 模式。
- 逐檔經 OS `canonicalize` 取得真實檔案身分，原請求 `PathBuf` 保留作錯誤來源；以完整 canonical path 防止同一檔案經 `./` 或連結別名重複登錄。**內容相同但真路徑不同**仍是不同來源，不假定模組名稱相等。
- 每份來源只讀取實際原始位元組，交由原 `PreparedProgram::prepare` 的唯一 P01 `Lexer→Parser→Names→TypedHIR→Flow→Functions` 正式 Checker。任一檔錯誤就整份登錄失敗，不回傳半成品。
- `RegistryFailure` 明確區分 OS I/O（含 `ErrorKind`）、重複 canonical 身分、真 Checker 靜態診斷及執行前來源變更；Unicode 路徑、真 `SourceSpan` 不丟失。
- `check_unchanged` 用原請求路徑重新解析 canonical 身分，並比對準備時**完整原始位元組**；同名別名改指另一檔，即使來源內容一字不變，也拒絕沿用既有驗證。
- 此登錄**不執行**程式；單檔 `PreparedProgram` 也不串成模組依賴圖或共享任何 `BorrowTicket`／`ResourceId`。不從靜態檢查推論跨檔所有權與初始化順序。

## 七項真正 Rust 正反測試

| 驗證 | 必需結果 |
|---|---|
| 繁體中文兩個不同檔案、內容相同 | 各自 canonical 身分不同，P01 真 Checker 及獨立純值求值 |
| 同檔 `./` 別名 | 拒絕 DuplicateSource，保留原請求路徑 |
| 第二檔不存在 | I/O `NotFound`，整份登錄不交付 |
| 第二檔非法 UTF-8 | 真詞彙診斷與繁體中文／emoji 原路徑、行號一致 |
| 成功後原始位元組改寫 | `SourceChanged`，不能沿用舊 HIR |
| 未核准跨檔 `import` 語法 | 保留原 P01 靜態拒絕，不自動選擇模組語法 |
| Unix 符號連結改指另一個同內容檔案 | 仍因身分變動 `SourceChanged`，不以內容相等掩飾 |

`tools/核對P21來源登錄切片.py` 對七項原 Rust 測試做名稱 Gate；執行由原 CI 全量 `rustc --test src/lib.rs` 承擔，不重複運行。G6／F00 四凍結、舊 CLI 和公開 P01 靜態前端一律不變。

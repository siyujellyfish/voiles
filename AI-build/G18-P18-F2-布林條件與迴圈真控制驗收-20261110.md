# G18／P18.1-F2：布林函式真 if／else-if 與 while P15 受限語意核對（2026-11-10）

## 已驗收基線與真正安全約束

已合併 PR #722 之 `main 1a01ed69699cc8ad97da8f39818267c7288a7926` 同 SHA 三必要 push CI 成功後開始。本批不得鬆動 P15：「**while 條件只能使用無資源副作用的合法純值**」。原 Checker 直接拒絕 `while(ready(...))` 等函式呼叫，不論該函式只返回 true/false，亦不得藉 Runtime 新增一條隱含放行路徑。

## 真正變更：符合原 Checker 的 if／else-if 動態來源

- 原 Lexer／Parser／Checker／TypedHIR 不變，只允許原已核准的同步 `bool` 函式回傳作 `if`、`else if` 條件。
- `PrivateScalarTask::CheckEarlyReturn` 遇到已核准 `bool` Call，先在同一原始顯式棧進入子函式／完成 `BoolReturned`，由 `FinishEarlyCondition` 取得型別化真值後才決定應執行的控制邊。未選中的 else-if／else 函式不建立任何動態事件或 P16 資源。
- `PrivateScalarEarlyIf::collect_calls` 追蹤原 Checker 准許的條件來源，`PrivateScalarBranchAction::collect_calls` 追蹤合法 if 分支 bool 局部及可達函式，以原 `matches_source` 防偽。
- while 的 `CheckWhile` 保持原本的 `PrivateScalarBoolExpr::from_checked` 純值準備與 `evaluate_runtime` 逐輪讀取；特意撤回 `FinishWhileCondition` 和任何非法 while 直接函式呼叫排程。原可配置步數預算、反向迭代、UTF-8 真 ResourceId 及 R05/HC14 清理依舊有效。
- 不新增公開 CLI，不創建第二套 Checker、執行器或自定義語意。完整 bool 多型別返回與多語句執行仍待後續 F2。

## 真正 Rust 八項正反案例

由 `src/struct_stage/g18_f2_bool_condition_tests.rs` 與 `tools/核對G18-F2布林條件真控制.py` 獨立 `--exact` 執行驗收：
1. if 條件中的同步 bool 函式真返回 true 才選中分支。
2. if 條件中的同步 bool 函式真返回 false，不造未選返回。
3. else-if 從 false→true 兩個條件依來源順序真正執行。
4. 第一個 if 已真選中，不執行後續 else-if 中的 bool 函式。
5. `while(ready(flag))` 由原 Checker 先拒絕；合法 `while(flag)` 每輪真讀最新 bool，維持 true→false 正確返回。
6. `while(ready(false))` 仍須被 Checker 拒絕，不能因「第一輪 false」偷偷放行；合法 `while(false)` 不建任何本體的真 UTF-8 資源。
7. `while(ready(true))` 仍須被 Checker 拒絕；合法 `while(true)` 的 D18 StepBudget 耗盡後真回收原外層 UTF-8 資源且不假 Returned。
8. int 函式回傳不能充當 bool 的 if 條件，原 Checker 靜態拒絕。

Gate 必須逐一核對八個原始 Rust 測試名稱與實際執行結果 `1 passed; 0 failed; 0 ignored`，納入必要 CI，並保留過去的 F00/G6/G17/R05/R06/R07 原 Gate。

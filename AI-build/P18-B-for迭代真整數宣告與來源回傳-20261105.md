# G18／P18.2｜原 Checker for 迭代器真 int 值與來源回傳（2026-11-05）

> **限非公開已核准子集，不是 G18 正式 Passed。** 基線最新主線 `11bd7d5b26cc0d98aca50bed9feb6b36c0642bc9`，G17 6／6 Passed，G18 原六項仍 `BlockedByDecision`；前批具名 bool while 10 項已合併，最新主線三 CI 成功。

## 修正的實際工程缺口

原 `PreparedPrivateLoop` 雖會逐輪呼叫 `OwnedStrRuntime` 建立 str 資源，但用 `for _ in lower..upper` 丟棄已核准的 `for i in lower..upper` 具名迭代器值；因此**不能真正執行由原 Checker 已核准的 `return i`**，也不能據此確認每輪 i64 值與內層遮蔽合法。這不是單純補測試，而是連結原 P15 靜態 Iterator 宣告到實際 evaluator frame 的缺口。

## 現行實作

1. `StmtKind::ForRange` 保留原 Parser `iterator` 名稱、`iterator_start`，先核對原正式 Checker 的 `declarations.matches(DeclarationId, "int", false)`；透過來源真 Lexer、`scalar_hir.reference(NodeSpan)`、`ScalarType::Int` 證明 `return i` 恰好指向作用域內**當次 for 迭代宣告**。不從字串名稱或執行器新造 HIR 猜測型別。
2. 準備階段的迭代名稱映射只在每個實際 For 本體可見；巢狀同名 `i` 會臨時遮蔽，離開後恢復外層 ID。已離域讀取 `i` 必須由原 Checker 在執行前拒絕。空區間不執行本體也不建立虛構 iterator 值。
3. 真執行每輪以唯一 `DeclarationId` 產生當下的 `int` Copyable slot，與 `OwnedStrRuntime` 逐輪 `enter_scope／declare／leave_scope` 配對；`return i` 從此真 slot 取出值，`break`、`continue`、`return` 和故障皆在本輪資源清理後撤銷 iterator slot，不得跨作用域外洩。
4. `iterations: Vec<(DeclarationId,i64)>` 只記錄真正執行過的每輪數值；同名巢狀迭代由不同 ID 區分。保留原 `condition_checks`、str 實際 `ResourceEvent`、來源 bytes／原 Checker 靜態計畫／動作投影重新驗證；若已準備的 for ID 或 `ReturnIterator` 身分遭篡改，必須在第一筆資源配置前 `SourceChanged`。
5. 原半開上界不含 `upper`、迭代器 const、空區間無效體零作用、P15 借用與安全反向邊不變；64 次內部支援界線不提升為正式語言限制，拒絕尚未證明之任意運算、方法或併發。

## 八項新 Rust 真來源正反

| 真來源類別 | 動態結果／安全責任 |
|---|---|
| `for i in 4..5 { return i }` | 真 int=4，當輪局部 str Released 後外層 Released |
| `for i in 2..5` | 真 `iterations=[2,3,4]`，沒有右端點 5；每輪獨立 UTF-8 |
| 巢狀 `for i`／`for j`，內層 `return j` | 返回 j 的當次數值，巢狀 str 逆序清理 |
| 同名內層 `for i` 遮蔽 | 原 Checker 每層獨立 DeclarationId，返回內層 i 真值 |
| 多輪 `continue` | 每輪值獨立、離域清理一致 |
| 空半開區間有 `return i` | 零次本體、零虛構迭代、後繼合法 int 返回 |
| `return i` 在 for 外 | 原 Checker 靜態拒絕，零資源分配 |
| 竄改 ForRange iterator ID／ReturnIterator ID | 同來源計畫比對失敗，零資源拒絕 |

# G18／P18 V1-F4：Copyable 結構間具名欄位真動態交接（2026-11-08）

> 本批承接已 Squash merge 的 `main 8037bcfffb88d5689f2afddf41898c2c6f48b4c6`，該 SHA 三項必要 CI completed/success。它是 V1-F4 一個明確合法來源錯拒的修正，**不是 V1 整體已完成或 P18 六項正式 Passed**。

## 原 Checker 合法但 evaluator Unsupported 的缺口

PR #668 已將原 Checker 受控 `int`／`bool` 名稱接入真 P16 結構具名參數。但 `Target(count=source.count)` 與 `Target(ready=source.ready)` 中，來源是原 Checker 確認的 **Copyable 結構欄位**，不屬純名稱或 P16 靜態常值，因此仍被普通函式 `checked_copy_struct` 保守拒絕。

## 本批實作

1. `PrivateScalarCopyStructSeed` 只新增 `IntField`／`BoolField`，拒絕 `str`、巢狀資源及其他沒有正式安全證據的來源。
2. 編譯具名值時只重用現成的 `PrivateScalarReturnExpr::from_checked_bindings` 與 `PrivateScalarBoolExpr::from_checked`；它們已核對原 Lexer／Parser、`TypedHIR`、原結構型別、全部欄位 Copyable、安全 `DeclarationId`。不能僅以字串 `source.count` 猜測已驗證結果。
3. 真執行抵達 `DeclareCopyStruct` 時，先核對目前函式框架的來源 `DeclarationId`／原詞彙名稱仍存活，再呼叫**同一 P16 MixedStructRuntime::field** 讀 `Observed::Int`／`Observed::Bool`，並把取得的純值交由既有 `construct` 依具名順序／預設計畫建立新結構。沒有隱含共享參照或被移動的二次讀取。
4. 建構後來源再修改也不應反過來更改目標的 Copyable 欄位。沒有新增 ResourceId，保留原 BorrowTicket／OwnedStr 正確退出與來源篡改守門。

## 五項新增真來源正反

- `g18_v1_f4_具名int欄位真值快照不受來源後續更新污染`：真源欄位寫成 7，建構目標後再把來源改成 9；返回目標欄位仍是 7，恰兩次結構建構。
- `g18_v1_f4_具名bool來源欄位真快照決定後續分支`：真源欄位改成 true，目標建構後原來源再改 false，目標仍選 true 分支返回 5。
- `g18_v1_f4_具名雙欄位由另一真結構讀int_bool混合參數`：具名 int/bool 混合來源依動態實參 true／false 分別生成兩個目標，合併結果為 10。
- `g18_v1_f4_具名欄位來源型別不合由原Checker先拒絕`：bool 欄位傳給 int 具名欄位由正式 Checker 靜態拒絕。

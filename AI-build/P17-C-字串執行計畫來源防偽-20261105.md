# P17-C｜真私有 `str` 執行計畫來源防偽與零資源拒絕（2026-11-05）

> 本批是已核准 P17-C 私有執行交接的安全補強，不是 G17 或 G18 正式結案；自 `main c3b6e251d174c0f1a1f1143f04f88983875317cc` 建立，該主線原三項必要 CI 均已成功。

## 必要安全缺口

既有 `PreparedPrivateStr::prepare` 在真正私有 Lexer／Parser／Checker／SafetyPlan 成功後生成 `PrivateStrAction` 與巢狀 `PrivateStrBranchBody`，`execute_with_test_faults` 已核對真原始位元組與 `plan.is_consistent`，但尚未對**已保存的動態動作投影本身**完整比較；同來源、同靜態型別下偷換字串常值、具名 move 來源／目的、具名 bool 值或巢狀返回，可能在資源分配後才暴露問題。

## 本批實作

- 對 `PrivateStrAction`、`PrivateBoolCondition`、`PrivateStrBranchBody`、`PrivateStrLocalAction` 和局部 `str` 值啟用完整相等比較，涵蓋每個巢狀分支的控制值、所有者身分及返回值。
- `is_same_prepared_payload` **每次進入執行器前**，使用**同一正式私有 Checker 與 Lexer/Parser**對未變的原始來源重新取得全份動作投影；只有保存的原始位元組及所有動作完全一致才放行。此處不新建另一套 Parser，也不公開執行入口。
- 在原 `is_consistent` 檢查後、第一個 `OwnedStrRuntime` 資源建立前執行這項稽核。不相等返回 `SourceChanged`，不產生任何真 `ResourceEvent`；原 `ResourceId`、`DeclarationId` 與借用票據沒有交叉捏造。
- 此保守措施會增加重複 Checker 成本，後續可在可驗證的不可變計畫封裝完成時優化；本批不自行設定新的效能接受門檻。

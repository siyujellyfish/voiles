# P16.6-R03 F07｜最後使用點改為單次詞彙 DeclarationId use-def 解析（2026-11-02）

> UTF-8。本批是 R03 的真正安全路徑替換，不新開未核准語意，不代表 F07、完整 CFG 或 R03 正式結案。

## 修正根因與正式實作

- 舊 `Checker::release_last_uses` 對每一個可提早歸還的 `LoanBinding`、每一個後繼重複執行 `scope_mentions_binding`，依單一名稱加來源 ID 追蹤遮蔽；分支數量、借用別名數量增加時會對同一 AST 多次掃描，並產生另一份名稱權威。
- 新 `scan_future_block_uses` 每個語句後繼只做一次完整詞彙環境掃描，將 `Name`、`.move()`、`.borrow()`、欄位讀／寫、函式與方法引數、算術子式等實際名稱出現解析成原始 `DeclarationId`，記錄 `BTreeSet<DeclarationId>`。`release_last_uses` 只按真正借用別名的 `Binding.declaration_start` 是否出現在當前及外層後繼身分集合決定是否歸還靜態票據代理。
- `Declare` 的 RHS 先讀取外層已解析來源，再將新宣告納入詞彙環境。if／else、while 及 for range 以獨立的名稱快照解析，迭代器只於其迴圈本體遮蔽同名外層來源；退出內層不污染外層。每個外層 continuation 依其實際詞彙深度建立可見來源環境，避免不同作用域的同名宣告合併。
- 仍保留 P15 原有函式借用參數在作用域出口才歸還、僅對真正有效借用進入掃描、只有必要時才觸發 `Rc::make_mut` 的寫入時複製。掃描後繼時對 return／break／continue 仍採保守可達近似，未完整證明的路徑不擅自提前釋放。
- 新增四項身份與安全回歸：分支內同名借用別名不可延長外層票據、宣告 RHS 在遮蔽前使用舊身分、for range 迭代器遮蔽不洩漏、else 或後續仍真正使用外層別名必須保留其票據。既有 P15 真實最後使用點與 P13～P16 所有權／借用測試繼續通過最新 HEAD 必要 CI。

## 首輪 CI 修正

- 首輪 Rust 建置揭露 `DeclarationId` 原設計僅提供 `Ord`、沒有 `Hash`，因此直接使用 `HashSet<DeclarationId>` 不符合現有型別契約；正式修正為 `BTreeSet<DeclarationId>`，**不修改**基礎所有權來源 ID 的 trait 與已核准設計。以修正後最新 HEAD 全面 CI 成功為合併依據。

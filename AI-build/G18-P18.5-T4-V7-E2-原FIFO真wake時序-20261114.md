## 原主線與可重現缺口

自 #785 已 Squash merge 且 `main bd1fea4cff6429d0b3f1a2ae1bc0da8bfd264e04` 同 SHA 三必要 CI completed/success 起步。先前新增 wake_order 已能以每份工作 poll 次數、當前 ready token、cancelled／completed 真帳拒絕偽造工作。但是 wake_order 若只保存工作 ID 與次數，即使對應次數一致，仍無法證明 wake 實際發生在上一次真 Suspended 之後、下一次同 ID poll 之前，也無法拒絕跨工作時間倒流。本批不增加 async 語意或新借用權限。

## 唯一原 FIFO 時序證據

- `PrivateScalarWakeReceipt { id, after_drive_count }` 每次僅由真正 `wake()` 在 E5／原 Checker 守門之後寫入，`after_drive_count` 為同一 FIFO `drive_order` 在當時的總筆數；不重新執行已完成圖，不引入計時器或新外部可見調度。
- `verify_wake_chronology` 唯讀地以全域 `drive_order` 索引對應同 ID 第 n 次 wake 與第 n、n+1 次真 poll：必須 `receipt.after_drive_count > previous_poll_index`，若下一 poll 已存在，必須 `receipt.after_drive_count <= next_poll_index`。跨不同工作可在相同 poll 次數合法 wake，但全域憑據不可倒序，任何 wake 的時間也不可在現在的原 FIFO 之後。
- 舊 `verify_cancellable_evidence` 和 `verify_terminal_evidence` 在原計數對帳之前共同執行時序守門。無效憑據於 drive、wake、cancel、shutdown、retire 的真正狀態與資源變更之前拒絕。Prepared/Completed/Cancelled 的原計數規則與 WrongState 契約不變。
- 持續允許真 Suspended 在合法 wake 後未再次 poll 的安全點 E3 取消，保留 R05/P16/HC14 逆序清理及同工作 ResourceId，不承諾多獨立 Runtime 的全域交易回滾。

# G18／P18.4-B4：原 Checker 單一 int 形參 helper 真參數框架與跨 self 錯誤退出（2026-11-14）

## 施工起點與既有安全核准

起點 `main 2ffea6ca93f5df5be02ef19cbf731fd639078fb0`，PR #765 已 Squash merge，主線同一 SHA 的「文件與工作紀錄」「Rust 前端建置」「Rust 獨立架構測試」三必要 CI 全部 `completed/success`。上一批 B4 的直接零參數純 int helper 已可在 main 局部、方法局部初始化及合法 `var int` RHS 真執行，並在加減溢位時依唯一 `UnwindStarted`、內後外框架退出與原 BorrowTicket 歸還。

但原 Checker／一般函式求值器已具備普通 int 形式參數的 `DeclarationId`／`TypedHIR`、Call argument HIR、加減與溢位傳播，同步 self 橋接的 `method_helper` 仍只保存 `(name, scalar-return)` 並以 `BTreeMap::new()` 評估，拒絕任何合法 int helper 形參，無法把 main／方法局部動態 int 傳入被呼叫者的真正獨立框架。本批**只限原 Checker 已證同步、零或一個 `int` 形參、單一 Return、純 Copyable int 常值／唯一形參／加減**，不開放一般遞迴、多參數、嵌套 Call、資源、借用、例外、async 及方法重入。

## Checker 靜態驗證與來源身分

- `safety_checker.rs::method_checked_int_locals` 的 `helper_arity` 必須透過**同一份 Checker `find_function`** 取得唯一普通函式，限定同步、結果 `int`、形參 `[]` 或 `[int]`、單筆 Return。返回純樹只能是 `Integer`、`Group`、`BinaryInt(+|-)` 與**精確同名唯一形參**；`Name(other)`、`Call`、`self.field`、Borrow／Move 都不能偷渡進 helper。本項形狀檢核不取代原 `evaluate`、Scoped Binding 和 `TypedHIR` 型別權威。
- 方法局部宣告或 `var int` RHS 仍只准**直接** `helper(int expression)`，實參只能原 Checker 已驗證的 Copyable int 常值、既有具名槽與純加減；運算子之下不得嵌入額外 Call，bool／str／struct／await 仍禁止。
- `PreparedPrivateSelfMethod::prepare` 僅依原 Lexer／Parser 的 `VerifiedTypedMember(Parameter)`、Checker `plan.members`、`DeclarationId`、`PrivateScalarReturnExpr::from_checked_bindings` 重建 helper 的 `name`、唯一形式參數 ID 和返回 HIR。`PrivateSelfApprovedHelper` 及 `private_self_pure_helper_int` 再以嚴格白名單審核返回樹，任何未綁定名稱及函式呼叫不能通過。
- `private_self_matches_helper_call` 要求計畫是同名、未 await 的 `Call`，形參／實參數量完全相等；若有實參，類型必為已由原 Checker 建立的 `PrivateScalarCallArgument::Int`，且內部只能 Copyable int `Constant`／`Parameter`／`Addition`／`Subtraction`。所有 plan 內容與原 Checker 安全來源由 `matches_source` 真重編二次對照，不能以同值偽造另一個參數身分。

## 動態求參優先與單次退出

- `private_self_helper_argument_frame` **先從呼叫者當前的 main／方法 int frame** 求值完整實參，成功才將值放入唯一 helper 形參 `DeclarationId` 的全新臨時 BTreeMap；不借用 self 值槽冒充 helper 參數。一般函式零參數路徑仍使用空參數 frame，不改變前兩批 B4 任何正常行為。
- **呼叫者實參溢位**：尚未真進入 helper，不得記 `FunctionEntered`、`ordinary_calls_entered` 或 `Returned`；若在 main 則不取得 self 票據，若在方法則依原方法 `UnwindStarted`、已初始化局部逆序 ScopeEnded、同一自動 self BorrowTicket 歸還及 `FunctionExited(false)`。在 prepare 對已知 int 值只能做來源快照，任何受控溢位留給 execute。
- **helper 返回計畫溢位**：實參已合法綁入，記一次 `FunctionEntered` 後才可能有返回式溢位；要從內層記唯一 `UnwindStarted`、`FunctionExited(false)`，然後外層方法逆序清理、退票；不能把失敗計入 `ordinary_calls_completed`。成功則 `Returned`、`FunctionExited(true)` 後才提交原局部 `LocalInitialized` 或 `LocalAssigned`，仍需原 R05 共通框架深度與單票據稽核。
- 既有 F00／G17／G18 凍結回歸及非 Copyable 資源安全維持，不虛構任何 `OwnedUtf8 ResourceEvent` 或一般 async 能力。

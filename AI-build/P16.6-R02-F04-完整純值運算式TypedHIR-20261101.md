# P16.6-R02 F04｜P10 完整純值運算式節點 HIR 供 P11 消費（2026-11-01）

> UTF-8。本批是正式 P09 → P10 → P11 型別化資料流的進一步工程，保持 P01 MVP-A 的已核准文法、錯誤順序及公開/私有能力隔離。

## 已完成實作

- `VerifiedScalarHir` 除前批的具名讀取及賦值目標外，新增 `VerifiedScalarExpression`：保存每個 P10 成功檢查的運算式來源 `NodeSpan` 與實際推導的 `ScalarType`，以原始位元組半開 `(start,end)` 整對作為索引：群組與內層運算式可能共享起點，但結束位置不同；嚴禁用單一起點覆蓋相異節點。
- P10 正式檢查每個運算式的 int/bool 字面值、名稱、加減、分組及零參數函式，檢查成功才記錄其型別；即使 P10 在某一子式失敗，部分紀錄也不會由 `check_with_names_and_hir` 對外交付。
- 正式 P11 `check_with_typed_hir` 每次訪問具名來源、字面值、加減子式、群組、函式呼叫與返回來源，都必須能在 P10 HIR 找到同來源跨度的型別事實；if 條件還必須對應 `bool`。不再由 P11 自己默默重新授予缺失 P10 型別證據的運算式合法性。
- 公開 `check_file` 仍保留 P09→P10→P11→函式規則的既有診斷優先順序。獨立舊測試入口保留，且 P10 不承認的 decimal/string/container/move 不因此進入 MVP-A。
- 回歸驗證 `if(true)`、`(n + helper())`、`helper()` 的真實 HIR 型別與位置、P11 真正消費所有節點、在常值 return 上缺少 P10 HIR 即拒絕，以及 P01 正例/反例的既有全面回歸。

- 首輪 Rust 架構測試發現合法群組／內部運算式存在相同起點、不同終點，原先以 `start` 單獨索引造成 HIR 衝突斷言，並影響 P01 基準。已改為完整 `(start,end)` 索引，保留每個合法巢狀節點，不改變 Parser 或公開語意。

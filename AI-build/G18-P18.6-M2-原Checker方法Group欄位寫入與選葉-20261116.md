## 執行器修改與安全界線

1. 在原已驗收 `private_self_checked_ungrouped_return(verified, value)`（#817）之上，直接寫入與真條件葉寫入均先逐層核對原 Lexer `(`／`)` 與原 Parser Group 的真位元組 Span 嚴格包含，再從相同 AST 內部的真正 `Scalar`／`Name`／`BinaryInt`／已核准 `Call` 值葉選擇已驗收實際執行路徑。無第二套 Parser、沒有新特殊方法語法。
2. `Scalar`／`Name` 的常值和方法形參 Token 核對改用**原值葉精確座標**，仍必須有原 Checker 同一個方法形參 DeclarationId、已綁定 Caller 參數及合法 Copyable int；外層 Group 不可被當作任意名字或資源的授權。任何方法直接消耗 `self`、非 int 或 Borrow／Move 仍由原 Checker 靜態拒絕。
3. `BinaryInt`／同步純 int helper 的 `PrivateScalarReturnExpr::from_checked_bindings` **仍讀最外層原 value AST／NodeSpan**，由原 Checker `ScalarHIR` 及所有參數逐一構成真 int 工作圖；不能因解開 Group 殼而編造不屬原來源的獨立 RHS 計畫或丟失真控制點位置。對 if/else/巢狀真選葉亦同，`checked_plans` 仍以原外層 RHS Span 封存。
4. 真 Runtime 每個 `self` 更新仍在唯一原 HC14 ExclusiveWrite `BorrowTicket` 取得、`FunctionEntered` 後實作；選中分支才對其 RHS 計算並寫入，未選分支不得被提前求值。任何溢位或子函式 RuntimeFailure 走既有 R05 SharedCallExit `UnwindStarted`、票據原子歸還與 `FunctionExited{returned:false}`；成功則正常 Returned 和票據歸還。

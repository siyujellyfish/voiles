# G18／P18.6｜依原 Checker 零參數唯一簽章真執行同步多載（2026-11-05）

> 來源基線 main `2454f6ec3c433d0c2499dd1d37309578f471af6d`。此為已核准 S20／D18-02-A 的**非公開同步子集**，不能用作完整 P18.6 或 G18 正式 Passed 的替代。

## 先前實際缺口

原 Parser／Checker 已能保留同名不同完整參數簽章並進行唯一選擇，但 `PreparedPrivateSelfMethod::prepare` 要求 `definition.methods.len()==1`，即使 `owner.get()` 的零參數方法與 `get(int)` 可以由原 Checker 唯一辨識，也因結構含有多個方法而一律不執行。使用第一個宣告作為執行方法更可能讀取錯誤返回或拿錯 self 借用權限，因此不得採用。

## 本批變更

- `src/struct_stage/execute_method_self.rs`：先核對原 Parser `main` 的真 `return instance.method()`，依確實呼叫的方法名稱與零參數簽章，從原 `StructDecl::methods_named` 全部候選**唯一**選擇；不使用宣告第一個方法作為捷徑。無匹配／多解在任何資源建立前拒絕。
- 選定的原 AST 方法仍須通過原 Checker `VerifiedMethodSafety` 來源跨度、實際 `call_borrows_at`、共享／獨占 `BorrowFact`、合法返回 TypedHIR、Copyable int 值及自動 self 權限核對。運行時每次真正借用、取得欄位值、寫入與 checked arithmetic 均沿用 `MixedStructRuntime`；錯誤時先歸還票據再離域。
- 真正選到的多載方法不受宣告順序干擾；未選具參數候選不被誤執行。這**只接通零參數方法與其他具參數候選並存**，尚未接通動態傳入參數／一般多載方法返回值與 async。
- 新六項正反 Rust：共享唯讀／const 接收者、顛倒宣告仍同值、獨占寫入、失敗票據歸還、篡改方法跨度／Kind 零效果拒絕、尚未接通具參數多載不假裝已執行。原同步方法 Gate 19→25，G18 原六項真執行追溯補入五項；保持嚴格 `--check` 不得提前通過。
- 不變更 `check_file`、P01 CLI、F00／G6 凍結快照、D18-01 框架預算及未核准 async 可觀察語言語意。

# P23～P27 原生工具鏈

## P23 共用表示與 G05 選型

公開模組入口產生的 LinkedProgram 持有來源快照與已連結的型別化 Program。兩種模式都須先完成相同的型別、所有權、跨模組借用驗證，再從 checked_plan 取用計畫。來源變更須重新準備。舊式單檔檢查維持原有支援範圍；公開模組入口目前支援直線函式。P18、P19 的內部完整案例仍依原入口驗證。

首個後端選擇轉譯為安全 Rust，由 stable rustc 在 Linux x86-64 GNU 環境連結。以現有有型別的動作、運算式及來源位置為共用表示。原生成功結果以 int 的低八位作程序結束狀態；執行失敗寫入 stderr 並退出 1，與合法值 1 依 stderr 區分。公開 run 維持輸出完整 int。後端尚未支援的動作必須明確拒絕。

共同樣本涵蓋基本加法 5、跨檔呼叫 42、錯誤型別、有效借用期間寫入及編譯前來源變動。P22 的 CLI 案例繼續覆蓋名稱遮蔽、診斷順序與跨檔錯誤位置。

## P24 最小原生程式

以 voiles build 入口.voil -o 產物 建置。支援 int 區域變數、重賦值、加減、同步無參數跨檔呼叫及 bool 常值 if/else 兩側各直接回傳純 int 運算。兩側都先檢查，執行時只求選中運算。保留溢位、來源位置、步數及呼叫深度限制。建置於輸出所在目錄暫存，成功後才發布至新檔名。

## P25 原生資源與連結

各模組解析後按定義函式連結。同步函式以安全 Rust 值移交整筆結構，內含的 String 隨正常返回與錯誤傳遞析構；int 依值複製。跨模組借用沿用原檢查、存取同一個 slot。字素讀寫與直譯共用 Unicode 15.1 資料與分界算法。跨檔含字串結構的成功、溢位、移動後使用、Unicode 讀取皆走公開命令，系統有 LeakSanitizer 時另以該工具執行原生產物。函式庫相依限 Rust 標準庫及系統 ABI，暫無對外 FFI。

## P26 獨立執行檔

pack 在 x86_64-unknown-linux-gnu 使用靜態 CRT，將模組、字串資料、Unicode 資料與執行期編入單一 ELF。build 保留開發機的系統動態相依。驗收讀取 ELF 程序標頭與動態段，並將唯一產物放入空根目錄實際執行。僅宣告 Linux x86-64 支援。既有目的檔、缺少匯入及缺少宿主工具均有失敗回歸。

## P27 雙模式一致性與穩定化

以公開 run、build、pack 及真正產物比較。雙模式腳本檢驗深度與總步數耗盡時的診斷及位置、單一程序內逾三萬次函式呼叫及 4,096 筆含字串結構移交、512 KiB 來源、Unicode 索引越界、寫後重讀及 60 秒重複執行；原生工具鏈腳本覆蓋資源移交、清理、語意拒絕及封裝。測量包含程序啟動；直譯含來源準備，原生不含建置時間。重測可執行 python3 tools/核對P27雙模式.py target/p02/voiles。

以 P26 主線提交 6eb227d 與此批 P27 修改在同一 Linux x86-64 環境執行，rustc 1.100.0，均使用預設最佳化等級。2,048 個中文字的來源、256 次同一字素按位元組讀取，原生三次程序耗時中位數由 230.09 ms 降至 1.95 ms。原生每個字串現在會保存字素邊界，整串賦值或覆寫後重建。這是指定工作量的本機量測，各次 CI 保留測量輸出，不設絕對時間門檻。

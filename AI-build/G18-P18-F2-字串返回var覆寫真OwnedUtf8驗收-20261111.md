# G18／P18.1-F2：str-return 作 var str 首次賦值與 P16 覆寫守門（2026-11-11）

## 原 Checker 真證據與基線

以 PR #729 已 Squash merge 的 `main bcca3bcf7e3f23f340b82b980f31e6fe28e569fc` 為基線。PR #730 初次 Rust CI 編譯通過、完整 2,279 項通過／4 項失敗；失敗均在新增的 str-return 賦值測試，原因已從原 Checker 診斷確定：「**P16：此型別／右值的既有資源覆寫尚未完成端到端清理證明**」。

這是**語意安全邊界，不是可以忽略的測試干擾**：原 Checker 允許 `var output:str` 未初始化後以 `output = make()` **首次賦值**；不允許 `var output:str = "old"; output = make()`，也不允許先由函式賦值後再第二次以函式返回覆寫。不得自行放寬 P16 Checker，也不能宣稱已初始化 var 的原子覆寫是合法執行來源。

## 修正後的實作範圍

1. P16 真資源原語 `OwnedStrRuntime::replace_return_as(name, OwnedUtf8)` 保留原子驗證能力：檢查已存在可寫 owner、下一資源序號，合法提交時使用同一 UTF-8 buffer／ResourceId，失敗時把完整 OwnedUtf8 還給呼叫者以 `release_detached` 產生真清理事件。此為**內部資源原語**，不代表 Checker 開放所有覆寫語意。
2. `PrivateScalarTask::AssignStr` 只在原 Checker 真合法的 str-return `Call`，沿原顯式 LIFO `Evaluate／BorrowArgument／MoveArgument／EnterCall／ExitCall` 求值，再以 `FinishStrReturnAssignment` 接管。真正接收前二次檢查 `resources.resource_id(name).is_ok()`：若目標已初始化，立即正式釋放 pending Returned，不准提交；只允許首次賦值。
3. 原 DeclarationId、BorrowFact、原 Token/HIR 來源須全等。沒有假 int ResourceId、重新配置、已返回未接收漏資源。仍維持「含 str 結構與 scalar str 同層交錯全域清理未證明」時保守拒絕，不變更 P15、P16 與 V7 安全界線。
4. 六項原 Checker→Runtime 真正反：首次賦值混 int/bool 形參、首次賦值唯一資源、已初始化及重複覆寫原 Checker 拒絕、str 借用後續溢位回滾、const/錯型別拒絕、動態 ResourceId 篡改拒絕。另有兩項 P16 原語級接收成功與拒絕返回資源防遺失，**原語測試不是已初始化 var 執行語意開放證據**。
5. `tools/核對G18-F2字串返回var覆寫.py` 使用原 Rust `--list` 驗證全部六項＋兩項名稱，以 `--exact` 各要求 1 passed、0 failed、0 ignored；納入既有必要 Rust CI，維持原 F00/G6/G17/R05/R06/R07 Gate。

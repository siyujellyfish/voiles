# G18／P18.1、18.3、18.4｜正式 Checker 普通函式 str 參數預設借用與真 BorrowTicket（2026-11-05）

> **施工候選，非 G18 六原項正式 Passed。** 基準：`main 4b535c993cd399e5c915def61edb4b74a17a9772`；G17 已 6／6 Passed，上一批 G18 有限迴圈真資源與主線三項必要 CI 已成功。

## 一、嚴格已核准的執行來源

- 使用同一套私有 Lexer→Parser→Checker→`VerifiedSafetyPlan`，只支援已核准的單一 `main()->int` 與另一個具有唯一 `str` 參數的普通函式、`main` 已驗證單一 UTF-8 `str` 所有者及直接 `return other(owner)`，被呼叫函式直接 `return int 常值`。其他函式／方法、遞迴、巢狀呼叫、未核准一般化參數模式仍保守拒絕；**不將已核准語言函式語法直接公開成執行能力**。
- 非 Copyable `str` 實參只有原 Checker 於這次原 AST `TermKind::Call` 成功簽發的 `call_borrows_at(NodeSpan)`，且恰好一張與真來源 `DeclarationId`、`BorrowKind::SharedRead`（const）或 `ExclusiveWrite`（var）完全一致時才可進入動態執行。原 Lexer 必須保留相同名稱 token，`return` 須由真 P10 TypedHIR 證明 `int`。
- 執行前重新對完整原始 UTF-8 bytes 運行正式 Checker、比對安全計畫一致性、`call_borrows` 全表、所有宣告和操作來源與實際返回內容；任何型別、來源、參數、借用權限、返回值或 bytes 竄改一律在配置第一筆 ResourceId 之前拒絕。

## 二、真實執行和離開責任

1. 真 `OwnedStrRuntime` 建立唯一 `String` 並產生真 `Created(ResourceId)`；在執行到普通函式呼叫時由同一原 Checker `BorrowFact` 真正 `BorrowSafety::acquire` 簽發 `BorrowTicket`，逐張與原靜態快照 `verify_static_snapshot` 核對。
2. 票據存活期間不允許原所有者直接讀寫／移動；函式內僅透過票據保障的非擁有視圖讀取原 UTF-8 位元組長度，不偷偷複製新字串或偽造 ResourceEvent。被呼叫函式確實產生原 Checker 核准的 `int` 返回值。
3. 被呼叫者正常 return 或 Rust 測試在真票據存活期間故障時，均先 `finish_scope_verified` 以**原 Checker 證據**完整原子歸還所有動態票據；若正常退出，再以 `check_direct_access` 確認持有者恢復合法。最後 `OwnedStrRuntime::finish` 建立／釋放一一對應的單一真 ResourceId。
4. 故障注入只供 Rust 內部測試，不新增任何 voiles 例外／中止語意。全程不動原 F00/G6/G17、對外 P01 單檔檢查及 P22 命令界線。

## 三、八項真 Rust 正反

| 代表案例 | 核對 |
|---|---|
| const str → 普通函式 | 真 SharedRead 票據／UTF-8 位元組／int 返回、Created→Released，一份計畫可重新執行 |
| var str → 普通函式 | 真 ExclusiveWrite 票據／直接所有者封鎖、只一個 ResourceId |
| 函式中 Rust 注入失敗 | 真票據先歸還，再釋放 UTF-8，不能誤記函式正常成功 |
| 錯型別或呼叫缺參數 | 原 Checker 靜態拒絕，不准建立 ResourceId |
| 來源 alias 再借用 | 原 Checker VB14 保守拒絕 |
| 竄改 BorrowFact 來源 ID／kind | 資源開始前 SourceChanged |
| 刪去 Checker 原 `call_borrows` | 原來源全表不吻合，資源開始前拒絕 |
| 竄改函式返回值或來源 bytes | 真投影不吻合，零資源拒絕 |

新增 `src/struct_stage/execute_call_borrow.rs`、`tools/核對G18函式借用真票據.py`；八項真 Rust 正反由現有 Rust 全量真正執行，專項 Gate 另核對精確名稱存在，絕不以空過濾器冒充通過。

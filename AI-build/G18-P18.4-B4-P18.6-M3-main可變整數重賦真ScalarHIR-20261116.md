## 程式修改及原子性

1. 在原 `main` 逐語句 Parser AST 遇 `StmtKind::Assign` 時，若名稱屬已宣告 int，必驗 `known_int_mutability[DeclarationId]=true`、原 Lexer Name Token 與 statement 真起點身分，以及原 `PrivateScalarReturnExpr::from_checked_bindings` 編譯的 Checker ScalarHIR／TypedHIR。只採用既有純 Copyable int 常值、具名值、加減與已驗證同步 int helper；不新增非純運算、Borrow／Move、資源變化或一般 CFG。
2. `main_int_assignments` 保存每筆目標真 DeclarationId、準備時期望 int 值及原 Checker ScalarHIR 計畫，`PrivateSelfMainScalarStep::IntAssign(index)` 僅由原 Parser 真順序簽發，並加入 `matches_source` 在原 `Self::prepare` 與全 Lexer Token 比對後的完整防偽。對未知、const、跨型別、重播或篡改索引一律拒絕，不允許局部操作冒充靜態許可。
3. 準備時對每筆已驗證 int RHS 只計算靜態一致性快照、不提前建立真 CallExit；對可配置 i64 溢位仍允許封存計畫，真正錯誤應到 Runtime。方法引數的原值快照更新為整份已依宣告／賦值次序得出的 `known_int_values`，不能誤採初始宣告舊值。
4. 真 `execute_with_fault` 按一份 `main_scalar_steps` 順序核對 BoolDeclare、IntDeclare、BoolAssign、IntAssign 四種索引恰好各被到達一次；對 IntAssign 先唯讀查目標存在，再用真 `main_values` 動態求完整 RHS，含 helper 時仍經原 `private_self_execute_arithmetic_call`／SharedCallExit 真 Enter/Exited，成功後才以原 DeclarationId 原子寫入。若 i64 溢位，設定原 `IntegerOverflow` 並中止後續步驟、不可借入 self；已完成的真 helper 退出不會被重寫。終態帳 `expected_pre_method_calls` 追加原 int 重賦計畫的子函式數，以免漏掉已執行事件。
5. E1 延遲佇列仍不支持含前置 `main` 局部，已核准直接 await 與 E2 FIFO、E3 安全點取消、E4 原錯誤、E5 借用限制一律不放寬。本批只是內部同步安全子集，不冒充完整 B4/M3/A1/A2。

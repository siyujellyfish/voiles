## 可重現的真實退出安全缺口

`AsyncSafePointFrames::unwind_frames(Failed, true)` 舊實作逐幀先 `finish_selected_verified` 真歸還 HC14 票據，再 `OwnedStrRuntime::leave_scope` 釋放 P16 ResourceId。該順序在**所有票據／BorrowFact 可信**時正確，但若上層框架的 BorrowFact 被竄改、同一 BorrowTicket 序號跨框架重播、或真 BorrowSafety 中存在未歸屬於任何框架的有效票據：

- 先前內框架可能已真 `LoanReturned` 與 `Released(ResourceId)`；直到外框架才偵測 `SnapshotMismatch` 或 `InvalidRelease`。
- 即使返回 `Err`，原借用者與 P16 資源可能已部分被清理，卻未形成可交付的完整 `AsyncSafePointEvidence`，違反 T3 來源／事件因果原子性。
- 本缺口僅針對已存在內部安全點模型之實際 T3 風險，不冒充已打通所有來源 `.voil` 的非同步跨 await 任務。

## 修正方式

在 `unwind_frames` 的任何真退出變更**之前**，若 `release_live_loans=true`，先呼叫只讀 `verify_unwind_loans`：

1. 以真正框架清單逐筆核對 `ticket.fact() == fact`；禁止跨幀重播相同 BorrowTicket（同序號即使靜態 BorrowFact 重數巧合一致仍須拒絕）。
2. 由**原 HC14 BorrowSafety** 的 `check_ticket_access(ticket,SharedRead)` 唯讀驗證追蹤器、來源、真序號與借用種類；`SharedRead` 僅為最小存活驗證，不授予原 Checker 未允許的寫入。
3. 由既有 `verify_static_snapshot(all_frame_facts)` 唯讀比對所有真活躍 BorrowFact 的來源、權限及重數，確保沒有另一份未被任何框架承擔的有效票據。
4. 三項均通過後，才執行**原本已實作的**逐幀 `finish_selected_verified` 與 `leave_scope`；仍保持內向外、同幀先還票後釋放資源、原 E4 `RuntimeFailure` 不變。未偽造 `LoanReturned`／`Released`，也未把 Rust `Drop` 當真實資源追蹤。

此防護是對原借用／資源追蹤器做完整預檢，不另建第二份借用權威。若下一步 P16 資源本身另有錯誤，仍需獨立驗證；本批只針對 BorrowTicket 原始來源受損避免半途退出。

## 三項不重複真正反

於 `src/execution/async_task.rs::v7_a2_safe_point_tests` 新增：

- `v7_unwind_t3_多框架父票據事實污染錯誤退出前須零部分資源釋放`：外層 BorrowFact 被篡改時，兩張真票據、兩個 OwnedStr RuntimeId、兩個框架與所有退出事件均保持未改；修復後保留原 RuntimeFailure，先歸還子票、釋放子資源，再歸還父票、釋放父資源。
- `v7_unwind_t3_跨框架重播同一真票據即使靜態重數相同亦不可先退出子框架`：兩張同源合法共享票據真序號不同，竄改父票重播子序號；不能僅按來源重數就允許前兩筆 Release，修復後正常完成。
- `v7_unwind_t3_退出前追蹤器多出無幀票據不得先釋放原框架資源`：tracker 真有第三方有效票據但框架責任表沒有；失敗須零部分退出，移除不屬框架的票據後唯一真歸還與釋放。

獨立 Gate `tools/核對G18-P18.5-T3-V7多幀錯誤退出票據原子預檢.py` 使用 `--list` 嚴格核對三個唯一真 Rust 入口、逐一 `--exact --test-threads=1` 驗證全部 1 passed／0 failed／0 ignored；已接入原 `.github/workflows/前端建置.yml` 必要架構 Gate。舊 #822 的直接 await 九項正式 Gate 仍獨立核對，不得互相冒充。

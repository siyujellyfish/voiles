## 真實增量及最小安全界線

目前原 Checker 的 `method_writes`／`method_return_type` 已檢查同步 self 方法 if 的條件、所有葉子的回傳型別，並以 `VerifiedMethodSafety.checked_returns` 記錄真來源；然而 M2 前兩批 Runtime 僅支援 `if(true/false)` 或 `if(flag:bool)` 的選中葉 `return self.int`，**不存在** `else` 的實際工作路徑。本批不新造 Parser／Checker，只在 `execute_method_self.rs` 正式接通：

- 方法須仍是原 Checker 已核准、包含**首句 if、最後 return** 的直線外部結構。if true 葉只有 `return self.<目前唯一已驗證的 Copyable int 欄位>`；else 葉只有一個 `return <原 Lexer int 字面常值>`，並且不得是 else-if、Move、Borrow 別名或其他控制工作。
- `else` 的整數值須由原 Parser `TermKind::Scalar(ScalarLiteral::Integer)`、原 Lexer `TokenKind::Integer` 同一起訖跨度取得；else 真 `Return` 的 `NodeSpan` 必須已存在於原 Checker `VerifiedMethodSafety.checked_returns`，否則不得進入 Runtime。
- `method_branch_else` 保存**值及 Return 身分**，既有 `matches_source` 比對重新使用同一原 Checker 編譯結果，禁止篡改 else 返回整數或 NodeSpan；沒有在 prepare 階段先行執行任何條件或建立動態事件。
- 真 Runtime 在普通函式已按序完成、取得原 `BorrowSafety` 唯一 self BorrowTicket、進入方法框架並通過原 Tracker 身分核對後，才由原 bool 字面或真正 bool 形參決定 if 葉或 else 葉的返回。被選中分支只能產生唯一 `Returned`，且未選中的最後算式／溢位不得提前求值。
- 保留原 `PrivateSharedCallExitEvent` 退出帳、`UnwindStarted`、歸還 BorrowTicket 後清理 owner 的順序；此純 Copyable 子集仍不得偽造 `ResourceEvent`。

## 八個獨立真來源

Rust `src/struct_stage/g18_m2_if_else_tests.rs` 與獨立 `tools/核對G18-P18.6-M2原if_else真控制.py`：

1. bool true 只走 self.int 早返、不執行 else；
2. bool false 執行原 else 常值返回，不落入最後 return；
3. false 早返後不求值不可達溢位；
4. true 選枝不受未選的合法 i64 最大常值干擾；
5. 原 bool 形參版與原 bool 常值版共用真分支語意，不混淆宣告身分；
6. 方法入口故障只走原 Unwind／還票，尚未選枝不得假記成功 Returned；
7. 已驗證 else 值或 Return 來源跨度遭竄改，在執行前 SourceChanged 拒絕；
8. else 返回 bool 或把 int 冒充 bool 實參，由原 Checker 靜態拒絕。

專用 Gate 先以 Rust `--list` 核對**完整八個名稱**，再逐條 `--exact --test-threads=1` 真執行且每條須 1 passed、0 failed、0 ignored；已接入既有必要 Rust CI，不能用籠統全量成功替代這八個原義務證據。

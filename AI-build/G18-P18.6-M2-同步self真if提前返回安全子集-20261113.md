# G18／P18.6-M2：同步 self 真 if 選葉／提前 return 的首個控制工作圖（2026-11-13）

## 實際修復的 Checker→Runtime 缺口

原 `src/struct_stage/safety_checker.rs` 已以 `method_writes` 在原 Parser AST 上遞迴核對 `if` 條件型別、每個提前 return 的結果型別，以及所有可能路徑的 self 共享／獨占 BorrowFact。然而 `execute_method_self.rs` 先前僅支援直線 `int` 局部、整數欄位覆寫及最後一個 return；方法內任何 `StmtKind::If` 都被 Unsupported，即使原 Checker 已完整接受也無法真執行。

本批只接通**原 Checker／Lexer 已核准的最小控制子集**：

- 同步方法恰有首句 `if(true)` 或 `if(false)`，沒有 else，選中葉只有 `return self.<已核准 Copyable int 欄位>`，隨後只有一筆原已核准最後 return（可以是 `self.int + int`）；不得有額外局部、資源事件、迴圈、未證 bool 參數或未證多分支。
- 條件值是原 `TermKind::Scalar(ScalarLiteral::Boolean)`，其原 Lexer `Keyword` 必須吻合 UTF-8 位置；提前 return 的 `NodeSpan` 必須存在於 `VerifiedMethodSafety.checked_returns`，讀取欄位必須與真 Parser 結構欄位一致，不能由來源字串重掃或自行增設 Checker 允許。
- `prepare` 只保留原 Parser true/false 與 return 來源跨度，不預寫任何已執行分支。只有方法真正取得 `BorrowSafety` 簽發的 `self` BorrowTicket、進入方法框架、完成前段可達局部後，`execute` 才實際選擇是否提前 return；被選中的路徑只留下唯一 `Returned` 和真正退出，未選擇的算式／溢位不得被提前求值。
- 原 `PrivateSharedCallExitEvent` 仍為唯一動態方法進退帳；真 `BorrowTicket` 由原 tracker 簽發／歸還。失敗、算術溢位、未進入方法，不得偽造成功返回，不能重複歸票；Copyable-only 方法不得產生任何 `OwnedStrRuntime` 資源事件。
- `matches_source` 比對重新編譯的相同原 Checker 分支計畫與來源跨度，避免使用另一個 bool 常值或被更動的提前返回位置執行。

## 七項真 Rust 正反證據

`src/struct_stage/g18_m2_self_if_return_tests.rs` 與 `tools/核對G18-P18.6-M2同步self原if提前返回.py`：

1. 真 `if(true)` 返回 self 欄位、忽略最後 return、唯一 Returned；
2. 真 `if(false)` 不走提前返回，執行最後 return；
3. 真 `if(true)` 不預先求值未達的整數溢位式；
4. `if(false)` 走到整數溢位，受控失敗且真歸還 self BorrowTicket；
5. 方法入口注入故障時，未走到 if，不得假記條件或成功返回；
6. 已核准 bool 常值或 return SourceSpan 被竄改，執行前 SourceChanged；
7. 原 Checker 拒絕 `if(1)` 與不存在的 self 欄位。

獨立 Gate 先以 Rust `--list` 精確驗證七個測試名稱完整，再逐筆 `--exact --test-threads=1` 真執行，每筆須 1 passed、0 failed、0 ignored；同時保留 F00/G6/G17、M1、B1/B2/B3/B5、B4 已成功子集的全部回歸。

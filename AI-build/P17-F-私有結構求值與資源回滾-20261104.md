# P17-F｜私有真結構建立式求值與預設順序（2026-11-04）

> **候選子批，不是 P17.6 或 G17 全面驗收。** 以真 `main` `3c135079bd057aace08d3cd22cb05178b7d317e7` 為基準：原 P17-C 真 str 6 項與 P17/P18 控制 32 項全 Rust 1,108/1,108、必要 CI 三項成功。

## 唯一來源與安全進入條件

`struct_stage::PreparedPrivateStruct::prepare` 先由既有 `verify_source_with_ability` 驅動**真私有 Lexer、Parser、Checker、已核准安全計畫**；完整驗證之後只接受：

- 一個 `struct`、一個無參數 `fn main()->int`；單一具型別結構實例宣告及末尾整數常值 `return`。
- 已核准 `Struct()` 空建立式或 `Struct(name=literal, ...)` 具名建立式。欄位限 `int`、`bool`、`str` 的字面值，預設值取真正 StructDecl 欄位宣告與原 Lexer 同跨度字串 token，不透過字串搜尋或第二套 Parser 重造 AST。
- 真 Checker `DeclarationId` 與型別／var-const 權限必須等同來源宣告；結構欄位的型別和記號已由私有 SafetyPlan 核對，不得插入模擬宣告權威。
- 方法、巢狀結構、未知型別、額外語句、未核准的字面形式，全部在建立任何 Runtime ResourceId 前拒絕；本工程沒有對外新增語法或 CLI 功能。

## 真實執行

`PreparedPrivateStruct::execute` 在重新核對原始位元組及 P16 SafetyPlan 一致後，將真實欄位 schema 與已命名引數交給 **原有 `MixedStructRuntime::construct`**：

1. `struct_eval_plan` 先完整檢查具名欄位未知、重複與不可變欄位預設規則；不先分配資源。
2. VB16-01-A 依**來源順序執行已命名引數**，再依**欄位宣告順序**求尚未覆蓋的預設值。已覆蓋預設不執行。
3. `str` 由原 `OwnedStrRuntime` 真實配置，包含實際 `ResourceId` 的 `Created/Released`；標量不產生假資源事件。
4. 中途失敗由原 MixedStructRuntime 對 pending 欄位真實**逆序回滾**；`finish` 核對真資源完整清理，絕不從靜態 CleanupObligation 造事件。
5. 故障注入 `execute_with_fault` 只供內部 Rust 回歸，不構成 voiles 已核准例外語意。

| 正反 | 必需結果 |

# G18／P18.6-M2：頂層 else 直接 self.int 返回與加減真執行（2026-11-13）

## 原 Checker 合法錯拒與修補責任

起點為已合併且在相同主線 SHA 完成三項 CI 的 `104d0191432d97ecc35668e78b82b0e2dc437a99`（PR #761）。原 Checker 已核准下列方法控制圖：

```voiles
struct Counter{
var n:int = 7
fn read(flag:bool)->int{
if(flag){return self.n+5}else{return self.n+3}
return self.n+1
}
}
fn main()->int{
var owner:Counter = Counter()
return owner.read(false)
}
```

但受限 `PreparedPrivateSelfMethod::prepare` 先前只允許頂層 else 的單一 Lexer 整數常值返回；要回傳 `self.n` 或 `self.n +/- i64` 竟需不必要的欄位賦值，違反原 Checker 已接受的只讀合法路徑。本批消除這一個明確的錯拒，不擴張語言語意。

## 真工程、權威及動態安全

- 單一原 `StmtKind::Return` 的頂層 else 現可返回原 `TermKind::FieldRead(self,n)` 或 `BinaryInt(self.n, +|- , 原 Lexer int)`。二元運算必由原 Parser 的 `BinaryInt` 證明，右端 `Integer` token 的字面內容、半開位置與來源中間精確運算子一一相符，超出 `i64` 即拒絕。
- 無欄位寫入的 else 只採 `SharedRead` 原 BorrowFact；真有寫入時仍強制入口 `ExclusiveWrite`。原有 `method_branch_else_field_return` 保存單筆直接或寫入後的真 `ReturnSpan`，與 `method_branch_else_calculation` 一一對照；只有寫入計畫存在時才要求其返回跨度。單一常值返回與欄位計畫互斥，不接受偽造額外動作。
- 同一 `matches_source` 重編稽核核對欄位、ReturnSpan、運算及 Checker；Runtime 使用原唯一 self `BorrowTicket` 真讀取 `MixedStructRuntime` 欄位，只計算被選葉。溢位則真 `UnwindStarted`、零 `Returned` 並退票；沒有 UTF-8 假資源。

## 八項原 Rust 獨立安全正反 Gate

`src/struct_stage/g18_m2_direct_else_self_return_tests.rs`、`tools/核對G18-P18.6-M2頂層else欄位與加減.py`：

1. 動態 false 時直接讀取欄位加 3 真返回 10；
2. 動態 true 時只有 true 葉加 5 返回 12；
3. 直接 `return self.n` 真返回 7，不需要獨占權限；
4. 原 Checker 減法 `self.n-20` 返回 -13；
5. 真達到 `self.n+i64::MAX` 溢位，`UnwindStarted`、零 `Returned`、借用歸還；
6. 動態 true 不求值未選中 else 的必溢位計算；
7. 竄改已簽發的 else 算式或 ReturnSpan 必 `SourceChanged`；注入故障不得生成假正常返回；
8. 非法 bool 加法與不存在欄位保留原 Checker 拒絕。

正式 CI 在原 Rust `--list` 精確核對八條獨立案例，逐一 `--exact --test-threads=1` 執行，每條要求 1 passed、0 failed、0 ignored，保留 F00、G6/G17、既有 G18 全部回歸。

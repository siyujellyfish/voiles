## 起點與真實缺口

## 只讀原 Checker TypedHIR／動態帳唯一授權

`src/struct_stage/execute_method_self.rs` 新增封存唯讀 `write_checked_int: Option<PrivateScalarReturnExpr>`，只接受**直接同步方法首句 FieldAssign** 之原 AST `TermKind::BinaryInt`，沿用原 `PrivateScalarReturnExpr::from_checked_bindings` 必須存在的 Checker int ScalarHIR、已宣告同步方法 `int` 形參 DeclarationId；`private_self_pure_helper_int` 限定完整樹為 `Constant／Parameter／Addition／Subtraction`，不接通 Call、Borrow/Move、str ResourceId、async 或 self 欄位讀取後再寫，絕不根據純文字猜測新語意。

prepare 只封存已核准工作計畫，**不得先計算欄位新值**；真正方法 Enter 後使用當前已綁定的 `parameter_frame` 逐步 `evaluate` 並以原 i64 checked_add／checked_sub 溢位傳遞。算術成功仍必須以原 `tracker.check_ticket_access(ticket, ExclusiveWrite)` 驗證唯一真 BorrowTicket，再 `runtime.write_int_field` 提交變更；任何溢位都在欄位寫入之前報 `IntegerOverflow`，由原 R05/HC14 進行方法 Unwind、退票、結構資源安全退出，不可假造 `OwnedStr ResourceEvent`。來源快照 `matches_source` 綁定完整算術計畫，原 Checker 授權的 `var` 接收者／`var int` 欄位限制及共享讀取原則不變。

## 第二輪 CI：既有 method Parameter 不在持有者宣告表，不能錯誤否決真來源

第二輪 HEAD `040462cc36715261703517f51ea57c57546f41e2` Rust 主測試 **2731 passed／26 failed**，包含新八項及原 P13/P14 方法測試。失敗共同原因為 `VerifiedDeclarationPlan::scalar_hir_is_consistent` 本來只允許「持有者一般 TypedDeclaration」作 `VerifiedScalarHir::Reference`，但 S11/S20 的**方法形參**依法只由 `VerifiedTypedMember(Parameter)` 核准，並不存在原持有者宣告表。當前批 Checker 為任何方法形參 int 寫入記錄來源 HIR 時，原雙帳稽核無法識別此合法 Parameter，整份靜態計畫因 P16 來源一致性失敗；**不可直接移除原 Checker HIR 交付或關閉一致性檢查**。

修正 `src/struct_stage.rs::scalar_hir_is_consistent` 新增仍須經真 Parser／Checker 的受限**方法 Parameter**來源分支：只有引用出現在原方法來源範圍內、引用的 `DeclarationId` 恰等於該方法原形參 `declaration_start`，且 `ScalarType` 與原形參型別、完整 UTF-8 來源名稱均匹配，才認列；所有普通函式／非方法來源原持有者 TypedDeclaration 判定保留，非法名、跨方法 DeclId、改型別或來源都不可通過。此分支以同一 `VerifiedSafetyPlan::member_sources_are_consistent` 先核對過的原 AST 方法與 `VerifiedTypedMember` 作信任基線，不據 runtime 值、文字猜測或無證借用授權。

第二輪仍不可採計；最新 HEAD CI／合併同 SHA CI 成功才可正式驗證。原 P13／P14 凍結回歸不可刪改。

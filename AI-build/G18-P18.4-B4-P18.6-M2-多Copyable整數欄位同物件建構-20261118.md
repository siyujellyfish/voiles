## 唯一來源與執行責任

1. 只保留原 Parser 結構**第一個**被原 Checker 簽章的 `int` 欄位，現有方法 SelfFieldRead／ExclusiveWrite、main owner int 欄位寫入及原 BorrowFact/NodeSpan 仍只使用原欄位；不能因增加其他欄位就私下讓方法操作尚未驗收的第二欄位。
2. 原 `verified.structs` 仍須唯一，原方法簽章與唯一 main 不變；額外欄位逐一使用 `VerifiedTypedMember::checked_private(NodeRole::Field, declaration_span, name_span, type_span, mutable)` 並與同一 `verified.plan.members` 對帳。每個都必須有原 Lexer `Integer` 真 Token、原 Parser 的獨立 int 預設常值及安全 i64 解析；非 int／資源、無預設、重複身分／混用欄位名稱一律 Unsupported，若原 Checker 更早拒絕則保留靜態拒絕。
3. `PreparedPrivateSelfMethod` 保存 `additional_int_fields: Vec<(name, value, immutable)>`，照原欄位宣告順序，不重排、不合併相等值、不造假建構事件；`matches_source` 必逐項比對新欄位資料及原 Lexer、HIR、來源、借票與整份原 plan。篡改任一預設值必在取得任何真 BorrowTicket 之前 `SourceChanged`。
4. 真 main 第一筆 `MixedStructRuntime::construct(owner, specs, ...)` 依原 Parser 宣告次序，把主 int 欄位及全部額外純值 int 欄位**一併**建立到同一 P16 物件；維持原 owner DeclarationId、真 self BorrowTicket／HC14 安全、方法寫入及 R05 共用逐框架退出，不產生 P16 `OwnedStr` 或虛假 ResourceId 事件。主 int 欄位被合法更新後，方法本體仍讀／寫**同一**原物件。
5. 原已有的 helper、main int/bool 值槽、直接 await E1～E5、安全點取消及來源防偽保留，不新增背景派送、跨 await 活躍借用、一般化多持有者、str 欄位與非 Copyable 資源所有權語意。

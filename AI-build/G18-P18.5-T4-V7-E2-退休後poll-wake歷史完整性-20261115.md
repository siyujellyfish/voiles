## 施工基線及原始缺口

上一已驗收主線 `main 94f69030b9ea809029fd42ba43cd422212570985`（PR #802 Squash，三項必要 main 同 SHA completed/success）。前批 PR #801 已核實 Submit 歷史與 `next_id` 一致、尚未消耗的 ready token 不得遺失。然而當原工作已正常經真 `Suspended→wake→Completed→retire_terminal` 後，`jobs` 及 `ready` 都為空。此時若錯刪 **`ready_issues` 的 Woken 授權與 `wake_order` 的同筆收據**，兩者對帳仍為空／相等，舊 `verify_ready_fifo` 不稽核已退休工作 `drive_order` 的真兩次 poll，遂錯把空佇列回報為成功。另舊稽核僅對存活工作檢查 wake 收據的 `after_drive_count`，已退休時間戳篡改可能被跳過。

## 安全修正及保守界線

在 `src/struct_stage/execute_call_scalar.rs::PrivateScalarCooperativeQueue::verify_ready_fifo` 中，將原 `Submitted` 歷史建立的完整唯一工作 ID 集合視為**包含已退休工作**的授權名冊，新增唯讀不變條件：

1. 所有 `drive_order` 真 poll 及 `cancellation_order` 真取消均必須來自已簽發的 `Submitted` ID，拒絕新生幽靈身分。
2. 對每份歷史工作（無論 jobs 是否存活）核對真 poll 次數及 `wake_order` 次數：第一次 poll 由 Submit 啟動，其後每次需要一次 wake，且尚未消耗的 wake 最多一筆；曾真正完成的工作不能先 Completed 又再 Suspended，也不能出現兩個 Completed。
3. 針對所有歷史 ID 共用原 `verify_wake_chronology`：收據時間必須晚於該工作相應 poll，且不跨越下一次 poll；整條全域時間線不得倒退。
4. 檢查位置仍在 `submit`／`drive_one`／`cancel`／`shutdown`／`retire_terminal` 原受控路徑：任何不一致時，不得先消耗 ready、進入真續行、取消其他工作或釋放原 P16/HC14／BorrowTicket。**不重建、不重新 poll、不重新擁有任何已退休工作**。

本批不聲稱可以阻止攻擊者同時惡意修改所有原始歷史及其獨立備份；若要建立抗全面篡改的不可變終態憑據，仍需額外設計及驗收，不將 T4 提前標記 Closed。原已核准 V7 E1～E5／P15/P16 生命期／語法 API 不變。

## 真原 Checker 來源新增六項

沿用 `src/struct_stage/g18_t4_fifo_missing_ready_conservation_tests.rs` 中 PR #801 原十二項；新增六項：

1. 真 `Suspended→wake→Completed→retire` 後同時刪 Woken 授權與收據，空 `drive_one`／新 `submit` 均拒絕，補回原真憑據才可重新提交工作。
2. 已退休工作 `wake.after_drive_count` 從原 1 篡改為 0，拒絕假時間並能安全恢復。
3. 全部退休後插入未有 `Submitted` 的幽靈 poll，必在執行前拒絕。
4. 退休完成後偽造 `Completed→Suspended` 歷史不得重新啟動原 ID。
5. 另一份真 Prepared 工作仍在 ready，已退休工作喚醒憑據被同步刪除時，`shutdown` 整批不得有任一取消副作用；修復後原逆序取消正常。
6. 已退休工作後追加未知 ID 的取消歷史，空佇列及新 `submit` 必拒絕。

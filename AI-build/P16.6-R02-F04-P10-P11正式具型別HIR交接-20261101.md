# P16.6-R02 F04｜正式 P09→P10 型別 HIR→P11 資料流（2026-11-01）

> UTF-8。本批將正式 `check_file` 的 P10/P11 資料交接由單純的 P09 名稱表升級為**成功通過 P10 的具型別存取 HIR**；仍非完整函式及 CFG 安全計畫，不代表 F04/F05/R02 結案。

## 實際完成

- `common_ir::VerifiedScalarHir` 保存已由 P10 親自驗證的每個具名讀取與賦值目標：來源 `NodeSpan`（UTF-8 半開位元組）、`DeclarationId` 與已解析 `ScalarType`；讀取與賦值分表，不可用途交叉冒充、不可用相同起點但不同結束位置偷渡。
- P10 正式分析運算式及賦值時，先驗證 P09 `TypedDeclaration` 與真正可見詞彙環境身分、型別、var／const 權限一致，才在內部累積 `TypedUse`；**整份 P10 檢查成功後**才交付 HIR。失敗路徑的部分事實無權交給 P11。
- P11 新增 `check_with_typed_hir`，每次具名讀取、賦值都須對照 P09 完整宣告表與 P10 HIR 內的相同位置及 `TypedUse`。P10 未交付的來源不能由 P11 直接以 P09 表格推估已通過型別檢查。
- 公開 `check_file` 正式串接 `P09 → P10 check_with_names_and_hir → P11 check_with_typed_hir → 函式驗證`，維持原有 P10 優先、P11 次之及函式最後的診斷順序。原獨立 P10、P11 測試入口仍保留，不能因此聲稱其它模式開放。
- 回歸保護一筆 `n = n + 2` 同時具備賦值目標、右值引用、後續 return 引用的真實來源證據，缺 P10 HIR 必須被 P11 拒絕；P01 19 正例及既有錯誤診斷完整回歸。

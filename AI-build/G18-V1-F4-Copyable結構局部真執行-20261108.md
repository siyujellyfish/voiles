## 起點、原缺口

起始 `main e8433cf4c10f7b3a5adbf509a5c0ac9898b36b37`，已核對三項必要 CI completed/success，承接 PR #652 的 F3 同源呼叫圖。原 V0 實證錨點 `g18_r01_真正可達的結構局部函式仍須保守拒絕` 當時以合法 `Archive{count:int=7}` 的 `route(false)→idle()` 證明 Checker 成功但標量 evaluator Unsupported。此 V0 清冊與來源仍作歷史基準，不改寫其原始結論；本批新的正例使用**原 V0 相同來源**再次實際驗證。

## 本批接通範圍

1. 原 Checker 封閉 `VerifiedPrivateSource`，用唯一 `DeclarationId` 核對函式、if/else、for/while 的局部結構宣告、名稱、型別與可寫性；只有真 `TermKind::Construct` 或正式分類的 `UnresolvedZeroArgs` 可建構。
2. 透過既有 P16 `approved_seed` 驗證純 int／bool 預設或具名覆蓋，保留 `Skipped` 以拒絕執行未選預設；只在動態執行到真宣告時交付 `MixedStructRuntime::construct`，不能提前計算或虛構零件。
3. 原普通函式／main／if／for／while 的 LIFO 工作計畫依詞彙作用域進退，正常返回、錯誤回滾、break/continue 都同步讓 P16 真結構值離域。新增 `CopyStructConstructed(DeclarationId)`、`CopyStructScopeEnded(DeclarationId)` 為 **純值局部來源帳**，與 OwnedUtf8 ResourceId 不混淆；納入 R05 事件順序與共用退出表，篡改事件須拒絕。
4. 此批嚴格拒絕任何 `str` 欄位、巢狀結構／資源或未接通的結構 move／方法，不會把 P16 的第二個獨立 OwnedStrRuntime 複合為已有真資源事件。任何預期外 P16 資源事件會成為 `StateMismatch`，以原子保守拒絕代替假雙帳互通。

## 真實正反入口

新增四項專案專項 Gate：
- `g18_v1_f4_原v0可達純int結構局部真建構並反序離域`：原 V0 完全相同 int 結構來源，`route(false)→idle()` 返回 99、實際一次 P16 建構及一次真離域、零 UTF-8 資源事件。
- `g18_v1_f4_未選分支純結構與資源均零建構`：`route(true)` 零 idle 框架、零結構建構、返回 7。
- `g18_v1_f4_純結構建構後int溢位逐框架離域不留資源`：建構一次後動態溢位、唯一回滾、結構真離域一次、零 ResourceId。
- `g18_v1_f4_含str欄位仍由原Checker後保守拒絕不得雙帳冒充`：合法 Checker 來源在未接通共同資源帳時仍受控 Unsupported。

歷史六項的 `Unsupported` 反例改為含 str 欄位的合法可達結構，使原負面安全界線在能力擴充後仍有測試約束；**不修改 V0 原始清冊**。G18 普通函式 Gate 327→331，P18.1／2／4／5 真來源追溯已增加實際案例。若最新 PR HEAD/合併後 main CI 尚未完成，不得宣稱此子批完成。

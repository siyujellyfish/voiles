## 真 Checker→Executor 落差

原 Checker `Checker::statement_body` 對直接 `owner.n = rhs` 先核對已初始化接收者、`var` 持有者及 `var int` 欄位、RHS 型別及來源；成功提交後在原 `statement.start` 記錄 `recorded_field_writes(owner DeclId, statement.start, field)`。封存原 `CheckedDeclarations::verified_field_write(owner, statement_start, ty, field)` 會再稽核唯一持有者、型別、mutable 與該語句唯一來源。合法 `var owner:Counter=Counter(); owner.n=11; return owner.read(false,true,5)` 應由方法真正讀取 11，不可仍只看到預設 7。

先前私有 `PreparedPrivateSelfMethod::prepare` 對 main 的直線語句只接受 int/bool `Declare`、`Assign`，遇到原 Checker 已核准的 `FieldAssign` 即 `Unsupported`。而 `MixedStructRuntime::construct` 原本位於所有 main 純值步驟之後，沒有在真正原語句位置執行欄位寫入與 helper 的因果順序。

## 本批有界安全設計

1. 前置原 Parser owner **仍限定主函式第一句**、唯一結構與單一獨立 `var int` 預設欄位；提前讀取原 Checker 已核准的 owner 名稱、型別、`DeclarationId` 並驗 `plan.declarations.matches`。保留後段完整 constructor／方法 receiver／借票與 ScalarHIR 核查，不自行猜接收者。
2. 遇主函式原 `StmtKind::FieldAssign {receiver,field,value}`，必同時核對接收者名稱完全等於唯一 owner、欄位名等於原 Checker 已核准的單一 int 欄位且可寫，及 `plan.declarations.verified_field_write(owner_id, statement.start, owner.ty, field).is_some()`；未簽發來源一律 Unsupported。RHS 僅使用既有 `PrivateScalarReturnExpr::from_checked_bindings`／原 Checker ScalarHIR、原 Lexer、已初始化 int 名稱、純 int 加減或已證同步 int helper；不新增 field-read RHS、Borrow、Move、容器、資源或一般 CFG 安全權限。
3. `main_owner_field_assignments: Vec<(i64, PrivateScalarReturnExpr)>` 封存每筆 Checker 核准的純 RHS、靜態值來源；`PrivateSelfMainScalarStep::OwnerIntFieldAssign(index)` 以**原 Parser 逐句**接入與 int/bool 宣告／重賦同一真工作圖。source 持續由 `Self::prepare(text)` 與完整 Lexer Token 核對全部 plan；步驟表索引須連續不重播、總數唯一，變造目標或 RHS 的新舊計畫必 SourceChanged，不允許假造多筆同值欄位寫入。
4. 真執行時將唯一 `MixedStructRuntime::construct(owner)` 移至主函式持有者第一句對應的時間點，**先於**所有可能產生真普通函式事件或溢位的 main 後續語句。遇 `OwnerIntFieldAssign` 先按原 `main_values` 動態求完整 RHS、既有 `private_self_execute_arithmetic_call`／SharedCallExit 真 helper Enter/Exited；成功且與原 Checker 封存值一致後才對**同一** `MixedStructRuntime` 執行 `write_int_field(owner,field,value,owner_mutable)`。若 i64 溢位或動態欄位錯誤，沿用現有 RuntimeFailure 中止後續主函式／方法，不借入 HC14 self，最後執行原 P16 清理，不能改寫已完成的普通函式事件或虛構 OwnedStr ResourceId。
5. 真方法 Enter 後仍經原 `BorrowSafety` 自借票，method 讀 `runtime.read_int_field` 的**同一物件最終值**；若方法本身有已核准 ExclusiveWrite，仍保留原方法內 write_int_field／LoanReturned 責任，不另造第二條 self 安全模型。新增 RHS helper 預期數至 `expected_pre_method_calls`，避免 SharedCallExit 雙帳漏項。
6. V7 E1～E5 原規格不變：沒有開放背景工作、借用跨 await 或額外 async 功能。這只是目前受限同步自借前的合法 owner Copyable int 寫入子集，不是整體 P18.4／P18.6 的完整 CFG／Borrow×Move／多資源安全結案。

# P17-C｜已驗證 str 整筆移動至現存 var 的真資源重綁（2026-11-04）

> 本批為 P17-C 私有安全切片增量，**不是 P17.3 或 G17 正式完成**。從 `main` `fe35060db6eb17e03b688da94d1b448eba3506be` 建立工作分支；該 SHA 三項必要 CI 成功。

## 核准來源與實作

原 VA16-03-A 已核准：非 Copyable `str` 可以明示 `source.move()` 轉交給既有可寫 `var`，目的地原有資源在成功提交後真實釋放，失敗不得先破壞任何持有者。此政策由原 `struct_stage::verify_source_with_ability` 實際 Checker 與 P16 `OwnedStrRuntime::replace_from` 實作，本批只連接**已核准交集**：

- `PreparedPrivateStr::prepare` 保留完整正式 Lexer/Parser、Checker/SafetyPlan 的前置證明。只有已驗證 `str` 來源及可寫 `str` 目標，且來源、目標 `DeclarationId` 不相同，才建立 `PrivateStrAction::AssignMoved`；未知來源、非法型別、別名、未核准控制流程不放行。
- `execute_with_fault` 的真正執行依原始語句順序呼叫 P16 `OwnedStrRuntime::replace_from(from,to)`：先完成所有可失敗的資格／排序檢查，再從來源 `Option::take()`，產生真 `Moved(ResourceId)`，原子替換目的地並立刻 `Released(舊資源)`。
- 一樣以 `finish` 完成所有剩餘資源逆序清理，且 `event_trace_balanced` 必須成功。靜態 `DeclarationId` 與真 `ResourceId` 保持分離，不從模擬義務造事件。
- 不將此私有路徑開放給 `check_file` 或 `voiles <單檔>`；沒有容器複製、未核准例外或新 OS 退出碼。

## 新增五項真來源／真資源驗收

| 測試 | 預期 |
|---|---|
| 具名來源移動覆寫既有 str | `Created(1),Created(2),Moved(1),Released(2),Released(1)` |
| 原來源移動後再賦獨立字串 | 真新資源建立與完成次序逆序釋放 |
| const 目的地與自身 move | 真 Checker 先拒絕，不進 Runtime |
| 已移動來源再次移動 | 真 Checker 先拒絕，不生 ResourceEvent |
| 準備後竄改來源 | `SourceChanged`，拒絕執行 |

`tools/核對P17私有字串切片.py` 對原六項及新五項合計十一項內部真 Rust 測試作 `--list` 存在性核對；它們由原 CI `rustc --test src/lib.rs` 全量執行，不另重跑以避免延長 CI。F00 四凍結與 G6 維持原始必要回歸。

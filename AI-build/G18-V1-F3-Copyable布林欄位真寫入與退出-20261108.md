# G18／P18 V1-F3：原 Checker 真 Copyable bool 結構欄位寫入與退出稽核（2026-11-08）

> 施工起點：`main f75ed141b49ffda7c117846832664ea1bb42c30c`；其前一批 PR #659 已更新可寫純 `int` 結構欄位。此批為 V1-F3 **合法 bool 欄位補洞子集**，並非 V1 全部完成或 P18.1～18.6 正式 Passed。

## 原因與採用的既有安全契約

原 Lexer／Parser／Checker 已接受 `var` 結構持有者上的 `var bool` 欄位寫入，例如 `flag.ready = true` 或 `flag.ready = other.field`，並以 `TypedHIR` 驗證布林 RHS。但普通函式 `execute_call_scalar.rs` 原本只會編譯與執行 `int` 欄位更新，仍對這一類 **Checker 接受的合法來源**回傳 `Unsupported`。不必新增語法、允許未授權 move 或擴張公開 CLI。

本批在既有 P16 `MixedStructRuntime` 增加受限 `write_bool_field`：它重查接收者可寫、完整結構值、欄位存在、`const` 欄位及 `StoredValue::Bool`，在原結構持有者上真正修改 bool，不建立或釋放 `OwnedUtf8`。

普通函式編譯器的 `checked_copy_struct_bool_write` 只接受同一 `VerifiedPrivateSource` 的原 `DeclarationId`、原 Lexer token、原結構的 `bool` 欄位及 `PrivateScalarBoolExpr::from_checked` 已核准 RHS。頂層函式與巢狀分支／迴圈的計畫均以原 Checker 對欄位的型別決定 `AssignCopyStructBool`；在真正抵達動態 `WriteCopyStructBool` 工作前不得預求值或留下寫入事件。

執行時仍要求活躍詞彙作用域的原 DeclarationId、已存活的 P16 結構及 `BorrowSafety::check_direct_access`，再執行 RHS `evaluate_runtime` 與 `MixedStructRuntime::write_bool_field`，完成後才新增 `CopyStructBoolFieldAssigned`。來源事件連同其他 Copyable 局部由既有 `shared_call_exit` 和 `has_balanced_frame_trace` 檢查；資源事件繼續只能由原 OwnedStrRuntime 產生。

## 原 Checker→Runtime 七項新正反

1. 可寫 bool 欄位 true 更新之後，真正以更新後的值選擇 if 返回 7。
2. 同一結構兩個 bool 欄位：讀右欄位更新左欄位後，再改右欄位；確認原 RHS 先讀後寫，沒有回退到預設值。
3. 雙次不同 bool 實參選擇 if/else 葉寫入，傳給下一個正式函式；未選葉不產生假更新。
4. `for` 真兩輪 `continue` 與 `while` 真 `break` 結合 bool 欄位更新，返回當下真值、離域及事件數。
5. 成功更新後發生 int 算術溢位：唯一 `UnwindStarted`、真結構單次反向離域、零 UTF-8 資源事件。
6. `const` 結構、`const bool` 欄位或 int RHS 寫 bool 由原 Checker 靜態拒絕。
7. 真執行結果的 bool 欄位事件 DeclarationId 被偽造時，正式稽核拒絕。

普通函式專項真來源 Gate **355 → 362**。本次證據加入 P18.1／18.2／18.4／18.5 的既有 `--audit`，但 `--check`、原 V0 初始 JSON 清冊、F00／G6／G17 凍結及 P18 六原項狀態都不修改。

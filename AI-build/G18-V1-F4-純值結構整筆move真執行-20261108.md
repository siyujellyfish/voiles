# G18／P18 V1-F4：原 Checker 純值結構整筆 .move() 與 P16 真持有者轉交（2026-11-08）

> 工程起點為已合併 `main a4678b52445ddabed9f367b64831f125e34aa2c7`。此文件是 V1-F4 的 **純 int／bool 欄位結構整筆 Move** 子批施工證據，不是 V1 完整驗收，不更動 P18 原六項 **0/6 Passed**。

## 原先合法來源錯拒

既有普通函式顯式堆疊可真建構、讀寫 `Meter` 的純值結構，但 `var target:Meter = source.move()` 即使經原 Checker 核准，`checked_copy_struct` 仍只接受原 `Construct`，回傳 `Unsupported`。強行把此 Move 當第二次 `construct` 會虛構新的結構值及所有權，也破壞 P13/P16 已核准的整筆移動契約。

## 正式安全接通

1. `PrivateScalarCopyStructInitializer` 明確區分 `Construct` 與 `Move { source, declaration }`；移動時必先經原 Checker 真來源及原 `PreparedPrivateMoveCall::checked_move_name` 核對合法 Lexer `.move()`，並以當前詞彙 `DeclarationId` 保證來源與目標結構型別一致，動態不可憑文字名稱猜測。
2. **僅允許所有欄位都是 `int`／`bool` 的結構**。含 `str`、巢狀複合資源、任何尚缺單一 ResourceId/票據共同帳本的結構，一律維持原 `Unsupported`；不得重新建立 UTF-8 來假裝移動。
3. 真執行時先核對來源實際存活於目前 frame 及合法借用權限，再交給**同一 P16 `MixedStructRuntime::move_whole`**；原 slot 變成已移動，目標新詞彙身分接收同一值，不呼叫 `construct` 或複製整筆資料。
4. 新 `CopyStructRelocated { source, target }` 事件與 `CopyStructConstructed` 分離。逐 frame 追蹤已轉交來源，禁止第二次轉交、假來源身分及已移走欄位寫入；真結構新詞彙身分與共用 `shared_call_exit` 一致，正常／失敗均依原建立順序逆序離域。

# G18／P18 V7 D18-01：真私有 FIFO 工作跨 await 保持同一累積執行預算（2026-11-09）

> 基準 main e953c141e5ccf74386f6435c44f125a9da0eb983，PR #716 Squash merge 後三必要 CI 在同一 SHA 全成功。本批只實作既有 D18-01「每次工作有執行環境預算」的**跨 suspend／wake 連續性**，不是修改語言固定遞迴／迴圈規格。P18.1～P18.6 正式 0/6 Passed；V0 26 條 OpenEngineering 仍待完整結案。

## 背景與缺口

主線已具有 PrivateScalarGraphContinuation／PrivateScalarGraphCheckpoint、真動態 Checked CFG、P16/HC14、PrivateScalarCooperativeQueue FIFO、PrivateScalarCheckedProgramCatalog 登錄及 E3 合法安全點取消。原 GraphCheckpoint 已保存 steps，原執行器每次 resume 會繼續累積，但原 PrivateScalarGraphContinuation::root_for_graph 每次總是由 PrivateScalarExecutionBudget::default() 重新建立環境限制；外部同一佇列的不同工作無法指定各自工作預算，亦不能證明一次工作在**多個真正 await 與 FIFO 調度之間**仍使用相同的 D18-01 額度。

## 真程式修改

1. PrivateScalarGraphContinuation<'a> 直接保存唯一 PrivateScalarExecutionBudget 結構；原 new() 保留原預設配置，新增僅內部的 new_with_budget(plan,budget)。只在原 Verified plan 完成的同一工作開端建立一次，不在 poll／wake 修改。
2. root_for_graph 必須使用已保存的 budget；複合 main 的唯一合成來源 frame 仍由原核准規則在 max_call_frames 上僅補 1，不把原 main 偽裝成真正函式呼叫。直接 main→函式快路維持原真層數。整個 checkpoint 仍保存前次真正使用的 steps，逐步檢查原 CallBudget／StepBudget 與逆序清理。
3. PrivateScalarCooperativeQueue::submit_with_budget 由同一原 Checker 計畫新建單獨工作；保留原 submit 預設值。submit_program_with_budget 由原 Box 擁有來源登錄取得同一計畫，未知 ID 在建立工作前拒絕；原 submit_program 仍使用預設值。相同來源可建立不同的工作與額度，不能互相竄改或重新配發。
4. 新增零執行額度保守拒絕：max_call_frames=0 或 max_steps=0 時，在工作身分配發、建立 ResourceId、寫入 ready FIFO 前原子拒絕。既有同步執行器零額度的合法 precheck RuntimeFailure 行為**沒有修改**；只是 V7 續行式工作不允許先暫存不可開始的工作。

## 五項真正 Parser／Checker→Runtime 正反（獨立 CI --exact）

- 測量原真函式圖到達第一個 await 之前的實際 steps，建立 max_steps=已消耗+1 的受限工作；真暫停後 wake 仍只能再計一次 EnterCall，隨後既有 StepBudget 受控失敗及唯一原 P16 UTF-8 ResourceId 釋放。原 wrapper 只進一次。
- 同一 main 有兩個已核准的 await，第二次暫停時 snapshot.steps 大於第一次；以第二個安全點累積步數+1 建立工作，第三次 poll 才因同一全局步數耗盡失敗，不能因兩次 wake 重新獲得額度。
- 同一原 Checker Box 登錄源建立兩個 FIFO 工作，其中一個自訂較小步數會受控 Failed，另一個保留預設預算、真成功且獨立 P16 ResourceEvent 平衡。
- 兩種零預算及未知原計畫 ID 必不消耗新工作身份，不污染舊 FIFO 排隊、資源或執行順序；既有有效工作仍可暫停並取消。
- 直接 main 快路真正父框架持 UTF-8 時，max_call_frames=1 禁止再進內層 async 子函式，CallBudget 真失敗並使用原 R05/P16 清理，未到達合法 await 不能虛造安全點。

新 tools/核對G18-V7協作工作累積預算.py 先核對 Rust 全名再逐項 --exact 真執行。原 G18 V7 E2/E3/A1、for/while 本體 await、R07、F00/G6/G17 全部 Gate 一律保留。

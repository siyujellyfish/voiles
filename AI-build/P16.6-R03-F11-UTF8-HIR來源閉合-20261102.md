# P16.6-R03 F11｜UTF-8 來源邊界與已驗證具名引用的 HIR 閉合（2026-11-02）

> UTF-8。本批補強已由正式私有 Checker 全部成功後交付的純值 HIR 安全證據完整性閘門，不新增語法、不推論動態 BorrowTicket 或執行期值表示。

## 根因修正
- 原 F11 `scalar_hir_is_consistent` 只核對 `0 <= start < end <= 原始碼長度`，沒有證明端點落在 UTF-8 **字元邊界**，會讓偽造的 `NodeSpan` 指向多位元組中文、表情符號的內部位元組而通過長度檢查。
- 將稽核 API 改成直接接收原始 UTF-8 `&str`，除了原本長度及順序，還要求 `is_char_boundary(start)` 與 `is_char_boundary(end)`。合法 Parser 既有來源位置不受影響。
- 每筆已驗證具名 `TypedUse` 讀取，額外要求**同一個半開跨度**存在真正 Checker 求型別成功的 `VerifiedScalarExpression`，而且 `ScalarType` 相同。避免只把既有合法宣告身分拼上虛構讀取跨度，就冒充已通過完整運算式檢查的安全證據。
- 保留所有來源 `DeclarationId`、型別、var／const 權限及賦值目標既有檢查，仍只在整份 Checker 成功且全部證據閉合後才交付 P16 來源橋接。

## 回歸與界線
- 正例涵蓋真實 Checker 完整 int、str 與含中文及表情符號的 UTF-8 來源；負例涵蓋名稱引用沒有同跨度型別運算式、中文字元內部位元組起點／終點、偽造宣告或型別以及 const 非法賦值。

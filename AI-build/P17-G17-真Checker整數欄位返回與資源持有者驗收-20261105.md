# G17｜已驗證混合結構整數欄位真返回與所有者身分（2026-11-05）

> 範圍：P17-C／P17-F 已核准私有子集延伸。**此工程不代表 G17 六項正式 Passed**。來源基準為最新 main `91789d4f5d22ce56b4ba1deb51f52ab082c53d78`；該 SHA 三項必要 CI 均已 completed/success。

## 一、施工原因與修正

原 `PreparedPrivateStruct::prepare` 已根據私有 Lexer／Parser／Checker／SafetyPlan 建構混合 struct，並以 P16 `MixedStructRuntime` 實際配置、轉移與回收 UTF-8，但 `fn main()->int` 的 `return` 僅能返回原始整數常值，無法觀察已完成建構的真實欄位。這使 P17.3／17.6 的執行值與原靜態安全來源之交接證據不充分。

本次將返回動作變為有辨別力的私有 `PrivateStructReturn`：
- `Int(i64)` 保持原核准直接整數常值。
- `IntField { owner, field }` 僅允許原 Parser 真 AST 的 `TermKind::FieldRead`，且**原私有 Checker 對同一原始跨度確實簽發 int `scalar_hir.expression`**；owner 必須是現有已驗證原始宣告名稱或同型別明確整筆 move 目標，欄位必須在已驗證 schema 中存在並為 int。
- 準備階段仍用同一正式 Checker 完成所有初始化、Copyable、Move 後可用性及型別安全；不在 Runtime 根據欄位名稱猜測已驗證權限。
- 真執行於 `MixedStructRuntime::construct` 及可選 `move_whole` 後，對**實際存活的持有者**呼叫 `field(owner, field)` 取得 `Observed::Int`，取回此刻真實求值；Runtime `finish` 再逐資源逆序釋放。絕不把計畫中的欄位預設種子直接充當觀察值。
- `is_same_prepared_payload` 以重新通過原 Parser／Checker 的同源計畫比較返回動作的**實際 owner 與 field**，拒絕修改返回目標以騙取已驗證來源的權限，進入任何資源配置前無真事件。

## 二、六項新增真 Rust 正反

| 類別 | 驗收目的 |
|---|---|
| 具名覆蓋實際返回 | `count` 預設 2，但建構時指定 9；兩次執行均真返回 9，且各次恰好建立／釋放一筆 str 資源 |
| move 後接收者欄位 | `original.move()` 後由 `moved.count` 返回 7，資源 `Created → Moved → Released` 唯一身分不變 |
| move 後原所有者 | `original.count` 於 Checker 階段拒絕，不得動態執行 |
| 未初始化 var 欄位 | `Note()` 缺少 count 預設且讀取 `note.count` 必拒絕，不能因欄位型別是 int 就偷讀 |
| 已準備返回計畫篡改 | 將合法 `note.count` 改成 `note.other`，即使兩者都為 int，必在任何資源建立前拒絕 |
| 非 Copyable str 欄位 | `return note.label` 不會把非 Copyable str 偷轉成 int，正式 Checker 先拒絕 |

原 21 項 P17-C/F 結構真執行、來源拒絕、const／具名、整筆 move、逆序回滾一項不刪，Gate 增為 **27 項**。CI 的 `rustc --test` 原核心全量真正執行，`tools/核對P17結構建立切片.py` 僅核對精確測試項存在，避免多次重跑。

## 三、安全邊界與正式差距

- 這不是一般任意結構方法或欄位動態賦值執行器；僅允許已核准 `int` Copyable 欄位讀取，原 `str` 依舊非 Copyable，不使用 BorrowTicket/ResourceId 的虛構證據。
- 未核准的巢狀 struct、方法、具副作用／非純常值的預設運算式、一般化函式返回借用／所有權及公開 CLI 執行入口仍維持封鎖。

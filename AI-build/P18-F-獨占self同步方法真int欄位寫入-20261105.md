# G18／P18.4、P18.6｜同步方法獨占 self 真 int 欄位寫入（2026-11-05）

> **僅已核准安全子集，非 G18 原六項 Passed。** 起點 `main 9793b497c2edcefe576212716979755686ebb403` 三項必要 CI success，G17 原六項正式 Passed，G18 原項仍 0/6。

## 問題與安全前提

現有 `execute_method_self.rs` 只接通原私有 Checker 已核准的同步零參數唯讀方法：`self.int欄位` 的共享借用返回。D18-02-B／S11～S15／HC14-A 已核准**方法有寫入時自動簽發獨占 self 借用**，但缺乏真正獨占票據授權的欄位寫入、返回與錯誤退出。另 `MixedStructRuntime` 原已記錄 schema 欄位是否 const，建構完成後的真 StoredField 尚未保留 immutable，若增加寫入會失去安全界線。

## 本批真正執行

1. 在 `MixedStructRuntime` 真 StoredField 保存原建構規格的 `immutable`，Copyable 結構合法複製時亦保存；新增受守衛 `write_int_field(owner,field,i64,receiver_mutable)`，先禁止 const 接收者、未完整或已移動的持有者、const 欄位、非 `int` 目標，**整體不影響 str ResourceId、不得造成 UTF-8 複製**。
2. 私有方法原 Parser AST 允許原 Checker 已核准、**第一句 `self.int欄位 = int常值`，最後一句 `return self.int欄位`** 的兩語句同步零參數子集；所有者必須是 `var`，欄位也必須為 `var int`。每項來源經真 Lexer token、P16 成員型別來源與原 `VerifiedMethodSafety.self_borrow`（預期獨占）核對；`call_borrows_at(NodeSpan)` 必須包含正確原持有者 DeclarationId 及 `BorrowKind::ExclusiveWrite`。
3. 呼叫時由真 `BorrowSafety` 簽發有效獨占票據，每次寫入前 `check_ticket_access(..., ExclusiveWrite)`，返回前再 `check_ticket_access(..., SharedRead)`，來源不同／過期／權限不足不得存取真執行器。原持有者借用期間仍禁止直接讀取。
4. 正常返回／動態測試故障依原 Checker 的 BorrowFact 快照原子歸還票據，再完成唯一結構真資源清理；不新增 voiles 例外、async 或公開 CLI。
5. 新增七項真私有同步方法來源正反（Gate **6→13**），三項 `MixedStructRuntime` 內部真資源／const／型別正反；G18 原六項 --audit 納入獨占 self 真來源，但 P18.6 仍 `BlockedByDecision`，D18-02-A 多載完整正反及 async 調度／取消正向執行尚缺。

## 驗收界線

本批不是任意方法本體、帶參數方法、任意結構欄位或通用 `self` 覆寫。多載唯一簽章、非同步與錯誤取消的完整安全行為不由本批推定。G18 `--check` 必須等六原項所有已核准模式的完整真執行正反才可成功。

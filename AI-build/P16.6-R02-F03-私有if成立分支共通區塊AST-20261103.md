# P16.6-R02 F03｜私有 if 成立分支真正保留共通 ParsedBlock（2026-11-03）

## 基準及不變契約

- 接續已完成 PR #419～#421、最新 `main`，集中解決 F03 私有 if 正式分支 AST 丟失來源區塊的重複建構問題。
- 共同 Parser 原本直接回傳 `ParsedIfChain<Term, ParsedBlock<Stmt>>` 所需的 if 條件和區塊，只是私有 `IfSyntax::Body` 使用 `Vec<Stmt>`，丟棄整個 block 起訖。這次保留真正解析產物，而不製作第二份由 byte offset 猜出的 AST。
- 已核准 `if`／`else if`／`else` 語法、條件 bool、返回、借用／所有權及 CFG 合流不變；公開 MVP-A 不取得任何私有能力。

## 變更

1. 私有 `StmtKind::If.branch` 的真實泛型型別由 `ParsedIfArm<Term, Vec<Stmt>>` 改為 `ParsedIfArm<Term, ParsedBlock<Stmt>>`，仍保存同一 `ConditionalBranch` 來源。
2. 私有 `IfSyntax::Body` 改直接回傳共同 `ParsedBlock`。`if_statement_kind` 的各成立分支不再抹除 Parser 回傳的原始 `start/end` 位元組範圍；既有 `else-if` 降為巢狀 `StmtKind::If` 的分支控制序列仍保留。
3. 目前舊 `else` 的否定分支 `no: Option<Vec<Stmt>>` 仍依既有安全 Checker 的 CFG 架構使用；這次**不假稱**已遷移全部 else 的來源位置，也不自行以合成大括號跨度當作真實 AST。
4. 靜態 Checker 透過 `ParsedBlock::Deref` 唯讀原分支執行所有權、借用、最後使用與退出分類，不新增借用票據或改動 P16 資源事件。
5. 回歸測試將私有既有手造分支明確標為合成來源，真實 `if／else if` 解析則在原有 parity test 檢查每條成立分支的 `ParsedBlock` 泛型與實際 UTF-8 半開來源。

# G18／P18.6-M2：原 Checker if/else 雙葉獨占 self.int 更新及錯誤退出（2026-11-13）

## 來源基準及實作缺口

起點為完成主線同一 SHA 必要三項 CI 的 `main 4cc449e9751ce17a0c0f410b220ad8da0fff3b1f`（PR #755）。已有 if true 葉獨占寫入、真寫入後加減溢位、false 葉常值返回；但原 Checker 的 `method_writes` 本已對 true 和 else 葉分別遞迴驗證 `FieldAssign`，並以「任一可達分支可能寫入」推導整個方法的 `ExclusiveWrite`。執行器仍拒絕 `else { self.n = 23; return self.n }`，無法證明**同一方法兩個可能寫入分支的互斥更新、票據權限和防偽退出**。

## 本批保守、可驗證的真控制圖

真來源：
```voiles
struct Counter{
var n:int = 7
fn read(flag:bool)->int{
if(flag){
self.n = 19
return self.n
}else{
self.n = 23
return self.n
}
return self.n+1
}
}
fn main()->int{
var owner:Counter = Counter()
return owner.read(true)
}
```

- 只沿用原 Parser 的 `StmtKind::If`、原 `VerifiedMethodSafety.checked_returns`、原 Lexer int token 的精確 UTF-8 半開座標，以及原 Checker 已驗證的 `BorrowFact(ExclusiveWrite)`；不新增第二份 Checker／擴張語言語意。
- else 分支目前僅支援兩種**互斥**的已證安全葉：（甲）單一 int 字面 `return`；（乙）單一 `self.<唯一 var int 欄位>=<原 Lexer int 常值>` 後立即 `return self.<同欄位>`。不開放 else-if、多語句可變借用、資源 Move、迴圈或 async。
- `method_branch_else_write` 保留 else FieldAssign 的真 int 值、原 `NodeSpan`；`method_branch_else_field_return` 保留其真 Return `NodeSpan`。`matches_source` 重新執行同一原 Checker 編譯並逐欄比對，任何值／來源位置篡改都在取得動態資源前拒絕。
- 若 **true 或 else 任一葉**具有寫入，方法入口便要求原 Checker 的 `ExclusiveWrite`，且持有者和欄位均須可寫。執行期只在真 `bool` 形參或 bool 字面條件決定方向後，使用**同一張原 BorrowSafety 的有效票據**更新真 `MixedStructRuntime` 欄位；true 葉只寫 19、else 葉只寫 23，絕不雙寫或把未選中葉的值轉發到真欄位。
- `branch_write_applied`、`branch_else_write_applied` 來自真實 `runtime.write_int_field` 成功後的事件，不在 prepare 預造；共用退出帳要求**同一呼叫不能雙葉同時有寫入**，成功時寫入的葉必須符合原 Checker 期望，注入故障則任何葉都不得偽造寫入。
- 讀取欄位仍需要原 `BorrowTicket` 有效唯讀權限；完成或 `UnwindStarted` 後以原 tracker 歸還唯一獨占借用。此 Copyable-only 子集不會產生 UTF-8 `ResourceEvent`。

## 八項獨立真 Rust 正反證據

`src/struct_stage/g18_m2_else_exclusive_write_tests.rs` 及 `tools/核對G18-P18.6-M2雙葉獨占self寫入.py`：

1. bool true 實際寫入 19，else 寫入未發生，Returned 僅一次；

6. 方法入口注入故障，尚未選葉、沒有任何寫入或 Returned，但真歸還票據；
7. 原 Checker 已核准的 else 寫入值或 Return 位置遭竄改，執行前拒絕；
8. const 欄位、不可寫接收者、錯型別／不存在欄位等原 Checker 直接拒絕，不由 Runtime 放行。

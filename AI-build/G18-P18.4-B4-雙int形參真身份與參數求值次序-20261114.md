# G18／P18.4-B4：原 Checker 雙 int 形參普通函式與同步 self 共通參數框架（2026-11-14）

## 基準與缺口

以 PR #766 已 Squash merge、`main 427a4760821a106c53bb606ac7493f1113767f93` 的**同 SHA 三項必要 CI 全部 completed/success**為基準。前版 `PrivateSelfApprovedHelper` 只能持有 `Option<DeclarationId>`，且 `private_self_helper_argument_frame` 僅能解析零／一個 Copyable `int` 實參；即使原 Checker 已有一般函式多參數／TypedHIR／Call args 的合法來源，`fn combine(a:int,b:int)->int{return a-b}` 在同步 self 橋接被錯拒。B4 必須能保留兩份不同的原 Checker 參數身分與原 Parser 實參次序，不能只用相同值或名稱推定參數對應。

本批僅增加**至多兩個原 Checker 已核准的 Copyable int 形參、單一 Return、只引用這些形參／常數／加減的普通同步 helper**；不放寬具有 Move/Borrow/str 的參數、一般函式多層呼叫、任意返回、方法重入或 async。B4、M2/M3 等仍 OpenEngineering。

## Checker 唯一型別與來源責任

- `safety_checker.rs::method_checked_int_locals` 的 `helper_arity` 只允許 `[]`、`[int]` 或 `[int,int]`。每個參數都必須是原 Parser 真宣告且不能遮蔽 `self` 或與前者重名；唯一合法 helper 返回工作圖只有 Lexer `Integer`、參數本名 `Name`、`Group`、`BinaryInt(+|-)`。返回算式中任意其他 `Call`、資源、欄位、非法名稱都先被拒絕；所有真型別、作用域與所有權仍由既有 `evaluate`、`TypedHIR`、Checker 決定。
- `PreparedPrivateSelfMethod::prepare` 對每個形參逐一驗證 `VerifiedTypedMember(Parameter)` 的原 Lexer／Parser 精確跨度、Checker `plan.members`、不可重複的 `DeclarationId` 及名稱。使用同一原 Checked Scalar HIR 構建返回計畫，白名單 `private_self_pure_helper_int` 的 `Parameter(id)` 必須恰好包含於 helper 原參數 ID 向量；`matches_source` 會把完整計畫與原來源真重編對照。
- `private_self_matches_helper_call` 只准同名、同步、無 await 的直接 `Call`，原 Checker 的 int 實參個數必與 helper 宣告完全相同，且每個參數都只能是已驗證的純 `Constant`／`Parameter`／`Addition`／`Subtraction`，不允許把任意 Expr、Borrow、Move、str／bool 或嵌套 Call 偽裝成 Copyable int。

## 真框架與錯誤退出

- `private_self_helper_argument_frame` 在**尚未進入 helper**前，按原 Parser 形參向量次序，逐筆從 caller（main 或已借用 self 的方法）動態 int frame 評估 Caller HIR 實參，綁入全新 `BTreeMap<DeclarationId,i64>`。不同形參 ID 不得碰撞；即使來源有相同整數值也不能混用身分。
- 第一或第二個實參的加減溢位皆屬 Caller，**不得發出額外 `FunctionEntered`／`ordinary_calls_entered`**。main 未取得 self 票據時直接受控錯誤；方法已取得 self 的情況只有方法錯誤退出、逆序 ScopeEnded 與 LoanReturned，不偽造 helper 函式退出。
- 實參全數成功且完成型別身分綁定後，才發出 `FunctionEntered`、進入 helper 的真正純整數返回工作圖；返回成功才 `Returned`、`FunctionExited(true)`、再提交原局部 `LocalInitialized／LocalAssigned`。若 helper 返回計算溢位，先在 helper 真框架記唯一 `UnwindStarted`、`FunctionExited(false)`，後依 R05 逆序局部和唯一 self BorrowTicket 退出，無幽靈值槽或資源事件。
- 舊零、一形參工作圖持續由**同一**新綁定與退出器處理；既有八項單參數測試、七項首批 B4 橋接測試、F00/G17/G18 Gates 不能退步。

## 八項不重複 Rust 真來源

新增 `src/struct_stage/g18_b4_two_int_helper_argument_order_tests.rs`、`tools/核對G18-P18.4-B4雙int形參身份與求參順序.py`：
1. main 局部與 Copyable int 加減組成兩個實參，確實先返回 helper 才借 self，結果 8；
2. 方法 `n:int` 衍生兩個不同動態實參，在 self 借用存活期間返回差值 9；
3. 不同宣告身分的兩個 main 局部交換實參順序，結果分別 17／-17，不因值型別相同偷換身分；
4. 方法 `var int` 以同一局部的兩個已核准 Copyable 值直接 helper 重賦，成功後原子提交；
5. 同一方法先 helper 初始化，再把首次返回用作後續 helper 的動態實參，兩次框架、值與 `Returned` 正確；
6. 第一或第二個實參任何一個溢位都不得虛構 helper 已進入，仍安全歸還 self；
7. 兩個形參合法綁定後 helper 本體溢位，內層先 `FunctionExited(false)`，外層才歸還 BorrowTicket；
8. 三個形參、錯型別、未知參數名稱、嵌套 helper 呼叫維持原 Checker 保守拒絕，篡改雙 DeclId 順序或重用 ID 被 `SourceChanged` 拒絕。

Gate 以 Rust `--list` 精確核對八個唯一名稱，逐筆 `--exact --test-threads=1` 需真正 `1 passed/0 failed/0 ignored`；加入必要 Rust 獨立架構 CI。舊 B4 Gate 的測試名稱與數量不動，只把原本「兩個 int 形參」負例替換成**仍禁止的三個 int 形參**；兩個純值計畫竄改測試改為包含 `Vec<DeclarationId>` 的相容封存型別，原 `SourceChanged` 保護不變。

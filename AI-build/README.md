## M8 合併後的程式碼審查

- 公開 CLI 從 src/main.rs 進入。模組計畫由 src/struct_stage/modules.rs 建立，直譯與原生輸出共用檢查結果；碰到兩種模式結果不一致時，應以同一份 .voil 輸入比對。
- 原生建置曾以程序 PID 作為唯一暫存目錄名。若前次中斷留下同名目錄，後續建置會提前失敗。現在以獨占建目錄取得可用名稱，並以真實建置驗證舊目錄仍存在、產物可執行。
- 合併請求的管理文件同步檢查涵蓋新增、修改、重新命名與刪除。Rust、voiles 及自舉來源也納入 UTF-8 檢查。M6 發行包與 P31 凍結矩陣供歷史重現，主線行為另由 M7、M8 案例驗證。
- 私有純量呼叫及方法執行仍集中在大型 Rust 模組中。歷史驗收含對這些模組的來源檢查；搬移程式碼前需核對對應的 CI 腳本與語意回歸。

## 三、不可變更的設計與工程界線

- voiles 風格為 Python 式簡潔可讀、Rust 式記憶體安全目標，**直譯優先**，再編譯／單檔封裝／自舉；採已核准的 `fn`、`struct`、`var`／`const`、大括號等自身語法，不擅自替換既定風格。
- AR04 相依順序保持不變；公開 `check_file`／CLI 只保證 MVP-A 靜態檢查，不將受限私有 `struct_stage` 暴露出去。
- 純命名按使用者 2026-10-25 授權可選擇清楚名稱；具體編譯器建議需逐項驗證與既定語意相容。授權不代表可以自行擴張未知語言規則、安全政策或公開 API。
- 任何程式／文檔修改均採新分支並同步更新 AI-build；最新 PR HEAD 三項必要 CI（文件與工作紀錄、Rust 前端建置、Rust 獨立架構測試）完成且成功、身分與 mergeable 確認後才 Squash merge。
- 舊的 [P13～P16 最新正式驗收差距（2026-10-27）](P13-P16-最新正式驗收差距.md)與 [P13～P16 封閉修正計畫（2026-10-29）](P13-P16-正式驗收封閉修正計畫.md)僅供追溯當時缺口；**不是** 2026-10-30 現行工作清單。已過時的 2026-10-28 一次性驗收勾選清單不再保留於工作樹，仍可從 Git 歷史查閱。

- 目前**沒有直譯器、編譯器或可執行的 voiles 語言核心**。
- 2026-10-10 已取得 GitHub Actions 真實正向成功與負向預期失敗紀錄：PR #2 [執行 #38041071974](https://github.com/siyujellyfish/voiles/actions/runs/38041071974) 成功，受控 PR #3 [執行 #38042273537](https://github.com/siyujellyfish/voiles/actions/runs/38042273537) 因未同步 `AI-build` 正確失敗並已關閉；**`文件與工作紀錄` 已加入啟用中的必要狀態檢查規則**。

- 後續每一階段都要先讀取 `AI-build/` 最新內容；任何新技術決策先經使用者確認；使用新分支、合併請求與**壓縮合併**，完成必要檢查後才合併。

## 二、階段狀態與執行規則

- **部分完成**：已有已合併成果，但該 Phase 的驗收條件尚未全部滿足。
- **待開始**：尚無相應功能完成證據；「需決策」表示不得直接啟動相關的語意或技術實作。
- 每個 Phase 再拆為 `Pxx.1` 至 `Pxx.n` 任務。每個任務建議作為一個小型工作分支或可獨立審查的合併請求；跨任務必須描述依賴和驗收證據。
- 不以 Phase 序號代替依賴判斷；已核准且無依賴的工作可平行，但語意未定工作不可先行實作。
- 下述功能是**預定議題**，不是預先決定要採用特定語法、資料結構、原生後端、平台或版本日期。

## 四之一、struct S01–S21 與實作／驗收對照（均尚未實作）

> 下表將**已確認的語言規格**對應至**尚未執行的任務與測試期待**。沒有藉此核准新的運算、型別、函式庫 API、資源清理或實作架構。每項的正反例必須待所依賴的 R 類未決語意裁決後才可正式作為執行驗收。

| 編號 | 已核准規則摘要 | 對應 Phase | 正向／反向驗收方向與未決限制 |
|---|---|---|---|
| S01 | 欄位只用 `var`／`const` | P07、P09 | 合法欄位可解析；`share` 欄位應拒絕 |
| S02 | 欄位不得重複名稱 | P09 | 不同名允許；重複欄位應拒絕 |
| S03 | 不允許巢狀 `struct` 宣告 | P07、P09 | 模組層結構宣告；結構內的 `struct` 拒絕 |
| S04 | 不支援泛型結構 | P07、P10 | 普通結構可解析；結構泛型宣告拒絕 |
| S05 | 建立式使用具名欄位參數 | P07、P10、P17 | 具名形式可表達；位置參數未核准，不可假定可用（R03） |
| S06 | 空建立式 `User()` 一律允許 | P07、P11、P17 | 空建立不因存在未初始化欄位被拒絕；讀取仍須受 S07 檢查 |
| S07 | 允許 `var` 欄位延後初始化（F01 限縮） | P10、P11、P17 | `var` 欄位讀前靜態初始化檢查；`const` 欄位必須宣告有預設值 |
| S08 | 欄位允許預設值，F01 要求 `const` 欄位必須有預設值 | P07、P10、P17 | 拒絕沒有預設值的 `const` 欄位；`var` 欄位預設值為選填 |
| S09 | 預設值每次建立重新求值 | P16、P17 | 每次新實例重新求值；參數覆蓋時是否求值尚未定（R03） |
| S10 | 不提供專用自訂建構方法 | P07、P09 | 僅使用已核准的結構建立形式；不得自行核准新建構入口 |
| S11 | 方法參數表不列 `self` | P07、P12 | 一般方法可省略 `self` 參數；不假定其他特殊接收語法 |
| S12 | 方法 `self` 只允許借用 | P12、P14 | 接收者借用；移動式接收者拒絕，別名與可變性仍待定（R04） |
| S13 | 方法修改欄位無額外方法標記 | P11、P12、P14 | 依實例／欄位權限驗證讀寫；修改權限細節待定（R04） |
| S14 | `self` 借用在離開方法時歸還 | P14、P15 | 借用界線測試；跨 `await` 行為待定（R04） |
| S15 | 方法不得消耗整個 `self` | P12、P13 | 方法消耗整個接收者應拒絕；外部整體移動仍可依一般規則 |
| S16 | 只用 `instance.method(args)` 呼叫 | P07、P12、P18 | 實例呼叫可表達；不自行加入 `Type.method(instance)` 呼叫 |
| S17 | 允許 `async fn` 結構方法 | P07、P12、P18 | 非同步方法宣告可解析；跨 `await` 安全尚待定（R04） |
| S18 | `const` 實例遞迴不可變 | P11、P14、P16 | 經由 `const` 實例巢狀寫入應拒絕；別名規則待定（R04） |
| S19 | 全部欄位皆可複製，結構才可複製 | P10、P13、P16 | 能力判定與拒絕測試；實際可複製型別清單待定（R04） |
| S20 | 方法可依參數簽章多載 | P07、P09、P12、P18 | 有效多載／歧義診斷；簽章等同性與解析尚未決定（R05） |
| S21 | 禁止只移動一個欄位 | P13、P16 | 單一欄位移動應拒絕；結構整體移動允許（其他安全細節待定） |

**追溯與測試要求**：每項 S 編號要映射至少一個正向或反向案例；不具判定基礎的測試先標記「等待 R 類決策」，不得靠猜測指定通過／失敗。表中 Phase 與關卡為工作拆分，不是已完成證據。

## 七、每個 Phase 的統一完成定義

1. 本階段依賴已完成，且使用者已核准所有必要語意與技術決策。
2. 對應功能、錯誤案例、邊界條件與回歸測試有可追溯證據；純規劃階段提供核准文件即可。
3. 文件、範例與程式註解使用繁體中文，文字檔明確採 UTF-8 編碼。
4. 合併請求同步更新 `AI-build/` 的現況、決策或工作紀錄，保持精簡、不重複累積。
5. 新分支上的變更完成必要檢查；明確確認結果後再採 **Squash merge** 進 `main`。
6. 若持續整合未執行、待執行或失敗，標記為未驗證並停止合併；避免高頻輪詢。
7. 合併後重新確認主分支狀態，再將此 Phase 的子任務勾選並記錄驗收證據。

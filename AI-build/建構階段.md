## 二、階段狀態與執行規則

- **部分完成**：已有已合併成果，但該 Phase 的驗收條件尚未全部滿足。
- **待開始**：尚無相應功能完成證據；「需決策」表示不得直接啟動相關的語意或技術實作。
- 每個 Phase 再拆為 `Pxx.1` 至 `Pxx.n` 任務。每個任務建議作為一個小型工作分支或可獨立審查的合併請求；跨任務必須描述依賴和驗收證據。
- 不以 Phase 序號代替依賴判斷；已核准且無依賴的工作可平行，但語意未定工作不可先行實作。
- 下述功能是**預定議題**，不是預先決定要採用特定語法、資料結構、原生後端、平台或版本日期。

**P01.1 已確認（2026-10-10）**：使用者選擇首版方向 **B｜記憶體安全核心**。首版必須具備強型別／靜態型別／強制型別標註、`Copyable` 值複製、`move(...)` 明確移動、`borrow(...)` 與 `borrow_mut(...)` 借用，以及必要靜態借用與所有權檢查；直譯執行是第一個可執行版本的執行方向。這項決議首先確認**能力種類**；宣告、基本型別與後續各項首版功能範圍已另外取得使用者決議，但 `Copyable` 適用型別、生命週期、函式與控制流程語法及技術選型仍未核准。

**P01.1 宣告關鍵字範圍已確認（2026-10-10）**：使用者選擇 **方案 C：首版同時支援 `var`、`const`、`share`**。三者在既有規格 v0.2 的方向分別是可變、不可變、外部可變。這是**首版納入範圍**的決議，並非批准 `const` 編譯期性質、`share` 修改權限／跨作用域及跨執行緒行為，也不代表 `share` 能繞過所有權或借用檢查。上述細節在對應 P01.2～P01.3 及必要安全階段確認之前，不得進入語意實作。

**P01.1 基本型別範圍已確認（2026-10-10）**：使用者選擇 **方案 B：首版納入 `int`、`float`、`bool`、`str`**。這四個名稱是首版的基本型別集合；`list[T]` **不列入這次已核准的首版基本型別範圍**（保留為後續容器議題），不能因範例使用 `list[int]` 就提前實作。尚未核准數值位元寬度、整數溢位／除零、浮點精度、字串編碼與運算、布林運算規則、隱式轉型、各型別 `Copyable` 能力或初始化方法。

**P01.1 運算與語句範圍已確認（2026-10-10）**：使用者選擇 **方案 C：首版包含基本變數讀寫、基本算術與括號運算式、比較、布林邏輯，以及條件分支與迴圈**。這是功能類別決議，不代表已核准任何實際運算符號、關鍵字、運算子優先順序、短路求值、型別相容、隱式轉型、控制流程區塊語法或迴圈種類。多分支與迴圈內的所有權狀態合併、移動與借用有效期也仍需後續裁決；不得以 Python 或 Rust 預設語意代替核准規格。

**P01.1 不可複製資源驗證範圍已確認（2026-10-10）**：使用者選定 **方案 B：首版額外提供一種最小的內建不可複製資源型別**，讓一般 voiles 程式得以驗證資源的建立、明確移動、唯讀／可變借用及資源生命週期安全。此型別屬於已決定納入的額外資源能力，**不修改既定的四種基本型別集合**。只核准能力範圍，不核准型別名稱、建立／操作介面、底層資源、釋放時機、析構規則、可複製能力判定程序、生命週期分析方式或跨控制流程權限；不得先行實作為預設語意。使用者自訂資源型別不屬於本次核准的首版必要能力。

**P01.1 函式功能範圍已確認（2026-10-10）**：使用者選擇 **方案 C：首版支援使用者自訂函式的定義、呼叫、基本型別參數與回傳能力，並可跨函式邊界傳遞不可複製資源的所有權、唯讀借用與可變借用，執行必要的靜態安全檢查**。此處僅確認首版能力目標，**不**核准函式宣告／呼叫的表面語法、函式簽章格式、參數的預設傳遞方式、`Copyable` 引數處置、回傳值／回傳借用語意、生命週期標註、遞迴、區域作用域與捕獲、跨函式逃逸及確切安全規則。P01.1 仍在逐項討論，不可標記完成。

**P01.1 輸入輸出範圍已確認（2026-10-10）**：使用者選擇 **方案 B：首版提供一般程式的基本文字輸出，不要求一般文字輸入或互動式輸入**。這只確認功能範圍；輸出內建名稱、呼叫語法、實際輸出目標／通道、參數型別、文字格式、值轉文字的方式、換行規則、錯誤處理及輸出牽涉的所有權與借用安全規則皆未核准。檔案與網路輸入輸出亦非本次決議所授權的首版必要能力。

**P01.1 檔案與模組範圍已確認（2026-10-10）**：使用者選擇 **方案 C：首版支援單檔執行、跨檔模組引用、套件組織及套件相依管理能力**。這是首版應有的功能範圍，不是已確認具體的套件管理方案。原始碼副檔名、執行進入點、模組與套件命名、匯入／匯出表面語法、名稱可見性、模組初始化、相依解析、版本限制、相依鎖定、循環相依、套件封裝與安裝方式、套件來源（本機或遠端）及跨模組所有權／借用檢查等細節都**維持待確認**；不得自行建立套件登錄服務或預先採用既有語言的慣例。

## 七、每個 Phase 的統一完成定義

1. 本階段依賴已完成，且使用者已核准所有必要語意與技術決策。
2. 對應功能、錯誤案例、邊界條件與回歸測試有可追溯證據；純規劃階段提供核准文件即可。
3. 文件、範例與程式註解使用繁體中文，文字檔明確採 UTF-8 編碼。
4. 合併請求同步更新 `AI-build/` 的現況、決策或工作紀錄，保持精簡、不重複累積。
5. 新分支上的變更完成必要檢查；明確確認結果後再採 **Squash merge** 進 `main`。
6. 若持續整合未執行、待執行或失敗，標記為未驗證並停止合併；避免高頻輪詢。
7. 合併後重新確認主分支狀態，再將此 Phase 的子任務勾選並記錄驗收證據。

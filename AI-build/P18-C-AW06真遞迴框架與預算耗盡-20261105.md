## 原問題與語言政策

既有 `src/execution.rs::Runtime::call` 依函式名稱檢查 `self.calls`，直接拒絕所有活躍遞迴，即使原 `P01` Checker 的 **AW06-A 已允許合法直接／互相遞迴**。本批移除這個過時的「語言能力全拒絕」閘門，保留真正 Lexer／Parser／P09／P10／P11／P12 來源與函式身分驗證。

## 實際工程

- 新增 `ExecutionBudget { max_call_frames, max_steps }`：屬**本次 evaluator 執行環境配置**，不是 voiles 語言的固定遞迴深度限制。既有非公開 `execute_with_trace()` 使用保守預設，本批 Rust 內部 `execute_with_trace_budget()` 可以調整，**未新設 CLI 參數或出口碼映射**。
- 每次真 `Runtime::call` 在進入下一層前檢查目前 `frames.len()`，合法同名與互相遞迴不再被拒絕；超出資源預算回傳 `RuntimeFailure`，絕不依賴宿主 Rust stack overflow。
- `Runtime::statements`／`expression` 僅在真正執行已核准 AST 節點時消耗執行步數；不提前計入不可達分支，正常零引數、前向呼叫與所有舊值語意不變。
- 深度／步數耗盡、動態溢位均沿用現有 `block`／`call` 清理架構，各個已進入框架都會 `pop`，並發出 `FunctionExited{returned:false}`。真正 `Returned` 只能由成功執行的來源 return 產生；事件仍經 `audit_control_events_against_source` 重新比對**原 Parser 函式／條件／返回來源位置與真進出堆疊**。
- 本批的 MVP-A scalar 框架**沒有 str／ResourceId**，故驗收的只是「無資源遞迴」與控制流退出；不能因此宣告 P18.3 的借用／巢狀資源遞迴已實作，也不向公開入口釋出原私有 P13～P16 能力。

## 七項真來源正反

1. 無限直接遞迴在預算內安全受控失敗，不爆宿主堆疊且所有已進入框架都退出。
2. 真全域 bool 切換終止直接遞迴，回傳值、三層真函式進出及原來源稽核一致。
3. 真全域 bool 透過前向的互相遞迴終止，執行順序 `main → first → second → first`，所有函式單獨退出。
4. 合法來源在不足的框架預算下不假造成功 return，並完整收束已進入框架。
5. 步數預算耗盡與框架預算分流，真執行控制事件完整且不冒稱成功。
6. 同一合法來源於不同預算下成功或受控耗盡，不更動 Checker／語言語意。

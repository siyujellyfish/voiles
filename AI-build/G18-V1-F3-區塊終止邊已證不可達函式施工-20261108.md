# G18 V1／F3：區塊終止邊與 Checker 已證不可達函式工作圖（2026-11-08）

> 本批對象是原 P18.1 的 F3／F4「同源 Checker 合法呼叫圖及不可達不進動態工作」，不是整個 V1 或 P18.1 正式 Passed。施工起點為 V0 已合併後的 V1 PR #648（空迭代來源排除）和 #649（普通函式子呼叫閉包由 Checked 工作計畫導出）的最新 main。

## 真工程缺口與最小修復

- 原 `src/struct_stage/execute_call_scalar.rs` `compile_early_branch` 在同一個原 Parser 區塊超過一條語句時，遇到 `PrivateScalarBranchAction::Return` 或所有葉子均返回的 `NestedIf`，即使完整 Checker 在控制流上已證後續語句不可到達，仍因 `index + 1 != statements.len()` 回 `Unsupported`。這與上一批已核准的「無條件 break／continue 後不編譯不可達 HIR」不一致，也使合法普通函式不能真執行。
- 改為只在**已經編譯成原 Checker／TypedHIR 工作計畫且 `action.always_returns()` 真成立**時，與原 break／continue 同樣停止進一步加入區塊工作。未知 bool 條件、只有一側返回的 if，`always_returns()` 仍為假，所有可能到達的其餘來源照常必須編譯；任何可達但未被標量 evaluator 支援的結構局部仍拒絕。
- 不修改 Lexer、Parser、Checker、BorrowFact、ResourceId、`shared_call_exit`、公開 CLI、P16／G17/F00 凍結。所有實際執行仍經原 `PreparedPrivateScalarCall::execute` 驗證同一份 Checked 來源，不能藉 AST 名稱或執行階段旗標猜測不可達。

## 三類真 Rust 證據（新增且與 318 項既有 G18 專項共用真執行）

1. `g18_v1_區塊已返回後結構函式不得進入工作圖`：合法 `route(true)` 的 if 分支先從 `good()` 真返回，分支後面的 `idle()` 在本區塊不可達且含原 Checker 合法但受限 evaluator 不支援的結構建立，要求結果正確且 `idle` 不在子圖、不建構假資源。
2. `g18_v1_巢狀全分支返回後不可達建構不得污染兄弟返回`：if 內兩個巢狀葉返回，後面的結構建構函式不得編入呼叫圖。原 Checker 已證左右分支可能走到的其他真函式仍須保留，動態只執行所選中的葉子並正確返回。
3. `g18_v1_未知條件的可達結構函式仍須在prepare保守拒絕`：`flag` 不具有準備期恆真／恆假的新授權；只要 Checker 合法路徑仍可能到達尚未接通的 `idle()`，即使測試進入 `route(false)`，編譯期間仍必須 `Unsupported`，不能以猜測常值繞過安全門檻。

普通函式專項 Gate 318→321，原六項稽核增加相應真來源（對 P18.1／P18.2／P18.5 分別標明，不以新增 3 項宣告 F3／F4 Closed）。原 V0 26 條義務的「工程未閉合／決策阻塞」仍屬真實狀態。

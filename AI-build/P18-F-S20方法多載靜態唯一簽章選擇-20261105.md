# G18／P18.6｜S20 同名方法完整參數簽章靜態唯一解析（2026-11-05）

> **施工子批，不能當成 P18.6 動態多載完整 Passed。** 自主線 `0c870dba6b6817d2a65fd9e7e2d6ff7ed9b5e79c`（三必要 CI 成功）開分支，沿用 2026-11-05 使用者核准 D18-02-A～D，不增加新語法、隱含型別轉換或公開 CLI。

## 原實作缺口

正式私有 Parser 的 `strukt()` 對同名方法直接因 `HashSet` 名稱重複拒絕，與已核准 S20「同名方法可依參數簽章多載」不一致；`StructDecl.method_index` 使用 `HashMap<String, usize>`，若直接允許重名會覆寫先前方法。Checker 的 `MethodCall` 只讀 `def.method(name)`，沒有來源唯一的候選解析，將造成方法安全借用模式被錯誤套用。

## 實作

1. 真私有 Parser 在讀入 `struct` 時保留**同名方法** AST 的原始位置與宣告順序，但**欄位與任何方法同名**仍依 S02／S20 舊禁令即時拒絕；同名同簽章交給唯一 Checker 的靜態語意診斷。
2. `StructDecl.method_index` 改為 `HashMap<String, Vec<usize>>`，保留所有同名候選和來源順序；舊 `method(name)` 僅在唯一候選時可取，避免靜默選最後一個。`methods_named` 供 Checker 走訪全部真 AST。
3. `Checker::all()` 依**方法名稱＋參數數量、順序及完整型別**判定簽章重複，回報 `DiagnosticKind::Static`，參數名稱／方法回傳型別**不**能作為多載區別。
4. `Checker::evaluate_inner(MethodCall)` 在多個同名候選時，只使用無副作用的靜態型別觀察（合法 Scalar、Name／Move 的現存 Binding、Group、已能確定為 int 的加減、真 struct 欄位型別）與每個候選的完整型別序列比對；零符合或仍有多個匹配皆靜態拒絕，缺乏安全型別證明不採猜測。唯一候選沿舊有 Checker 真型別／借用檢查流程。
5. 正常方法仍由原 `check_method` 確認 `VerifiedMethodSafety`，`call_borrows_at(NodeSpan)` 記錄真正 `self` 共享／獨占來源，並遵守已核准 const 接收者不能呼叫獨占方法。
6. 新九項 Rust 正反測試與 `tools/核對G18方法多載靜態唯一簽章.py` CI Gate，覆蓋同名不同簽章、宣告次序反轉、共享／獨占選擇、同簽章不同參數名或不同返回型別拒絕、const 接收者、安全不匹配及欄位／方法同名舊禁令。
   
## 驗收界線

此批完成的是 **S20 靜態唯一方法選擇**，不等於所有多載版本已能動態呼叫；`src/struct_stage/execute_method_self.rs` 仍只支援一個方法的受限真執行子集。不能把此靜態 Gate 加到 G18 `--audit` 的「真正動態執行測試群」來灌水。後續必須把具體唯一方法身分交給真正 Runtime，補上有參數及多載方法的真求值、借用與故障退出正反，並另行封閉 async 調度／取消。原 G18 P18.1～P18.6 六原項維持未勾選。

# G18／P18 V1-F3：頂層全返回後不可達局部與 main 入口同源收口（2026-11-08）

> 本文件記錄 V1-F3 的一個新工程缺口修復與可稽核正反測試，**不是 V1 全項或 P18.1 正式 Passed**。工作起點為已合併 main `b39c014c2dfeff7ef6c0fbd164d2647e6632c85b`，起點同 SHA 必要三項 CI completed/success。

## 問題與原契約

原 `prepare_function_locals` 雖已在區塊的 `compile_early_branch` 中阻止已證 `Return` 後綴被錯編，但函式本體的頂層前置語句遇到原 Checker 已證所有 `if/else-if/else` 葉均返回時，仍繼續逐筆準備後面的局部宣告。原 Checker 合法、但未提供可達 TypedHIR 的頂層死碼，會錯被當作必需的動態執行工作，且有時讓未接通的結構函式 `idle()` 阻塞真正返回。

此外，`main` 用已編譯 Checker 工作計畫建立依賴閉包，但尋找第一個入口函式依舊另外掃原 AST，造成兩個不同的可達呼叫權威。

## 實際修正

1. `prepare_function_locals` 編好頂層 `PrivateScalarEarlyIf` 後，只有在 `always_returns()` 靜態證明全葉必返回才停止編譯本層後續語句；任何仍可能落入後綴的來源繼續完整編譯，不憑傳入參數的值猜測可達性。
2. `main` 在選第一個真候選呼叫前先編譯原 Checker `ReturnExpr` 與 `LocalStep`；以同一份 `collect_calls` 結果作首入口與傳遞函式圖，不再用獨立 AST `first_source_call_in_statements` 決定入口。無函式呼叫仍保守 `Unsupported`。
3. 保留原 `VerifiedPrivateSource`、`TypedHIR`、`DeclarationId`、原 BorrowFact/OwnedStrRuntime 與呼叫時資源事件。來源變造仍要在 `matches_source` 階段先拒絕。

## 本批新增原 Lexer／Parser／Checker → Runtime 真正反

- `g18_v1_頂層普通函式全葉返回後局部不可達不再錯編`：分支的 true/false 合法候選均存在，已證必返回後的 `idle()` 與結構局部不得進入可達圖，真正返回 4、無未建資源。
- `g18_v1_main全葉返回後局部不可達不再污染首入口`：main 原 Checker 已簽發兩葉返回，未執行 `idle()` 不是入口；實際選 false 返回 8，無假框架／資源。
- `g18_v1_頂層非全葉返回仍不得忽略可達結構局部`：只有 true 返回而 false 仍可到達 `idle()` 時，未接通的結構局部一律保守 `Unsupported`，不靠剪枝偷渡。

G18 普通函式專項來源 Gate **324 → 327**；P18.1／18.2／18.5 原項真來源追溯同步。舊 V0 26 項機讀義務清冊保持初始快照，原六項正式狀態及嚴格 `--check` 均不修改；F00、G6、G17 以及公開 CLI 不改。

# G18／P18.3｜原私有 Checker bool 參數遞迴 UTF-8 真逐框架清理（2026-11-06）

> 基線 main d7ef6357d5145210941c17c9ee22ed88a0a284cd，承接 D18-01-A～D、AW06-A、P16 真 OwnedStrRuntime。**此為非公開、可證明的有限直接／互相遞迴子集，不能代表原 P18.3／G18 正式 Passed。**

## 舊功能與缺口

公開 MVP-A 的原 P01 Checker／evaluator 已可使用執行環境預算做合法零參數 AW06 遞迴，但其值僅 int/bool，沒有 UTF-8 OwnedStr。私有 Checker／P16 已有真正 OwnedStrRuntime、條件字串分支及單次函式退出清理，但先前真正執行器的 Prepare 形狀限單函式，無法證明遞迴跨多真框架釋放次序。

## 本批工程

- 新增 src/struct_stage/execute_recursive_str.rs，僅使用原私有 verify_source_with_ability 通過的函式、bool Parameter TypedMember／DeclarationId、條件的 ScalarHIR Reference、遞迴呼叫 int 返回 Expression HIR、原 Lexer bool/int/UTF-8 字面來源。真 main 與一或兩個 bool 參數函式；其餘形狀保守拒絕，不因推測放行。
- 遞迴分支僅允許已驗證的 if(flag)、真正呼叫另一核准函式的 return、末尾 int 常值返回；各函式及被選分支可含原 Checker 已核准 str 區域初始化。每次進入函式與分支時，都在**同一個原 P16 OwnedStrRuntime** 中建立獨立 scope；真正建立 ResourceId，錯誤或返回時依 scope 和完成初始化次序逆序釋放。不創造未實際執行分支的資源事件。
- 採顯式工作框架 Vec，不以 Rust 宿主 call stack 作為遞迴深度保護。max_call_frames／max_steps 是 Rust 內部**本次執行設定**；沒有固定語言深度上限、新 CLI 或公開錯誤退出碼。
- 成功與預算／測試故障均記錄真框架進出，錯誤不能偽裝成功 return。允許測試於第 N 個實際資源配置後注入故障；所有 Created 都必須恰好 Released 一次。執行前重跑同一來源 Checker 並比對整份準備計畫，竄改來源與分支內容則不得配置。
- 八項 Rust 真來源正反：直接遞迴、互相遞迴、框架預算耗盡、步數耗盡、第二層故障、來源／預備計畫竄改、Checker 錯誤型別與不存在目標、空預算零事件。tools/核對G18遞迴真資源逐框架.py 專用重跑；G18 原 P18.3 --audit 另增五項動態追溯。

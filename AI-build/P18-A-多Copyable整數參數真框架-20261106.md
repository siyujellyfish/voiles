## 原驗收差距

P18.1／P18.4 原已支援獨立一個 Copyable int 參數及單一 str 借用，卻拒絕原 Checker 核准的多個 Copyable int 參數；不足以對多參數求值次序、型別、來源身分與跨參數算式做真執行驗收。

## 本批

- 原 Preparation 可接通 1～3 個 int 函式參數（僅此私有可證明子集支援上界，並非語言規格固定上界），對每筆原 Parser Parameter 的宣告位置、名稱／型別 Lexer token、Checker TypedMember、原 DeclarationId 逐項核對。
- main 可在呼叫前建立 0～3 個真正已驗證 int 常值 var／const 局部所有者，具名實參經原 ScalarHIR ResolvedUse 對應到原來源 DeclartionId；同一 Copyable 持有者可合法供多個實參使用而不被消耗；仍拒絕未執行的多餘語句。
- 所有實參按 Parser 書寫順序實際執行；之後建立同一真正 callee 執行框架，為各參數逐 DeclarationId 寫入獨立 i64 slot；返回算式可對任何該函式參數按原 Checker Arithmetic TypedHIR 證據進行巢狀加／減及括號運算。原動態溢位及內部故障不得產生成功 Returned，執行完必須清空全部參數槽。
- 每次 execute 重新運行原 Checker 比對整份準備計畫、參數與實參來源及全量 call_borrows 事實；第二／第三參數的身分或值遭篡改，必須在動態框架進入前拒絕。
- 新增八項真來源正反：二參數、三參數、同持有者重用、var/const 多來源、整數溢位、故障回滾、來源竄改、錯誤型別／數量／多餘語句拒絕。獨立 Gate 16→24，原 G18 六項增加真正 P18.1 追溯，Gate 強制實際重跑 24 項，不只檢查測試名稱。

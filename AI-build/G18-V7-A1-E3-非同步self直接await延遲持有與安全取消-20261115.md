# G18／P18.6-A1／V7 E1/E3：非同步 self 直接 await 的未啟動真計畫持有、喚醒與安全取消（2026-11-15）

## 正式語意、起點及真工程缺口

主線起點 `b781a45ff5bbcba98f63b51fe6c63a7e9859514b`，前批 #810（正式 `await owner.method(args)`）、#811（方法原封存 Lexer/AST 執行前防偽）、#812（普通 async GraphContinuation 全來源憑據再驗）均已完成 Squash merge，該 `main` 同 SHA 三必要 CI completed/success。

V7 依使用者已核准 D18-02-E1=A 延遲啟動、只接直接 await、不開放背景工作；E2=A 單執行緒協作；E3=A 未啟動及真安全點取消；E4=A 既有執行期錯誤傳播；E5=VB15-01-A 維持有效借用不可跨未證安全等待。使用者另核准 `await owner.method(args)`：方法本體真開始才取得 `self` 票，不允許活躍借用跨內層 `await`、不開放背景或其他語法。

#810 已驗收只在實際直接 await 當下進入同步控制圖的 async self 方法（原單一 int 欄位，正式 Checker／S20／BorrowFact、R05／HC14 真退出）。但跨 Rust API 呼叫尚不能像原普通 `PrivateCheckedDeferredAwaitQueue` 一樣保存**尚未啟動**的 async self `PreparedPrivateSelfMethod`；因此準備者與執行者仍得在同一次呼叫直接求值，無法證明「準備時零借用，明確喚醒才取得 BorrowTicket」的跨呼叫責任。

## 已核准子集的最小動態接線

新增私有 `src/struct_stage/execute_method_async_deferred.rs`，**直接持有同一份原 Checker 已驗證的完整計畫**，不複製／重編第二份 AST、不引入 async self 方法內的可重入中途協程；`struct_stage.rs` 於既有同步 `self` 執行器之後引入：

1. `PrivateCheckedDeferredSelfAwaitQueue::prepare(source)` 唯一入口呼叫現有 `PreparedPrivateSelfMethod::prepare`，由真正 Parser/Checker `TermKind::AwaitMethodCall`、`method.is_async`、MethodSafety／BorrowFact 證明合法；額外保守限定 `main` 只有原 struct owner 初始化及最後直接 `return await owner.method(args)`，沒有 main 局部、迴圈或未曾保留的前置副作用；成功只發唯一遞增 u64 工作身分、保存原 VerifiedSource／Token／計畫，狀態 `Prepared`，不執行方法、不簽 self 票、不配 P16 ResourceId。
2. `suspend(id)` 只從 `Prepared` 移到 `Suspended`；不建立框架。重複暫停、已取消或已完成工作保守拒絕。
3. `cancel(id)` 只對 `Prepared／Suspended` 的**未啟動**計畫有效，取消時清掉原擁有的計畫，狀態 `Cancelled`，仍零執行、零假票、零資源事件；`Running／Succeeded／Failed／Cancelled` 不再取消，不宣稱已執行幀可任意搶占。
4. `wake(id)` 只接受 `Suspended` 的原計畫，在此一明確直接 await 入口才呼叫已驗收的 `execute()`：原 main 形參按既定次序真求值，直到進入 async 方法時原 `BorrowSafety::acquire` 簽唯一 self 票；正常保留 `Succeeded／PrivateSelfMethodOutcome`，原 `IntegerOverflow` 真 Unwind／內後外還票保留 `Failed`，只追加一次 `execution_order`；重複 wake 拒絕。若原來源封存身份重驗失敗則 `SourceChanged` 並恢復 `Suspended`，不能謊報方法失敗或消耗不曾啟動的工作。
5. `next_id.checked_add(1)` 防止工作 ID 回繞，靜態拒絕與計畫源資料變造不得消耗新 ID；不同工作各有獨立真原 Checker 執行實例，不會在 Prepare 時共享動態 BorrowTicket 或假的 P16 ResourceEvent。

**限制**：此為 `async self` 的首次**未啟動**持久化延遲工作，沒有開放 async self 方法本體內的多個 await、已執行幀的跨 await 暫停恢復、任意取消或與普通 `PrivateScalarCooperativeQueue` 的單一整合 CFG／資源清理圖；這些仍為 A1/A2/M3 原義務缺口，不因具備 `suspend` 方法名稱就宣稱完整可恢復協程。

## 十二項真 Checker 執行正反

`src/struct_stage/g18_v7_async_self_deferred_session_tests.rs` 實際以原 `.voil` `async fn read()->int` 與 `async fn set(n:int)->int` 開始，經原 Parser/Checker 及真 Runtime，覆蓋：

1. `prepare` 只留下 Prepared、零結果、零執行序；未 suspend 不得喚醒。
2. `suspend→wake` 才真進共享 self BorrowTicket 方法，真返回 10、正確 R05 出入及不可重播。
3. `ExclusiveWrite` 的 async set 方法直到 wake 才真正寫欄位，真返回 14／唯一還票。
4. 兩工作可按顯式 wake 次序串行完成而不預先執行未被喚醒者。
5. Prepared 安全取消零資源／票據事件，Cancelled 後不得重播。
6. Suspended 安全取消同樣零真執行，重複取消／暫停拒絕。
7. 被喚醒方法本體真 IntegerOverflow：唯一 Unwind→LoanReturned，狀態 Failed 且不得再 wake。
8. 靜態拒絕漏 await、await 同步方法、實參型別不符均零工作 ID 消耗。
9. 即使原普通方法準備器可接受，帶 main 前置 int 局部者仍不允許冒充無副作用直接 await 延遲圖。
10. 封存 `awaited_method` 身分被改後 wake `SourceChanged`、工作保留 Suspended；還原原計畫才可真喚醒。
11. 封存原 Lexer 的 `await` Token 被篡改時，相同工作只拒絕不執行，修復後能正常 wake。
12. u64 工作 ID 耗盡不回繞、不配發重複工作；未知 ID 拒絕。

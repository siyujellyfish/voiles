# G18／P18.4-B4／M3：普通純 int helper 作同步 self 方法直接實參（2026-11-14）

## 已驗收起點與原真缺口

以已 Squash merge、`main 10acf67671156f0ab47268b914cf78b3c7e3e97d` 同 SHA 必要三項 CI 全部 completed/success 為基準。過去 B4/M3 已在 main int 局部、方法內 int 局部／重賦、方法 Return 與 true／else／巢狀葉、混合 bool/int 方法形參接通原 Checker 純 Copyable int helper 的單一動態工作圖。但**主程式直接以 `owner.read(helper(9,2))` 傳遞 int 實參**仍遭拒：原 `method_argument_safe_before_borrow` 在借用 self 前不允許任意 Call；受限方法執行器的 `argument_plans` 雖能由 Checker ScalarHIR 建構 `Call`，仍一律拒絕具 Call 的實參，不會產生真函式返回值。

## 僅准原 Checker 同源的純 Copyable int 直接 Helper

- 原 `method_argument_type_without_effect` 用於 S20 唯一方法簽章決議，不可先求值；本批只對**整個方法引數正好是** `Call` 或原 F02 `ZeroArgResolution::Function` 的 `UnresolvedZeroArgs`，透過新增 `method_direct_pure_int_helper_argument` 保守判定已知的同步普通函式、回傳 `int`、單一原 `Return`、所有形參互不重複的 `int`，返回只引用那些形參、Lexer 整數和加減，所有呼叫者引數都只由 Lexer 整數、Group、BinaryInt(+|-) 組成。絕不放行任意 Nested Call、`1+helper()`、str、Move、Borrow、方法重入、await 或未知名稱；沒有新的語言語意。
- 同一驗證只作可安全進入原方法引數求值的**前置純值白名單**。真正來源仍交由原 Checker `self.evaluate(arg, vars)`：簽發具原 Lexer／Parser 半開跨度的 `ScalarHIR`、原所有權與借用責任，並於所有引數求值完成後才檢查接收者、簽發原 `self` 自動 `call_borrows`。不能在純值白名單直接寫入 `TypedHIR` 或把結構 `name()` 混成普通函式。
- 受限 `PreparedPrivateSelfMethod::prepare` 將真來源 `Call` 經 `PrivateScalarReturnExpr::from_checked_bindings` 封存，僅允許完整整筆直接 `private_self_matches_helper_call`。核對原 helper 形參 `DeclarationId`、回傳純 int 工作樹、無 await、每個 int argument 皆由原 Checker 認可；準備時計算僅作**純值來源快照**，不改 Runtime 事件／BorrowTicket，若溢位則沿既有零哨兵保留真執行期故障路徑。
- `execute_with_fault` 在 main 已完成局部初始化後，依原方法實參次序逐筆求值；遇直接純 helper，先由 Caller 目前 `main_values` 求完子函式全部參數，成功才記 `FunctionEntered` 並在獨立 helper frame 真求返回算式，返回後才交付方法 int 參數。**所有方法實參皆完成，才可 `LoanAcquired(self)`、`FunctionEntered(method)`**。Caller helper 的最後實參溢位時，沒有 helper Enter、也沒有 self Loan；helper 本體真溢位則記唯一 `UnwindStarted`、子框架 `FunctionExited(false)`，方法仍未借入 self；前一個 helper 完成但後一個故障時，只保留已完成子框架事件，不會偽造方法 Enter 或成功 Return。
- `matches_source` 依原 Checked HIR 重編整份實參工作計畫與各原真 `DeclarationId`，不允許竄改為相同數值常數後繞過。原 S20 多載、M2 bool/int 值槽、R05／HC14 真票據、P16 UTF-8 ResourceId 安全界線皆不動。

# P18-E｜執行控制事件完整性 Gate（2026-11-04）

> **施工候選、不是 G18/P18 正式驗收。** 以已通過主線 CI 的 `69e7c3e19a17ddbb3a5d406de477402f97ddffec` 為基底；原 P17/P18 控制事件實測 28 項已在此主線存在。

## 工程實作

- 新增 `src/execution/trace.rs` 的 `audit_control_events`，驗證真正 Runtime 產生的函式呼叫堆疊，要求 `FunctionEntered`／`FunctionExited` 名稱與原始範圍成對。
- `FunctionExited { returned: true }` 只能與同框架**恰好一次**完成的 `Returned` 對應；`returned: false` 不能有成功 `Returned`。巢狀函式框架彼此獨立。
- `ConditionChecked`、`ElseSelected`、`Returned` 均必須位於實際已進入函式的原始來源半開跨度內，空跨度、跨函式、函式外事件均拒絕。
- 真正 `PreparedProgram::execute_with_trace` 在交付成功結果前審查本次 Runtime 發出的控制事件；如果堆疊或跨度不一致，回傳內部 `RuntimeFailure`，不把錯誤計算偽裝成功。
- `FunctionExited.returned` 進一步要求函式實際求得的 `Value` 與 P10 已驗證結果型別一致；動態錯誤退出仍留下實際已執行的事件，不能冒稱完成返回。

## 四項新增正反 Rust 驗收

| 案例 | 預期 |
|---|---|
| 真正巢狀進入／返回／退出 | `Ok(())`，內外返回各一次 |
| 缺少進入或漏退出 | `UnmatchedFunctionExit`／`DanglingFunctionFrame` |
| 回傳次數或成功狀態被假造 | `ReturnCountMismatch` |
| 來源跨度外、函式身分錯誤、函式外條件 | `EventOutsideSource`／`FunctionIdentityMismatch`／`EventOutsideFunction` |

已將此四項加入 `tools/核對G17內部切片.py`；原 28 項加本批 4 項為 **32 項非公開 Rust 測試**。CI 原完整 `rustc --test` 真執行全部案例，Gate 只核對已執行的測試名稱，不重複耗時。

## 未完成邊界

控制紀錄不能充當靜態 `CFG`／`SafetyState`、`BorrowFact`、`BorrowTicket` 或實際 `ResourceEvent`。真正 P17-C 私有 str／struct 資源執行、P17-F 建構預設欄位求值、P18 的全部 for/while／借用／資源退出與 async 規格尚未由此提交處理。**G17、G18 及 P19～P22 均維持未驗收**；公開 `check_file`／CLI 完全不改。

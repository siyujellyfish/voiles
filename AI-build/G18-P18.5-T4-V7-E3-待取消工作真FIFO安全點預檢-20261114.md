# G18／P18.5-T4／V7-E3：待取消 Prepared／Suspended 工作原 FIFO 身分及安全點雙帳（2026-11-14）

## 基準與實際缺口

從 PR #782 已 Squash merge 且最新 `main a3293ca3d5c4b986f2225f108091a8ab6667461b` 的三必要 CI `completed/success` 起步。前批修復 T4 已完成／已取消工作的完整 FIFO poll 歷史，`retire_terminal` 與 `shutdown` 對 Succeeded／Failed／Cancelled 終態已共用 R05／P16 退出證據守門。

仍有真安全缺口：`shutdown` 對**待取消**的 `Prepared` 直接納入取消清單，對 `Suspended` 只核對現在有無 checkpoint／pending_await 與 borrow 安全點，未驗證此工作 ID 從未 poll 或確實只經歷合法 Suspended，也未檢查結果／取消歷史是否仍不存在。若某已成功、失敗或取消工作被篡改為 Prepared／Suspended，單筆 `cancel` 可能因僅信任狀態標籤而改動同一工作，整批 `shutdown` 更可能在發現偽造身份前先取消其他仍待命的工作。

## 唯一安全修補

新增 `PrivateScalarCooperativeQueue::verify_cancellable_evidence(id)`，**唯讀**整合原 FIFO、Checker Continuation、R05／P16 的待取消證明，不執行函式、不新簽 BorrowTicket／ResourceId、不改動狀態：

- 共通入口需工作真實存在、該 ID 尚無 `cancellation_order`、`job.cancellation` 或成功／失敗 `outcome`，且可執行 FIFO 中該 ID 不可重複排入。
- `Prepared` 必須尚未有任何原 `drive_order` poll、checkpoint、普通函式事件或 ResourceEvent，且仍在唯一準備佇列位置；原 Checker 工作預執行拒絕仍不應製造假動態歷史。
- `Suspended` 必須原 FIFO 至少有一筆真 `Suspended`，且整條該 ID 的 poll 歷史皆只能為 Suspended；不能包含 Completed。也必須仍保有原真 checkpoint、pending await 位置、動態 HC14／VB15 E5 借用安全點。已 wake 且重新排入 ready 但尚未真正再次 poll 的 Suspended 仍可合法取消，不改 E3 核准的取消時間窗。
- 原 `cancel` 在變更任一工作之前先呼叫這個共通守門，原 `shutdown` 則在對任何工作採取取消之前，先逐一調用相同守門驗證全部 Prepared／Suspended；已終結工作仍走上一批嚴格 `verify_terminal_evidence`。任一預檢失敗都回 `Engine` 而不移除工作、不取結果、不釋放資源、不取消其他工作。通過後仍呼叫既有唯一 `cancel_suspended`，真正執行原 R05/P16 清理，不推定跨 Runtime 清理故障具備完整事務回滾（未經證明的安全權限不新增）。
- 本批不新增語言層 async 語法、取消形式、並行／背景工作或跨 await 借用權限。

## 八項原 Lexer／Parser／Checker 真 Rust 正反及必要 Gate

1. 從未 poll 的 Prepared 真取消，交付 `Cancelled(None)`，零假函式／資源事件；

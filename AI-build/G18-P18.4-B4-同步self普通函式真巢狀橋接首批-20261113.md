# G18／P18.4-B4：原 Checker 普通函式與同步 self 真巢狀執行（首批，2026-11-13）

## 既有工程缺口

原 `execute_method_self.rs` 僅接受一個原 Checker `main`，即使原 Checker 已核准同源普通 `fn helper()->int`，也會在 `verified.functions.len()!=1` 拒絕；即使放寬函式數量，方法內 `const local:int = helper()` 在原 `PrivateScalarReturnExpr` 具有 Call 工作圖時仍被保守拒絕。普通函式執行器 `execute_call_scalar.rs` 又尚未支援 MethodCall；分別測試兩個執行器不能冒稱 **B4：同一 CFG 的 self／函式安全責任** 完成。

## 本批真程式橋接與不可放寬邊界

- 對原 `.voil` 字串僅執行一次 `verify_source_with_ability`，允許 `main` 與至多一個附加的同步零參數 `fn helper()->int`。該 helper 必須是真 Parser 單筆 Return，經原 Checker `TypedHIR`、原 Lexer 位置編譯出 `PrivateScalarReturnExpr::Constant`，不可有副作用、額外函式呼叫、資源所有權或借用。
- 只允許已被原 Checker 編譯的同步方法局部 `const/var from_helper:int = helper()` 作唯一普通函式橋接位置；呼叫必須具真 `Call` 節點、唯一函式名稱、沒有實參、沒有 await。其餘參數、MethodCall／普通函式多層控制路徑維持原先 Unsupported；不因本批而擴張 Checker 的所有權與 async 授權。
- 真正走到同步方法局部初始化時，**在已取得 self BorrowTicket 後**才於共同 `PrivateSharedCallExitEvent` 帳記錄普通 helper 的 `FunctionEntered`，執行原 Checked int 常值工作，記錄 `Returned` 及 `FunctionExited(true)`，再完成局部初始化。不是在 prepare 靜態預寫動態事件或假造 ResourceId。
- 共享 R05 退出驗證改以巢狀動態深度追蹤 `LocalInitialized/ScopeEnded`，要求進／退、已完成普通呼叫次數與方法結果互相一致；內層正常退出不會誤把方法外層視為已退出。方法注入故障時未進入的普通 helper 不得留下任何事件，已取得的 self 票據須照舊歸還。
- 比對同一次原 Checker 真來源重新編譯的 helper 工作計畫；來源／計畫被竄改則在執行前拒絕，不得藉相同 int 返回值或補平衡虛假事件通過。

## 真正正反測試

Rust `src/struct_stage/g18_b4_mixed_self_call_tests.rs` 七筆及 `tools/核對G18-P18.4-B4同步方法普通函式橋接.py` 逐項 `--exact` Gate，覆蓋：
1. self 真票據在普通 helper 的進退期間維持活躍，同一巢狀 SharedCallExit 事件次序，返回值精確；
2. 方法內注入故障，尚未實際到達 helper，不允許虛構普通函式事件，且 self 票據確實歸還；
3. 靜態已編譯 helper 的返回計畫被竄改必於真執行前拒絕；
4. 同一安全計畫重跑，各次 frame、借用和結果獨立；
5. 不存在的函式或返回型別不符由原 Checker 靜態拒絕；
6. helper 有形參或不具無副作用單值計畫，仍保守 Unsupported；
7. 已發出的真事件缺少 Returned 或額外重播呼叫數必拒絕。

## B4 未閉合清單

此首批**只接通一個可嚴格證明的真普通函式→同步 self 方法內局部呼叫形狀**。尚缺：
- 普通函式在 main 初始化、返回、條件與迴圈中的真方法交錯；多參數、多層普通函式返回、同一 CFG 重入；
- 方法／函式共同擁有的非 Copyable `str` ResourceId、BorrowTicket、跨 frame Move／Borrow 的單一退出責任；
- 正常、提前 return、受控預算、算術溢位及故障時所有可達動態框架的內後外歸票與清理；
- 原 Checker 靜態方法多載／self 權限在上述高風險交叉中的完整 B4/M1～M3 閘門。

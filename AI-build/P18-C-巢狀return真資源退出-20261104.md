# P18-C｜私有巢狀 return 真退出與多層資源清理（2026-11-04）

> 本批為受限 P18-C 工程候選，不能視為 P18.3 或 G18 正式 Passed。基準 main `c0c2a5c6575624d5dbc879e5967a122513847b59`，PR #508 巢狀資源分支合入並通過主線三項 CI。

## 真實施工

沿原 `struct_stage::verify_source_with_ability` 的正式私有 Lexer/Parser/Checker/SafetyPlan、DeclarationId 與已核准 bool 常值條件，延伸 `PrivateStrBranchBody` 的既有**最後一筆整數常值 return**。僅在所有巢狀分支語句與資源宣告已通過原 Checker 後，Runtime 才會進入資源配置。

此前 P18-B 的巢狀 `if/else` 具備 `enter_scope/declare/leave_scope`，但遇內層真 `return` 仍會保守拒絕。本批在真正 `execute_str_literal_branch` 由內向外傳遞 `Option<i64>`：內層在返回前 `leave_scope`，外層收到值後不執行後續語句，同樣 `leave_scope`，再由最外層 `finish` 釋放剩餘持有者，事件一律出自 P16 唯一 `OwnedStrRuntime`，按動態建立次序逆序清理。未執行分支不配置資源或產生假事件。

**維持界線**：巢狀分支條件目前只支援真 bool 常值；return 僅限直接已驗證整數常值。一般運算式 return、借用、方法、循環、任意失敗取消、跨函式資源移動尚未具備完整安全證據，必須保守拒絕。

## 六項舊新測試更新

- 原 `p18_b_巢狀分支內的_return_動態清理尚未接通必須拒絕` 轉為已證實巢狀 return 成功、內層先清理的正例。
- 原 `p18_b_巢狀_return_控制轉移尚未驗證仍必須保守拒絕` 的**相同來源**轉為三筆真資源依序逆序釋放的正例；不刪原來源素材。
- 新增內層提前返回後不執行外層剩餘資源建立、巢狀 false/else 回傳、最外層 false 不觸發內層 return 的正例。
- 新增巢狀 `return 1+2` 的保守拒絕負例，確保尚未接通一般運算式不偷渡。

`tools/核對P17私有字串切片.py` 保留原 34 項有效測試與來源，重新命名上述兩項過時負例以反映功能進展、另增四項，合計**38 項**真 Rust 正反。CI 不重複跑核心測試，只核對測試名稱已列入原 Rust 全量執行。F00 四組凍結、G6、公開 CLI 不變。

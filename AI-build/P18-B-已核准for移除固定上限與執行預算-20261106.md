# G18／P18.2｜合法半開 for 移除私有 64 次拒絕，改可配置執行步數預算（2026-11-06）

> 基線 main 00734bac003a0594eb89a0a421073cf7781fccc5 三必要 CI success。延續原 P15 合法 for 迭代與 D18-01 已核准的執行資源預算原則；不新增語言固定迴圈上界、不公開新 CLI 或 OS 退出碼。

## 原驗收阻礙

此前私有 PreparedPrivateLoop::verified_actions 把合法的 for i in 0..65 直接拒絕，儘管原 Checker 允許這個半開區間。固定 MAX_PRIVATE_ITERATIONS=64 只為早期小型實驗支援，與原 P18.2 合法迴圈正向執行驗收衝突。舊 Gate 甚至把「超過 64 次必須拒絕」當成負例，需一併修復，而不是只在文件辯稱屬內部限制。

## 真工程

- 移除 prepare 階段大於 64 次的私有拒絕。原 Checker 已核准、Lexer／Parser 解碼的所有合法 i64 半開區間可進入同一真 OwnedStrRuntime 執行器。
- 新增 PrivateLoopExecutionBudget {max_steps} 和每次執行的 PrivateLoopStepCounter。預算於每筆真正可達動作、每次真 for 迭代及 while 條件檢查消耗，包含空本體。預設 10,000 步只屬非公開本次執行環境設定，可由 Rust 內部 execute_with_budget() 覆蓋；**不是 voiles 固定語言上界**。
- 執行耗盡以 StrRuntimeError::ExecutionBudgetExhausted 獨立受控返回，不冒稱正常 return、不因巨大合法 i64 區間阻塞。原 run_scoped 在正常、break、continue、return、耗盡時逐層真離域，每份 ResourceId 只建立及清理一次。
- 以同一執行期預算支援 Checker 已驗證的真正 bool while **多輪重讀、continue 再檢查、正常與錯誤逐輪釋放**；不再要求每個 while 都必須靜態證明一次內退出。原不終止拒絕負例改為受控預算耗盡正反，原 continue 靜態拒絕負例改為合法真正繼續迭代並耗盡正反。
- 原65次拒絕負例改為合法 65 輪真執行；新增五項：65 輪小／大預算對照、巨大 i64 區間受控耗盡、零步數零配置、巢狀 for 預算耗盡逆序回滾、while(false) 真條件步數。
- P18.2 Gate 由 31→36，升級為獨立重新執行，不只檢查案例名稱；G18 原六項 P18.2 新增六筆真來源追溯。

## 未驗收界線

本批支援原 Checker 已核准的具名 bool while 真多輪與 continue，但不擅自擴張 Lexer／Checker 未核准的複雜條件式、跨函式資源借用、結構方法或 async 調度。P18.2 仍 SubsetVerified，原 G18 六項保持未完成。需 PR 最新 HEAD 三必要 CI completed/success、作者/base/mergeable 和 Squash merge，合併 main 同 SHA 再驗。

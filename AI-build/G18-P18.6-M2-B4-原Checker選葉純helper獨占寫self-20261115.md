## 不新增語意的相容接線

- `private_self_checked_branch_write` 只接受原 Lexer／Parser／Checker／ScalarHIR 完整認證的 `TermKind::Call` 或 `BinaryInt`，並要求 `private_self_approved_int_call_arithmetic` 真正解析出所有純 int 同步 helper；不得自行解析文字、綁新名稱、執行 async、Move、Borrow、str ResourceId 或資源別名。
- 原方法參數 `DeclarationId` 唯一身分仍由已驗證 `VerifiedTypedMember`、原方法形參及真呼叫引數位置綁定。每個選葉 RHS 只保留原 `NodeSpan` 對應的 `PrivateScalarReturnExpr`，沿用現有 `method_branch_int_plans` 和 `matches_source` 完整對帳，禁止執行期篡改或重播。
- 原動態分支在取得唯一 ExclusiveWrite `BorrowTicket` 後，才執行真正選中葉的 RHS。含 Call 時直接復用已存在的 `private_self_execute_arithmetic_call` 及 `private_self_execute_nested_argument_call`；所有 helper 各自持有真參數框架及 `PrivateSharedCallExitEvent`，在計算完成後才 `write_int_field`，不新簽另一張 self 票據。
- 未選中葉不得預先 Enter helper 或評估算式；內層引數或函式本體溢位時不得提交欄位，先退出已開始的普通函式，再循原 R05／HC14／BorrowTicket 退出路徑歸還 self。單純 int 不得偽造 P16 UTF-8 ResourceId；原 P13～P16、E1～E5 及公開 CLI 保持不變。

## 首輪真 CI 阻塞與根因閉合施工

PR #802 首輪 HEAD `606c246a11958863eec47f2895b9253b027ac32d`：必要 Rust 核心內部測試 **2769 passed／10 failed**。十項新測試均於準備時收到 `Unsupported("M2 選葉 RHS 缺少原 Checker int ScalarHIR／Lexer 來源")`。查核 `src/struct_stage/safety_checker.rs` 確認：`method_pure_value_type` 早已正式靜態接受合法的同步純值 Call，`method_writes` 隨後卻只透過 `record_method_pure_int_hir` 交付「不含 Call」的加減算式節點。既有 `method_branch_checked_pure_helper_return` 僅為 Return Call 交付 `self.evaluate` 的真 TypedHIR，無法授權欄位 RHS，因此執行器不應跳過缺失的原 Checker 事實。

保守修復：於原 `method_writes` 既有 Copyable／欄位／借用權限驗證成功之後，新增 `record_method_checked_helper_write_hir`。先只讀同一原 Parser 的完整 RHS AST／普通函式宣告，要求 RHS 為 int 常值、方法 int 形參、加減與真正同步無副作用純 int helper 的樹；helper 必須單筆 `return` 且僅用其原形參與 int 常值加減；每個 Call 實參須同樣符合安全樹。然後與既有 M3 Return helper 一樣，建立原方法 int 形參的 Checker Scope，呼叫**原 Checker `evaluate`** 逐節點寫入真正 `ScalarHIR`。對不符合此純值安全子集的其他原合法語意，**不簽發 HIR 也不擅自讓 Checker 新增拒絕**，執行器仍保守 Unsupported。保留原始十項失敗紀錄；必須以更新後最新 HEAD 重跑三 CI 並確證成功才可正式採計。

## 真執行與安全界線

1. 在修改任何工作／FIFO 前，先以工作 ID **逆登錄順序**完整掃描所有現有工作；Prepared 可直接取消（零動態事件），Suspended 必有真正 checkpoint 和待進 await 名稱且重新用原 BorrowSafety／incoming BorrowFact 逐祖先安全檢查，否則拒絕；Running 保守 WrongState，不冒充可中斷的安全點。
2. Finished（Succeeded／Failed／Cancelled）工作不再清理、不消耗已返回結果；若任一終止工作仍有可達的真 checkpoint，拒絕整批成功，不得假稱完成。
3. 整批安全預檢若發現任何工作有有效票據、錯誤續行狀態或缺失 checkpoint，**全體零狀態變更**：此前已排入 FIFO 的喚醒 token、各真 ResourceId、原工作與取消次序均不受影響。票據真正歸還後可重試關閉。
4. 預檢通過後，按工作 ID 逆序委派既有 PrivateScalarCooperativeQueue::cancel(id)：已建立的真內層 frame 使用原 PrivateScalarGraphContinuation::cancel_suspended → 唯一 evaluate_graph_driver 的 R05／HC14／P16 逆序回滾，不執行未開始的 async 子函式，不假造成功返回，且只有清理成功才移除排程 token。
5. 真清理過程若遇原執行器／R05 稽核失敗，保守回傳 Engine，不宣稱整批成功。**不承諾跨獨立 Runtime 故障的全體回滾原子性**；預檢的零狀態變更界線僅保證在可驗證的已存在有效借用／狀態錯誤下先拒絕。
6. 重複 shutdown 在全部已結案時返回空集合，不重播任何原動態 ResourceEvent；已完成的合法結果保持可查。尚未執行的所有工作不因此構造任何 UTF-8 或假釋放。
7. 此 API 是內部安全關閉協定，不是已完成的擁有式 Runtime 自動 Drop 清理；呼叫端仍必須明確 shutdown，並處理拒絕後仍持有的合法借用。原 Rust 借用生命週期／E1 延遲啟動與單執行緒限制保持。

# P15.6 結構方法非 Copyable 參數預設借用交叉證據（2026-10-30）

> 本批承接已合併一般函式 P15.6 PR #253，僅支援真正可在私有來源 AST 內證明安全的結構方法資源參數借用，不提前驗收 P15／P16。

## 原始契約

- 函式參數預設借用，函式離開作用域才歸還；struct 方法的 self 獨立由實際讀／寫行為推導共享／獨占並於方法結束歸還（S14/S15）。
- 非 Copyable 既有具名 str 不得透過普通讀取／複製形成新所有者，方法若確實以 .move() 消耗參數，仍需呼叫端提供獨立字面值或明確 .move()。
- HC14-A 使用同一來源宣告身分檢查 var 獨占與 const 共享；不得把 self 及方法另一參數的重疊借用當成獨立安全來源。
- 不擴張 await／例外、借用逃逸、方法借用欄位、容器索引、方法一般可寫資源覆寫、P17 實際直譯。

## 本批來源檢查

- 方法參數按來源順序於 self 借用前求值；非 Copyable 具名、且被呼叫端未以 .move() 消耗的參數，改成 BorrowSafety 呼叫作用域票據，不透過 ValueSlot.duplicate() 偷複製資源。
- 多參數之間沿 HC14-A 判斷同來源雙獨占衝突與共享相容；先借用後明確 move／直接讀取仍拒絕；已有作用中借用與新的方法參數借用衝突也拒絕。
- 若方法的 self 與參數指向同一原來源，在缺乏跨位置別名的完整安全證明前保守拒絕，不能把同一次方法呼叫的兩個資源入口視為不相干。
- self 在既有 check_method 推導模式下完成借用與退出；方法參數票據緊接方法退出以 finish_scope 全數歸還，避免一般 .borrow() 的最後使用點演算法提前釋放。
- 過去一項「唯讀方法消耗不到 str 參數卻禁止具名參數」的 P13 歷史測試改按已核准預設借用合法，其餘會消耗參數的 .move() 正反測試保持。

## 七項真實 .voil 安全回歸

1. 唯讀方法取得具名 str 預設借用後，來源仍可在方法退出後 .move()。
2. 同次方法兩個 var 來源獨占借用衝突拒絕。
3. 同次方法 const 來源雙共享借用合法。
4. 同次方法先借用後再 .move() 同來源拒絕。
5. self 與方法參數同一原來源保守拒絕。
6. 原所有者已有仍活躍獨占別名時，方法不得再借用原所有者。
7. 真正消耗資源的 relay(text.move()) 正例與沒有 move 負例。

## 正式驗收保留

- 仍需 P15.3／P15.6 原始條文與全語言範圍逐條查核；方法局部非 Copyable 參數執行期及跨函式重入的完整借用生存證明留待後續。
- PR 最新 HEAD 三項必要 CI 成功、GitHub 身分與 mergeable 核對後才 Squash merge；單批 CI 成功不表示 P15／P16 整體驗收已完成。

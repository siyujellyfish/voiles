# P16.6-R02 F04｜公私正式 Checker 共用具型別宣告身分契約（2026-11-01）

> UTF-8。此批是正式 P09→P10／P11 與私有 P13～P16 Checker 的 Typed HIR 來源契約整合，不宣告全部 Typed HIR、F04、R02 或 R03 結案。

## 本批實際架構

- 新增 `common_ir::TypedDeclaration<T>`，以同一語意資料結構保存 `DeclarationId`、已核准型別、var／const 權限；`matches_use` 必須同時比對宣告原始來源身分與型別，`use_at` 以原 UTF-8 半開位元組位置產生既有 `TypedUse`。
- 正式公開 P10 `TypeChecker` 的詞彙作用域與頂層環境直接使用 `TypedDeclaration<ScalarType>`。當正式 P09 已有引用或賦值目標 `TypedUse` 時，先比對**真正當前詞彙環境**的同一 `DeclarationId` 與相同型別，才授權 P10 型別判斷；偽造 P09 同型別不同來源、來源型別或目標賦值位置，不得再跳過權威綁定。
- 正式公開 P11 `Flow::Variable` 改為保存 `TypedDeclaration<()>`，仍只消費來源身分、初始化與可變權限，不假裝具有 P10 型別／所有權推論。分支快照及合流持續用同一具型別宣告身分，保留 P01 原有不可達語句與初始化規則。
- 私有 P13～P16 `Binding::semantic_declaration` 以 `TypedDeclaration<&str>` 表達真實名稱、來源、型別及可變權限，`semantic_use_at` 只從此綁定產生既有 `TypedUse<&str>`，`str`／結構及 Copyable 安全權限維持私有，不進入公開純值 AST。
- 新增 P10 正式已解析身分與詞彙環境篡改回歸、同型別不同 DeclarationId、型別遭篡改拒絕，以及私有非 Copyable `str` 身分／來源跨度的共同契約驗證。

## 風險與未完成

- 本批未以共通 Typed HIR 替代所有公私控制流程、函式語意、借用權威與資源計畫；`TypedDeclaration` 是已驗證來源共通表示，不代表 F04 全工作包完成。P10 沒有改變合法來源的診斷種類、錯誤文字或 P11 初始化／const 安全順序。
- 最新 PR HEAD 專案檢查、Rust 前端建置及 Rust 獨立架構測試須 completed/success，核對作者、head SHA、mergeable 後 Squash merge；P16.6-R 維持 4／6，P17 不開放。

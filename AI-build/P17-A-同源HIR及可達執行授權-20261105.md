# P17-A｜正式 P09／P10／P11 執行前同源權威證據重核（2026-11-05）

> 此工程仍為**非公開**直譯垂直切片，不是 G17／G18 或 P17～P22 正式驗收。施工基準 `main 444ce5afb3b234477e994b7dcfa31221f6819e88`，該 SHA 三項必要 CI 均已 completed/success。

## 發現與補強

既有 P17 `PreparedProgram` 已保存原始位元組、P01 公開 Parser AST、`ResolvedNames`、`VerifiedScalarHir` 以及 P11 可達表達式與賦值集合。執行前比對原始位元組及 AST/TypedHIR 的來源角色可防單筆節點造假，但**不能將被竄改的宣告身分、可變性、具型別 HIR 與可達集合**等同於同一次原 Checker 真正簽發的完整集合。

新增 `has_original_checker_facts`：由 **原保存的同一來源原始位元組**重新調用既有公開 `PreparedProgram::prepare`，它本身仍走原 `Source→Lexer→Parser→P09 Name→P10 Type/HIR→P11 Flow→P12 Functions`；比較**完整的** `ResolvedNames`、`VerifiedScalarHir` 與可達表達式／賦值 `NodeSpan` 集合。僅在現行 `is_same_verified_source` 與此項重新核對皆成功才開始建 Runtime，否則返回內部 `RuntimeFailure`、**零真控制事件、零動態效果**。此處沒有第二套 Parser、沒有新公開 CLI、也不將 `Passed` 單一狀態當權限。

實作 `ResolvedNames`／`VerifiedScalarHir` 的結構相等比較，所有被比對子欄位均使用 Rust 完整型別相等，而非 Debug 字串或非保證雜湊。這會增加 Checker 的重跑成本，直到可證明的不可變封閉計畫落地；不能以新效能門檻取代原安全檢查。

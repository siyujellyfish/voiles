## 單一原 Parser 签章、分離值槽與真借用

- **唯一來源**：原 Lexer／Parser／Checker／TypedHIR／`VerifiedTypedMember(Parameter)`／`DeclarationId`／`VerifiedMethodSafety` 及 `call_borrows` 不變；方法多載候選仍由原 `definition.methods_named` 與**完整形參數量和逐位 int／bool 型別**唯一性選中。此子集允許**最多一個原 Lexer bool 字面實參**（但位置不限）與其餘原 Checker 已核准的純 Copyable int 實參混合；不開放一般化 bool 表達式、bool 重複參數、str／Move／Borrow／資源、隱式 int→bool 或 bool→int。
- 所有 main→方法實參按原 Parser 次序辨識。bool 必須與原真 Lexer `true`／`false` token 半開跨度吻合，記其原實參**位置**，並在選中的原方法對應 `VerifiedTypedMember(Parameter)` 的原 `DeclarationId` 綁到獨立 `bool_parameter_frame`。int 每個實參仍由原 `PrivateScalarReturnExpr::from_checked_bindings` 取得 TypedHIR、拒絕未經核准的巢狀 Call，準備階段只封存可稽核值快照，實際在任何 self BorrowTicket 簽發前由 `execute` 重新從真 main int 框架求值。bool 常值無副作用，因此跳過 bool 值槽不會交換具副作用的實參求值順序。
- 每個方法形參都重新核對**原 Checker `plan.members`** 與原 Parser／Lexer 具位置的 `VerifiedTypedMember`；`BTreeSet<DeclarationId>` 只做唯一性防偽，不替 Checker 補發型別。int 只進 `argument_binding/additional_argument_bindings` 的純 int 序列，bool 只進 `method_bool_argument`，兩者不可用相同 ID 或在非原位置代入。
- M2 `if(flag)` 與巢狀 `if(flag)` 的唯一布林來源仍須匹配原方法**任一合法 bool 形參的名稱、型別、DeclarationId 和原 Lexer Name token**；不再人工要求方法簽章只有一個形參。原 Checker `method_bool_condition`、方法寫入模式 `BorrowKind` 和 `checked_returns` 不變，未選分支仍不得執行 helper 或誤報溢位。
- `private_self_checked_helper_return_leaf` 與動態普通 helper 原始工作計畫**完全沿用**，只在方法真到達所選葉、成功求完整 Caller int frame 後才 Enter 普通函式；helper 成功／失敗沿既有 R05 `Returned/FunctionExited`、唯一 `UnwindStarted`、內後外 `LoanReturned`。不因支援混合方法簽章擅自修改 P16 非 Copyable 清理或 V7 async。

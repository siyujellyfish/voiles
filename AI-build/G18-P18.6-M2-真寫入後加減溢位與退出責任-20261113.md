# G18／P18.6-M2：真自借用寫入後的加減與受控溢位退出（2026-11-13）

## 基準和未完成責任

本批起點為已完成合併後主線同一 SHA 三項必要 CI 的 `main 12b9af7a26ffb47ea28ac55a93dfea46a0aaabb8`（PR #754）。此前原 Checker 已能核准同步方法中的 `if(flag) { self.n = 19; return self.n } else { return 22 }`，且真 Runtime 只有被選中的 true 葉才能取得獨占權限寫入欄位；但如果原 Checker 允許 `return self.n+5` 或 `return self.n+9223372036854775807`，真執行器仍會在 method branch 計畫建構時以 Unsupported 拒絕。這造成已寫入後發生溢位的**真錯誤退出與唯一借用歸還**無法測試。

## 本批原 Checker→Runtime 最小擴張

- 保留同一原 Parser `StmtKind::If`、真 `TermKind::BinaryInt`、真 `VerifiedMethodSafety.checked_returns` 與原 `BorrowTicket`。選中 true 葉只新增 `return self.<原唯一 int 欄位> + <Lexer int 常值>` 或相同 `-` 運算。左端仍必須是原 `FieldRead(self,...) `，右端必須是原整數 token；原 UTF-8 源碼半開跨度內的 `+`／`-` 必須與 AST 運算子完全一致，不能單純憑來源字串自行解析。
- `method_branch_return` 為原 Checker 所選 true 葉的唯一計算計畫，型別仍為已核准 `PrivateSelfIntReturn` 的 `Field/Add/Subtract`；由 `matches_source` 比對同一真來源重新編譯的計畫，改寫加減值或偷換運算子要在動態配置前拒絕。
- 實際執行順序為：在原 Checker 決定的共享／獨占 self 權限下取得真 BorrowTicket → 選擇 true 葉 → 若已核准 true 葉 FieldAssign，驗證獨占票據才真寫入 `MixedStructRuntime` → 用同一有效票據讀取**更新後的欄位值** → 真執行 checked i64 加減。若算術溢位，只能回報既有 `IntegerOverflow` 和 `UnwindStarted`，**不得記錄 Returned**，且先歸還真票據再清理 owner；無論成功或故障都不虛構 UTF-8 ResourceEvent。
- false／else 葉完全不執行 true 葉的寫入和算術，即使該真運算式一經執行必溢位，false 葉仍返回原值。
- 原 Parser／Checker 不合法的 self 欄位與 int+bool 仍維持靜態拒絕，不改動任何複雜 CFG、泛化借用、await、公開 CLI、所有權相依決策。

## 八項獨立真來源與 Gate

Rust `src/struct_stage/g18_m2_post_write_overflow_tests.rs` 及 `tools/核對G18-P18.6-M2寫入後溢位與借用歸還.py` 分別驗證：

1. 已寫入 19 後 true 葉真計算 `19+5=24`；
2. false 葉未寫入且不計算 true 葉，正確返回 22；
3. **已寫入** 19 後實際加上 i64 最大值，發生受控溢位、`UnwindStarted`、沒有 `Returned`，且唯一獨占票據真歸還；
4. 同一帶溢位的 true 葉若未被選中，false 正常執行；
5. true 葉以更新後欄位計算 `19-20=-1`；
6. 沒有任何欄位寫入的純共享 self 方法仍可早退加法，不冒稱持有獨占票據；
7. 真 Checker 已選定 `Add(5)` 受到竄改，執行前 `SourceChanged` 拒絕；
8. 不存在欄位／int+bool 組合仍由原 Checker 在準備階段拒絕。

新增專用 Gate 先用 `--list` 精確鎖定全部八項 Rust 名稱，再以 `--exact --test-threads=1` 逐項真執行並要求每筆 **1 passed／0 failed／0 ignored**。必須同時保留原 F00/G6/G17、G18 V0/R07、B1～B5 已驗子集、M1 以及先前三批 M2 的安全回歸。

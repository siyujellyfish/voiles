## 批次與核對紀律

第一批只做無行為的測試抽離：`src/struct_stage.rs` 的原 `#[cfg(test)] mod` 群組移到 `src/struct_stage/tests_ownership.rs`、`tests_lifetime_resources.rs`，於原層使用 `include!` 引入而非巢狀 `mod`；保留 `struct_stage::舊模組::舊測試` 的識別路徑，避免 `tools/核對-P13-驗收證據.sh` 等依測試名稱過濾的檢查失效。私有 `inspect` 與公開 `check_file` 無變化。

每批在最新 HEAD 的 GitHub 三項必要 CI `completed/success` 且 mergeable 後 Squash merge。不能把新的整治項目冒稱原本 24 個語意條文；也不能因總測試數相同就認定所有安全行為已被新設計覆蓋。

## 第二批（R04／R06）實作設計（#267 最新 HEAD CI 已通過）

- `flow.rs` 使用 `Rc<HashMap<...>>` 實作詞彙作用域寫入時複製；分支 `clone` 不再直接複製每層全部變數，`Rc::make_mut` 僅在受影響作用域寫入或合流時複製該層。新測試檢查共用指標、原來源未被修改、遮蔽與分支負例仍拒絕。此為 MVP-A 確定初始化層，不宣稱私有 P15 迴圈已同步優化。
- 人工驗收腳本在**預設手動執行**保持全部獨立編譯；CI 可設 `VOILES_REUSE_CI_ARTIFACTS=1`，在**同一 test 工作**使用先前已自己重編的 rlib、CLI、Rust --test 執行檔。從另一個 CI job 重用 binary 仍未允許，BK06 不變。
- 官方 GitHub `actions/checkout@v7.0.1` 取代 v4；生成 P01 測試只對固定核准驗收名稱局部 `allow(non_snake_case)`，Rust stable 依編譯器棄用警告改 `AtomicU64::try_update`。無原始診斷／權限語意變更。

## 第四批（R02）共通解析基礎，仍保留明確的公開／私有入口

新增 `src/syntax_shared.rs`，供公開 MVP-A 與私有 `struct_stage/syntax.rs` 同時使用 `keyword`／`symbol`／`newline`／`end` 的 token 判斷；同時讓 MVP-A 型別檢查與私有 Parser 使用同一 `integer_i64` 的進位、底線、範圍規則，且公開診斷文字保持原樣。共通測試新增整數正反邊界與詞彙終點對齊。P13 私有語法仍不得對外開放。

此批**沒有**將不同 AST 或函式／struct 文法完全合併；公開的 `parser::parse` 仍只允許 P01，私有的 `struct_stage::inspect` 仍保守拒絕尚未能證明安全的完整語言來源。完整 R02 必須在 P17 入口方案確認之後有共同 AST 或內部 IR 與來源範圍的跨模式正反一致性證據，不可以「共用幾個 helper」偽稱全部完成。

## 第五批（R05）私有名稱定義索引

- 每個已核准 StructDecl 於 Parser 完成、經欄位／方法同層重複名稱拒絕後，保存 `field_index`／`method_index`；`fields`／`methods` 的 `Vec` 原順序不改，VB16 求值及清理不能使用 HashMap 迭代順序。

- 加入 96 個欄位與 24 個方法查找／順序測試及重複欄位拒絕反例；新模組和舊矩陣必須通過最新 HEAD 三項 CI，才能標記正式通過。
- 本批消除 Checker 的相關熱點查找，**不宣稱整個解析或執行器都變成 O(1)，亦不保證 HashMap 最壞時間複雜度**。待完成實際欄位數 scaling 基準方能評估速度改善幅度。

## 第六批（R03）單一已驗證來源事實與資源前置門檻

建立 `VerifiedPrivateSource`，在唯一 `verify_source_with_ability` 路徑依序完成 UTF-8、詞彙、私有 Parser、完整 Checker（Copyable／移動／借用／生命週期）檢查，再交付 `Source`、`StructDecl` 與 `Function` AST。原本八個真實 P16 UTF-8 資源來源追蹤分別重複檢查，現全部消耗同一已驗證來源；靜態 `inspect_with_ability` 也由同一入口判定。測試比較安全正例與非 Copyable 隱含複製負例的完整診斷一致性及原始位置。

**安全界線**：這是對齊靜態證明與資源橋接的不可繞過前置檢查，不把模擬器合併成可執行 P17 的通用執行期，也不將 `BorrowSafety`、`ValueSlot`、`ResourceEvent` 強行縮成一個不具證明的新狀態型別。完整 R03 還必須在後續一般執行器 IR 將其持有者轉移／借用票據／資源清理一致性持續驗證，現階段不得視為全部完成。

## 第七批（R04）私有分支／迴圈環境寫入時複製

由原 `Scopes = Vec<HashMap<String, Binding>>` 改為 `Vec<Rc<HashMap<String, Binding>>>`，以 `Rc::make_mut` 在實際修改單一作用域時才進行 clone。來源身分、`Binding`／`LoanBinding`／`ValueSlot` 的安全欄位完全保留，`if` 與 `for`／`while` 仍依原本可達路徑及反向邊保守合流，不引入新合法來源。增加私有快照共享、移動後來源讀取獨立與迴圈正反案例；不得在 Rust CI 通過之前聲稱沒有狀態污染。此批降低 clone 快照的重複資料成本，但下游尚有 AST／後繼語句清單的 `clone()`，不可宣稱所有分支建構已完成效能最佳化。

- `File` 起終跨度、`Block` 起點仍須保留給 P08 AST 來源除錯，只對尚未由公開前端取用的位置欄位使用局部 `#[allow(dead_code)]`。
- `ast_debug.rs` 的 P08 整檔內部除錯用途以局部模組註記保留，不全域關閉 Rust 警告。
- 兩個 Rust 受限來源測試刪除未使用的 `DiagnosticKind` 匯入；八處 `VerifiedPrivateSource` 解構只留下真實使用的欄位並使用 Rust 正式簡寫，絕不跳過私有 Checker 前置驗證。

#274 針對無活躍借用作用域的無效深複製完成後，下一次 CI 的相同形狀負載中位數（微秒）記錄為 if 298／2,034／9,840，for 165／750／2,644（8／8、32／24、96／48）。因兩次觀測由不同 runner 啟動，這是性能走向的輔助訊號，**不是精密同環境 A／B 的改善百分比證據**。

## 第十二批（R03）真實資源事件與雙層責任表來源身分交叉核對

新增 `src/struct_stage/resource_contract_tests.rs`：只使用已通過 `VerifiedPrivateSource` 的單次 `str` 建立、具名整筆 `.move()` 與正常 `return 0`，以兩個語句的**原始位元組起點**建立 `DeclarationId`，並要求 `OwnedStrRuntime` 真正持有 UTF-8 緩衝區輸出 `Created(id)→Moved(id)→Released(id)` 的同一資源識別；同時使用既有 `SafetyPipeline`（含 `BorrowOwnershipGate`、`ResourceObligationAudit`）驗證原來源失效、目的唯一可用、只清理一次、總責任歸零。負例對照靜態檢查與資源入口皆拒絕 `str` 隱含複製，且診斷一致。

## 第十三批（R02.2）共同標量 AST 第一個真實結點契約

新增 `src/common_ir.rs`：把公開 P01 與私有 P13 已核准的交集表示為同一 `SharedAst`，包括帶來源宣告位元組起點的 `Declare`、`Assign`、`Return`、單層 `If`、`int`／`bool`／具名值／已核准加減和無參數函式呼叫。公開 `parser::File` 與私有 `struct_stage::Function` 各自實作無副作用投影；兩者的同一原始來源直接比較**實際共同 AST**、宣告起點和函式順序，不能以只比較 `Passed` 代替。

未屬交集的 `str`、資源移動、借用、結構及多分支 `else if` 均採 `None` 保守拒絕投影，並保留舊有 Lexer／Parser／Checker／公共 CLI 的正式接受規則。此為 **R02.2 的第一批共同語意樹資料結構**，不是兩套完整 parser 已合一，更不是 P17 一般 IR。下一批才能在維持既有診斷次序與所有權安全不變的前提下，逐步讓更多語句直接消耗共通表示。

## 第十四批（R03.2）真正接通已驗證來源持有者／資源事件 IR

新增 `src/verified_resource_ir.rs` 中的 `NamedResourceTransfer { source: DeclarationId, target: DeclarationId }`，由已完成 Lexer／Parser／Checker 驗證的 `Stmt.start` 來源位元組位置建構。它只接受 P16 原已核准的單次具名 `str` 建立、明確 `.move()`、最終清理路徑：

1. 真實 `OwnedStrRuntime` 的 UTF-8 緩衝區所有權確實產生 `Created(id)→Moved(id)→Released(id)`，每步同一資源識別且恰好一次。
2. 在回傳資源事件前，正式私有 `trace_named_string_move_source` **實際呼叫** `NamedResourceTransfer::verify_actual_events`，用 `SafetyPipeline` 的 `BorrowOwnershipGate` 與 `ResourceObligationAudit` 交叉驗證唯一宣告所有者、移交後來源不可讀、目標可讀、單次清理責任及最終歸零。
3. 新負例拒絕同一宣告身份、虛假移動資源 ID、清理另一資源、未清理、錯誤事件順序及重複清理；失敗不返回看似通過的資源事件。

此處刻意限制 `verified_resource_ir` 只在 Rust 內部測試編譯（`#[cfg(test)]`），沒有對公開 CLI 擴張任何 P13／P16 來源語法。**這是 R03.2 第一個會在真正來源橋接執行的資料流／資源責任 IR，不等於所有 CFG、欄位移交或借用有效期的通用 IR 已完成。** 未通過最新 HEAD 必要 CI 前仍不得標記完成。

## 第十五批（R02.3）公開／私有 else-if 共同 AST 順序與合流入口

公開 MVP-A 解析器以 `IfChain { branches, otherwise }` 儲存平面分支；私有 P13 受限解析器以 `If { no: Some([If]) }` 遞迴表示 `else if`。二者在完全相同的合法 `.voil` 來源其實屬同一核准語意，不應因資料形狀不同而無法對照。修改共通 AST 投影：依原分支順序倒序收摺，生成一致的 `ScalarStmt::If` 階層，並保留有／無最終 `else` 的控制流程可達性差異。新增多段分支、缺少最終 else 的兩組逐結點正反回歸。**本批只改共同投影，不改任一正式解析器及 Checker，仍不得替未核准語法產生假的共用證明。**

## 第十六批（R02／R03 交界）共通 AST 的強型別來源身分

將共同 `ScalarStmt::Declare` 的裸 `usize` 來源起點正式收斂為已有的 `ownership_ledger::DeclarationId`。公開 P01 由 `Binding.start`、私有 P13 由 `Stmt.start` 建立同一型別的宣告身分；兩個投影仍必須比較整棵 AST 與各自原始來源位元組位置。新增內外詞彙作用域同名遮蔽測試，要求相同名稱仍有不同 `DeclarationId`，避免把名字或行號錯誤當作所有權資源識別。此型別也是前一批 `NamedResourceTransfer` 真正借用／資源帳簿 IR 使用的相同身分系統。

**不因身分型別共用就宣稱所有權、借用與函式／結構語意已統一。** P17 尚未驗收；既有公開 CLI、私有 Checker、資源清理順序及診斷文字不變。

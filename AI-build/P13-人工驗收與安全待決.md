# P13 人工驗收與 P13～P16 安全規格待決

**驗收定位**：P12 已可使用，P13 目前只是內部所有權狀態及多來源身分模型。手動測試通過不得視為 P13～P16 安全 Phase 已通過，也不得把尚未核准的 .move()／.borrow() 加入 MVP-A。

## 步驟一：確認 GitHub 合併與 CI 身分

1. 在 voiles GitHub 儲存庫確認最新 P13 PR 的 HEAD SHA。於該 PR 的 Checks 確認「文件與工作紀錄」「Rust 前端建置」「Rust 獨立架構測試」皆為 completed/success，且來源 GitHub Actions App ID 為 15368。
2. 確認 PR mergeable=true、mergeable_state=clean，再依既有規則使用 **Squash merge**。人工測試若是在合併前做，須檢查的是該 PR 分支而非誤認 main 已有成果。
3. 目前 GitHub CI 正式驗證 Linux x86-64；其他平台手測屬補充觀察，不能自行宣稱已正式支援。

## 步驟二：取得原始碼並在本機執行

需要 git、bash、rustup、Python 3；**不要求 Cargo 或第三方 Python 套件**。

```bash
git clone https://github.com/siyujellyfish/voiles.git
cd voiles
git fetch origin
git checkout main
git pull --ff-only origin main

```

若你已經在 voiles 專案資料夾，可從 git fetch 開始。若 PR 還沒合併，須切換到該 PR 的實際最新分支並記錄 SHA，不可把未合併分支當作 main。腳本會使用 Rust stable 重新編譯核心／CLI、執行正反例、驗證不支援 .move()、執行完整 Rust 核心測試，再生成並真正執行 P01 的 49 個正反語意案例和 1 個素材驗證；暫存結果位於 target/p13-accept。

## 步驟四：人工程式碼安全審查

1. 檢查 src/ownership_ledger.rs 的 DeclarationId：以各宣告原始來源位置區分身分，不應只靠同名字串；移動內層同名來源不能使外層來源失效。
2. 檢查 duplicate_to：CopyPermission::Undecided 和 Forbidden 必須拒絕，不應產生目的宣告，且不影響原來源。
3. 檢查 move_to：目標身分若已存在、來源不存在或未初始化，應拒絕且不得發生半完成的轉移。
4. 檢查 join_reachable：不同分支來源宣告身分集合必須一致，任一可達分支已移動，不能合流後假裝來源可讀；已 return 的分支可排除。
5. 檢查 src/lib.rs：沒有接入所有權模型改變原有 P01 check_file；P13 仍未具有可對完整語言宣稱安全的型別／借用／資源執行期檢查。

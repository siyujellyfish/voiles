# G18／P18.3、P18.4｜明確 str.move() 跨普通函式與遞迴真資源轉交（2026-11-06）

> 基線 main 5d241c30888e09bb546a93d236e80fdf1aa0c77c 三必要 CI success。原 Checker 已核准 HB13-A 整筆 .move()、P15.6 參數被消耗時呼叫者必須顯式轉交、VA16/OwnedStrRuntime 唯一 ResourceId，以及 AW06／D18-01 合法遞迴和可配置預算。本批**不制定新語言語意、不擴張公開 MVP-A**，六原項須完整驗收後才可 Passed。

## 原實際缺口

現有真 P18.3/P18.4 執行器已能以 BorrowTicket 跨多函式傳遞多個 str 的非擁有借用，卻無法執行 Checker 已核准的普通函式明確 str 整筆 .move()。預設借用不能假冒真正的所有權交接；此外原 P16 的 move_named 只在基礎作用域獨立驗證，缺少原 Parser Call→被呼叫參數消耗→執行／返回／故障的同一條真來源證據。

## 施工

- 直接在 src/struct_stage/execute_call_borrow.rs 增加以原私有 Checker 授權的整筆 move 呼叫圖分支，**使用同一原 OwnedStrRuntime、原 Parser AST、Lexer 真 token、P16 VerifiedTypedMember／DeclarationId／ScalarHIR**，並檢查整份 call_borrows 計畫。所有轉交一律須為真實 TermKind::Move(具名來源)，不能用 TermKind::Name 代替，亦不能把借用別名升為所有者。
- main 先建立唯一 UTF-8 所有者，再以已驗證具名 .move() 真進入函式；callee 按原簽章接管同一 ResourceId，允許直接返回 int、將 str 參數再明確移入當次局部唯一所有者、或在真正 return 中將所有權移交下一個函式。函式圖可為非循環、多層、合法直接遞迴；使用顯式迭代工作框架，不依賴 Rust 主機遞迴。
- 每次執行環境可配置 max_call_frames／max_steps，並可在主所有者建立後、任一真正 move 成功後測試注入故障。框架預算、步數預算、移動階段失敗與正常返回均由內到外離開真正 OwnedStrRuntime 作用域；來源 move 後失效、每次轉交只記錄 Moved(同一 ID)，最後持有者唯一 Released 一次。沒有任意資源複製，沒有假返回或幽靈釋放。
- 每次 execute 先重跑原 Checker 與整份準備計畫來源比對，變造已核准函式／返回方案／真 UTF-8 時，在首次真資源配置前拒絕；原 Checker 仍拒絕雙重 move、遺漏顯式 move、move 後再使用或借用別名轉交。
- 新十項真來源正反：單次轉交、參數轉局部、三函式連續轉交、合法直接遞迴受控耗盡、步數耗盡、每個轉交點故障、零預算零資源、Checker 重複移動／漏轉交拒絕、借用別名不可轉所有權、竄改來源零配置拒絕。獨立真 Gate 10／10，G18 原 P18.3、P18.4、P18.5 新增追溯及真執行群組。

## L01–L06 批次決策（2026-10-24）

- **L01-A**：非十進位整數的數字間允許連續多個底線（`0xFF__AA`），補充 K02。
- **L02-A**：進位前綴後可緊接底線（`0x_FF`），補充 K02 尚未確定的詞彙交界。
- **L03-A**：浮點常值結尾允許底線（`1.25_`）。
- **L04-B**：浮點小數點之前必須有數字；`.5` 不合法，`0.5` 合法。
- **L05-A（詞彙外觀已確認）**：`1.` 是表示 `1.0` 的合法浮點常值。**與 D04 `1..4` 的詞彙切分／優先方式仍未確認**。須明確保留既定區間語意；不得自行實作最長匹配、語法優先或特例。
- **L06-B**：一般字串常值僅允許雙引號；單引號字串 `'hello'` 不合法。三重雙引號仍作為既定多行註解標記，字串／註解詞彙界線另決。
- 保留其他 S／D／E／F／H／I／J／K 已確認規格，尤其 D04 的不含尾端區間、I04 decimal64 捨入未決、D11 Optional 容器方向未決。

## K01–K06 批次決策（2026-10-23）

- **K01-B**：整數進位前綴限小寫 `0x`、`0b`、`0o`；`0X`、`0B`、`0O` 不視為合法前綴。
- **K02-A**：非十進位整數常值**數字之間**允許底線，如 `0xFF_AA`；是否允許連續多個底線、前綴後緊鄰底線仍待決。
- **K03-A**：十進位整數允許前導零，`007` 等於 `7`，不導出八進位語意。
- **K04-A**：float 常值允許連續多個底線，如 `1__000.25`。
- **K05-A**：float 常值允許底線緊鄰小數點，如 `1_.25` 與 `1._25`；尚未裁決開頭或結尾底線。
- **K06-B**：`struct` 宣告至少有一個欄位或方法，`struct Empty{}` 應拒絕。此限制與 J06 語句區塊不得空分開，不擴及空容器或其他 `{}` 語法。
- 六項與現行 `struct` S01–S21、I03/J01–J06 整數／浮點數規則相容；D11 Optional 及 I04 decimal64 預設捨入、所有權與借用細節仍未決。

## J01–J06 批次決策（2026-10-23）

- **J01-B（後續 K02 擴充範圍）**：整數常值可連續底線且須位於數字間；K02 已確認非十進位數字間也可使用底線，但非十進位底線**是否可以連續**仍未決。
- **J02-A（後續 K01/K02 明確化）**：支援十六、二、八進位常值；K01 已確認進位前綴只能小寫，K02 已確認非十進位數字間可使用底線。前綴旁與非十進位連續底線細節待決。
- **J03-B**：float 常值不支援 `1.2e3` 等科學記號。
- **J04-A（已由 K04/K05 補充）**：float 可有底線；K04 確認可有連續底線，K05 確認底線緊鄰小數點合法（如 `1_.25`、`1._25`）；其他邊界待決。
- **J05-A**：`#` 可作為程式碼之後的行尾註解；字串與註解邊界尚待詳細文法。
- **J06-B（K06 獨立新增 struct 要求）**：語句區塊至少有一條有效語句；K06 另要求 struct 宣告至少一個欄位或方法。兩者均不決定空容器字面值是否合法。
- 六項與既定 I03 整數底線、F06 空白行忽略、J02 int 範圍及 decimal64 格式相容；S、D、E、F、H、I 原決策不變，I04 與 D11 繼續未決。

## I01–I06 批次決策（2026-10-23）

- **I01-A**：一般 const 變數須明確型別標註，原 E06 立即初始化規則保留；例如 `const x:int = 3`，不得 `const x = 3`。
- **I02-A**：share 變數須明確型別標註，原 H04 立即初始化規則保留；例如 `share count:int = 0`，不得 `share count = 0`。
- **I03-A 與 J01-B 後續更新**：整數常值可使用底線，J01 已確認連續多個底線合法但底線群組須位於數字之間。非十進位底線與進位前綴交界仍待議。
- **I05-A**：一般 var 允許 `var x:int` 宣告後再賦值；讀取前須通過靜態初始化檢查。I05 不自動決定結構實例 `var s:Stru` 省略建立式是否合法、分支／迴圈初始化分析與借用安全。
- **I06-A**：不相等比較運算子採 `!=`，不採 `<>`；完整比較運算元型別和結果語意仍待決。
- **I04 未選**：decimal64 預設捨入候選為「取最近值、平手取偶數」（建議）與「朝零捨去」，只有解釋，沒有使用者的選型同意。
- **相容性**：I01/I02 延續 H03、H04 的宣告設計；I05 保留 H03 必須型別標註且不修改 struct S07 或 F01 規格。既有 S、D、E、F、H 批次已確認內容保持有效。

## H01–H06 批次（2026-10-23）

- **H01-B**：`float` 為 IEEE 754 十進位 `decimal64`（16 位十進位有效數字），**完成 F04**；具體捨入模式、編碼與特殊值仍待議。
- **H02-A**：函式宣告參數列表尾逗號合法，F05 原已確認的函式呼叫尾逗號維持。
- **H03-B**：一般 `var` 變數宣告一律必須標註型別；不再將一般 `var` 型別推導列為待決，也不據此補定 `share` 類的標註規則。
- **H04-A**：`share` 必須宣告時初始化，未初始化的 `share` 宣告屬錯誤。
- **H05-A**：同一作用域不可重複宣告同名變數，違反時為靜態錯誤；跨宣告類別共用名稱空間的精確範圍待決。
- **H06-A**：內層可遮蔽外層變數；遮蔽與借用、所有權、可變性、生命週期的安全交互待決。
- **相容性**：六項彼此相容，未修改 S01–S21、D01–D13、E01–E07、F01–F06 的其他已決語意；D11 Optional 問題獨立未決。


## F01–F06 批次（2026-10-23）

- **F01-A**：明確修訂 D09-A；struct const 欄位宣告時必須指定預設值，例如 `const id:int = 0`。禁止延後首次寫入；S07 只對 var 欄位保留延後初始化。
- **F02-A**：const 結構實例變數宣告時必須有初始化運算式，例如 `const u:User = User()`；不據此宣稱其中所有 var 欄位均已初始化。
- **F03-A**：int 溢位能靜態判斷則靜態報錯，其餘執行時報錯；確切分析範圍及錯誤型別待定。
- **F05-A**：一般函式呼叫允許尾逗號，例如 `add(1,2,)`；函式宣告參數表尾逗號未決。
- **F06-A**：忽略空白行。
- **F04 歷史記錄**：此批原本未選浮點格式，但**H01-B 後續已明確選用 IEEE 754 `decimal64`**，不再作為未決選型。
- **其他未決**：const 結構實例中仍未初始化的 var 欄位、S18 遞迴不可變與可變借用交會；D11 的 Optional 容器提議亦保持未決。

## E01–E07 批次（2026-10-23）

**原始 E 批次狀態（後續 F 批次已進一步修訂）**：E01 有號 64 位元整數、E02 溢位必須報錯（F03 已決定何時報錯）、E03 64 位元 float（F04 格式未選）、E04 未知欄位靜態錯誤、E05 具名尾逗號、E06 一般 const 必須初始化（F01/F02 已擴充）、E07 圓括號內允許跨行。

**E06 的 struct 擴充衝突（歷史，已由 F01/F02 解決）**：

- **原 D09-A** 曾允許未初始化的 struct const 欄位延後首次寫入；**F01-A 已明確修訂，此條不再生效**。
- **使用者已確認 F01/F02**：struct const 欄位宣告時必須有預設值；const 結構實例變數宣告時必須提供初始運算式。
- **現行處置**：已取得使用者明確授權改動 D09，S07 對 var 欄位的延後初始化及 S06 空建立仍有效；const 實例與其中尚未初始化 var 欄位的權限及 S18 交互仍待確認。

**其餘待補細則（依最新 H01 更新）**：F03 已確定溢位報錯時機，錯誤型別未決；F04 的二進位／十進位選型已由 H01-B 選定 `decimal64`，其捨入及特殊值仍未決；其他續行與 D11 Optional 容器範圍提議維持未決。

## struct 批次決策狀態（2026-10-23）

**最初確認、原決策未變動的 19 項**：S01-A、S02-A、S03-A、S04-B、S05-A、S06-A、S07-B、S08-A、S09-A、S10-A、S11-B、S13-A、S14-A、S16-A、S17-A、S18-B、S19-A、S20-B、S21-B。完整原文與適用範圍記於 [語言規格-v0.2.md](語言規格-v0.2.md)「三之一、struct 批次決策」。

**後續裁決完成的 2 項**：

- **S12（原方案 A 經使用者指定的衝突處理方案 A 修訂）**：`self` 只允許借用；取消原先「明確指定時才移動 `self`」的條款。不得將 `self` 作為可被方法消耗的移動接收者。
- **S15-B（維持）**：方法不允許消耗整個 `self`。
- **不受影響**：仍允許在方法呼叫以外，依既定通用所有權規則明確移動**整個**結構實例；S21 禁止只移動單一欄位。
- **結論**：S01–S21 共 21 項現在均有一致的已確認決策；不因此自動補齊借用可變性、生命週期、例外路徑與非同步安全細則。

**其他後續細則（非本批次選項衝突）**：

- S05–S09：S06 空建立有效，S07 延後初始化只適用 var 欄位；F01 要求 const 欄位宣告時有預設值、取消 D09 延後首次寫入；D08 具名引數覆蓋預設值時不求值，其他求值時序待議。
- S11／S14／S17：`self` 不列於參數表、方法結束歸還借用、跨 `await` 及失敗路徑的靜態安全檢查。
- S19／S21：各欄位是否 `Copyable`、複製深度、整體移動後的有效狀態與資源處理。
- S20：允許方法按參數簽章多載，但如何比較簽章、選擇多載、處理相同簽章及同名欄位仍需更完整規則，既定的欄位／方法同名禁令保持有效。

## 已確認且無須重複選擇

- 例外使用 `except`；`exception` 為筆誤。
- `fn`、`async fn` 與 `struct` 方法預設公開；名稱以 `_` 開頭者為模組內部函式／方法，同模組的其他函式或結構可呼叫，跨模組不可呼叫；不需要 `share fn`。
- `struct` 方法內存取自身欄位必須明確寫成 `self.欄位名稱`；S11 已確認 `self` 自動提供且不列在方法參數表，S14 已確認方法借用離開方法時歸還。S12／S15 已裁決方法 `self` 僅能借用、不可消耗整個 `self`，完整借用權限、可變性及非同步安全細則仍待確認。
- `struct` 的欄位與 `fn` 方法直接宣告在同一個結構區塊內，不另設 `impl` 或其他外部方法實作區塊。
- `struct` 欄位採方案 B：一般名稱預設公開，`_` 前綴欄位僅模組內可見；與函式、方法的模組可見性規則一致。這是存取範圍規則，不改變欄位可寫性或其他安全語意。
- 同一個 `struct` 的欄位與方法共用名稱空間，採方案 A：若欄位與方法同名，編譯器應回報名稱衝突；不自行擴張至其他同名、過載或解析規則。
- `struct` 型別名稱採方案 A：不含 `_` 前綴的結構預設公開；`_` 前綴結構只能於同一模組引用，不能由其他模組使用。
- 結構實例的 var 變數宣告須明確型別，例如 `var s:Stru = Stru()`。F01 要求 struct const 欄位在宣告時有預設值；F02 要求 const 結構實例變數有初始運算式；S07 延後初始化只適用 var 欄位；方法 self 只允許借用不可消耗，其餘借用可變性及安全規則未決。
- 一般借用至借用變數最後一次使用；函式借用在執行離開函式作用域歸還。
- `Optional` 同時具有多型別聯集與缺失值語意。
- 字串索引：先字元，後 UTF-8 位元組。

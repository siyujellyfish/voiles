## BE01～BE06 首版 Rust 前端 EOF、UTF-8 字元及核心介面（2026-10-25）

- **BE01-B**：首個 Rust 前端遇到**檔案結尾（EOF）需指出來源錯誤且原始檔中確實至少存在一個來源字元時**，採**最後一個存在的來源字元之完整原始來源範圍**指出該錯誤，**不**使用 EOF 後一欄的零長度範圍作為本情境診斷位置。來源範圍仍依 BC01／BD01 以**從 0 起算、起含終不含的原始位元組偏移**保存，對外換算成 AW05 從 1 起算的原始 UTF-8 位元組行／欄半開範圍。**來源為空檔案而沒有最後字元時如何定位仍未決**；若最後物理字元屬於 CRLF，完整 CRLF 邏輯換行的來源範圍依 BD02 必須涵蓋 CR 與 LF、一次換行，但**不得自行推斷該診斷一定採整個 CRLF 或 LF 的個別字元範圍**，其特殊邊界仍待核准。也不決定 EOF 以外語法錯誤定位、非法位元組替代標記作最後來源時的詞法與復原、行索引或 AST 節點內容。
- **BE02-B**：首個前端遇到**非法原始 UTF-8 位元組造成的專用無效標記**時，先依 BA02／AZ03 **每一非法原始位元組各報一項詞彙錯誤並保留其對應替代標記**，依 BD03 **語法階段辨識、略過標記後嘗試繼續解析**。**如果後續語法分析確實發現與該來源詞彙錯誤不同、可安全辨識的獨立語法錯誤，允許另外提出語法診斷**；但**不得因同一非法來源位元組或略過同一標記而重複報告相同詞彙錯誤**，也不能將非法標記兩側字元跨標記拼成合法記號。與 AX05 安全續行及 BC03 原則依來源排序／AQ06 特殊優先規則並行。本項**不強制一定能繼續或一定產生額外語法錯誤**，不自定診斷去重演算法、同位置次序、句法復原同步點或具體錯誤文字及標記資料型別。
- **BE03-B**：首個**單檔 Rust 前端**對**來源檔中原本以合法 UTF-8 位元組直接編碼出現的 U+FFFD 字元**，**另列為首版不接受的來源字元**，不可因此構成首版合法詞彙或利用原始字元身分繞過不接受限制。這與 AZ03／BA02／BB02 對**非法原始位元組替換而成的 U+FFFD 專用無效標記**不同：後者繼續每位元組替換及各自詞彙錯誤、保留專用標記供復原。**完整語言已核准的 `\u{...}` Unicode 跳脫在特定不合法內容時代入 U+FFFD 的 T02／T03／V02／Q02 等處置仍維持**，本項只限制首個前端的**原始來源字元**，不得自行將其擴張到跳脫解碼所得字元或變更完整語言規格。對該合法編碼但首版不接受字元的**具體錯誤分類、文字、是否續析或復原方式**，以及其他 Unicode 字元／字串詞法仍未決；不可把它誤記為「無效 UTF-8 原始位元組」以觸發 BA02 每位元組錯誤或逐位元組替代。
- **BE04-B**：首個 Rust 前端**核心程式庫 `voiles_core` 供獨立測試及 CLI 使用的單一前端檢查操作**，其來源輸入形式選為**單一 `.voil` 檔案路徑，由核心負責讀入原始來源**，並在內部依已核准的原始位元組／非法 UTF-8 處置與來源範圍規則處理；不改變 BC06-A 僅對測試提供一項前端檢查操作介面或 BB06-B 先以 rustc 編程式庫再供獨立測試連結。**不核准另外公開接受原始位元組的檢查介面**。此選擇不決定 Rust 路徑參數具體型別、相對／絕對路徑、檔案 IO 失敗的**核心結果表示**、CLI 如何從核心取出錯誤、錯誤字串／診斷無位置時的結構、檔案讀入方式、測試暫存檔與權限、安全／所有權及公開 API 穩定性；CLI 使用 BA04 單一位置路徑引數、BC05／BD04 檔案不可讀退出 `1` 且 stderr 分類文字的外部行為仍有效。
- **BE05-A**：首個 Rust 前端**核心 `voiles_core` 的單一檢查操作結果**，選擇**同時提供檢查是否成功的明確狀態，以及可取得的診斷集合**；沿用 AX05 在能安全分析時得收集多項獨立錯誤、BA02 各非法原始位元組必報詞彙錯誤、BC03 一般來源排序與 AQ06 特例優先，以及 BB04 診斷對外由 CLI 透過 stderr 呈現的規則。這只核准**語言前端檢查結果的概念資料**，不自定 Rust `bool`／`Result`／enum 等具體型別、診斷資料結構／封裝或排列、公開 API 函式名稱、錯誤時 AST 是否保留、何種警告影響成功、檔案 IO／命令用法失敗是否及如何表現在此資料，亦不據此修改 BB05 靜態檢查 CLI 成功 `0`／失敗 `1` 或 BC05／BD04 IO 失敗退出 `1` 的外部規則。
- **BE06-A**：首個 Rust 前端在**GitHub 提供的 Linux x86-64 CI 執行器**執行建置／測試驗收時，**必須在 CI 紀錄輸出 `rustc --version` 的結果**，供確認當次實際使用的 Rust 編譯器版本；沿用 AT06-A **建置時可用穩定版 Rust，不釘固定或最低版本**、AZ06-B **直接 rustc 編譯＋Rust 內建測試**、BB06／BD05 Rust 核心庫 `voiles_core` 先建再連結獨立測試、AY06-A **前端建置與自動測試必須通過**，及 BD06-A GitHub 託管 Linux x86-64 runner。此項**只補定版本記錄命令**，不另要求 `rustc -vV`、不選 runner 映像標籤／固定版本、Rust 安裝方式、rustc 核心與測試的完整命令／旗標、快取、測試案例、格式或靜態程式碼風格檢查，也**不替代現有 PR 最新 HEAD「文件與工作紀錄」必要 CI completed/success 的合併門檻**。

- **仍未決**：空來源的 EOF 定位、CRLF 尾端／中間位置顯示、合法 UTF-8 U+FFFD 首版拒絕的錯誤分類與復原、與非法替代標記的去重機制和其他詞法、完整診斷模板／同位置順序、單一 Rust 檢查 API 的路徑參數與結果具體型別、檔案 IO 失敗如何表示、CLI 額外使用行為、完整 rustc 建置／測試連結命令、runner 具體映像及更多測試證據。BE 各項皆只按其合法首版使用位置核准，不更改 AR04 Phase 原依賴及已核准資源／所有權規則。

## BD01～BD06 首個 Rust 前端來源端點、錯誤復原、CLI 與 CI（2026-10-25）

- **BD01-A**：首個單檔 Rust 前端**內部原始來源位元組起點與終點偏移以 `0` 為起算基準**；保留 BC01-A 起點包含、終點不包含的原始位元組半開區間。有效解碼字元跨其實際原始位元組，非法原始來源位元組所產生的專用替代標記仍各自對應原始單一位元組。依 AW05-B 對外診斷及必要 AST 來源位置時，**另轉換為從 `1` 起算的原始 UTF-8 位元組行／欄半開範圍**，不能將內部 `0` 起算位元組偏移原樣顯示為對外欄位。本項只核准偏移起算，不自定資料型別、CRLF 中間的特殊端點、檔尾／零長範圍的換算、行索引構造、錯誤訊息或各 AST 節點清單。
- **BD02-A**：首個 Rust 前端在表示**完整 CRLF 邏輯換行的來源範圍**時，該半開原始位元組範圍**必須同時涵蓋 CR 與 LF 兩個原始位元組**；依 BD01-A 內部採從 `0` 起算的原始位元組偏移，仍維持 BA01-A CRLF **只算一個邏輯換行**，其來源跨兩位元組。單獨 CR、單獨 LF 各仍是合法的一次換行；BC01 字元／來源範圍與 AW05 一基行欄要求不變。此決策只針對**整個 CRLF 的完整換行範圍**，不自行指定 CR 與 LF 各別字元跨度之內部呈現、CRLF 中間端點如何折算成對外行／欄、檔尾特殊位置、註解與字串內換行或行索引演算法。
- **BD03-A**：首個前端在**語法分析階段**遭遇 BC02-B 先前保留的**專用非法原始 UTF-8 替代標記**時，**保留該標記及其來源範圍供錯誤處置辨識，略過該標記並嘗試接續解析後續內容**。這**不**代表詞彙階段可以提前刪除該專用標記：BC02-B「保留供後續辨識」與 BB02-A「不得構成合法詞彙」仍有效；BA02-A 每非法原始位元組都必須各有獨立詞彙錯誤、AZ03-A 每非法位元組各一替代標記，不能因語法階段略過便取消、合併或將標記兩側文字跨越標記拼接為單一合法記號。**僅核准遇標記時嘗試接續的復原方向**，不得自動保證一定可安全解析後續語句、必須收集全部後續錯誤、增加同一原始原因的額外重複診斷，或自訂解析同步邊界、AST 遺失節點、同位置排序與其餘詞法復原細節；其餘多錯分析仍受 AX05-B 安全續行要求及 AQ06 既定優先序約束。
- **BD04-A**：首個 `voiles` CLI 對**缺少或多餘來源檔案位置引數的命令用法失敗**，以及**指定檔案不存在／無法讀取的 IO 失敗**，都**輸出人類可讀的錯誤文字至標準錯誤輸出（stderr）**，並在文字中**區分用法失敗與 IO 失敗類別**；仍依 BC04-A／BC05-A 使用退出碼 `1`。這兩種錯誤不是受檢來源內的語言詞彙／語法／靜態錯誤，**來源檔尚未合法讀入時不得虛構來源行／欄**；BA03-A 對可定位的語言診斷須含檔案與一基原始 UTF-8 位元組行／欄的規則仍有效。僅核准失敗時的**輸出通道、可讀形式與兩類可辨識性**，不自定診斷字串模板、用法指令範例、來源檔路徑字串格式、是否有顏色、錯誤識別碼、其他種類的 CLI 選項失敗、其它 OS／IO 異常及回復策略。
- **BD05-B**：首個 Rust 前端**核心程式庫的 Rust 識別名稱選為 `voiles_core`**；沿用 BB06-B 先以 `rustc` 將核心編成可連結的 Rust 程式庫、再由獨立測試原始碼引用及執行 Rust 內建測試的順序，以及 BC06-A **測試只可引用一項前端檢查操作介面**的限制。此處只核准**程式庫識別名稱**，不等同確定輸出檔名、crate 類型、對外公開穩定 API、函式名稱／參數／回傳結構、模組可見性、CLI 如何引用核心、`rustc` 旗標、資料夾配置、其他依賴或正式後端目標。CLI 執行檔名稱仍依 BB03-A 為 `voiles`，兩者不可混同。
- **BD06-A**：首個 Rust 前端的 **Linux x86-64 CI 驗證，使用 GitHub 提供的 Linux x86-64 執行器（GitHub-hosted runner）**，不要求專案自行管理此驗證執行器；沿用 AV06-A Linux x86-64 目標、AT06-A 建置時可用的穩定版 Rust、AX06-A 核心只用標準函式庫、AZ06-B 直接 `rustc` 及 Rust 內建測試、AY06-A CI 須建置成功及自動測試通過。此項僅決定**首個前端 CI 執行器的供應來源與目標架構**，**不**指定 runner 映像標籤／固定映像版本、Rust 確切版本或最低版本、下載與安裝工具方式、版本記錄輸出、rustc 編譯與連結指令、測試目錄與快取／逾時等設定；更不能取代現有 PR 最新 HEAD 必要「文件與工作紀錄」檢查的合併門檻，或視為現在已執行前端建置／測試。

- **尚待核准**：完整 CRLF 中間位置／EOF 等對外一基行欄映射、字元索引資料結構、合法原始 U+FFFD 的詞法、略過無效標記後的安全同步邊界與多錯去重、診斷文字模板與同位置優先順序、CLI 其他未知選項與檔案路徑細節、唯一核心前端檢查函式的 Rust API 簽章與 crate 類型、rustc 建置／連結命令、runner 具體映像與 Rust 版本記錄、AST 內容與所有權／安全。未決內容不得因本批決策自動補定；AR04 原階段依賴保持。

## BC01～BC06 首版 Rust 前端來源偏移、診斷排序與單一檢查介面（2026-10-25）

- **BC01-A**：首個 Rust 前端的**解碼後字元／非法來源替代標記所附原始來源範圍在內部以原始檔位元組起點偏移與終點偏移表示，起點包含、終點不包含**。保留 BB01-A 每個有效字元及每個非法原始位元組替代標記的一對應原始跨度；有效 UTF-8 字元以其實際原始位元組長度計，非法來源標記以其對應**一個原始位元組**為範圍，不使用 U+FFFD 編碼後長度代替原始來源長度。**需要對外診斷或 AST 來源位置時再換算成 AW05-B 從 1 起算的行號／原始 UTF-8 位元組欄位半開範圍**，並沿用 BA01-A CR、LF、CRLF 各計一個邏輯換行且 CRLF 保留兩原始位元組。尚**未**決定原始位元組偏移從 0 或 1 起算、整體 offset／行索引資料結構、CRLF 中間端點／EOF 等特殊位置的換算規則、Tab 與跨行／非法 UTF-8 診斷文字細節；不得誤把內部位元組偏移當成對外一基欄位。
- **BC02-B**：首個 Rust 前端詞彙處理時對**非法原始 UTF-8 位元組產生的 U+FFFD 替代標記保留可供後續階段辨識的專用無效標記**，而不直接把它當成合法詞彙或完全丟失，並**繼續處理其後來源及記號**；標記仍攜帶 BB01／BC01 已核准的原始單位元組來源跨度。**BB02-A 明定該替代標記不得構成任何合法詞彙**，BA02-A 明定每非法來源位元組各產生一項詞彙錯誤，這兩條均須同時成立；前後文字不得跨越無效標記被錯誤拼成單一合法記號。此項僅選定**專用無效標記的保留方向**，不自訂標記資料型別、放置於記號序列或其他資料通道、與下一階段的傳遞界線、語法復原與重複診斷去重策略，亦不判定**原始合法 UTF-8 的 U+FFFD**本身是否為合法詞彙。

## AW01～AW06 首版 Rust 前端算術、前向讀取、來源座標及遞迴（2026-10-25）

## 已確認且無須重複選擇

- 例外使用 `except`；`exception` 為筆誤。
- `fn`、`async fn` 與 `struct` 方法預設公開；名稱以 `_` 開頭者為模組內部函式／方法，同模組的其他函式或結構可呼叫，跨模組不可呼叫；不需要 `share fn`。
- `struct` 方法內存取自身欄位必須明確寫成 `self.欄位名稱`；S11 已確認 `self` 自動提供且不列在方法參數表，S14 已確認方法借用離開方法時歸還。S12／S15 已裁決方法 `self` 僅能借用、不可消耗整個 `self`，完整借用權限、可變性及非同步安全細則仍待確認。
- `struct` 的欄位與 `fn` 方法直接宣告在同一個結構區塊內，不另設 `impl` 或其他外部方法實作區塊。
- `struct` 欄位採方案 B：一般名稱預設公開，`_` 前綴欄位僅模組內可見；與函式、方法的模組可見性規則一致。這是存取範圍規則，不改變欄位可寫性或其他安全語意。
- 同一個 `struct` 的欄位與方法共用名稱空間，採方案 A：若欄位與方法同名，編譯器應回報名稱衝突；不自行擴張至其他同名、過載或解析規則。
- `struct` 型別名稱採方案 A：不含 `_` 前綴的結構預設公開；`_` 前綴結構只能於同一模組引用，不能由其他模組使用。
- 結構實例的 var 變數宣告須明確型別，例如 `var s:Stru = Stru()`。F01 要求 struct const 欄位在宣告時有預設值；F02 要求 const 結構實例變數有初始運算式；S07 延後初始化只適用 var 欄位；方法 self 只允許借用不可消耗，其餘借用可變性及安全規則未決。
- 一般借用至借用變數最後一次使用；函式借用在執行離開函式作用域歸還。
- `Optional` 同時具有多型別聯集與缺失值語意。
- 字串索引：先字元，後 UTF-8 位元組。

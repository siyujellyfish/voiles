# G18／P18 V7 A1／E2：原私有 Checker 計畫持有式來源目錄（2026-11-09）

> 基準為 PR #713 Squash merge 後的 main 4e6bd0ead3deefb8db4094c3166ce37e4359e009，同一 SHA 三必要 CI completed/success。這批把原 Checker 已核准的真來源擁有權放入 Rust 安全的、可穩定借用的目錄，再讓 #713 FIFO 協作排程器以原計畫的穩定身分交付真續行。**不是**一個透過自我參照持有所有來源與 checkpoint 的單一物件，亦不是一般公開 async 執行期。P18.1～P18.6 正式 0/6 Passed，V0 26 義務尚待逐項結案。

## 起因與真正改動

在前一批 #713 中，PrivateScalarCooperativeQueue<'a> 已有多工作 ID／明確 wake／FIFO 驅動／真 await 動態 checkpoint／P16+HC14 取消與 E5 安全點重驗，但計畫生命週期仍由每個呼叫端自行保管，未有集中的原 Parser／Checker 來源持有者。不能以裸字串再次重新解析與重跑已執行來源，也不能在一個持有式 Vec 中放入依賴自己的 Rust 引用而使用 unsafe 自我參照。

新增 **PrivateScalarCheckedProgramCatalog**：用 BTreeMap<計畫ID, Box<PreparedPrivateScalarCall>> 持有原 Parser／Checker／TypedHIR／已核准函式圖。Box 的堆配置不因 BTreeMap 插入／擴容而改變計畫位置；真正來源修改仍受 Rust 編譯期唯一可變借用限制。這是「持有來源目錄＋借用式單執行緒工作排程器」的安全分層，不是新 Checker 或第二套 Runtime。

## 工程規則

1. catalog.prepare(source)：先走唯一 PreparedPrivateScalarCall::prepare 驗證原始 UTF-8／Checker，並且由原 PrivateScalarGraphContinuation::new 驗證可續行工作圖形狀（已核准 main 動態工作圖或既有直接 Copyable int 快路）。非法來源及尚未經原 Checker 證明可續行的直接快路**不得**消耗目錄 ID；原 Checker 已完整核准的 bool 動態 main 圖則必須保留合法入口，不得因 int-only 快路限制而錯誤拒絕。
2. 成功後由目錄單調分配計畫 ID，真正 Box 存入同一份已簽核計畫。ID 達上限拒絕，不回繞、不污染現有登錄；查詢只給不可變借用。
3. queue.submit_program(&catalog, program_id)：先核對真來源 ID 存在，才經既有 queue.submit 使用原 PrivateScalarGraphContinuation::new 交付真動態工作。未知計畫 ID 不消耗 FIFO 工作 ID；不以字串搜尋冒充身分。
4. 同一份原 Checker 來源可透過**不同工作 ID**建立兩份彼此獨立的 checkpoint／真 P16 OwnedStrRuntime／HC14 BorrowSafety：其中一份正常完成、另一份安全取消，都由各自原資源帳發出真 Created／Released。原計畫本身不可被正在執行的工作修改或移走。
5. 在排程器仍借用來源目錄時，Rust 生命週期規則阻止目錄被可變修改或釋放；排程器工作真正結案且 Rust 作用域結束後，目錄仍可繼續接受新來源，不需 unsafe 或全域變數。
6. 原 #713 的 drive_one／wake／cancel 及全祖先 BorrowTicket 安全重驗完全照舊；工作只在呼叫端明確驅動時執行，沒有背景工作／spawn／作業系統執行緒，也不引入新的語言錯誤或資源釋放路徑。

## 七項真 Parser／Checker→Runtime 正反

新增 struct_stage::g18_v7_checked_program_catalog_tests，由 tools/核對G18-V7原Checker來源持有登錄.py 在必要 CI 對原 Rust 內部測試執行檔逐項 --exact：

- 原 Checker 已核准來源保存在真正 Box 目錄，排程前、中、完成後皆用 std::ptr::eq 確認**同一計畫身分**，沒有複製 AST／重建準備計畫；真 await 成功返回原值。
- 靜態型別非法來源不消耗任何目錄 ID；原 Checker 合法 bool 主動態圖可真正登錄並執行，第一份合法計畫得到 ID 1，後續 int 來源得到 ID 2，不能錯將 bool 動態圖混入 int-only 快路拒絕。
- 未知 program_id 不得占用 FIFO 工作 ID、改變原待排程順序。
- 同一登錄來源提交兩份不同真正工作，兩份都真正 await 暫停；其中一份真取消、另一份真恢復成功，兩份各自 HC14/P16 清理而不相互污染。
- 兩份目錄登錄來源分別走原整數溢位與安全點取消，沿唯一既有退出流程保持真資源清理與零假成功 Returned。
- 計畫 ID 耗盡保守拒絕，已登錄計畫仍可照常排程。
- 工作作用域結束、釋放目錄借用後才能再安全登錄下一份來源，完整核對身份及新真結果。

這七項是在 #713 原真 FIFO 八項、#710～#712 checkpoint／快路／取消十五項及全部 F00／G6／G17／G18 R07 正式 Gate **之上追加**，不降低或移除任何原有安全關卡。

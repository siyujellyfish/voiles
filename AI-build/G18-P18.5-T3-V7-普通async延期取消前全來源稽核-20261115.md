## 原實際缺口

普通 async 真執行器 `PreparedPrivateScalarCall::execute_with_budget_and_fault_scheduler` 在建立真動態資源／BorrowTicket 之前，原已嚴格驗證 `original` UTF-8 位元組、**封存的原 Lexer Token**、`VerifiedPrivatePlan::is_consistent`、`matches_source` 後重新產生的原 Checker/Parser／TypedHIR/FunctionExit/ControlEdge 完整計畫。因此來源如 `main_dynamic_call`、`callee_name`、原 await token 或原 bytes 遭私有層變造，真 `execute` 會在任何動態操作前拒絕。

但小型 `PrivateCheckedDeferredAwaitQueue::suspend` 與 `cancel` 原本只看 Prepared／Suspended 狀態；`cancel` 會直接清空 `job.plan`。若封存工作被變造且在尚未喚醒前取消，偽造證據可能消失；若其它工作已被污染，仍可能允許不同合法工作先執行。此守門與真正執行的原 Checker 權威分岔，屬 T3 來源一致性與 E3 取消前原子性缺口，不是重新要求使用者決策。

## 具體修補

1. `src/struct_stage/execute_call_scalar.rs` 新增 `PreparedPrivateScalarCall::checked_source_still_intact()`，**只提取原 `execute_with_budget_and_fault_scheduler` 完全同一份**原 Lexer／Checker／TypedHIR 來源守門；`execute` 仍必先通過此唯一權威，預檢不建立動態 ResourceId、BorrowTicket、FunctionEntered 或結果。
2. `PrivateCheckedDeferredAwaitQueue::verify_pending_sources` 逐一核對整個佇列全部尚存的 Prepared／Suspended 工作，而不是只核對目前選定 ID。待啟動工作必保持其未完成狀態、唯一 plan、沒有 Outcome，且同一完整 Checker 來源有效；Succeeded／Failed 必持有已平衡真結果、與成功身分一致且無計畫，Cancelled 必無原計畫或 Outcome，Running 不得冒充穩定安全點。此函式不修改佇列。**任何有一份污染，其餘合法工作也不得先消耗、取消、喚醒或配發新 ID。**
3. `prepare`、`suspend`、`cancel`、`wake` 都在狀態、工作 ID、執行器開始、計畫清空之前先重驗；`prepare` 返回既有 `Unsupported`，其餘使用既有 `SourceChanged`，沒有引入語言新異常。原 `next_id.checked_add(1).expect` 改成 `ok_or(Unsupported)`，確保 u64 工作 ID 耗盡拒絕而非 Rust panic，無回繞簽發重複身分。
4. 保留已合法完成 Outcome 的 P16 真 `Created/Released` ResourceId 事件、原 Unwind／R05 平衡；取消**尚未開始**的工作仍零假事件，不將同步普通函式當 async。此小型佇列不是已完備的所有工作協作式調度器，仍須以原 `PrivateScalarCooperativeQueue`／跨框架續行獨立驗收才可能正式關閉 A1/A2。

# voiles 現行語言規格（新版草案，尚未封閉）

> 最後調整：2026-10-24。本文件是**新版 voiles 語言規格的權威草案**，以使用者 2026-10-23 起的明確決策為準。舊版 v0.2／2026-10-10 P01 的具體語言設計不再作為規範；檔名暫保留以維持既有索引。**本文件優先於舊合併請求與舊範例**，未列為已確認的事項以 [待確認事項.md](待確認事項.md) 為準。文件僅記錄規劃，不代表功能已實作、規格已封閉或範例可執行。

## 一、型別與容器

- 基本型別：`int`、`float`、`str`、`bool`、`none`。
- **D06-A、E01-A、E02-A、F03-A**：`int` 為**有號 64 位元整數**，允許負數；運算超出此範圍時必須報錯，不得靜默回繞或截斷。**能在靜態分析時確定溢位，就在編譯／靜態檢查階段報錯；其餘在執行運算時報錯。**靜態常值計算能力的界線、錯誤型別／訊息及轉型規則仍待確認。
- **I03-A、J01-B、K03-A**：十進位整數常值可用 `_` 分隔數字，連續多個 `_` 合法，但須位於數字之間，例如 `1__000`。**K03-A** 允許十進位常值前導零，`007` 與 `7` 值相同。底線與數值進位前綴交界、帶前導零常值的其他詞彙細則仍待獨立確認。
- **J02-A、K01-B、K02-A、L01-A、L02-A**：整數支援十六、二、八進位，且只允許小寫前綴 `0x`、`0b`、`0o`。數字之間可以有**連續多個底線**（例如 `0xFF__AA`，L01），進位前綴後**允許直接接底線**（例如 `0x_FF`，L02）。J01 在數字之間的原限制對此兩項已有明確新增許可；整數常值其他開頭／結尾底線、進位數字合法性以外的詞彙邊界及錯誤復原待決。有號 64 位元 `int` 與溢位規則不變。
- **E03-A、H01-B、T06-A（完成 F04 與 I04）**：`float` 固定 **64 位元**並採 **IEEE 754 `decimal64`**（16 位十進位有效數字）。**T06-A** 已明確選定預設捨入為**最接近可表示數值，恰好落在兩數正中間時選擇尾數為偶數者**（nearest, ties to even）；此前 I04 只比較方案而尚未決定的狀態已正式結束。此規則不決定可否切換捨入模式、特殊值、異常旗標、下溢／上溢及位元編碼選擇等其他語意。
- **J03-B、J04-A、K04-A、K05-A、L03-A、L04-B、L05-A、M01-A、M06-A**：`float` 為 `decimal64` 且不支援科學記號；常值允許連續底線、小數點相鄰底線及尾端底線（依 J/K/L 已定限制）。小數點前須有數字（`.5` 不合法），小數點後可省略數字（`1.` 表示 `1.0`）。**M06-A** 允許浮點常值前導零，例如 `00.5` 與 `0.5` 值相同。**M01-A** 使詞彙分析器在連續兩個點時優先辨識 `..` 為區間符號：`1..4` 分成整數 `1`、`..`、整數 `4`，保留 D04 不含右端點的既定語意；單獨 `1.` 仍為浮點常值。超過兩個點的串列、其他與點相鄰字元的詞彙規則及錯誤復原尚待確認；此規則不延伸到未批准的語法形式。
- 容器型別：`list[T]`、`dict{K,V}`。
- **Y/Z/AA/AB/AC/AD/AE/AF/AG/AH/AI/AJ/AK 各批次（D11 持續細化）**：`Optional` 僅能位於容器元素／字典值型別位置（Z01），其用途為候選型別聯集加缺失值 `none`。Z02 允許單候選及多候選；**AB01-A** 規定**至少一個候選型別**，`list[Optional[]]` 不合法；**AB02-B** 限候選型別為**非容器型別**，例如 `list[Optional[list[int]]]` 不合法（不自行定義尚未核准的型別分類）；AA01 禁直接 Optional 包 Optional，AA02 重複候選型別為靜態錯誤，AA05 候選排序不影響型別身分。**AB03-A** 規定在合法 Optional 元素／字典值位置直接使用非缺失候選值時，須符合**已列出的候選型別**，不額外執行隱含數值型別轉換；其他型別轉換、候選歧義與匹配細節待議。`none` 僅在已知合法 Optional 型別上下文使用（AA04），容器合法位置可直接以 `none` 表示缺失（Z04），或直接使用符合候選型別的值（AA06）。合法 Optional 值可用**`x == none` 判斷缺失**（Z03）、**`x != none` 判斷有值**（AA03）；**AB05-B** 確認 `none` 在這兩種比較**只能位於右側**，不允許 `none == x`／`none != x`，也不重新開放 `str == str` 或 `str != str`。**AB04-A** 確認 `x != none` 條件**成立分支中排除缺失可能**，但 `Optional` 的候選型別集合仍保留；分支外、別名、重新賦值、其他比較條件、縮限傳播與安全規則不據此決定。**AB06-A** 確認**相同 Optional 型別的值**可直接用於**另一個合法容器 Optional 元素位置**；跨容器複製／移動／借用、生命週期、插入語法／API 等未決，不自行擴張。 **AC01-A** 確認 `x == none` 判斷為假之 `else` 分支排除缺失可能、保留全部候選型別；**AC02-A** 在 `x == none` 成立分支確認 `x` 只有缺失值；**AC03-A** 在 `x != none` 不成立的 `else` 分支確認 `x` 只有缺失值。均僅適用已知合法 Optional 值的上述條件分支，不自動制定其他邏輯複合條件、分支後傳播或借用別名規則。**AC04-A** 在具有上述縮限資訊的分支中，若合法地對**同一已檢查變數重新賦值**，賦值後取消其既有缺失／非缺失縮限資訊；可否賦值仍依一般 `var`／`const`／`share` 權限，不推定別名修改或所有權安全。**AC05-A** 在 AB06 相同 Optional 型別值可直接使用於另一容器元素位置之外，也允許直接使用於另一個合法**字典值位置**；不新增字典插入操作或決定複製／移動／借用。**AC06-A** `none` **不可列為 Optional 候選型別**，例如 `list[Optional[int,none]]` 不合法；`none` 僅是合法 Optional 上下文的缺失值，此項不刪除既有一般 `none` 回傳用途。 **AD01-A** 離開 `if`／`else` 分支後恢復完整原 Optional 型別與缺失可能，不保留分支內縮限；並非移除已確定的 Optional 宣告型別。**AD02-B／AD03-B**：`and` 或 `or` **右側運算元均不繼承左側 Optional 縮限資訊**，但 D03 短路求值順序不改，不能據此推定右側可安全直接使用候選值。**AD04-A**：合法 Optional 值的候選集合若為目標 Optional 候選集合的**子集合**，可直接在合法目標元素／字典值型別位置使用（如 `Optional[int]` 至 `Optional[int,str]`）；缺失值仍為 Optional 語意，**不新增隱含數值轉型或容器寫入 API**。**AD05-B**：候選較多的 Optional **不得直接轉用**至較少候選的 Optional 位置，即使特定控制流程可證明值目前落於較少候選集合也不因此開放；明確轉換機制待裁決。**AD06-A**：在已經**排除 none** 且**靜態能確定唯一候選型別**的情況，可直接按此候選型別使用；不藉此自創拆箱語法、持有權／借用操作、複製／移動、對多候選的隱含轉型或安全檢查。 **AE01-A** 已核准 `not` 反轉合法 Optional 缺失比較時可依反轉後的真假分支縮限（例如 `not (x == none)` 為真時排除缺失），但不推定其他 `not` 運算、布林組合、別名與穩定性規則。**AE02-A** 已核准追蹤儲存於 `bool` 變數的 Optional 缺失比較結果，以便相關條件判斷使用其缺失資訊；比較來源值及布林值是否仍穩定、重新賦值、作用域與別名影響**尚待裁決**，不得先實作持續有效性的推定。**AE03-B** 即使 `while` 條件包含 `x != none` 或 `x == none`，**迴圈本體不因該條件自動縮限 Optional**；不改變條件求值、其他控制流程或既有 `if` 真／假分支規則。**AE04-B** `Optional` 候選**不得為自訂 `struct` 型別**，只限制 Optional 候選位置，不限制一般 struct 定義或使用；**AE05-A** 允許基本型別 `bool` 為 Optional 候選；**AE06-A** 允許 `int` 與 `float` 同時存在於 Optional 候選型別集合，例如 `list[Optional[int,float]]`，保留 decimal64 浮點規則及 AB03 **不得額外隱含數值轉型**。候選值判別、確切型別分類、其他縮限、借用／所有權與容器操作未決。 **AF01-A**：直接對**來源 Optional 變數**合法重新賦值後，**取消先前由 `flag` 儲存比較結果對該來源變數的縮限關聯**；不推定任何其他別名修改。**AF02-A**：儲存比較結果的**`bool` 變數本身**合法重新賦值後，**取消該 `flag` 的原始縮限關聯**；不意味其先前關聯永遠有效，也不禁止一般合法重新賦值。**AF03-A**：未失效的比較關聯可從宣告 `flag` 的作用域在**內層詞彙作用域**追蹤使用，仍遵守一般可見性、變數遮蔽及已選的重新賦值失效限制；別名／非同步與其他生命週期規則未決。**AF04-A**：對仍具有效缺失比較追蹤關聯的 `flag`，`not flag` 可依反轉真假結果用來縮限原 Optional；不擴充其他 bool 運算的跨運算元縮限。**AF05-A**：`int`／`float` 候選同時存在時，非缺失值**依來源的靜態型別**選擇相符候選；遵守 AB03 禁止新增隱含數值轉型，來源型別含多候選或歧義的處理另議。**AF06-A**：允許 `bool` 與 `int` 共同列為同一合法 Optional 的候選，例如 `list[Optional[bool,int]]`；其他候選相容／比較與型別判別細節不擅自增加。 **AG01-B**：將儲存 Optional 缺失比較結果的 bool 值複製到另一 bool 時，**僅複製 bool 值、不複製來源追蹤關聯**；不禁止原本合法的 bool 複製，原旗標關聯仍依原本有效性檢查。**AG02-B**：將旗標 bool 傳入函式參數時，**不跨函式參數傳遞縮限追蹤關聯**，不等於禁止函式呼叫或一般布林參數。**AG03-B**：函式回傳 bool 時**不保留 Optional 缺失追蹤關聯**，不等於禁止回傳 bool；函式呼叫及其對來源的副作用／別名安全另議。**AG04-A**：在同一 Optional 同時包含 `bool` 和 `int` 候選時，依非缺失值**來源的靜態型別**選擇對應候選；遵守 AB03 禁隱含數值轉型，不自行推導 bool/int 互轉。**AG05-A**：`str` 與 `float` 可同時列為合法 Optional 候選，例如 `list[Optional[str,float]]`，**候選選擇／判別細節另議**，不解除 Q05/T05 禁 `str == str`／`str != str`。**AG06-A**：允許**多個 bool 旗標分別追蹤同一 Optional 來源**，每個關聯各自檢查是否失效；AF01 的來源**直接合法重新賦值**會使指向該來源的既有追蹤關聯失效，AF02 的個別旗標重新賦值使該旗標的舊關聯失效；其他旗標的保留仍須符合自身有效性，不推定別名或非同步變更如何檢查。 **AH01-A**：在 `Optional[str,float]` 的兩候選中，依**非缺失來源的靜態型別**選擇對應候選，不加入隱含型別轉換；來源型別不明或歧義情境另議。**AH02-A**：允許 `bool`／`float` 並列為 Optional 候選，**具體判別另議**；**AH03-A**：允許 `str`／`bool` 並列為候選，**具體判別另議**；不從 AF/AG 已決的其他成對候選判別自行推導二者的判別。**AH04-A**：追蹤旗標與 Optional 來源的關聯**綁定原變數身分**，內層同名變數依 H06 遮蔽規則處理，**不得把原來源的縮限誤套用到新的同名變數**；不由此授權存取被遮蔽的外層來源，也不補定別名或借用規則。**AH05-A**：**每次函式呼叫完成後，一律取消呼叫者既存的 Optional 旗標追蹤關聯**，不論函式是否實際修改相關 Optional；此為保守的追蹤失效規則，**不表示函式具有特定副作用**，亦不取消 bool 值本身。**AH06-A**：Optional 候選型別**不設固定數量上限**；仍須至少一個候選、不可重複、限符合既有非容器及非自訂 struct 規則的合法型別，不能解讀為任何未核准型別皆可當候選。 **AI01-A**：`bool`／`float` 並列的 Optional 候選，依非缺失來源**靜態型別**選對應候選，**不隱含轉型**，補定 AH02 原未決的選擇。**AI02-A**：`str`／`bool` 並列的候選同樣依來源靜態型別擇候選、**不隱含轉型**，補定 AH03；不解除 `str == str` 或 `str != str` 禁令。**AI03-A**：當 Optional 具**三個以上候選**，若來源的靜態型別能**唯一符合一個**已列的合法候選，則直接選擇該候選；不自動解決零個／多個匹配或隱含轉型。**AI04-A**：在已知來源靜態型別**不符合任何合法候選**時屬**靜態型別錯誤**，不延至執行期；來源型別不明、候選歧義或靜態證明能力未定。**AI05-A**：在依 `x == none`／`x != none`（包括已核准的 `not` 反轉）建立**直接分支縮限**後，若在該分支內完成一次**函式呼叫**，也**取消該分支先前直接比較建立的縮限資訊**，不只取消 AH05 規定的旗標追蹤；不表示函式必然修改來源，不自行判定所有權／別名副作用，並維持 AD01 分支結束恢復完整 Optional 的規則。**AI06-B**：外層 bool 旗標之有效 Optional 比較追蹤**在內層詞彙作用域被追蹤使用後，離開該內層作用域即取消原旗標追蹤關聯**，即使在內層未發生已核准的其他失效條件亦然；bool 值本身不變。僅限此已指定的**跨入內層並離開**情境，不自行推導所有進出任意區塊都使未使用旗標失效，亦不更改 H06 名稱遮蔽、別名／借用生命週期。 **AJ01-A**：若待用於合法 Optional 候選位置的非缺失來源值之**靜態型別無法確定**，報**靜態型別錯誤**，不自動延遲至執行期或臆定來源型別。**AJ02-A**：若來源靜態型別**同時符合多個候選**，報**靜態型別錯誤**，不得自行選任一候選；保留 AI03 唯一匹配、AI04 無匹配的規則。**AJ03-A**：依 AI05／AH05 因函式呼叫取消既有直接分支縮限及旗標關聯後，可在同一合法控制流程位置**重新進行 `x == none`／`x != none` 等已核准的直接缺失比較**並按既有真／假分支規則**建立新的直接縮限**；不代表舊 bool 旗標自動復效，或新增縮限／副作用分析。**AJ04-B**：有效的外層 Optional 比較旗標關聯，**離開進入過的內層詞彙作用域後即取消原關聯，即使該內層沒有使用該旗標**；補定 AI06 原已決的「內層使用後退出失效」，但不取消其**在內層未失效期間**可依 AF03 使用的資格，也不取消 bool 值。**AJ05-A**：`struct` **方法呼叫**（沿用 S16 `instance.method(args)`）在**呼叫完成後**同樣適用 AI05／AH05 的規則，取消呼叫者原有 Optional 比較旗標關聯及呼叫前直接比較建立的當前分支縮限；只將方法呼叫歸入這項**保守追蹤失效規則**，不推定方法的實際副作用、可變借用、所有權或新方法語法。**AJ06-A**：將提供**Optional 非缺失候選型別專用檢查機制**，但**具體語法、關鍵字、輸入與結果型別、候選檢查與縮限的作用範圍及安全規則均待另議**；不自動建立型別判別操作、容器 API 或標準函式庫。 **AK01-B**：AJ06 的 Optional 候選型別專用檢查採**專用運算子形式**，實際符號、詞彙和優先順序未核准；**AK02-A** 僅適用於**合法 Optional 值**，不擴張到一般非 Optional 值。**AK03-A** 每次**只檢查一個合法候選型別**。**AK04-B** 必須**先依既有合法檢查排除 `none`** 才能使用專用候選型別檢查；排除缺失的靜態證明細節未定。**AK05-B** 該檢查**僅用於專用條件判斷，不產生可獨立儲存、傳參、回傳的 `bool` 值**；不能把它當成 AE02 的 bool 比較追蹤來源。**AK06-A** 在已核准適用的 `if` 條件內，**只有檢查成立的分支**將來源縮限至被檢查的單一候選型別；**不成立分支是否排除候選完全未決**，也不自行增訂 `not`、`and`／`or`、迴圈、重新賦值、函式呼叫後的專用檢查縮限規則。一般 Optional `== none`／`!= none` 與既有呼叫後追蹤失效規則均不變。
- **AL01-A～AL06-A（承接 AK01–AK06）**：Optional 單一候選型別專用檢查採運算子字詞 `is`（**AL01-A**，尚未核准完整語法、左右運算元順序、詞彙地位、結合性及優先序）；使用前須依**仍有效的直接缺失比較分支縮限**先排除 `none`（**AL02-A**，如 `x != none` 成立分支或 `x == none` 不成立分支），不得將 `not` 反轉或儲存結果的 `bool` 旗標追蹤直接當成此項專用前置證明；一般 Optional 缺失比較的 AE01、AE02、AF04 已核准規則不因此撤銷，AC04、AI05、AJ05 既有追蹤失效仍有效。`is` 在 `if` 不成立分支不進一步縮限候選型別集合（**AL03-A**），不代表撤銷進入該分支時仍有效的其他既有非缺失證明；成立分支維持 AK06-A 僅縮限受檢候選。**AL04-A** 禁止對 `is` 直接套用 `not`；**AL05-A** 禁止與 `and`／`or` 組合；**AL06-A** 禁止在 `while` 條件中使用 `is`。這些限制只針對專用 `is`，不變更既有一般邏輯運算、缺失比較或 D03 短路語意。`is` 不產生獨立 `bool`，不擴展 Optional 適用位置或候選數量。專用檢查的完整文法、型別運算元寫法、候選值取得與轉換、運算子優先序、錯誤時機、重新賦值／函式呼叫後專用候選縮限、別名／非同步、函式副作用與借用、容器 API、複製／移動、Unicode／UTF-8、所有權及標準函式庫仍未決。

- **AN01-A～AN06-A／B（2026-10-25，承接 AK～AM）**：**AN01-A** `is` 右側直接書寫**該 Optional 已列出的一個合法候選型別名稱**，不要求另加型別標記包裝；仍按 AM01 左合法 Optional 值、右候選型別規則，不新增型別名稱、候選轉換或取得機制。**AN02-B** 專用 `is` 作為 `if` 條件時**必須以圓括號包住整個專用檢查條件**；僅限制此專用條件，不改動一般 `if` 的括號要求或其他運算式括號語意。**AN03-A** 允許於 `else if` 使用專用 `is`，並沿用同一合法 Optional、單候選、AL02 的有效直接缺失比較前置證明、AN02 括號以及 AK06／AL03 成立與不成立分支縮限規則；**不表示**前一個 `if` 的縮限可自動延續至 `else if`，也不開放 `not`／`and`／`or`／`while` 組合。**AN04-B** `is` 左側若是**非 Optional 值**，拒絕並歸類為**語法錯誤**（為此專用檢查所選的診斷類別；不自行決定分析器實作階段）；與 **AM04-A**「右側候選型別非法屬靜態型別錯誤」是**不同錯誤情境**，不可混用。**AN05-B** 將專用 `is` 當作**獨立的普通 `bool` 運算式**時，歸類為**語法錯誤**；維持 AK05-B 僅專用條件、不產生獨立 `bool`，不自創賦值、傳參、回傳合法性。**AN06-A** 對僅有**一個已列合法候選型別**的 Optional，也**允許**符合所有既有前置條件的 `is` 檢查；不免除先排除 `none`，不推定編譯器可消除檢查，也不新增候選值提取、靜態常值傳播或其他使用位置。未選的運算子結合性、完整文法與優先序其他層級、括號其他用途、`else if` 其他縮限傳播、候選取得／轉換、診斷訊息與位置、別名／函式副作用／非同步、複製／移動／借用、容器 API、Unicode／UTF-8、所有權及標準函式庫仍未決；同條件已核准規則直接沿用。
- **AO01-A～AO06-A／B（2026-10-25；承接 AK～AN）**：**AO01-A** 專用 `is` 左側**僅允許已綁定的具名 Optional 變數**，不核准臨時計算結果、呼叫結果、容器存取表達式或其他複合來源；仍須符合已核准合法 Optional 位置與 AL02 非缺失證明，且不自行補定變數建立／取出 API。**AO02-A** `is` 右側候選型別名稱**不得另加括號**，例如專用條件內的 `x is (int)` 不合法；**AO03-B** 左側來源也**不得另加括號**，例如 `(x) is int` 不合法。此二項只限制**運算元自身**的額外括號，不取消 **AN02-B** 已核准的**整個 `if`／`else if` 專用條件須加圓括號**（如 `if (x is int)` 為條件片段，不表示來源取得與完整可執行語法已核准）。**AO04-A** 同一個 `if`／`else if` 條件鏈可**在多個分支分別使用合法的 `is` 專用檢查**；各次檢查必須獨立滿足適用位置、候選型別、AO05 前置位置及既有縮限有效性，不推定不同分支的證明自動繼承，也不允許 `not`／`and`／`or`／`while` 組合。**AO05-B** 使用 `is` 必須**緊接在建立直接非缺失證明的條件區塊內**，**建立該證明後至所檢查的專用條件之間不得穿插其他語句**；此限制是 AL02 有效直接缺失比較證明的**額外位置約束**，不撤銷一般 Optional 缺失比較縮限可以在原適用範圍內持續有效的既定規則，也不自行決定跨其他區塊／else if 的證明傳播、函式副作用、別名及借用。**AO06-A** `is` **右側完全缺少候選型別名稱**時，歸類為**語法錯誤**；不同於 **AM04-A**「有指定右側型別但該候選不合法」的靜態型別錯誤，以及 **AM06-A**「缺乏有效非缺失證明」的靜態錯誤。不補定錯誤訊息、解析器恢復策略及診斷先後次序。其他運算式形式、條件鏈縮限傳遞、型別值取得／轉換、複製／移動／借用、非同步、Unicode／UTF-8、所有權、容器 API、標準函式庫等仍未決。

- **AQ01-A／AQ02-A／AQ03-B／AQ04-B／AQ05-A／AQ06-B（2026-10-25；承接 AK～AP）**：**AQ01-A** 同一 `if`／`else if` 條件鏈中的合法 `is` 候選型別檢查**不強制依 Optional 宣告的候選順序排列**，承接 AA05 候選排序不影響型別身分；各次仍須符合 AO05／AL02，不另定候選優先次序或跨分支縮限。**AQ02-A** 同一條件鏈中，**一般條件分支可置於專用 `is` 分支之前、中間或之後**；僅補定分支排列，並非任何排列都自然滿足 AO05，所有 `is` 仍各自須依有效直接缺失比較證明及緊接條件區塊使用；不開放 `is` 與 `and`／`or` 在同一條件中組合。**AQ03-B** 專用 `is` 左側是**可靜態辨識為合法 Optional，但不是 AO01 核准的已綁定具名變數的表達式**時，診斷為**靜態型別錯誤**；不同於 AN04 已知非 Optional 左值的語法錯誤與 AP06 未宣告名稱的靜態名稱解析錯誤，不開放該類來源表達式。**AQ04-B** 當 AP05 已合法縮限到唯一候選的具名 Optional **再次合規檢查同一候選時**，編譯器須發出**不阻止編譯的冗餘檢查警告**；AP05 合法性仍有效，仍要求 AO05／AL02，警告的文字、識別碼、抑制方式及是否支援其他警告保持未決，不因警告判定或自動消去求值。**AQ05-A** 同一條件鏈 `is` 專用檢查次數**不另設固定數量上限**；仍受已核准的語法、同一具名來源 AP02、每次 AO05 緊接位置等限制，不表示放寬一般編譯資源或巢狀深度限制。**AQ06-B** **僅限同一專用 `is` 左側使用未宣告名稱、且右側同時完全缺少候選型別名稱**這一雙重錯誤時，**優先回報左側未宣告的靜態名稱解析錯誤**（AP06），而非右側缺漏的語法錯誤（AO06）；不改變兩項各自的診斷類別，不推定通用「名稱解析優先於語法」規則、解析器實際階段／復原策略或多重診斷一般次序。除這六項外，完整語法、跨分支證明傳遞、候選取得與轉換、警告政策其他細節、別名／非同步、借用與所有權、容器 API、複製／移動、Unicode／UTF-8 及標準函式庫仍未決。

- `var` 容器可進行寫入操作（例如 `append`、`pop`）；`const` 容器僅允許查詢操作（例如 `get`、`index`）。具體方法清單與返回型別尚未核准。

## 二、基本語法及宣告

- 大括號 `{}` 劃定作用域區塊；不沿用舊版以縮排界定區塊的提案。
- **D01-A、E07-A、F06-A**：語句以換行分隔，不採分號作為語句分隔符號；**圓括號 `()` 內允許跨行**（如多行函式呼叫）；**空白行一律忽略，不算語法錯誤**。括號外運算式跨行、註解與換行邊界的其他詳細規則仍待確認。
- **D02-A**：布林常值使用小寫 `true`、`false`；不以 `True`、`False` 表示布林常值。
- `#` 為單行註解、`"""` 為多行註解標記；N/O/Q/T/U 詞彙規則仍有效。Unicode 跳脫 `\u{...}` 的數字最多六位（U01），允許前導零、十六進位大小寫；缺少右大括號依 U02 為語法錯誤。**V01-A** 已明定 Unicode 跳脫內包含空白（如 `\u{ 41 }`）為**語法錯誤**，補定 U03 的處置；**V02-B** 已明定內含底線（如 `\u{1F_600}`）**以替代字元 �（U+FFFD）處理**，補定 U04 與 T03 的交會，不代表底線成為合法十六進位數字；**V03-A** 已明定超過六位數字（如 `\u{0000041}`）為**語法錯誤**。T02 `\u{}`、T03 `\u{GG}` 及 Q02 無效碼位的替代字元規則、N04 未知跳脫錯誤規則均保留。其他未明確選擇的 Unicode 格式診斷與 Unicode 版本仍未決。
- **J06-B 與 K06-B**：J06 要求 `{}` **語句區塊**至少有一條語句，空白行與註解不算語句，`if true{}` 應拒絕；**K06-B** 另要求 `struct` 宣告至少有**一個欄位或方法**，所以 `struct Empty{}` 為靜態／語法拒絕案例，但僅有一個欄位或僅有一個方法都滿足此項非空要求（仍須遵循各自其他規則）。空容器字面值及其他非語句的大括號仍未決。
- `var`：可變，受所屬 `{}` 作用域限制。
- **H03-B、I05-A**：所有一般 `var` 變數宣告都**必須標註型別**，可寫 `var x:int = 3`，也可寫 `var x:int` **延後初始化**；未能在讀取前靜態證明已初始化時必須拒絕讀取，未初始化不自動等於 `none` 或任何預設值。不得以 `var x = 3` 推導型別。結構實例 `var` 必須標註型別的舊規格保持有效；I01/I02 另確認一般 `const`／`share` 也須標註型別。I05 僅定一般 `var` 延後初始化，不自行決定 `var s:Stru`（無建立式）的結構實例宣告合法性、逐分支檢查演算法、借用或資源安全細則。
- **H05-A、H06-A**：同一 `{}` 作用域內重複宣告同名變數為**靜態錯誤**；但巢狀 `{}` 區塊可宣告與外層同名的變數，**內層名稱遮蔽外層名稱**。變數跨 `var`／`const`／`share` 分類的衝突範圍、遮蔽時的借用／移動／生命週期安全與其他宣告類別的名稱解析，尚待獨立確認。
- `share`：可變，宣告作用域外可以讀取。**X06-A、Y04-A** 明確確認：**模組級 `share str` 可由同模組其他函式修改，且不需要額外寫入意圖標記**，一律依既有模組宣告作用域寫入權限判定；**跨模組仍不能修改**。不推定區域級 `share`、其他型別、借用／別名、非同步或資源安全規則。**H04-A、I02-A**：`share` 宣告必須標註型別並立即初始化，例如 `share count:int = 0`。
- `const`：不可變，作用域同 `var`。
- **E06-B、F01-A、F02-A、I01-A（衝突已解決）**：一般 `const` 變數宣告時**必須標註型別並給初始值**，例如 `const x:int = 3`；不允許 `const x = 3` 或宣告後才首次賦值。`struct` 的每個 `const` **欄位宣告時必須有預設值**，由 F01 明確**修訂並取代 D09-A 原先允許延後首次賦值的內容**；`const` **結構實例變數**宣告時也必須立即提供初始值，例如 `const u:User = User()`。F02 僅要求有初始化運算式，不自行決定該運算式產生的實例是否已初始化全部 `var` 欄位，也不放寬 S18 的遞迴不可變限制。

```voiles

share f:float = 1.23
const s:str = "hello world"
```

## 三、函式、結構與模組

- 函式宣告為 `fn 名稱(參數)->回傳型別{...}`；例如 `fn main()->none{...}`。
- **F05-A、H02-A**：一般函式**呼叫的引數列表**允許尾逗號，例如 `add(1,2,)`；一般函式**宣告的參數列表**也允許尾逗號，例如 `fn add(a:int,b:int,)->int{...}`。此規則沿用既定函式宣告語法，不額外決定參數預設值、位置／具名混用、回傳型別或方法多載解析。
- **已決定：一般 `fn` 預設公開**，可由其他模組呼叫，**不需要 `share fn`**。
- **已決定：函式名稱以 `_` 作為前綴時為內部函式**，不對其他模組公開；一般函式及 `async fn` 均依此命名規則。
- **已決定：`struct` 方法遵循相同規則**：方法預設公開；名稱以 `_` 開頭的方法為內部方法，不對其他模組公開。
- **已決定：內部函式／方法的可見範圍是宣告所在模組**。同一模組內的其他函式及結構方法可以呼叫 `_` 前綴方法；其他模組不可呼叫。這是模組內部可見性，不是僅限所屬結構的私有性。
- **已決定：`struct` 欄位同樣採 `_` 前綴可見性方案 B**。欄位名稱未以 `_` 開頭時預設公開；以 `_` 開頭時只允許所屬模組內存取，同模組的其他函式或結構皆可存取，跨模組禁止。此規則僅控制可見性，不變更 `var`／`const` 的可寫性語意，亦不賦予跨模組修改權限。
- **已決定：`struct` 型別名稱採方案 A**，與函式、方法及欄位共用 `_` 前綴的模組可見性規則：例如 `struct User` 預設公開，`struct _InternalUser` 僅限所屬模組使用，其他模組不得引用此結構型別。這不代表擁有公開型別就可繞過其欄位與方法的獨立權限規則。
- `_` 前綴可見性目前適用一般函式、非同步函式、`struct` 型別名稱、方法與欄位；**不自動擴及**一般變數或其他識別字。方法接收者由 S11 確認為自動提供，S12/S15 限定為只借用及不得消耗，S16 確認呼叫形式僅為 `instance.method(args)`；其餘借用可變性、別名與安全細節仍待定。
- **已決定：`struct` 方法存取自身欄位時，必須明確使用 `self.欄位名稱`**，例如 `self.name`；不採用省略 `self` 的隱式欄位存取。後續 S11 已確認 `self` 自動提供、不寫入使用者參數表，S14 已確認方法借用離開方法時歸還。**S12／S15 已採衝突處理方案 A**：方法接收者 `self` 只允許借用、禁止方法消耗或移動整個 `self`；結構實例在方法呼叫之外仍可依既定通用規則明確移動。可變借用權限、可變性及非同步生命週期安全細節仍未決。
- **已決定：`struct` 方法的宣告位置採方案 A**，欄位與方法直接寫在同一個 `struct 名稱{...}` 區塊內；不使用額外的 `impl` 或其他結構外專用實作區塊。方法宣告沿用 `fn` 關鍵字；S11 確定方法簽章不必列出 `self`，但方法接收者已限制為借用、不允許消耗整個 `self`，其他借用權限、別名及生命週期安全細則仍待決。
- **已決定：`struct` 欄位與方法同名規則採方案 A**。同一個 `struct` 內欄位與方法共用名稱空間；若欄位和方法宣告相同名稱，編譯器應回報名稱衝突並拒絕程式。此項禁止欄位與方法同名。後續 S02 已禁止欄位彼此重複，S20 已允許依參數簽章區分同名方法；相同簽章如何判斷、方法多載解析以及跨結構／模組名稱規則仍待確認。

```voiles

    var name:str       # 公開欄位
    var age:int = 18    # 每次建立實例重新求值的預設值
    var _token:str     # 僅模組內可見的欄位

    fn is_adult()->bool{
        return self.age >= 18
    }
}
```

> 此例僅示範已確認的欄位宣告、預設值、模組可見性、方法位置與 `self.欄位` 語法；其餘初始化求值順序、`const` 欄位首次賦值、方法借用可變性與資源安全細則仍待定。`>=` 的型別與比較語意尚未完整確認。
- 結構宣告以 `struct Stru{...}` 表示，可建立實例並以 `S.a` 等形式存取欄位；結構實例的 `var` 變數宣告須明確標註型別，例如 `var s:Stru = Stru()`，不可改用 `var s = Stru()` 或直接以 `s = Stru()` 作為變數宣告。**H03-B 已將明確型別標註義務擴及所有一般 `var` 宣告**，不只結構實例；**I01-A/I02-A** 也分別確認一般 `const`、`share` 的明確型別標註義務。其他未列入的宣告種類仍待議。
- `Stru()`／`Stru(欄位名稱=值)` 的形式已透過 S05、S06 確認，允許空參數建立及具名欄位參數；初始化不完整與預設值按 S07–S09 辦理。這不構成自訂建構方法（S10 禁止）的核准。**D07-A** 確認具名參數可任意排列；**D08-A** 確認欄位有具名值時不求值該欄位原預設值；**D10-A** 確認重複提供同一欄位的具名參數為靜態錯誤；**E04-A** 確認使用不存在的具名欄位為靜態錯誤；**E05-A** 確認具名參數列表允許尾端逗號（如 `Stru(name="A",)`）。欄位求值的其他順序及資源生命週期仍待決。結構實例的其他宣告種類是否需標註型別，仍須獨立確認.

- 模組可使用 `import a`，並有 `import a from b as c` 的別名方向；搜尋路徑、具體語法細節待確認。

## 四、流程控制、例外與非同步

- 條件判斷：`if`、`else if`、`else`。 **AN02-B／AN03-A**：僅當 `if` 或 `else if` 使用 Optional 專用 `is` 檢查時，整個專用條件必須以圓括號包住；可使用的 `else if` 專用條件仍須滿足先行有效直接缺失比較的非缺失證明，不由前一個分支自動繼承。一般 `if`／`else if` 與一般條件的括號要求不受此項改動。 **AO04-A／AO05-B**：同一 `if`／`else if` 鏈允許多個各自合法的 `is` 專用檢查，但每次均受「在建立有效直接非缺失證明的條件區塊內緊接使用，兩者間不得插入其他語句」限制；不自動核准跨分支縮限傳遞、一般 `if` 額外位置限制或新容器存取方式。 **AP01～AP03、AP05**：同鏈可重複相同候選、混合一般條件分支與 `is` 分支，惟所有 `is` 使用同一具名 Optional 變數、各自滿足 AO05／AL02；已縮限唯一候選時重複檢查也不得跳過這些先決條件。混合一般條件分支不等於准許 `is and`／`is or`；不同分支之縮限傳播未決。 **AQ01-A／AQ02-A／AQ05-A**：合法同鏈專用 `is` 的候選排列順序不受宣告先後限制、一般條件分支可置於 is 前／中／後、專用檢查次數不額外設固定上限；這些均以每次 `is` 各自符合 AO05／AL02 等前置條件為前提，不新增任何一般條件資料流推論。
- 迴圈：`for`、`while`；支援 `break` 與 `continue`。
- **D04-A**：`for i in 1..4{...}` 等區間表示法使用**不包含右端點**的規則，示意序列為 `1,2,3`；步幅、倒數區間及其他型別仍待確認。
- `match case` 參考 Python 的比對概念；voiles 的正式區塊語法與模式支援範圍待確認。
- 例外處理使用 `try{...} except SomeErrorType{...}`，要求明確例外型別。**`exception` 是先前筆誤，不是關鍵字**。
- 型別轉換以函式進行，要求明確錯誤處理，示例為 `.to_int()` 與 `except TypeConversationError`（錯誤型別拼寫暫依使用者原例保留，名稱是否調整待確認）。
- 非同步使用 `async fn`、`await`。

## 五、字串與索引

- 一般字串插值依 Python `f-string` 概念；樣板字串依 Python `t-string` 概念。
- 使用者提出 `const s:str = "函式已經呼叫 {count} 次"` 作為樣板字串形式，並要求樣板為 `const`；儲存插值資訊、何時求值、是否另設型別仍待確認，不得自行認定 Python t-string 的物件型別等同 `str`。
- `str` 具雙層索引：第一層取得字元，第二層取得該字元 UTF-8 編碼中的位元組。
- **D12-B、U05-A、U06-A、V04-A、V05-A、W04-A、X01-A、X02-A、X03-A、X04-A、X05-A、Y01-A、Y02-A、Y03-B、Z05-A、Z06-A**：`str` 第一層讀取以 Unicode 字素叢集計算、回傳獨立複製的 `str`（X05）；第二層回傳 `int`（0–255）且不允許單位元組索引賦值（X01/X03）。第一層索引賦值受一般 `var`／`const`／`share` 權限限制，替換值必須恰好一個字素（X02），允許 UTF-8 位元組長度不同（X04），違反單字素條件靜態可判時靜態報錯、其餘執行期報錯（Y02）。允許替換後字素與相鄰內容合併（Y01），**Z06-A 規定每次替換完成後立即對修改後完整字串重新判定字素邊界**；不自行決定修改的原子性、索引失效、分割過程記憶體安全及 Unicode 跨環境差異。Y03 使第一層索引賦值可為運算式、結果是寫入的字素 `str`，**Z05-A 明定其結果是獨立複製的字素 `str`（非借用）**；此結果持有方式的選擇不決定其相對於重分割的精確求值順序、複製成本、隱含轉型或其餘所有權／資源清理規則。

```voiles
const s:str = "你"
# 底層示意：[[\xE4,\xBD,\xA0]]
print(s[0])     # "你"
print(s[0][0])  # \xE4
print(s[0][1])  # \xBD
print(s[0][2])  # \xA0
```

> **Z06** 已確定每次第一層字素替換完成就立即對修改後字串重分割字素叢集；**Z05** 已確定第一層字素索引賦值運算式結果為獨立複製的 `str`，而第一層索引讀取依 X05 亦為獨立複製。X03 第二層索引仍只讀，結果為 `int`（0–255）。寫入與分割之間的具體求值順序、借用、索引失效、UTF-8 更新與資源安全仍待核准。

## 六、所有權及借用

- `copy`：一般變數呼叫**預設複製**，取得同值的新所有權；哪些型別支援複製與複製成本待確認。
- `move`：**永久轉移**所有權，來源失效；目標是否可變依目標的新宣告決定。語法採 `a.move()` 的設計範例。
- `borrow`：暫時借用，借用有效期間來源不可使用；借用變數的可變性必須跟隨來源，不同則錯誤。語法採 `a.borrow()`。
- 一般借用的歸還點：**借用變數最後一次使用**。
- 函式參數預設借用，並以**函式執行離開該函式作用域**為借用歸還點。
- 函式接受移動的語法示例如下；借用跨分支、容器元素、非同步與回傳值的細節仍待確認。

```voiles
fn test(a.move():int)->int{
    return a+10
}

fn main()->none{
    var a:int = 5
    var b:int = test(a.move())
    print(a)  # 錯誤：所有權已轉移
    print(b)  # 15
}
```

## 七、運算子

- 邏輯：`and`、`or`、`not`。
- **D03-A**：`and`／`or` 確認採**短路求值**：當左側已決定布林結果時，不計算右側，例如 `false and check()` 不會呼叫 `check()`；運算元的完整型別約束仍待決。 **AD02-B、AD03-B** 後續確認：`and`／`or` 右側**不傳遞左側的 Optional 縮限資訊**；這只規範靜態型別檢查，不取消 D03 短路求值。 **AE01-A** 對合法 Optional 缺失比較使用 `not` 時可依反轉真假結果縮限，**AE02-A** 允許追蹤儲存於 `bool` 變數的缺失比較結果（穩定性未決）；**AE03-B** `while` 迴圈本體不因條件中的 Optional 缺失判斷而自動縮限。均不修改 D03 或 AD02／AD03 短路及縮限傳遞限制。 **AF01/AF02** 分別確認來源 Optional 重新賦值、儲存比較結果的 bool 重新賦值都取消相關追蹤；**AF03** 允許未失效的關聯在內層作用域繼續追蹤，**AF04** 允許 `not flag` 反轉該關聯的缺失判斷；`and`／`or` 右側不承繼左側縮限及 D03 短路求值維持。 **AG01/AG02/AG03** 分別確認 bool 比較結果複製、函式參數傳遞及函式回傳不攜帶 Optional 縮限追蹤關聯；bool 值的正常操作仍依既有型別規則。**AG06** 多個原生旗標可各自追蹤同一來源，仍逐項套用 AF01/AF02 的直接重新賦值失效條件。 **AH04** 追蹤依來源變數身分，內層同名遮蔽不得誤套用到新變數；**AH05** 每次函式呼叫完成後取消呼叫者原有 Optional 比較旗標關聯，即使沒有證據表明來源被修改。這僅限制縮限追蹤，不改變 bool 或函式呼叫本身的語意。 **AI05-A** 在函式呼叫完成後也清除 Optional 直接比較於當前分支建立的縮限，擴充 AH05 原僅旗標關聯失效的範圍；**AI06-B** 已跨入內層作用域使用的外層旗標，離開內層後取消原追蹤關聯，bool 值仍存在；不更動布林短路規則或一般作用域生命週期。 **AJ03-A** 允許函式呼叫後對來源 Optional 重新進行已核准的直接缺失比較，按結果新建分支縮限；**AJ04-B** 外層旗標經內層作用域退出後不論有無使用皆取消追蹤（bool 值不變）；**AJ05-A** struct 方法呼叫完成也適用 AI05／AH05 的追蹤失效，不能視為推定方法具有副作用。 **AK01–AK06** 將 AJ06 的專用候選型別檢查細化為**未定具體符號的專用運算子**，只用於合法 Optional 非缺失值的**單一候選專用條件判斷**，**沒有獨立 bool 結果**；只確認 `if` 條件**成立分支**縮限至該候選。上述為 AK 階段未決部分；**AL01–AL06 已補定專用字詞 `is`、有效直接缺失比較先決縮限、if 不成立分支不額外縮限，以及禁止 `is` 的 not／and／or／while 用法**，但其餘運算子語法與安全條件仍未定；不改寫一般 D03 短路及 Optional 缺失比較規則。
- 算術：`+`、`-`、`*`、`/`、`**`、`//`、`%`。
- **D05-B**：允許複合賦值 `+=` 用在回傳運算式中，例如 `return i+=1`；此形式先更新 `i`，並回傳更新後的值。這不自動決定其他複合賦值運算子是否都可作為運算式，亦不免除對 `i` 的寫入權限檢查。
- **I06-A**：不相等比較運算子採 `!=`（例如 `a != b`）；不採 `<>`。運算元可比較的型別、值相等語意及優先順序仍待定。
- **O06-B、Q05-B、Q06-B、T05-A、Z03-B、AA03-A、AB04-A、AB05-B**：`str` 不支援 `+` 串接、`==`／`!=` 文字比較或 `*` 重複；已知合法 Optional 值可用**`x == none` 判斷缺失**，用**`x != none` 判斷有值**。**AB05** 只允許 `none` 在這兩種比較的**右側**，`none == x`／`none != x` 禁止。**AB04** 在 `x != none` 為真的分支內排除缺失，但**不刪減非缺失候選型別集合**；其他縮限及有效期未決。這是 Optional 專用檢查，不准由候選包含 `str` 推出 `str == str` 或 `str != str` 合法，也不准自行補定任意 Optional 候選值比較、運算優先順序或其他型別相等規則。 **AC01/AC02/AC03** 已分別確定 `x == none` 假分支排除缺失、真分支確認缺失，及 `x != none` 假分支確認缺失；**AC04** 對合法重新賦值的相同變數立即取消先前縮限，候選型別與其他條件縮限仍待議。 **AD01** 規定退出 `if` 分支即恢復完整 Optional，**AD02/AD03** 不將左右布林短路運算元之間的縮限資訊傳遞；**AD06** 排除 none 後若靜態確定唯一候選即可直接按該型別使用，其他縮限及轉型規則不擅定。
- 使用者範例包含比較、複合賦值與 `..`，但完整運算子清單（已確認者除外）、優先順序及型別規則待確認。 **AM03-A** 僅補定 `is` 與 `==`／`!=` 在同一優先層級，不補定其他運算子階層、結合性或混合條件合法性。

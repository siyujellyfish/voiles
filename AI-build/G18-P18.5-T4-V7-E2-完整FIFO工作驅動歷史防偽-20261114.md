# G18／P18.5-T4／V7-E2：完整 FIFO 工作驅動歷史與終態退休防偽（2026-11-14）

## 已驗收起點與實際缺口

以 `main 919efb386985a6772b3b4a31623e1d4ca0c3baf8` 作為真實最新基準，三必要 CI「文件與工作紀錄」「Rust 前端建置」「Rust 獨立架構測試」皆 `completed/success`。主線已有 PR #779～#781 的 T3 HC14 工作框架生命期、T4 原取消工作 R05／P16 雙帳及 shutdown 整批終態預檢；但 `PrivateScalarCooperativeQueue::verify_terminal_evidence` 以 `drive_order.iter().rev().find(id)` **只取最後一筆** poll 來驗證終態。

合法 FIFO 真工作在 Prepared 之後，只能依原 Checker 安全點多次 `Suspended`，然後唯一一次 `Completed` 或在尚未完成的安全暫停點取消。工作一旦 `Completed`，不能再 poll；原 `PrivateScalarGraphContinuation::poll` 對 Succeeded／Failed 本就有明確拒絕。因此任意同一 ID 的 `Suspended → Completed → Completed`、`Suspended → Completed → Suspended` 都是無法由真佇列簽發的偽造歷史。只看最後 poll，對重複 Completed 仍可能誤判合法；若被改為 Cancelled 且後續偽造 Suspended，也可能藉終態標籤躲過「曾完成」記錄。

## 不新增語意的安全修補

`src/struct_stage/execute_call_scalar.rs::PrivateScalarCooperativeQueue::verify_terminal_evidence` 改為逐工作 ID 收集完整 `drive_history`，在共通退休／shutdown 預檢 **讀取全歷史而非只讀最後一項**：若存在 `PrivateScalarGraphPoll::Completed`，它必須是唯一一筆且正好是最後一次；之前任意真 `Suspended` 仍合法。原 Succeeded／Failed 必須最後為 Completed 且有符合結果型別與完整 R05/P16 證據；原 Cancelled 必須由真 Prepared 零 poll／零資源，或真 Suspended 與完整唯一 Unwind、P16 ResourceId 清理證據交叉支持；`cancellation_order` 必須唯一一次。這些原驗收政策一律保留。

守門在 **`jobs.remove`、`outcome.take`、`cancel` 之前**執行，故偽造重複／過期 poll 歷史必先返回 `Engine`，不得移交假結果、吞掉原 ResourceId 或因 `shutdown` 先取消其他 Prepared 工作造成部分狀態變更。這不開放背景 async、不新增例外／await 語意或任意取消點，也不構成 T4 原義務正式 Closed。
